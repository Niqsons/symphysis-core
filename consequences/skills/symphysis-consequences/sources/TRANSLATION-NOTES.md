Решения этой редакции, которых журнал дословно не задаёт (записаны в отчёте части B,
снимаются человеком):

- правило рекомендации и цена Specify (F-130.A называет скиллы проб) перенесены
  на кандидатов этого шага: исходы те же (F-16.A), а заполненный образец
  `tests/fixtures/consequences-filled/decisions.json` уже называет цену;
- префикс записи `[ветка]`, `[допущение]`, `[pre-mortem]`: предположение д плана
  считает записью пробы префикс `[`, а имена префиксов выбраны здесь;
- в опись идут ветки кода, который конструкция вызывает или на чьё поведение рассчитывает:
  журнал не называет границу внутри файла, а без неё большой файл дал бы всю свою обработку ошибок;
- строка описи — одна на ветку, шаблон говорил «пункт на механизм»: цитата одна на строку,
  а исход и сверка у каждой ветки свои;
- допущение с последствием «если это не так, …»: правило `gsd-assumptions-analyzer.md:93`,
  образец из F-02, хотя заполненный образец в тестах пишет только первую половину.

## Соответствие терминов — смысл тот же

| В источнике | У нас |
| --- | --- |
| assumption | допущение, подстрока `допущение:` |
| If wrong | вторая половина той же фразы: «если это не так, …» |
| Why this way, evidence | `путь:строка «цитата»` или путь файла |
| codebase hints | вывод `journal.py code-sites` |
| plan, phase | изменение OpenSpec |
| reason for failure | причина провала |
| acceptance criteria | `#### Scenario:` |
