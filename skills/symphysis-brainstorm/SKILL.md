# symphysis-brainstorm

Брейншторм шага `decisions` схемы symphysis и второго круга в конце шага
`research` — после отчётов исследования.
Механики — из GSD Core: перспективы интервью и порция вопросов
(`upstream/gsd-core/gsd-core/workflows/spec-phase.md:25-52`, `:136`),
«человек — визионер, модель — строитель», серые зоны и ограда объёма
(`discuss-phase.md:52-99`), обратимость решения
(`discuss-phase/templates/context.md:58-70`). Оригиналы — `references/`;
где смысл инструкции изменён против источника — `TRANSLATION-NOTES.md`.

## Главное правило

**Решает человек, не модель.** Модель читает материалы, формулирует
развилки с вариантами и уликами, пишет факты с цитатами и одну
рекомендацию — а `decision` в журнале появляется только из слова
человека через `apply`. Числового гейта ясности нет: круг кончается
счётом новых решений и фактов и словом человека (F-07).

**Развилка обсуждается в просмотрщике, не в чате.** В чат идёт только
то, чего нет ни в файлах, ни в виде выбора между вариантами.

## Файлы и команды

`<каталог изменения>` — `openspec/changes/<имя>/`. Журнал —
`<каталог изменения>/decisions.json`, шаблон уже лежит там (`title`,
`source`, `intro`, `records: []`). CLI — `python .symphysis/tools/journal.py`:

```bash
# после каждой записи: схема и правила (код 1 — журнал негоден, чини), улики (сигнал)
python .symphysis/tools/journal.py check <каталог изменения>/decisions.json
python .symphysis/tools/journal.py render-md <каталог изменения>/decisions.json --out <каталог изменения>/decisions.md

# круг просмотрщика: человек решает в HTML, промпт возврата вносит apply
python .symphysis/tools/journal.py render-html <каталог изменения>/decisions.json --out <каталог изменения>/decisions.html
python .symphysis/tools/journal.py apply <каталог изменения>/decisions.json <каталог изменения>/answers/<дата>.md
```

JSON правят только модель (записи, факты, парковки, обратимость, `notes`)
и `apply` (слово человека). `decisions.md` и `decisions.html` — рендер,
в них не пишут.

## Порядок круга

**Круг** — один проход по пяти перспективам; вопросы человеку идут
**порциями** по 2–3 (`spec-phase.md:136` «Each round: 2–3 questions
max»). Порция кончается ответом человека.

### 1. Прочитай материалы до первого вопроса

**Первым — `intent.md`** (`<каталог изменения>/intent.md`, F-13.A).
Каждый критерий готовности из его раздела «Критерии готовности» —
факт `addressee: постановка` (F-17.A, значение строчными, без пробелов):
`question` — «Критерий готовности: <критерий>», одна улика: `path` —
`openspec/changes/<имя>/intent.md` (от корня проекта, как у всех улик),
`quote` — строка критерия дословно; `status: решён`. Факты постановки —
первые записи журнала, по одному на критерий. `intent.md` не правится:
переработанное намерение живёт записями журнала, файл остаётся словами
человека на входе.

- **`intent.md` пуст** (0 байт или одна строка заголовка): форк засчитывает
  `intent` по существованию файла, а читать нечего — сначала спроси
  намерение и сохрани ответ дословно по шаблону `intent.md` (слова —
  в «Намерение», критерии — в «Критерии готовности»), затем круг
  (F-24.E). Это единственная запись в `intent.md`; дальше он не правится.
- **Критериев ноль** — в `intent.md` их нет (раздела нет, он пуст,
  в нём одна мотивация) и фактов `addressee: постановка` в журнале нет:
  первый вопрос человеку в чат — «назови критерии готовности»; в `notes[]` —
  строка «намерение без критериев» с датой (F-43.E). Ответ сохрани
  как есть в `<каталог изменения>/answers/<дата>-criteria.md`: каждый
  названный критерий — факт `постановка` с цитатой из этого файла;
  ответ «Без критериев готовности» — тоже факт `постановка` с этой
  цитатой: критерии заполнены. Факты постановки в журнале уже есть
  (критерии названы в `answers/<дата>-criteria.md`) — вопрос не задаётся,
  второй строки `notes[]` нет: `intent.md` не правится, и без журнала
  второй круг спросил бы снова. Строка «Без критериев готовности»
  в самом `intent.md` — заполненные критерии: вопроса нет, факт — по ней.
- **Второй круг** перечитывает `intent.md`: факт постановки с той же
  цитатой второй раз не заводится (F-44.E). Текст критерия изменился —
  новый факт только по слову человека: спроси в чат, заводить ли его.

**Схема решения — на первом круге, после `intent.md`** (F-01, F-22). Проверь
`<каталог изменения>/scheme.md`: один блок mermaid `flowchart TD`, схема нужна
человеку, шаги от неё не зависят.

- Файла нет, сценарий в `intent.md` есть: составь файл по сценарию и дай
  на него ссылку в чат.
- Файла нет и сценария нет: предложи своё видение сценария и задай вопросы;
  файл и ссылка — после составления.
- Файл есть: не меняй его и дай на него ссылку. Файл человека и файл
  оборвавшегося круга не различаются (F-57).

Перед записью проверь ещё раз: файл появился, пока схема составлялась, —
не перезаписывай, покажи свой вариант в чате (F-58). Дальше файл меняется
только по слову человека: он правит его сам и сам об этом говорит. Просит
поправить — правишь файл и даёшь ссылку. При закрытии круга о схеме
не спрашивай и утверждения файла не жди (F-102).

Затем — запрос, каталог изменения, файлы и каталоги, которые назвал человек.
«Scout the codebase BEFORE the first question — grounded questions
only» (`spec-phase.md:542`). Найденное — сразу в журнал фактом с уликой
(путь и дословная цитата), не в памяти. Заполни `title` («Журнал
решений: <изменение>») и `intro`: от какого корня считаются пути улик,
какие материалы читались.

### 2. Пройди перспективы по порядку

| Перспектива | Что вскрывает | Вопросы |
| --- | --- | --- |
| Исследователь (Researcher) | текущее состояние | что уже есть в материалах по теме; разница между сегодня и целью; что сломано или чего нет — откуда работа |
| Упрощатель (Simplifier) | минимальный объём | простейшая версия, решающая основную задачу; что останется, если срезать половину; что сделает изменение успешным без приятных мелочей |
| Хранитель границ (Boundary Keeper) | периметр | что в этом изменении точно не делается; какие соседние задачи тянет решить, а не надо; как выглядит «готово» — что сдаётся |
| Аналитик отказов (Failure Analyst) | края, ломающие требования | худшее, если требования поняты неверно; как выглядит сломанная версия; за что атака отвергнет артефакт |
| Закрывающий (Seed Closer) | остаток | запись F-NN открыта — можно решить сейчас; о чём пожалеешь, если не решить до планирования |

Оригинал вопросов — `references/spec-phase.md`. Перспектива без
вопросов к этому изменению пропускается молча.

### 3. Маршрут каждого вопроса

- **Ответ в файлах** — человека не спрашивай: прочитай и запиши факт
  с уликой. Не прочитать сейчас (материалов нет, объём велик) —
  парковка `материалы`: бриф исследованию.
- **Выбор между вариантами** — развилка: запись с вариантами, уликами,
  одной рекомендацией; идёт в просмотрщик, в чате выбор не предлагай.
- **Знает только человек, и это не выбор** (чего он хочет, что главное,
  как выглядит «готово») — вопрос в чат, порцией. Ответ — развилка
  с одним вариантом или с вариантами, которые ответ назвал; слово
  человека дословно — в `apply` строкой `- F-NN: A — «слово»`
  (безальтернативная развилка тоже пишется как решение, F-10).
- **Канон ИБ** (инъекции, пути, токены, права) — парковка `ИБ`; записью
  журнала не становится, его закрывает чек-лист `security.md`.
- **Новая возможность, не уточнение этого изменения** — парковка
  `человек` на записи, где всплыла: «новая возможность: …». Эвристика
  GSD (`discuss-phase.md:69`): уточняет ли это, *как* сделать
  запланированное, или добавляет то, что могло бы быть своим
  изменением. Объём изменения в записях не растёт — ограда объёма
  в `references/discuss-phase-gray-areas.md`.

### 4. Что пишется в запись

Формат — `journal.schema.json` symphysis (ключи английские, значения
русские); `check` сверяет по нему.

**Развилка** (`kind: развилка`, `status: открыт`, `addressee: человек`):
`question` — конкретная серая зона этого изменения, не категория
(«интерфейс», «поведение» — нет; «что видит человек на пустом
журнале» — да, `discuss-phase.md:89`); `options[]` — все варианты,
включая маловероятные с `unlikely: причина` (без причины `check`
отвергнет), у каждого `evidence[] {path, quote}` — путь от корня
проекта и дословная строка файла; `recommendation {option, why, text}` —
одна, пишется **после** вариантов: человек находит её под списком,
не первой строкой; `depends_on` — записи, без решения которых выбор
здесь — догадка; `antipodes` — варианты других развилок, несовместимые
с вариантом этой; `consequences` — что следует из решения.
`decision: null` — его напишет `apply`. Вариант «ничего не менять»
начинается словами «Оставить как есть»: по этому началу `render-design`
ставит у решения пометку «конструкция не меняется»
(`.symphysis/tools/journal_render.py`, `UNCHANGED_PREFIXES`).

**Отступление от постановки** (F-08.A, F-28.E): вариант, чьё наблюдаемое
поведение противоречит сценарию факта `addressee: постановка`, несёт
поле `options[].deviation: F-NN` — номер этого факта. Пометка
у варианта, не у записи: при выборе видно, какой вариант отступает.
Уточнение без противоречия (вариант сужает критерий, сценарий факта
остаётся верным) — без поля. Решает человек, как по любой развилке:
пометка — видимость, не замок (F-55.E); `check` годен и при выборе
отступающего варианта, а развилку, чей выбранный вариант несёт
`deviation`, proposal назовёт в разделе «Отступления от постановки».

**Факт** (`kind: факт`, `options: []`, `addressee: материалы`;
факт из `intent.md` — `addressee: постановка`, шаг 1):
`question` — утверждение; `evidence[]` на записи — путь и цитата,
взятая из прочитанного файла, не по памяти; `status: решён`, когда
улика есть. Факт без улики не пишется — это парковка `материалы`.
`consequences` — какие записи на нём стоят.

**Правило предписания** (F-09.A): находка, из которой напрашивается
конструкция («по образцу X», «требует новой …»), пишется двумя
записями — фактом-наблюдением (что есть, с цитатой) и развилкой
с вариантами: образец X, иной путь, маловероятные с причиной — и одной
рекомендацией. В факте — наблюдение, не предписание в `consequences`:
design стоит на решении развилки, опору на факт атака считает блокером.

**Узлы схемы** (F-23): `nodes` — необязательный список идентификаторов узлов
`scheme.md`, к которым относится запись; идентификатор пиши дословно, как
в схеме. Подходящего узла нет — поля нет, это не дефект (F-114). `apply` поле
не пишет: поменять просит человек в чате.

**Парковка** — элемент `parking[]` записи: `addressee` из трёх —
`материалы | человек | ИБ` (F-11), `text` — вопрос с границами (что
выяснить, где читать). Запись без решения с парковкой —
`status: припаркован`. Ответ исследования приходит файлом
`research/<F-NN>.md`: во втором круге внеси его в `finding`, цитаты —
уликами.

### 5. После каждой записи

`check`, затем `render-md`. Код 1 — журнал негоден по схеме или
правилам (факт с вариантами, зависимость на несуществующую запись,
антипод без варианта): исправь до следующего шага. Вердикт улики
«цитаты нет дословно» — сигнал, не стоп (F-12): обычно это пересказ —
открой файл и возьми строку как есть; «файла нет» — проверь путь.

### 6. Круг просмотрщика

Когда порции круга кончились — сверка антиподов. До показа: новые варианты
между собой и с уже выбранными, отвергнутые не смотри; несовместимая пара —
поле `antipodes` у обоих вариантов (F-50). Антипод бывает только между разными
записями: варианты одной развилки и так исключают друг друга, такой антипод
`check` отвергнет кодом 1 (F-97). Сверка идёт всегда и в этом же контексте,
субагента для неё не заводи (F-51).

Затем `render-html`, назови человеку путь к `decisions.html`. Человек выбирает варианты, пишет слово, добавляет
варианты и развилки, паркует, оспаривает факты — и копирует промпт
возврата. Сохрани промпт в `<каталог изменения>/answers/<дата>.md` как
есть и внеси `apply`. Всё или ничего: отказ называет запись и причину —
исправь строку промпта, не JSON, и внеси заново. После `apply` —
`check`, `render-md`, `render-html`.

После выбора сверь выбранные за круг между собой и с прежними решениями, тоже
в этом же контексте. Находка — новая развилка об этом расхождении; пара, по которой
развилка уже заведена, новой записи не даёт (F-98). Тексты вариантов, рекомендации
и `decision` прежних записей сверка не меняет: решает человек (F-110).

«Реши сам» — тоже слово человека: внеси рекомендованный вариант строкой
`- F-NN: X — «реши сам»`; делегирование остаётся видным в журнале.
Слово к выбору необязательно: строка `- F-NN: X — (без слова)` законна,
`apply` её принимает; объяснения выбора у человека не требуй (F-55.E).

### 7. Обратимость

У каждой записи с `decision` и `reversibility: null` оцени, чего стоит
отменить решение: `level` — `обратимо | дорого | в одну сторону`,
`why` — назови миграцию, контракт или зависимую систему, не «трудно
менять» (`context.md:62-64`). Причина обязательна при любом уровне
(F-10). Где варианты различаются по обратимости, скажи это в `text`
варианта — до выбора.

### 8. Выход из круга

Круг закончен, когда перспективы пройдены и круг просмотрщика (шаг 6)
прошёл: развилка без решения не закрывает круг, пока человек её
не видел. Сосчитай за круг: K — новых решений (записей, получивших
`decision`), M — новых фактов, D — новых развилок, оставшихся без
решения, P — парковок `материалы`. Закрой круг строкой `notes[]`:
`{date, text: «круг N закончен: решений K, фактов M, открытых развилок D, парковок материалам P, антиподов A»}`,
где A — пары, найденные сверкой за круг; ноль значит «смотрел, таких нет» (F-50).
Дальше — первое подходящее:

- P > 0 — круг закрыт, вопрос о новом круге не задаётся: его задаст
  instruction `research` в конце шага `research`, после отчётов: закроет
  парковки находками и позовёт этот скилл.
- K = 0 и M = 0 — брейншторм закончен, только если и D = 0: `notes[]` ←
  «круг N без новых решений и фактов — брейншторм закончен». При D > 0
  человек видел развилки и не решил ни одной — молча не заканчивай,
  спроси «Начать новый круг?».
- иначе спроси человека в чате: **«Начать новый круг?»** «Нет» —
  `notes[]` ← «брейншторм закончен по решению человека» с датой.
  «Да» — круг N+1 с шага 1 по открытым записям и находкам.

Числа кругов скилл не ограничивает (F-44): открытое без решения подхватят атака
и Open Questions. Строка о конце брейншторма новому кругу не мешает: человек просит
ещё круг — идёт круг N+1, прежняя строка остаётся, в конце новая (F-96).

Номер круга N — число строк «круг … закончен» в `notes[]` плюс один.

## Чего скилл не делает

- не решает развилки и не пишет `decision` сам — только `apply` словом
  человека;
- не ведёт интервью без материалов: вопрос, ответ на который лежит
  в файле, человеку не задаётся;
- не считает число ясности: критерия «достаточно ясно» нет, есть счёт
  новых решений и фактов и слово человека;
- не правит `intent.md` — намерение человека остаётся словами на входе
  (пустой файл заполняется ответом человека дословно, F-24.E);
- не исследует парковки `материалы` — это артефакт `research`;
- не пишет требования, proposal, design — они стоят на решённых записях
  позже;
- не атакует журнал — `symphysis-attack`;
- не надзирает за схемой: не спрашивает о её обновлении и не ждёт утверждения,
  созданный файл меняет только по слову человека.

## Приёмка

| Проверка | Чем держится |
| --- | --- |
| решает человек | `decision` появляется только из `apply`; слово дословно, с датой |
| улика — не пересказ | `check`: путь и цитата найдены; несверенная помечена, не замолчана |
| рекомендация не ведёт | одна на развилку, после всех вариантов; в чате не озвучена |
| маловероятное видно | вариант с `unlikely` и причиной, не удалён |
| парковка адресована | адресат из трёх; текст называет, что выяснить и где |
| круг кончается счётом | строка `notes[]` с K, M, D, P и A на каждый круг; числа кругов скилл не ограничивает |
| новый круг — по слову | вопрос «Начать новый круг?» задан — и когда круг дал лишь открытые развилки; не задан при парковках `материалы` (спросит `research` после отчётов) и когда круг не дал ничего нового; отказ записан дословной строкой |
| схема не мешает | файл создан один раз, дальше по слову человека; при закрытии круга о нём нет вопроса |
| антиподы сверены | до показа и после выбора, в том же контексте; в строке круга их число, находка — новая развилка |
| намерение первым | первые записи круга 1 — факты `addressee: постановка` с цитатой из `intent.md`, по одному на критерий; `intent.md` байт в байт прежний; нуль критериев — вопрос «назови критерии готовности» и строка `notes[]` |
| постановка не дублируется | второй круг не заводит факт с той же цитатой; новый текст — новый факт по слову человека |
| отступление видно | вариант против сценария факта постановки несёт `deviation: F-NN`; уточнение — без поля; выбор отступающего варианта законен |
| конструкция — развилкой | «по образцу X», «требует новой …» — факт-наблюдение и развилка с вариантами и рекомендацией |
| обратимость с причиной | у решённой записи `level` и `why` с именем контракта или системы |
