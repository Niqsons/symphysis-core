# symphysis-brainstorm

Брейншторм шага 1 схемы symphysis и второго круга перед атакой.
Механики — из GSD Core: перспективы интервью и порция вопросов
(`upstream/gsd-core/gsd-core/workflows/spec-phase.md:25-52`, `:136`),
«человек — визионер, модель — строитель», серые зоны и ограда объёма
(`discuss-phase.md:52-99`), обратимость решения
(`discuss-phase/templates/context.md:58-70`). Оригиналы — `references/`;
где смысл инструкции изменён против источника — `TRANSLATION-NOTES.md`.

## Главное правило

**Решает человек, не модель.** Модель читает материалы, формулирует
развилки с вариантами и уликами, пишет факты с цитатами и одну
рекомендацию — а `decision` в журнале появляется только из слова
человека через `apply`. Числового гейта ясности нет: круг кончается
счётом новых решений и фактов и словом человека (F-07).

**Развилка обсуждается в просмотрщике, не в чате.** В чат идёт только
то, чего нет ни в файлах, ни в виде выбора между вариантами.

## Файлы и команды

`<каталог изменения>` — `openspec/changes/<имя>/`. Журнал —
`<каталог изменения>/decisions.json`, шаблон уже лежит там (`title`,
`source`, `intro`, `records: []`). CLI — `py -3.13 .symphysis/tools/journal.py`:

```bash
# после каждой записи: схема и правила (код 1 — журнал негоден, чини), улики (сигнал)
py -3.13 .symphysis/tools/journal.py check <каталог изменения>/decisions.json
py -3.13 .symphysis/tools/journal.py render-md <каталог изменения>/decisions.json --out <каталог изменения>/decisions.md

# круг просмотрщика: человек решает в HTML, промпт возврата вносит apply
py -3.13 .symphysis/tools/journal.py render-html <каталог изменения>/decisions.json --out <каталог изменения>/decisions.html
py -3.13 .symphysis/tools/journal.py apply <каталог изменения>/decisions.json <каталог изменения>/answers/<дата>.md
```

JSON правят только модель (записи, факты, парковки, обратимость, `notes`)
и `apply` (слово человека). `decisions.md` и `decisions.html` — рендер,
в них не пишут.

## Порядок круга

**Круг** — один проход по пяти перспективам; вопросы человеку идут
**порциями** по 2–3 (`spec-phase.md:136` «Each round: 2–3 questions
max»). Порция кончается ответом человека.

### 1. Прочитай материалы до первого вопроса

Запрос, каталог изменения, файлы и каталоги, которые назвал человек.
«Scout the codebase BEFORE the first question — grounded questions
only» (`spec-phase.md:542`). Найденное — сразу в журнал фактом с уликой
(путь и дословная цитата), не в памяти. Заполни `title` («Журнал
решений: <изменение>») и `intro`: от какого корня считаются пути улик,
какие материалы читались.

### 2. Пройди перспективы по порядку

| Перспектива | Что вскрывает | Вопросы |
| --- | --- | --- |
| Исследователь (Researcher) | текущее состояние | что уже есть в материалах по теме; разница между сегодня и целью; что сломано или чего нет — откуда работа |
| Упрощатель (Simplifier) | минимальный объём | простейшая версия, решающая основную задачу; что останется, если срезать половину; что сделает изменение успешным без приятных мелочей |
| Хранитель границ (Boundary Keeper) | периметр | что в этом изменении точно не делается; какие соседние задачи тянет решить, а не надо; как выглядит «готово» — что сдаётся |
| Аналитик отказов (Failure Analyst) | края, ломающие требования | худшее, если требования поняты неверно; как выглядит сломанная версия; за что атака отвергнет артефакт |
| Закрывающий (Seed Closer) | остаток | запись F-NN открыта — можно решить сейчас; о чём пожалеешь, если не решить до планирования |

Оригинал вопросов — `references/spec-phase.md`. Перспектива без
вопросов к этому изменению пропускается молча.

### 3. Маршрут каждого вопроса

- **Ответ в файлах** — человека не спрашивай: прочитай и запиши факт
  с уликой. Не прочитать сейчас (материалов нет, объём велик) —
  парковка `материалы`: бриф исследованию.
- **Выбор между вариантами** — развилка: запись с вариантами, уликами,
  одной рекомендацией; идёт в просмотрщик, в чате выбор не предлагай.
- **Знает только человек, и это не выбор** (чего он хочет, что главное,
  как выглядит «готово») — вопрос в чат, порцией. Ответ — развилка
  с одним вариантом или с вариантами, которые ответ назвал; слово
  человека дословно — в `apply` строкой `- F-NN: A — «слово»`
  (безальтернативная развилка тоже пишется как решение, F-10).
- **Канон ИБ** (инъекции, пути, токены, права) — парковка `ИБ`; записью
  журнала не становится, его закрывает чек-лист `security.md`.
- **Новая возможность, не уточнение этого изменения** — парковка
  `человек` на записи, где всплыла: «новая возможность: …». Эвристика
  GSD (`discuss-phase.md:69`): уточняет ли это, *как* сделать
  запланированное, или добавляет то, что могло бы быть своим
  изменением. Объём изменения в записях не растёт — ограда объёма
  в `references/discuss-phase-gray-areas.md`.

### 4. Что пишется в запись

Формат — `journal.schema.json` symphysis (ключи английские, значения
русские); `check` сверяет по нему.

**Развилка** (`kind: развилка`, `status: открыт`, `addressee: человек`):
`question` — конкретная серая зона этого изменения, не категория
(«интерфейс», «поведение» — нет; «что видит человек на пустом
журнале» — да, `discuss-phase.md:89`); `options[]` — все варианты,
включая маловероятные с `unlikely: причина` (без причины `check`
отвергнет), у каждого `evidence[] {path, quote}` — путь от корня
проекта и дословная строка файла; `recommendation {option, why, text}` —
одна, пишется **после** вариантов: человек находит её под списком,
не первой строкой; `depends_on` — записи, без решения которых выбор
здесь — догадка; `antipodes` — варианты других развилок, несовместимые
с вариантом этой; `consequences` — что следует из решения.
`decision: null` — его напишет `apply`.

**Факт** (`kind: факт`, `options: []`, `addressee: материалы`):
`question` — утверждение; `evidence[]` на записи — путь и цитата,
взятая из прочитанного файла, не по памяти; `status: решён`, когда
улика есть. Факт без улики не пишется — это парковка `материалы`.
`consequences` — какие записи на нём стоят.

**Парковка** — элемент `parking[]` записи: `addressee` из трёх —
`материалы | человек | ИБ` (F-11), `text` — вопрос с границами (что
выяснить, где читать). Запись без решения с парковкой —
`status: припаркован`. Ответ исследования приходит файлом
`research/<F-NN>.md`: во втором круге внеси его в `finding`, цитаты —
уликами.

### 5. После каждой записи

`check`, затем `render-md`. Код 1 — журнал негоден по схеме или
правилам (факт с вариантами, зависимость на несуществующую запись,
антипод без варианта): исправь до следующего шага. Вердикт улики
«цитаты нет дословно» — сигнал, не стоп (F-12): обычно это пересказ —
открой файл и возьми строку как есть; «файла нет» — проверь путь.

### 6. Круг просмотрщика

Когда порции круга кончились: `render-html`, назови человеку путь
к `decisions.html`. Человек выбирает варианты, пишет слово, добавляет
варианты и развилки, паркует, оспаривает факты — и копирует промпт
возврата. Сохрани промпт в `<каталог изменения>/answers/<дата>.md` как
есть и внеси `apply`. Всё или ничего: отказ называет запись и причину —
исправь строку промпта, не JSON, и внеси заново. После `apply` —
`check`, `render-md`, `render-html`.

«Реши сам» — тоже слово человека: внеси рекомендованный вариант строкой
`- F-NN: X — «реши сам»`; делегирование остаётся видным в журнале.

### 7. Обратимость

У каждой записи с `decision` и `reversibility: null` оцени, чего стоит
отменить решение: `level` — `обратимо | дорого | в одну сторону`,
`why` — назови миграцию, контракт или зависимую систему, не «трудно
менять» (`context.md:62-64`). Причина обязательна при любом уровне
(F-10). Где варианты различаются по обратимости, скажи это в `text`
варианта — до выбора.

### 8. Выход из круга

Круг закончен, когда перспективы пройдены и промпт возврата внесён
(или вносить нечего). Закрой круг строкой `notes[]`: `{date, text:
«круг N закончен: новых решений K, новых фактов M, парковок материалам P»}`.
Дальше — первое подходящее:

- N = 2 — брейншторм закончен: `notes[]` ← «два круга пройдены —
  брейншторм закончен». Открытое остаётся открытым — его подхватят
  атака и Open Questions.
- P > 0 — круг закрыт, новый круг — после исследования: instruction
  `attack-decisions` закроет парковки находками, спросит человека
  и позовёт этот скилл.
- K = 0 и M = 0 — брейншторм закончен: `notes[]` ← «круг N без новых
  решений и фактов — брейншторм закончен».
- иначе спроси человека в чате: **«Начать новый круг?»** «Нет» —
  `notes[]` ← «брейншторм закончен по решению человека» с датой.
  «Да» — круг N+1 с шага 1 по открытым записям и находкам.

Номер круга N — число строк «круг … закончен» в `notes[]` плюс один.

## Чего скилл не делает

- не решает развилки и не пишет `decision` сам — только `apply` словом
  человека;
- не ведёт интервью без материалов: вопрос, ответ на который лежит
  в файле, человеку не задаётся;
- не считает число ясности: критерия «достаточно ясно» нет, есть счёт
  новых записей и слово человека;
- не исследует парковки `материалы` — это артефакт `research`;
- не пишет требования, proposal, design — они стоят на решённых записях
  позже;
- не атакует журнал — `symphysis-attack`.

## Приёмка

| Проверка | Чем держится |
| --- | --- |
| решает человек | `decision` появляется только из `apply`; слово дословно, с датой |
| улика — не пересказ | `check`: путь и цитата найдены; несверенная помечена, не замолчана |
| рекомендация не ведёт | одна на развилку, после всех вариантов; в чате не озвучена |
| маловероятное видно | вариант с `unlikely` и причиной, не удалён |
| парковка адресована | адресат из трёх; текст называет, что выяснить и где |
| круг кончается счётом | строка `notes[]` с K, M и P на каждый круг; третьего круга нет |
| новый круг — по слову | вопрос «Начать новый круг?» задан; отказ записан дословной строкой |
| обратимость с причиной | у решённой записи `level` и `why` с именем контракта или системы |
