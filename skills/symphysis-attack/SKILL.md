# symphysis-attack

Атака шагов `attack-decisions` и `attack-artifacts`: проход по цели
в поиске утверждения без опоры и вердикт во frontmatter файла атаки.
Механика — слой проверки GSD Core:
«FORCE stance» (`upstream/gsd-core/agents/gsd-plan-checker.md:30`,
`gsd-doc-verifier.md:29`); классификация находок и два измерения
plan-checker — Context Compliance и Numeric/Factual Claim Authority
(`gsd-plan-checker.md:39-46`, `:376`, `:705-720`); форма разрыва
и самопроверка статуса verifier (`gsd-verifier.md:609-631`, `:828-839`);
воздержание honest-verifier (`gsd-core/references/honest-verifier.md:35-43`);
утверждения о файлах doc-verifier (`gsd-doc-verifier.md:58-98`); выписки —
`references/`. Линза следования `scenario-run` — своя (SELF, F-07.A).
Нижняя планка — бинарный исход
`sdd-review`: «READY TO PLAN or NEEDS REVISION»
(`sdd-superpowers/skills/sdd-review/SKILL.md:34`) — `passed | gaps_found`.
Где смысл источников изменён и что осталось от гриля store —
`TRANSLATION-NOTES.md`.

## Главное правило

**Цель негодна, пока опора не доказала обратное.** Считай каждую запись
журнала негодной и каждое утверждение specs, design, security, tasks
ложным, пока улика не доказала обратное. Исходная гипотеза — цель
не держится. Назови доказуемо, что дисквалифицирует
(`references/force-stance.md`); «do not credit effort or intent, only
verifiable coverage» (`gsd-plan-checker.md:9`).

**Строка без линзы, тяжести и инварианта невалидна.** «Issues without
a severity classification are not valid output. Neither are issues
without a `required_property` (the invariant that failed) and evidence
for the failure» (`:43-44`). `блокер` — цель не будет достигнута, держит
`status` и `apply`; `предупреждение` — страдает качество, идёт человеку
списком и ничего не держит; `справка` — не блокирует (`:40-42`).
Инвариант — свойство, не правка: «у задачи
есть проверка», а не «добавь проверку» (`:933-934`). «Чем закрыть» —
пример пути, «never a prescription» (`:45-46`).

**Опора — не пересказ.** «Есть» — `путь:строка «цитата»` из прочитанного
файла или решённая `F-NN` (у журнала — только цитата); остальное — «нет».

**Невыводимое — не «есть».** Утверждение, ответ на которое не следует
из цели и её улик, не получает ни «есть», ни «нет»: опора — «по спеке
не выводится», тяжесть `предупреждение`, закрыть — `вопрос человеку`;
такая строка идёт человеку вопросом и `status` не держит. Повод внешний,
не самооценка (`honest-verifier.md:25-29`): у `scenario-run` — сценарий
стоит на крае с исходом Defer в журнале; у `claim-authority` — число,
которого не измерить. Остальное — «есть» или «нет» (`:41`).

**Читает, не исполняет.** Атака не запускает код образца, тесты, сборку
или команды цели — ни ради `scenario-run`, ни ради других линз. Разрешены
чтение файлов и греп: `claim-extraction` — существование грепом,
не исполнение (`gsd-doc-verifier.md:77`); `claim-authority` — измерение
командой чтения (`wc`, `grep -c`, `sha256sum`), не запуск цели; исход
сценария — чтением кода и рассуждением. Проверка правила — суждение:
ревью транскрипта атаки, в нём нет вызовов сборки, тестов и запуска
цели (F-53.E).

## Файлы и команды

`<каталог изменения>` — `openspec/changes/<имя>/`. Шаблон — из
instruction (`openspec instructions <артефакт> --change <имя> --json`,
поле `template`):

| Вызов | Цели | Выход · шаблон | Frontmatter |
| --- | --- | --- | --- |
| `attack-decisions` | `decisions.json` | `attack/decisions.md` · `attack-decisions.md` | `status`, `target: decisions.json`, `target_sha256` |
| `attack-artifacts` | `decisions.json` (опора, не атакуется), `specs/**/*.md`, `consequences.md`, если файл есть, `design.md`, `security.md`, `tasks.md` | `attack/artifacts.md` · `attack-artifacts.md` | `status`, `targets[]` — `path` и `sha256` на файл, журнал первым; `consequences.md` в `targets[]`, если файл есть |

```bash
# журнал (у обоих вызовов): check --write пишет line/found/verdict — хеш после него
python .symphysis/tools/journal.py check --write <каталог изменения>/decisions.json
# хеши — из каталога изменения; путь для `path:` — как печатает sha256sum, но без `*`
# перед ним (Git Bash печатает `<хеш> *<путь>` — двоичный режим)
(cd <каталог изменения> && sha256sum decisions.json)
# артефакты (Git Bash): specs — все уровни
(cd <каталог изменения> && find specs -name '*.md' | sort | xargs sha256sum)
(cd <каталог изменения> && sha256sum design.md security.md tasks.md)
# опись — если файл есть
(cd <каталог изменения> && sha256sum consequences.md)
# живое измерение — только чтение (wc -l, grep -c)
openspec status --change <имя> --json   # verdict: ok | missing | mismatch | stale
```

В `target:` и `path:` — путь относительно каталога изменения, как его
печатают команды выше и как в шаблоне: `decisions.json`,
`specs/<cap>/spec.md`, `design.md`. Форк считает хеш от каталога
изменения: путь с префиксом `openspec/changes/<имя>/` или вне каталога
даёт вечный `stale`.

Непонятно, что делает скрипт, когда его звать или что значит код выхода, —
зови `--help` этого скрипта или подкоманды (`journal.py <подкоманда> --help`),
а файл скрипта не читай.

Атака пишет `attack/<цель>.md` и строку итога в `notes[]` журнала. Цели
не правятся — кроме `line/found/verdict`, которые пишет `check --write`.

## Порядок атаки

### 1. Вход

`check --write`, затем хеши целей. Файла атаки нет — создай из шаблона:
`status: gaps_found`, хеши, пустая таблица. Файл есть — сравни хеши:
совпали — прежние строки действительны, проход только по строкам
«не пройдено»; разошлись (у `attack-artifacts` — и хеш журнала) —
атака с начала, прежние строки не переносятся. Цели нет (`security.md`
не написан): у журнала — строка «не пройдено» в разделе с именем файла;
у артефактов — строка `claim-extraction` с именем файла, опора «нет:
файла нет», `блокер`. Исключение — `consequences.md`: изменение начато
до этого шага, файла нет — его нет в `targets[]`, строки о нём нет.

### 2. Проход по разделам

**Журнал** — запись за записью, поле за полем; раздел — `<F-NN>,
<поле>`. Улики руками не грепать: `found: false` от `check --write` —
строка «нет» с текстом `verdict`, `found: true` — «есть».
**Артефакты** — два прохода. `scenario-run`: спека за спекой, сценарий
за сценарием — механизм design, код, исход, THEN (форма — шаг 3).
`claim-extraction`: specs, design, security, tasks — пути, команды,
`F-NN`, имена модулей; раздел — `<файл>, <место>`; `consequences.md` —
исключения и строки описи (шаг 3).

Строка — одно утверждение: «Утверждение» — цитата или пересказ
с номером строки; «Линза» — слуг, латинское имя линзы из списка своего файла (шаг 3);
«Инвариант» — нарушенное свойство; «Опора» — «есть: …», «нет: <на чём
держится>» или «по спеке не выводится»; «Тяжесть» — у «нет» по линзе,
у «по спеке не выводится» всегда `предупреждение`, у «есть» — `справка`;
«Чем закрыть» — из списка шаблона.

**Понижение тяжести.** Тяжесть строки с опорой «нет» — тяжесть линзы:
у всех линз обоих списков — `блокер`. Иная — только по слову человека:
причина в скобках в той же ячейке называет решённую запись журнала:
`предупреждение (решено человеком в F-NN)`. Своё суждение модели тяжесть
не снижает: `status` держат только блокеры, и такое понижение открыло бы
`apply` мимо человека. Блокер, который кажется завышенным, остаётся блокером,
а сомнение идёт человеку вопросом. Без причины — нарушение правила:
просмотрщик показывает такую строку как «понижение без причины».

**Правило ячейки.** Черта в ячейке — только `\|` или внутри backticks;
цитата кода — в backticks. Литеральная обратная косая перед литеральной
чертой в цитате кода пишется `\\|`: внутри backticks `\\|` = `\|`; вне
backticks `\\` — литеральная косая, следующая черта — разделитель.
В цитате кода литеральная обратная косая пишется `\\`: парсер читает
`\\` как `\` и внутри backticks.
Пустых ячеек нет: нет содержимого — «—». Парсер просмотрщика отвергает
нарушение ошибкой с файлом, строкой и столбцом, код 2.

**Покрытие у журнала — поимённо.** Раздел без находок —
`| чисто | <раздел> | coverage | — | справка | есть | — |`; раздел,
до которого проход не дошёл, —
`| не пройдено | <раздел> | coverage | — | блокер | нет | повторить атаку по разделу |`;
строки покрытия («чисто», «не пройдено») инварианта не несут,
в «Инварианте» — «—».
У артефактов покрытие держит `scenario-run` (шаг 3).

### 3. Линзы — закрытые списки по файлу атаки

Список закрыт; просмотрщик группирует строки по слугу. Слуг не из списка
своего файла — группа «вне списка», строка невалидна. Линзы присутствия
сняты: что из них детерминируемо, ловят `journal.py check`
и `openspec validate --strict`, остальное снято решением F-07.A
(перечень — `TRANSLATION-NOTES.md`).

**Линзы журнала** — `attack/decisions.md`:

| Линза | Источник (`путь:строка`) | Что ищется · тяжесть «нет» |
| --- | --- | --- |
| `context-compliance` | Context Compliance, `gsd-plan-checker.md:376` | `decision.word` против варианта по смыслу; `consequences` не из решения; решённая запись на `открыт`; оба антипода решены; опора решения design на факт или на запись без решения — факт с конструкцией в `consequences` без развилки (F-09.A); решение, чей выбранный вариант противоречит факту `addressee: постановка`, без пометки «отступление от постановки» — поле `deviation: F-NN` варианта (F-08.A, F-28.E); выбранный вариант с полем `deviation` — `справка`, опора «есть: deviation F-NN у выбранного варианта»; слово человека не требуется (F-55.E) · блокер |
| `claim-authority` | Numeric/Factual Claim Authority, `:705-720` | число, версия, «уже есть» — измерение первым: сошлось — «есть» с командой; разошлось — блокер; не измерить — «расхождение: цель X, улика Y» без назначения правого, опора «по спеке не выводится» · блокер |
| `claim-extraction` | `<claim_extraction>`, `gsd-doc-verifier.md:58-98` | путь, команда, `F-NN`, имя модуля в записи — существование грепом, не исполнение (`:77`); несуществующее · блокер |
| `coverage` | — (store, `TRANSLATION-NOTES.md`) | строки «чисто» · справка и «не пройдено» · блокер |

**Линзы артефактов** — `attack/artifacts.md`:

| Линза | Источник (`путь:строка`) | Что ищется · тяжесть «нет» |
| --- | --- | --- |
| `scenario-run` | SELF: калибровка camunda-bid, F-03, F-07.A | исход сценария spec по коду механизма design против THEN; расхождение или механизм не назван · блокер |
| `claim-extraction` | `<claim_extraction>`, `gsd-doc-verifier.md:58-98` | путь, команда, `F-NN`, имя модуля в specs, design, security, tasks — существование грепом, не исполнение (`:77`); `F-NN` как опора — запись `решён`, кроме строк `кандидат:` и раздела «Pre-mortem» в `consequences.md`: там номер открытой записи законен; в `consequences.md` — исключение без довода о конкретном файле и строка ветки без цитаты; несуществующее · блокер |

**`consequences.md` читает `claim-extraction`**, своей линзы у него нет. Строка
пишется на место; «Раздел» — `consequences.md, <путь места>`; опора у находки «нет: …»,
тяжесть `блокер`. Находок две:

- **исключение без довода о конкретном файле** — раздел «Исключения»; инвариант
  «исключение называет, что делает этот файл и почему изменение на него не опирается».
  Признак: подставь в довод другой файл проекта; довод остался верным — это шаблон.
  Сверка `check` считает такое место закрытым и молчит, поэтому держит его только атака;
- **строка ветки без цитаты** — раздел «Опись», строка `**Состав:**` называет ветки отказа
  включёнными, а строка описи называет ветку без `путь:строка «цитата»`; инвариант «ветка
  названа цитатой из кода». Строка «веток отказа не найдено, искал: …» ветку не называет,
  и при выключенных ветках цитат нет законно: находки в обоих случаях нет.

Файл со строкой `**Причина:**` описи и исключений не несёт, находок этих двух видов в нём
нет. Причины провала в разделе «Pre-mortem» атака не судит: это делает человек в просмотрщике.

**Строка `scenario-run`.** «Утверждение» — сценарий spec
(`<файл>, <требование> / <сценарий>`); «Раздел» — механизм design
(решение `F-NN` или раздел); «Инвариант» — THEN сценария; «Опора» —
`есть: <путь:строка> «код» → исход совпал`, либо
`нет: <путь:строка> «код» → исход <какой>, THEN <какой>`, либо
`нет: design не называет механизм`; тяжесть — `блокер` у «нет»,
`справка` у «есть». Одна строка на пару «сценарий × механизм»: два
механизма на сценарий — две строки, инвариант каждой — исход по своему
коду. Механизм не назван — `блокер`, воздержания нет: ответ выводится
из design. «По спеке не выводится» — только когда сценарий стоит на крае
с исходом Defer в журнале. Исход выводится чтением кода и рассуждением;
существование путей и имён — грепом.

У артефактов покрытие держит `scenario-run`: каждый сценарий каждой
спеки цели — хотя бы в одной строке, строка «есть» — `справка`; перед
вердиктом сверь список сценариев спек со строками. Сценарий, до которого
проход не дошёл, —
`| <файл>, <требование> / <сценарий> | — | scenario-run | — | блокер | нет: не пройдено | повторить атаку по разделу |`.

Не репортится (`gsd-plan-checker.md:238-243`, `gsd-doc-verifier.md:100-110`):
стиль; решённое человеком с причиной; примеры и подстановки `<…>`;
термины OpenSpec; то, что ловят `check` и `openspec validate --strict`.
Гигиену журнала — парковка `материалы` без `finding` при
`research/<F-NN>.md`; `факт` без улики; `recommendation` с пустым `why`;
буква решения вне вариантов — ловит `journal.py check` (код 1 / `[!!]`,
F-12.A): строки атаки о ней нет. Находка вне линз — под ближайшей
линзой своего файла, с причиной; нет и ближайшей — предпочтение,
не дефект (`gsd-plan-checker.md:934-935`).

### 4. Закрытие строк

Таблица написана — строки не перечитываются и не выбрасываются
(заимствование store, `TRANSLATION-NOTES.md`). «Чем закрыть» — путь,
не действие атаки: у журнала — `исследование`, `вопрос человеку`,
`правка записи`; у артефактов — `правка артефакта`, `запись журнала`,
`вопрос человеку`; у обоих — `повторить атаку по разделу`. Вопросы
человеку — в чат одной порцией после
вердикта; ответ — через `apply`, не в файл атаки. Правки делают
брейншторм, пробы и шаги артефактов; затем — с шага 1. При `status: passed`
строки `предупреждение` повтора не требуют: новый круг вокруг них находит всё более
узкие края, что с ними делать, решает человек.

### 5. Вердикт и самопроверка

`status: passed` ставится, только когда в таблице нет ни одной строки
с тяжестью `блокер`; строки `предупреждение` идут человеку списком и `apply`
не держат, строки `справка` не блокируют; иначе `gaps_found`. Перед записью
сосчитай строки по тяжестям (у артефактов — и сверь покрытие сценариями, шаг 3)
и сверь `status` с таблицей; после записи прочитай `status` заново
(`gsd-verifier.md:828`); это счёт, не пересуждение. Строка итога — в `notes[]`
журнала до `check --write` и хешей: `{date, text: «атака <цель>: строк
N, блокеров a, предупреждений b, справок c, не выводится d —
<status>»}`. Форк читает только `status`; при `mismatch`, `missing`
или `stale` `/opsx:continue` снова зовёт атаку
(`upstream/openspec/UPSTREAM.md:21-22`, `:28-29`).

### 6. Итог человеку

Одной порцией: вердикт, счёт по тяжестям, список строк `предупреждение`
(раздел и утверждение каждой), разделы «не пройдено», вопросы, путь к файлу
атаки; прочие строки таблицы не пересказывать. Список идёт и при `passed`:
иначе предупреждения останутся в файле, которого никто не откроет.

## Чего скилл не делает

- не правит цель — ни `decisions.json` (кроме `line/found/verdict`
  от `check --write` и строки итога `notes[]`), ни артефакты: дыры
  закрывает правка цели вне атаки;
- не исполняет ни цель, ни код образца — ни команд, ни тестов,
  ни сборки: читает и грепает (главное правило);
- не решает за человека и не пишет `decision`; ответ — через `apply`;
- не ставит `passed` при чужом хеше;
- не перечитывает и не судит свои строки, не репортит стиль
  и гигиену журнала, не предписывает правку;
- не предлагает добавить требование или решение — это брейншторм
  и пробы.

## Приёмка

| Проверка | Чем держится |
| --- | --- |
| вердикт по таблице | `status: passed` ставится, только когда в таблице нет ни одной строки с тяжестью `блокер`; строки `предупреждение` идут человеку списком и `apply` не держат, строки `справка` не блокируют |
| предупреждения названы | итог человеку несёт список строк `предупреждение`, и при `status: passed` |
| опись прочитана | `consequences.md` в `targets[]`, если файл есть; исключение без довода о конкретном файле и строка ветки без цитаты — строки `claim-extraction` |
| строка валидна | слуг из списка своего файла, тяжесть из трёх, инвариант (кроме покрытия журнала); у «нет» — на чём держится, тяжесть линзы или причина в скобках; у воздержания — `вопрос человеку`; у «есть» — `справка` |
| ячейка разбирается | правило ячейки; `render-html --attack` даёт код 0 |
| хеши свежие | равны `sha256sum` на момент записи, путь — от каталога изменения; журнал — после `notes[]` и `check --write` |
| покрытие | у журнала — у каждого раздела строка: находка, «чисто» или «не пройдено»; у артефактов — каждый сценарий в строке `scenario-run` |
| опора — не пересказ | у «есть» — `путь:строка «цитата»` или `F-NN`; у `scenario-run` — код и исход; число — с командой; улики — по `found` из `check` |
| второго такта нет | строки после записи не удалены и не переоценены; стиля и гигиены журнала в таблице нет |
| цель не тронута | кроме `line/found/verdict` и строки `notes[]`; новых `decision` нет; цель и код образца не исполнялись — ревью транскрипта |
