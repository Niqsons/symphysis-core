# symphysis-attack

Атака шагов `attack-decisions` и `attack-artifacts` схемы symphysis:
проход по цели в поиске утверждения, которое ничем не подкреплено,
и вердикт во frontmatter файла атаки. Установка — строки «FORCE stance»
проверяющих GSD Core (`upstream/gsd-core/agents/gsd-plan-checker.md:30`,
`gsd-code-reviewer.md:22`, `gsd-doc-verifier.md:29`; дословно —
`references/force-stance.md`). Форма прохода — гриль из store
(`store/change-intake/references/grill-form.md:3-4`: «не «чего не
хватает», а «какое утверждение ничем не подкреплено»»): пять линз
с «чего не репортить» (`:24-27`; переложение для целей атаки —
`references/grill-lenses.md`, своё), второго такта нет (`:31-32`),
покрытие поимённо (`:69-82`). Вердикт — F-13.B: «статус по вердикту
считает форк». Где смысл источников изменён — `TRANSLATION-NOTES.md`.

## Главное правило

**Цель негодна, пока опора не доказала обратное.** Три строки GSD
в переложении на цели атаки (оригинал — `references/force-stance.md`):

- планы → журнал: считай каждую запись негодной, пока улика не доказала
  обратное; исходная гипотеза — решения не доведут изменение до цели;
  назови, что их дисквалифицирует (`gsd-plan-checker.md:30`);
- код → артефакты: считай, что в каждом поданном артефакте есть дефект;
  исходная гипотеза — требования, дизайн, чек-лист и задачи расходятся
  между собой и с журналом; назови то, что доказуемо
  (`gsd-code-reviewer.md:22`);
- документация → утверждения: считай каждое утверждение факта ложным,
  пока улика из файла не доказала его; исходная гипотеза — текст
  разошёлся с источником; назови каждое ложное (`gsd-doc-verifier.md:29`).

Короткая форма той же установки — правило конфигурации
(`openspec/config.symphysis.yaml:23`): «FORCE stance: считай каждое
утверждение неподкреплённым, пока улика не доказала обратное».

**Опора — не пересказ.** «Есть» — `путь:строка «цитата»` из прочитанного
файла или решённая запись `F-NN`; у журнала — только цитата, `F-NN` —
опора артефактов. Всё остальное — «нет», как бы правдоподобно
ни звучало.

**Второго такта нет.** Модель не перечитывает свою находку и не судит
её — «судила бы та же модель, что спрашивала» (`grill-form.md:31-32`).
Строку закрывает человек или правка цели, не атака.

**Молчание — не «чисто».** Раздел без находок получает строку «чисто»;
раздел, до которого проход не дошёл, называется поимённо: «Молчание
по разделу читалось бы как «претензий нет»» (`grill-form.md:81-82`).

## Файлы и команды

`<каталог изменения>` — `openspec/changes/<имя>/`. Два вызова, два
шаблона (`openspec/schemas/symphysis/templates/`); шаблон приходит
с instruction (`openspec instructions <артефакт> --change <имя> --json`,
поле `template`) и заполняется, а не пересказывается:

| Вызов | Цели | Выход · шаблон | Frontmatter |
| --- | --- | --- | --- |
| `attack-decisions` | `decisions.json` | `attack/decisions.md` · `attack-decisions.md` | `status`, `target: decisions.json`, `target_sha256` |
| `attack-artifacts` | `specs/**/*.md`, `design.md`, `security.md`, `tasks.md` | `attack/artifacts.md` · `attack-artifacts.md` | `status`, `targets[]` — `path` и `sha256` на каждый файл, specs первыми |

Таблица у обоих одна — «Утверждение · Раздел · Опора есть / нет · Чем
закрыть»; закрытый список «чем закрыть» и правило вердикта — в комментарии
и последней строке шаблона.

```bash
# attack-decisions: check --write пишет line/found/verdict в decisions.json — хеш берётся после него
py -3.13 .symphysis/tools/journal.py check --write <каталог изменения>/decisions.json
sha256sum <каталог изменения>/decisions.json
# attack-artifacts: хеши до прохода и после каждой правки цели (Git Bash); specs/**/*.md — все уровни, сортировано
find <каталог изменения>/specs -name '*.md' | sort | xargs sha256sum
sha256sum <каталог изменения>/design.md <каталог изменения>/security.md <каталог изменения>/tasks.md
# вердикт глазами форка: у артефактов с verdict — ok | missing | mismatch
openspec status --change <имя> --json
```

Атака пишет только `attack/<цель>.md`. Цели не правятся: журнал меняют
`apply` и скиллы проб, артефакты — их шаги.

## Порядок атаки

### 1. Вход

Позвала instruction `attack-decisions` — цель `decisions.json`, шаблон
`attack-decisions.md`; сначала `check --write`: он пишет `line/found/verdict`
в `decisions.json` — хеш берётся после него. `attack-artifacts` — четыре
вида файлов, шаблон `attack-artifacts.md`. Файла атаки нет — создай
из шаблона:
`status: gaps_found`, хеши целей, пустая таблица. Файл есть — сравни
его хеши с `sha256sum` сейчас (журнал — после `check --write`): совпали —
цель с прошлой атаки
не менялась, прежние строки действительны, проход идёт только по строкам
«не пройдено» (шаг 3) и — у `attack-artifacts`, если менялся журнал, —
по строкам с закрытием «запись журнала»; разошлись — вердикт обесценен,
атака с начала:
frontmatter и таблица пишутся заново, прежние строки не переносятся
непрочитанными. Цель, которой нет (`security.md` не написан), — строка
«нет» в разделе с именем файла, не пропуск.

### 2. Установка

До первой строки — `references/force-stance.md`. Исходная гипотеза
записана заранее: цель не держится. Атака ищет не «чего не хватает» —
это брейншторм и пробы, — а утверждение без опоры и утверждение, опоре
противоречащее. Находка называется только доказуемо: в строке стоит,
что проверено и где.

### 3. Проход по разделам

Единица прохода — раздел, в нём — утверждения.

**Журнал** — запись за записью, поле за полем; раздел строки —
`<F-NN>, <поле>`. Улики (`evidence[]` записи и её вариантов) руками
не грепать: строки по ним даёт `check --write` шага 1 — улика с `found: false`
становится строкой «нет» с текстом `verdict` («цитаты нет дословно»,
«файла нет»), с `found: true` — опора «есть». Чего `check` не видит
и что ищет модель:

- `decision.word` противоречит выбранному варианту или повторяет его
  текст без слова человека;
- `факт` с пустым `evidence[]`; `status: решён` без `decision`;
  `припаркован` без парковки;
- `consequences`, не следующие из решения; решение без следствий, на
  котором стоят другие записи (`depends_on`);
- оба варианта пары `antipodes` решены;
- парковка `материалы` без `finding`, когда `research/<F-NN>.md` есть;
  парковка, не говорящая, что выяснить и где;
- `recommendation` с пустым `why`; `outcome` без `decision`;
  `outcome.reason`, не равный `decision.word`.

**Артефакты** — файл за файлом, заголовок за заголовком; раздел строки —
`<файл>, <место>`: `### Requirement:` и его `#### Scenario:` в spec.md;
Context, Goals / Non-Goals, каждое решение Decisions, Risks, Open
Questions в design.md; каждая строка таблицы security.md; каждая задача
`- [ ] N.M` в tasks.md. Опора требования — решённая `F-NN` или
proposal.md; решения design — запись журнала с тем же смыслом;
«применимо» в security.md — требование specs, закрывающее пункт,
по имени; задачи — требование или решение, которое она реализует,
и проверка в её строке.

Строка — одно утверждение без опоры: «Утверждение» — цитата или
короткий пересказ с номером строки; «Опора» — «нет: <на чём держится>»;
«Чем закрыть» — из списка шаблона. Раздел без находок — строка
`| чисто | <раздел> | есть | — |`. Раздел, до которого проход не дошёл
(предел выхода, обрыв), — строка `| не пройдено | <раздел> | нет |
повторить атаку по разделу |`: при ней `passed` невозможен. Утверждение,
бывшее строкой «нет» и получившее опору после правки, пишется строкой
«есть» со ссылкой — закрытие видно.

### 4. Линзы

К каждому разделу — пять линз из `references/grill-lenses.md`:
эхо требования, ветви без сценария, переход состояния,
термин без определения, реализация в постановке. У каждой «что искать»
и «чего не репортить»; вторая половина обязательна — без неё атака
репортит стиль, «и порция человека уходит на шум» (`grill-form.md:26-27`).
Находка линзы несёт её тег в «Утверждении» (`[эхо]`, `[ветвь]`,
`[переход]`, `[термин]`, `[реализация]`); утверждение без опоры вне линз
идёт без тега. Машинные проверки атака не повторяет: схема и правила
журнала, цитаты улик, Dismiss без причины — `check`; требование без
SHALL или без сценария — `openspec validate <имя> --strict`.

### 5. Закрытие строк

Таблица написана — строки не перечитываются и не выбрасываются.
«Чем закрыть» — путь, не действие атаки: у журнала — `исследование`
(что искать и где), `вопрос человеку`, `правка записи`; у артефактов —
`правка артефакта`, `запись журнала`, `вопрос человеку`. Вопросы
человеку задай в чате одной порцией после вердикта; ответ вносится
в журнал через `apply` (слово к записи, спор факта, заметка), не в файл
атаки. Правки делают брейншторм, пробы и шаги артефактов — затем атака
повторяется с шага 1.

### 6. Вердикт

`status: passed` — только когда в таблице нет ни одной строки «нет»;
иначе `status: gaps_found`. Аналог — `openspec-verify`: «only when every
in-scope requirement resolved to `PASS` or `NOT_APPLICABLE`»
(`docs/analysis/gsd-openspec-integration.md:27`). Хеши в frontmatter —
на момент записи таблицы, у журнала — после `check --write`; вердикт
при хеше, не равном хешу файла, недействителен. Форк читает только
`status`: `openspec status`
показывает у артефакта `verdict: ok | missing | mismatch`,
а `/opsx:continue` при `mismatch` — и при `missing` с существующим
файлом — снова зовёт instruction атаки вместо следующего шага
(`upstream/openspec/UPSTREAM.md:21-22`, правки C3 и C4). После каждой
правки цели: у журнала снова `check --write`, хеши заново, таблица
заново, статус по таблице.

### 7. Итог человеку

В чат одной порцией: вердикт, число строк «нет» по видам закрытия,
разделы «не пройдено», вопросы человеку, путь к файлу атаки. Строки
таблицы не пересказывать.

## Чего скилл не делает

- не правит цель — ни `decisions.json`, ни spec.md, design.md,
  security.md, tasks.md: дыры закрывает правка цели вне атаки, затем
  атака повторяется;
- не решает за человека и не пишет `decision` в журнал; вопрос
  человеку — строка таблицы, ответ — через `apply`;
- не атакует `upstream/`, материалы и чужие проекты — только артефакты
  изменения; файл улики читается ради цитаты, не атакуется;
- не ставит `passed` при открытых строках и не переносит вердикт
  на цель с другим хешем;
- не перечитывает и не судит свои строки, не репортит стиль;
- не повторяет машинные проверки `check` и `openspec validate`;
- не предлагает добавить требование или решение — это брейншторм
  и пробы; атака говорит лишь, на чём написанное не стоит.

## Приёмка

| Проверка | Чем держится |
| --- | --- |
| вердикт по таблице | `status: passed` только при нуле строк «нет»; при строке «не пройдено» — `gaps_found` |
| хеши свежие | `target_sha256` / `targets[].sha256` равны `sha256sum` файлов на момент записи, у журнала — после `check --write`; у `attack-artifacts` — запись на каждый файл specs, design, security, tasks |
| покрытие поимённо | у каждого раздела цели хотя бы одна строка — находка, «чисто» или «не пройдено»; раздела без строки нет |
| опора — не пересказ | у «есть» — `путь:строка «цитата»` или решённая `F-NN` (у журнала — только цитата); у «нет» — на чём держится и чем закрыть из списка шаблона |
| улики из `check` | строки по уликам совпадают с `found: false` после `check --write`; руками не грепано |
| линзы с отсевом | у находки линзы — тег; стиля, грамматики spec.md и правил журнала в таблице нет |
| второго такта нет | в пределах одной атаки строки после записи не удалены; закрытие — только правкой цели и повторной атакой |
| цель не тронута | хеши целей после `check --write` и после атаки равны — поля `line/found/verdict`, которые он пишет, правкой цели не считаются; в журнале нет новых `decision` |
