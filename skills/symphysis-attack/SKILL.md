# symphysis-attack

Атака шагов `attack-decisions` и `attack-artifacts` схемы symphysis:
проход по цели в поиске утверждения, которое ничем не подкреплено,
и вердикт во frontmatter файла атаки. Механика — слой проверки GSD Core:
«FORCE stance» (`upstream/gsd-core/agents/gsd-plan-checker.md:30`,
`gsd-doc-verifier.md:29`); классификация находок и измерения
plan-checker (`gsd-plan-checker.md:39-46`, `:126-720`); форма разрыва
и самопроверка статуса verifier (`gsd-verifier.md:609-631`, `:828-839`);
воздержание honest-verifier (`gsd-core/references/honest-verifier.md:35-43`);
утверждения о файлах doc-verifier (`gsd-doc-verifier.md:58-98`); выписки —
`references/`. Нижняя планка — бинарный исход `sdd-review`: «READY TO PLAN
or NEEDS REVISION» (`sdd-superpowers/skills/sdd-review/SKILL.md:34`) —
`passed | gaps_found`. Где смысл источников изменён и что осталось
от гриля store — `TRANSLATION-NOTES.md`.

## Главное правило

**Цель негодна, пока опора не доказала обратное.** Считай каждую запись
журнала негодной и каждое утверждение specs, design, security, tasks
ложным, пока улика не доказала обратное. Исходная гипотеза — цель
не держится. Назови доказуемо, что дисквалифицирует
(`references/force-stance.md`); «do not credit effort or intent, only
verifiable coverage» (`gsd-plan-checker.md:9`).

**Строка без линзы, тяжести и инварианта невалидна.** «Issues without
a severity classification are not valid output. Neither are issues
without a `required_property` (the invariant that failed) and evidence
for the failure» (`:43-44`). `блокер` — цель не будет достигнута;
`предупреждение` — страдает качество, идти дальше можно; `справка` —
не блокирует (`:40-42`). Инвариант — свойство, не правка: «у задачи
есть проверка», а не «добавь проверку» (`:933-934`). «Чем закрыть» —
пример пути, «never a prescription» (`:45-46`).

**Опора — не пересказ.** «Есть» — `путь:строка «цитата»` из прочитанного
файла или решённая `F-NN` (у журнала — только цитата); остальное — «нет».

**Невыводимое — не «есть».** Утверждение, ответ на которое не следует
из цели и её улик, не получает ни «есть», ни «нет»: опора — «по спеке
не выводится», тяжесть `предупреждение`, закрыть — `вопрос человеку`;
«abstain → ⚠️ `insufficient_spec`, flagged, → `human_needed` — never
`passed`» (`honest-verifier.md:43`). Повод внешний, не самооценка
(`:25-29`): исход Backstop или Defer в журнале у требования; число,
которого не измерить. Остальное — «есть» или «нет» (`:41`).

## Файлы и команды

`<каталог изменения>` — `openspec/changes/<имя>/`. Шаблон — из
instruction (`openspec instructions <артефакт> --change <имя> --json`,
поле `template`):

| Вызов | Цели | Выход · шаблон | Frontmatter |
| --- | --- | --- | --- |
| `attack-decisions` | `decisions.json` | `attack/decisions.md` · `attack-decisions.md` | `status`, `target: decisions.json`, `target_sha256` |
| `attack-artifacts` | `decisions.json` (опора, не атакуется), `specs/**/*.md`, `design.md`, `security.md`, `tasks.md` | `attack/artifacts.md` · `attack-artifacts.md` | `status`, `targets[]` — `path` и `sha256` на файл: журнал первым, затем specs |

```bash
# журнал (у обоих вызовов): check --write пишет line/found/verdict — хеш после него
py -3.13 .symphysis/tools/journal.py check --write <каталог изменения>/decisions.json
sha256sum <каталог изменения>/decisions.json
# артефакты (Git Bash): specs — все уровни, сортировано
find <каталог изменения>/specs -name '*.md' | sort | xargs sha256sum
sha256sum <каталог изменения>/design.md <каталог изменения>/security.md <каталог изменения>/tasks.md
# живое измерение — только чтение (wc -l, grep -c, файл версии)
openspec status --change <имя> --json   # verdict: ok | missing | mismatch
```

Атака пишет `attack/<цель>.md` и строку итога в `notes[]` журнала. Цели
не правятся — кроме `line/found/verdict`, которые пишет `check --write`.

## Порядок атаки

### 1. Вход

`check --write`, затем хеши целей. Файла атаки нет — создай из шаблона:
`status: gaps_found`, хеши, пустая таблица. Файл есть — сравни хеши:
совпали — прежние строки действительны, проход только по строкам
«не пройдено»; разошлись (у `attack-artifacts` — и хеш журнала) —
атака с начала, прежние строки не переносятся непрочитанными. Цели нет
(`security.md` не написан) — строка «нет», `coverage`, `блокер`,
в разделе с именем файла.

### 2. Проход по разделам

**Журнал** — запись за записью, поле за полем; раздел — `<F-NN>,
<поле>`. Улики руками не грепать: `found: false` от `check --write` —
строка «нет» с текстом `verdict`, `found: true` — «есть».
**Артефакты** — файл за файлом; раздел — `<файл>, <место>`: требование
и его сценарии; Context, Goals / Non-Goals, каждое решение, Risks, Open
Questions; строка таблицы security.md; задача `- [ ] N.M`.

Строка — одно утверждение: «Утверждение» — цитата или пересказ
с номером строки; «Линза» — слуг из списка шага 3; «Инвариант» —
нарушенное свойство; «Тяжесть» — по линзе; «Опора» — «есть: …»,
«нет: <на чём держится>» или «по спеке не выводится»; «Чем закрыть» —
из списка шаблона. Покрытие поимённо: раздел без находок — `| чисто |
<раздел> | coverage | — | справка | есть | — |`; раздел, до которого
проход не дошёл, — `| не пройдено | <раздел> | coverage | раздел
прочитан | блокер | нет | повторить атаку по разделу |`.

### 3. Линзы — измерения plan-checker по целям

Список закрыт; просмотрщик группирует строки по слугу. Тяжесть — как
у источника; иная — с причиной.

| Линза | Источник GSD (`путь:строка`) | Цели | Что ищется · тяжесть |
| --- | --- | --- | --- |
| `requirement-coverage` | Requirement Coverage, `gsd-plan-checker.md:126` | tasks, specs | требование или решение без задачи; требование без сценария и наоборот; capability без proposal и наоборот · блокер (`:137`) |
| `task-completeness` | Task Completeness, `:155` | tasks, security | задача без файлов, действия, проверки, «готово»; «применимо» без требования или «чем проверено», «неприменимо» без причины · блокер |
| `dependency-correctness` | Dependency Correctness, `:189` | tasks | задача стоит на более поздней, на Open Question design или на записи `открыт` · блокер |
| `key-links` | Key Links Planned, `:262` | design | компонент без связи с тем, кто его зовёт; Migration Plan без «до» и «после» · предупреждение |
| `scope-sanity` | Scope Sanity, `:297` | tasks | задача шире сеанса; группа без задач · предупреждение |
| `verification-derivation` | Verification Derivation, `:346` | tasks, specs | проверка задачи — «сделано» вместо наблюдаемого результата; требование о реализации вместо поведения · предупреждение |
| `context-compliance` | Context Compliance, `:376` | design, журнал | решение design противоречит `decision`, не стоит на записи или принято здесь; Open Question, уже решённый; `decision.word` против варианта; `consequences` не из решения; решённая запись на `открыт`; оба антипода решены · блокер |
| `scope-reduction` | Scope Reduction Detection, `:423` | tasks | «пока», «упрощённо», «позже», «заглушка» там, где `decision` требует полного · блокер всегда (`:446`) |
| `data-contracts` | Cross-Plan Data Contracts, `:532` | design | два места преобразуют одни данные несовместимо · предупреждение; без сохранения исходного — блокер (`:549`) |
| `research-resolution` | Research Resolution, `:597` | журнал | парковка `материалы` без `finding` при `research/<F-NN>.md`; `факт` без улики; `recommendation` с пустым `why` · блокер |
| `claim-authority` | Numeric/Factual Claim Authority, `:705-720` | журнал | число, версия, «уже есть» — измерение первым: сошлось — «есть» с командой; разошлось — блокер; не измерить — «расхождение: цель X, улика Y» без назначения правого · по спеке не выводится |
| `claim-extraction` | `<claim_extraction>`, `gsd-doc-verifier.md:58-98` | журнал, design, tasks | путь, команда, `F-NN`, имя модуля — существование грепом, не исполнение (`:77`); несуществующее · блокер |
| `honest-verifier` | Honest Verifier, `honest-verifier.md:35-43` | specs, design, tasks | край Backstop или Defer в журнале, который сценарий, design или задача выдают за решённый · по спеке не выводится |
| `coverage` | — (store, `TRANSLATION-NOTES.md`) | все | строки «чисто» · справка и «не пройдено» · блокер |

Не репортится (`gsd-plan-checker.md:238`, `gsd-doc-verifier.md:100-110`):
стиль; решённое человеком с причиной; примеры и подстановки `<…>`;
термины OpenSpec; то, что ловят `check` и `openspec validate --strict`.
Находка вне линз — под ближайшей, с причиной; нет и ближайшей —
предпочтение, не дефект (`gsd-plan-checker.md:934-935`).

### 4. Закрытие строк

Таблица написана — строки не перечитываются и не выбрасываются
(заимствование store, `TRANSLATION-NOTES.md`). «Чем закрыть» — путь,
не действие атаки: у журнала — `исследование`, `вопрос человеку`,
`правка записи`; у артефактов — `правка артефакта`, `запись журнала`,
`вопрос человеку`. Вопросы человеку — в чат одной порцией после
вердикта; ответ — через `apply`, не в файл атаки. Правки делают
брейншторм, пробы и шаги артефактов — затем атака с шага 1.

### 5. Вердикт и самопроверка

`status: passed` — только когда в таблице нет ни одной строки `блокер`,
`предупреждение` или «по спеке не выводится»; `справка` не блокирует
(«every consuming gate counts only BLOCKER + WARNING»,
`gsd-plan-checker.md:42`); иначе `gaps_found`. Перед записью —
самопроверка: сосчитай строки по тяжестям и сверь `status` с таблицей,
«confirm that status is not `passed` when human verification items
exist» (`gsd-verifier.md:611`); после записи прочитай `status` файла
заново (`:828`). Это счёт, не пересуждение. Строка итога — в `notes[]`
журнала до `check --write` и хешей: `{date, text: «атака <цель>: строк
N, блокеров a, предупреждений b, справок c, не выводится d —
<status>»}`. Форк читает только `status`; при `mismatch` или `missing`
`/opsx:continue` снова зовёт атаку (`upstream/openspec/UPSTREAM.md:21-22`).

### 6. Итог человеку

Одной порцией: вердикт, счёт по тяжестям, разделы «не пройдено»,
вопросы, путь к файлу атаки; строки таблицы не пересказывать.

## Чего скилл не делает

- не правит цель — ни `decisions.json` (кроме `line/found/verdict`
  от `check --write` и строки итога `notes[]`), ни артефакты: дыры
  закрывает правка цели вне атаки, затем атака повторяется;
- не исполняет цель — ни команд, ни тестов: существование грепом
  (`gsd-doc-verifier.md:77`);
- не решает за человека и не пишет `decision`; ответ — через `apply`;
- не ставит `passed` при открытых строках и при чужом хеше;
- не перечитывает и не судит свои строки, не репортит стиль,
  не предписывает правку — «Чем закрыть» лишь пример;
- не предлагает добавить требование или решение — это брейншторм
  и пробы.

## Приёмка

| Проверка | Чем держится |
| --- | --- |
| вердикт по таблице | `passed` только при нуле строк `блокер`, `предупреждение` и «по спеке не выводится» |
| строка валидна | слуг из списка, тяжесть из трёх, инвариант; у «нет» — на чём держится; у воздержания — `вопрос человеку` |
| хеши свежие | равны `sha256sum` на момент записи; журнал — после `notes[]` и `check --write`; у `attack-artifacts` первым — `decisions.json` |
| покрытие поимённо | у каждого раздела цели строка — находка, «чисто» или «не пройдено» |
| опора — не пересказ | у «есть» — `путь:строка «цитата»` или `F-NN`; число — с командой; улики — по `found` из `check` |
| второго такта нет | строки после записи не удалены и не переоценены; стиля в таблице нет |
| цель не тронута | кроме `line/found/verdict` и строки `notes[]`; новых `decision` нет; цель не исполнялась |
