# symphysis-edge-probe

Проба краёв шага `specs` схемы symphysis: по каждому требованию —
конкретные края, которых требование не оговорило. Механика — из GSD
Core: закрытая таксономия восьми категорий, фильтр применимости и отказ
только с причиной (`upstream/gsd-core/gsd-core/references/edge-probe.md:62-90`),
конкретный край вместо напоминания и четыре исхода
(`workflows/spec-phase.md:344-352`, Step 5.5). Оригинал целиком —
`references/edge-probe.md`; где смысл инструкции изменён против
источника — `TRANSLATION-NOTES.md`.

## Главное правило

**Решает человек, не модель.** Модель называет форму требования,
поднимает категории и пишет кандидата с четырьмя вариантами — а исход
появляется только из слова человека: `decision` пишет `apply`,
`outcome` — его зеркало. **Отказ без причины не принимается**:
«Dismissal requires a reason string. "N/A — input is a bounded enum,
no boundary exists" is valid; silence is not» (`edge-probe.md:89-90`);
`check` красит Dismiss без причины.

**Край — конкретный, не напоминание.** «Подумать о границах» —
не кандидат; «R2 сливает интервалы — что с `[[1,2],[2,3]]`, которые
только касаются?» — кандидат (`spec-phase.md:344-345`).

**Зачем проба стоит до кода.** Проверяющий видит только записанные
утверждения: на краях, которых спека не назвала, он уверенно ошибается
(«~0.93 confidence while catching 0/12 omitted-edge defects»,
`edge-probe.md:20`). Лечится не проверяющим, а полнотой спеки: край
становится сценарием до того, как появился код.

## Файлы и команды

`<каталог изменения>` — `openspec/changes/<имя>/`. Требования —
`<каталог изменения>/specs/<capability>/spec.md`, журнал —
`<каталог изменения>/decisions.json` (тот же, что вёл брейншторм;
кандидаты получают следующие номера F-NN). CLI —
`py -3.13 .symphysis/tools/journal.py`:

```bash
# после каждой записи: схема и правила (код 1 — журнал негоден, чини), улики (сигнал)
py -3.13 .symphysis/tools/journal.py check <каталог изменения>/decisions.json
py -3.13 .symphysis/tools/journal.py render-md <каталог изменения>/decisions.json --out <каталог изменения>/decisions.md

# круг просмотрщика: человек решает в HTML, промпт возврата вносит apply
py -3.13 .symphysis/tools/journal.py render-html <каталог изменения>/decisions.json --out <каталог изменения>/decisions.html
py -3.13 .symphysis/tools/journal.py apply <каталог изменения>/decisions.json <каталог изменения>/answers/<дата>.md
```

JSON правят только модель (кандидаты, `outcome`, `consequences`,
`notes`) и `apply` (слово человека). `spec.md` модель правит только
по решённому исходу. `decisions.md` и `decisions.html` — рендер, в них
не пишут.

## Порядок пробы

### 1. Вход

Все `### Requirement:` файлов `specs/**/spec.md` изменения; нет ещё
spec.md (скилл позван раньше) — решённые записи журнала, у которых
`consequences` называет поведение. Требование читается как есть,
на русском: перевода `text_en` и cue-слов нет, форму называет модель
по смыслу (F-08.D; `edge-probe.md:52` «The classifier reads English;
`text` does not have to be.»). Проба идёт по ясным требованиям
(`spec-phase.md:193`): вопрос «что требование значит» — не край,
а развилка брейншторма.

### 2. Назови форму

Пять форм (`edge-probe.md:47`), у требования одна или несколько:

| Форма | Признак |
| --- | --- |
| `numeric-range` | число с границей, порогом, округлением |
| `collection` | список, множество, интервалы, записи |
| `text` | строка: длина, равенство, нормализация |
| `stateful` | меняет состояние: запись, повтор, отмена |
| `io` | граница системы: файл, сеть, процесс, прерывание |

Форма называется всегда: наблюдаемое поведение хотя бы меняет
состояние или пересекает границу — сомнение решается в сторону
`stateful`/`io`, лишнего кандидата человек отведёт с причиной. Форма
пишется в префикс вопроса записи; человек правит её там же (F-08.D:
«форма модели предлагается, человек правит»).

### 3. Подними категории

Таблица GSD дословно (`edge-probe.md:70-79`), перевод рядом:

| id | name (QA term) · по-русски | applies to shapes | probe question · по-русски |
| --- | --- | --- | --- |
| boundary | Boundary values · граничные значения | numeric-range | What happens exactly at each min/max/threshold — and one step either side? · Что происходит ровно на каждом min/max/пороге — и на шаг в обе стороны от него? |
| adjacency | Adjacency / touching · смежность / касание | collection | When two things are exactly equal or just touch, do they merge, collide, or separate? · Когда два элемента в точности равны или только касаются — они сливаются, сталкиваются или остаются раздельными? |
| empty | Empty / degenerate · пустое / вырожденное | collection, text | What is the result for empty, single-element, or null input? · Каков результат на пустом, одноэлементном или null-входе? |
| encoding | Encoding / representation · кодировка / представление | text | Whose definition of length/equality applies — bytes, code points, grapheme clusters, or normalized form? · Чьё определение длины и равенства действует — байты, кодовые точки, графемные кластеры или нормализованная форма? |
| ordering | Ordering / stability · порядок / устойчивость | collection | When elements compare equal, is output order specified and stable? · Когда элементы равны при сравнении, задан ли порядок вывода и устойчив ли он? |
| precision | Precision / overflow · точность / переполнение | numeric-range | Where can precision loss, overflow, or rounding/tie-breaking occur — and what is the exact contract (e.g. half-up vs half-to-even, ceil/floor/truncate)? · Где возможны потеря точности, переполнение, округление и разрешение «ровно половины» — и каков точный контракт (half-up или half-to-even, ceil/floor/truncate)? |
| idempotency | Idempotency / repetition · идемпотентность / повтор | stateful | What happens if this runs twice on the same input? · Что будет, если выполнить это дважды на одном входе? |
| concurrency | Concurrency / effect ordering · параллельность / порядок эффектов | stateful, io | If interrupted or run in parallel, what is guaranteed? · Что гарантировано при прерывании или параллельном запуске? |

**Фильтр применимости:** поднимаются только категории, чьи `applies to
shapes` пересекаются с формами требования — «A pure-text requirement is
never asked about overflow» (`edge-probe.md:85-88`). Девятой категории
нет: «a fixed eight the author must explicitly clear beats thirty nobody
finishes» (`:64-65`). Край, уже решённый в журнале (Аналитик отказов
брейншторма), второй раз не поднимается — в комментарий spec.md идёт
номер той записи (`spec-phase.md:343`).

### 4. Запиши кандидата

На каждую поднятую категорию — одна запись `decisions.json` по
`journal.schema.json`:

- `kind: развилка`, `status: открыт`, `addressee: человек`,
  `reversibility: null` — кандидат не проектное решение;
- `question` — `[<id категории> · <форма>] <конкретный край>`: префикс —
  поле формы, которое человек может переписать; край — один, с данными
  этого требования; вопрос таблицы — подсказка модели, не текст записи;
- `evidence[]` — путь spec.md и дословная строка требования
  (`### Requirement: <имя>` или строка с SHALL), чтобы `check` нашёл её;
- `options[]` — ровно четыре, тексты дословно:
  - `A. Specify — уточнить: строка «проходит/не проходит» в критерии приёмки spec.md`
  - `B. Dismiss — не относится; причина обязательна`
  - `C. Backstop — тест-страховка на крае; строки в spec.md нет`
  - `D. Defer — отложено; остаётся открытым`
- `recommendation` — одна, после вариантов: A с черновиком сценария,
  когда край формулируется; C — когда край известен, а в прозу не
  ложится; B — только с готовой причиной в `why`; D не рекомендуется;
- `depends_on` — записи, на которых стоит требование;
  `decision: null`, `outcome: null` — их заполнят `apply` и шаг 6.

После каждой записи — `check`, затем `render-md`.

### 5. Круг просмотрщика

Когда кандидаты по всем требованиям записаны — `render-html`, назови
человеку путь к `decisions.html`. Человек выбирает исход и пишет слово:
у B слово — причина; у A — строка критерия, если он задаёт её сам.
Промпт возврата сохрани в `<каталог изменения>/answers/<дата>.md` как
есть и внеси `apply`; отказ называет запись — исправь строку промпта,
не JSON. «Реши сам» — тоже слово человека: внеси рекомендованный
вариант строкой `- F-NN: X — «реши сам»`; на B «реши сам» не ложится —
отказ без причины человека не принимается, рекомендованный B при «реши
сам» становится C (`spec-phase.md:370-371` «never auto-dismiss — a wrong
dismissal is the exact silent failure being eliminated»).

### 6. Зеркало исхода

После `apply` у каждой записи пробы с `decision`:

- `outcome` ← `{kind: "проба", value: <слово варианта: A → Specify,
  B → Dismiss, C → Backstop, D → Defer>, reason: <decision.word дословно>}`;
- A: в spec.md под требованием — новый `#### Scenario:` с GIVEN/WHEN/THEN
  на этот край (грамматика OpenSpec: критерий приёмки — сценарий);
  `consequences` ← «в spec.md: <имя сценария>»;
- C: `consequences` ← «тест-страховка: <что проверяет>»; тест пишет
  `tasks`, здесь только намерение;
- D: `consequences` ← «край не решён — tasks считает его допущением»
  (`spec-phase.md:364-365`);
- B: `consequences` ← причина; spec.md не меняется.

Затем `check`: B без слова — красное «исход Dismiss без причины».
Причину не выдумывай: спроси человека в чате и внеси строкой
`- F-NN: к решению B — «причина»` через `apply`, зеркало повтори.

### 7. След в spec.md и итог

Под каждым требованием заполни комментарий шаблона
(`openspec/schemas/symphysis/templates/spec.md:10`):
`<!-- проба краёв: форма=<формы>, исходы: F-NN Specify, F-MM Dismiss, … -->`.
Закрой пробу строкой `notes[]`: `{date, text: «проба краёв: кандидатов N,
Specify a, Dismiss b, Backstop c, Defer d»}`; кандидаты без решения
входят в N и перечисляются номерами. Затем `render-md`, `render-html`.
Открытый кандидат артефакт не блокирует: его увидят атака
`symphysis-attack` и Open Questions дизайна.

## Чего скилл не делает

- не ставит исход сам: `decision` — только из `apply`, `outcome` — зеркало
  слова человека, не оценка модели;
- не принимает Dismiss без причины и не сочиняет причину за человека;
- не переводит требование и не ищет cue-слова: форму называет модель
  по смыслу, человек правит (F-08.D);
- не добавляет категорий и не поднимает `unclassified`;
- не оценивает обратимость: кандидат — не проектное решение;
- не пишет тест страховки — только намерение в `consequences`;
- не спрашивает «чем это станет молча» — `symphysis-prohibition-probe`.

## Приёмка

| Проверка | Чем держится |
| --- | --- |
| решает человек | `decision` только из `apply`; `outcome.value` совпадает с буквой решения, `reason` — слово дословно |
| отказ с причиной | `check` зелёный: ни одного Dismiss с пустой причиной; причина — слово человека, не модели |
| край конкретный | `question` называет данные этого требования; вопрос таблицы дословно в `question` не встречается |
| фильтр соблюдён | у каждого кандидата категория из восьми и форма из пяти; категория применима к форме по таблице |
| форма правится человеком | префикс `[id · форма]` в `question`; переписанный человеком префикс моделью не возвращается |
| след в spec.md | у каждого требования комментарий «проба краёв» с формой и исходами по номерам; на каждый Specify — сценарий |
| проба закрыта счётом | строка `notes[]` с N, a, b, c, d и датой |
