# Команды журнала решений

Общий файл скиллов `symphysis-*`: вызовы `python .symphysis/tools/journal.py`, коды выхода,
маркеры, кто что правит. `<каталог изменения>` — `openspec/changes/<имя>/`, пути от корня
проекта. Справка скрипта — `journal.py --help` и `journal.py <подкоманда> --help`; строки
«Коды» и «Маркеры» ниже повторяют её дословно.

## Вызовы по шагам

```bash
# после каждой правки журнала или описи: схема и правила, улики, опись
python .symphysis/tools/journal.py check <каталог изменения>/decisions.json
python .symphysis/tools/journal.py render-md <каталог изменения>/decisions.json --out <каталог изменения>/decisions.md

# показ человеку: страница; --attack повторяемый, для режима «атака»
python .symphysis/tools/journal.py render-html <каталог изменения>/decisions.json --out <каталог изменения>/symphysis.html \
    [--attack <каталог изменения>/attack/decisions.md] [--attack <каталог изменения>/attack/artifacts.md]

# слово человека: промпт возврата или строки из чата, сохранённые как есть
python .symphysis/tools/journal.py apply <каталог изменения>/decisions.json <каталог изменения>/answers/<дата>.md

# перед атакой журнала: line/found/verdict улик пишутся в JSON, хеш берётся после
python .symphysis/tools/journal.py check --write <каталог изменения>/decisions.json

# начало шага consequences: места кода из улик решённых развилок
python .symphysis/tools/journal.py code-sites <каталог изменения>/decisions.json

# шаг design: Decisions, Risks / Trade-offs, Open Questions из журнала
python .symphysis/tools/journal.py render-design <каталог изменения>/decisions.json --out <каталог изменения>/design.md
```

## Коды и маркеры

Коды: 0 — шаг сделан; 1 — негодный журнал, нет или нечитаем вход, отказ apply; 2 — неверный
вызов, `check --strict` при строках `[!!]`, битый файл атаки у `render-html`, отказ связки
у `apply-md4h`.

Маркеры: `[ok]` сделано; `[!!]` расхождение или отказ; `[--]` не проверить; `[..]` сведения,
исходом не являются.

Код → действие:

- `check` код 1 — журнал негоден по схеме или правилам (факт с вариантами, зависимость на
  несуществующую запись, антипод без варианта, недостающее поле): модель MUST исправить журнал до
  следующей записи; иначе `render-md`, `render-html` и `apply` откажут тем же кодом.
- `check` строка `[!!]` — сигнал, не стоп: «цитаты нет дословно» — обычно пересказ, открой файл
  и возьми строку как есть; «файла нет» — проверь путь; «выбор мимо рекомендации без слова» —
  спроси слово у человека; парковка `агент` без `finding` при `research/F-NN.md` — находка
  есть, в запись не внесена: внеси её вторым кругом (скилл `symphysis-brainstorm`); парковка
  `человек` без `finding` — разбери её (скилл `symphysis-viewer`, «Порядок», шаг 5). Шаг идёт
  дальше, строка SHOULD попасть в итог человеку.
- `check` строка `[!!] F-NN: адресат «материалы» — старое значение, новые записи пишут «агент»` —
  сигнал, не стоп: у старых журналов (архив, журнал плана) значение законно и не правится; в журнале
  активного изменения запись или парковка переписывается на `агент` — `материалы` новые записи не
  пишут, строку `apply` с ним скрипт отвергает кодом 1.
- `check` строка `[..] атака журнала: …` или `[..] атака артефактов: …` — состав устаревшего
  вердикта: сколько и какие записи добавлены после атаки журнала, какие цели артефактов изменились;
  сведения, код выхода прежний. Повтор атаки идёт по этому составу, не с начала (скилл
  `symphysis-attack`, шаг 1); при совпавших хешах строк нет.
- `check` строка `[!!] attack/<файл>: файл атаки не разбирается: <причина>` — файл атаки есть, но без
  frontmatter, таблицы или не в UTF-8: правит его скилл `symphysis-attack` по `attack-table.md`;
  остальные проверки идут, с `--strict` код 2.
- `apply` код 1 с именем записи — всё или ничего: журнал не изменён; модель MUST исправить
  строку промпта в файле ответа и внести заново; JSON руками не правится.
- `apply` код 1 по строке `- тяжесть: …` — всё или ничего вместе с журналом: ни журнал, ни файлы атаки
  не изменены. Причины: нет обоснования; две строки для одной строки атаки; путь не файл атаки этого
  изменения (`attack/decisions.md`, `attack/artifacts.md`); файла нет или он не UTF-8; строки нет или
  таких строк две; ячейка тяжести не разбирается; тяжесть не меняется (покрытие, справка, уже такая,
  ход вне блокер ↔ предупреждение); файл атаки не разбирается (нет frontmatter, таблицы или `status:`,
  другая строка битая).
- После такого отказа модель MAY поправить только форму строки; тяжесть, утверждение и обоснование
  MUST NOT писаться моделью (F-36): они только из промпта страницы или слова человека дословно.
  «Строки нет» — пересобрать страницу и взять её новый промпт; «нет обоснования» — спросить слово у
  человека; «файла нет», «не UTF-8», «файл атаки не разбирается» — файл правит скилл `symphysis-attack`
  по `attack-table.md`.
- `apply --dry-run` печатает отчёт и `[..] --dry-run: <файл> не записан`, ничего не пишет; порядок записи без
  него — журнал, затем файлы атаки.
- `render-html` код 2 — битый файл атаки, страница не записана: правит файл атаки скилл
  `symphysis-attack` по `attack-table.md`.
- `code-sites` строка `[..] F-NN: выбранный вариант без улик` — списка по записи нет: прочитай
  запись и реши, есть ли за ней код.

## Кто что правит

- JSON журнала правят только модель (записи, парковки, `outcome`, `consequences`, `notes[]`)
  и `apply` (слово человека: `decision`, добавленные варианты, зависимости, парковки, заметки).
  `decision` модель MUST NOT писать сама: решение без слова человека атака считает блокером.
- Файл атаки (`attack/decisions.md`, `attack/artifacts.md`) правят скилл `symphysis-attack` и `apply`
  строкой о тяжести: только ячейка тяжести и `status`; журнал от такой строки не меняется.
- `decisions.md` и `symphysis.html` — рендер; в них MUST NOT писать: следующий рендер
  сотрёт правку.
- `design.md` после `render-design` — Decisions, Risks / Trade-offs, Open Questions из журнала;
  руками дописываются только Context и Goals / Non-Goals, и только после последнего рендера.
- После каждой правки журнала — `check`, затем `render-md`; после `apply` — `check`,
  `render-md`, `render-html`.
- Непонятно, что делает подкоманда, когда её звать или что значит код, — зови
  `journal.py <подкоманда> --help`; файл скрипта MUST NOT читать: справка короче и она контракт,
  а код — нет.
