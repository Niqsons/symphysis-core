# Security

Чек-лист канона ИБ по `specs/` изменения `step-help-tab`. Источники пунктов: instruction артефакта (пять пунктов), три парковки адресату «ИБ» (F-54, F-63, F-88) и чтение кода при составлении чек-листа. Канон в журнал не чеканится, он отмечается здесь. Реализации ещё нет: «чем проверено» называет пробу и чтение, которые уже были, и тест, который обязан появиться в `tasks.md`. Механика, названная здесь сверх спек, входит в реализацию так же, как сценарии.

| Инъекции через содержимое файлов: вывод хука в контекст агента (парковка F-54) | применимо — вывод хука модель читает с большим доверием, чем файл проекта, а `events.jsonl` и имя каталога изменения можно подложить. Закрывает требование `plugin-agent-hook` «Хук печатает непрочитанные события этой сессии», сценарий «Сессия без скилла»: в контекст идут постоянный текст и только проверенные поля: имя изменения по `\w[\w.-]*`, файл ответа по шаблону `openspec/changes/<имя>/answers/<дата>.md`, хеш из шестнадцатеричных цифр. Строка не по форме пропускается. Отчёт `apply`, слова человека и текст журнала в контекст не идут: они остаются в `events.jsonl` и в отчёте плагина. Это ответ на вопрос парковки: из журнала в контекст не идёт ничего. Агент получает сообщение, что развилки внесены, и файл ответа, а прочитать его отдаёт модели (слово человека 2026-11-04) | новый тест: `events.jsonl` с посторонним текстом в `change`, `answers` и `report`, текста в выводе нет; каталог изменения с посторонним именем, строки о нём нет; `events.jsonl`, указывающий на чужой файл, содержимого в выводе нет |
