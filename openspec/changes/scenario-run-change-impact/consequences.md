# Последствия: scenario-run-change-impact

**Состав:** ветки отказа, допущения

## Опись

- **Показ записи у строки атаки** — `viewer/playground-template.html:1107` «if (!id) return '';»
  - при отказе: если в разделе строки не найден номер записи, карточка не показывает текст вопроса и ссылку на запись
  - допущение: сохранение кода recordBlock гарантирует прежний результат только при сохранении номера в его входе. Группировка новой линзы может изменить этот вход
  - сценарий: Прежний механизм получает другой вход

- **Разрешение ссылки задачи на сценарий** — `trace/trace_graph.py:800` «put_unresolved(claim,»
  - при отказе: резолвер не находит мастер-сценарий среди сценариев дельты и записывает неразрешённую ссылку без связи satisfies
  - допущение: проверочная задача может ссылаться на реально существующий мастер-сценарий указанной capability. Простое подавление сигнала оставит задачу без связи
  - сценарий: Единственная ссылка на сценарий мастера

- **Подстановка живого мастера** — `trace/trace_graph.py:606` «return self.live[cap].get(previous, self.live[cap].get(name)), False»
  - при отказе: при отсутствии записи в снимке используется живой мастер. После sync его совпадение с дельтой может быть результатом самой синхронизации
  - допущение: для вывода о происхождении нужно отличить исходное состояние от текущего совпадения, иначе изменение сценария будет выглядеть как дословный перенос
  - сценарий: После синхронизации исходной базы нет

- **Первая заморозка после синхронизации** — `openspec/changes/scenario-run-change-impact/verification/baseline-code.md:18` «found.setdefault(folder.name, {}).setdefault(req.name, entry)»
  - исходное место до реализации: `trace/trace_graph.py:2105`
  - при отказе: если после sync правка соседнего сценария нарушила совпадение целого блока с дельтой, защита от поздней заморозки пропускает запись живого мастера в снимок
  - допущение: структура снимка сама по себе не подтверждает, что его получили до sync. Ошибка в порядке событий позволяет принять перенесённый результат за исходную версию
  - кандидат: F-11; ближайший сценарий: После синхронизации исходной базы нет

- **Сигнал о сценарии без задачи** — `trace/trace_graph.py:1869` «if s["id"] not in closed and state.get(s["id"]) in ("new", "changed"):»
  - при отказе: при формальной связи с задачей граф не печатает сигнал о непокрытом сценарии, даже если проверка в задаче подаёт только прежние данные
  - допущение: по существу закрытый THEN подтверждается проверкой изменённого входа. Само ребро лишь связывает документы
  - сценарий: Задача проверяет прежний вход

- **Состав причин устаревания** — `attack/attack_scope.py:113` «for target in attack["frontmatter"]["targets"]:»
  - при отказе: при совпавших локальных целях расчёт не даёт причины устаревания при изменении использованного мастер-блока
  - допущение: состав причин и вердикт учитывают фактически использованный блок. Хеш всего мастер-файла без границы блока обесценит вердикт из-за соседнего требования
  - сценарий: Общий состав называет мастер-опору

- **Чтение файла при проверке свежести** — `attack/attack_scope.py:125` «if sha256_file(full) == sha:»
  - при отказе: после успешной проверки существования read_bytes может выбросить OSError. Общий расчёт прерывается и не возвращает причину
  - допущение: проверка используемой мастер-опоры должна закончиться согласованным исходом при отказе чтения. Иначе статус и справка по одному отчёту дадут разные результаты
  - кандидат: F-12; ближайший сценарий: Общий состав называет мастер-опору

- **Разбор целей отчёта** — `openspec/changes/scenario-run-change-impact/verification/baseline-code.md:26` «if (m := RE_TARGET_PATH.match(line)):»
  - исходное место до реализации: `attack/attack_table.py:45`
  - при отказе: Python добавляет подходящую строку path из любой части frontmatter в targets. Если отдельный список мастер-опор использует ту же форму, запись попадает в проверку локальных целей
  - допущение: ядро и OpenSpec одинаково различают области сравнения. При расхождении читателей новая опора может потеряться в одном из них, а другой продолжит считать старый вердикт годным
  - кандидат: F-13; ближайший сценарий: Мастер-опора изменилась до реализации

## Исключения

- `anchors/sync_check.py` — сверяет перенесённый текст и происхождение ссылок на журнал. Проверка времени исходного снимка относится к ветке заморозки `trace/trace_graph.py`, разобранной выше.

## Pre-mortem

1. Первый снимок создают после sync и правки соседнего сценария. Атака принимает его за исходную базу и пропускает регрессию уже перенесённого сценария — кандидат: F-11
2. Мастер-опора становится нечитаемой после проверки существования. Один читатель прерывает расчёт причины, а другой продолжает с результатом, который не учитывает отказ, и оператор теряет ясный сигнал о допуске — кандидат: F-12
3. Один отчёт проводит мастер-опору через разные парсеры. Поле опоры попадает в локальные цели ядра, а в OpenSpec учитывается по другой схеме, и вердикт расходится с причиной устаревания — кандидат: F-13
