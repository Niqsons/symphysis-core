# Spec Delta

## MODIFIED Requirements

### Requirement: Строка атаки валидна только с линзой, тяжестью, инвариантом и опорой
Скилл `symphysis-attack` SHALL писать в `attack/<цель>.md` таблицу, где строка — одно утверждение цели с разделом, линзой из закрытого списка, инвариантом (кроме строк покрытия), тяжестью из `блокер | предупреждение | справка` и опорой `есть | нет | по спеке не выводится`; невыводимое SHALL получать тяжесть `предупреждение` и путь `вопрос человеку`; `status: passed` SHALL ставиться только при нуле строк `блокер`, строки `предупреждение` вердикт не держат (F-25.B, F-131.A, F-76).

#### Scenario: Одна строка предупреждения
- **GIVEN** таблица атаки с 53 строками `справка` и одной `предупреждение`
- **WHEN** скилл ставит вердикт
- **THEN** frontmatter несёт `status: passed`, строка итога в `notes[]` журнала — «…предупреждений 1… — passed», итог человеку называет эту строку

#### Scenario: Невыводимое
- **GIVEN** сценарий spec, опирающийся на край с исходом Defer в журнале
- **WHEN** скилл пишет строку `scenario-run`
- **THEN** опора — «по спеке не выводится», тяжесть — `предупреждение`, чем закрыть — `вопрос человеку`

#### Scenario: Сценарий не следует из механизма
- **GIVEN** сценарий spec «переменной нет — инцидент», решение design «новая оценка по образцу `NULLABLE_DATE_TIME_RESULT_TYPES`» и код образца `case NULL -> Either.right(Optional.empty());`
- **WHEN** скилл проходит сценарий линзой `scenario-run`
- **THEN** строка с цитатой кода `путь:строка`, исход «пустое значение без инцидента», опора «нет», тяжесть `блокер`, `status: gaps_found`

#### Scenario: Гигиена журнала не в атаке
- **GIVEN** журнал с фактом без улики
- **WHEN** скилл атакует `decisions.json`
- **THEN** строки об этом факте в таблице нет; `journal.py check` даёт код 1 с именем записи

#### Scenario: Черта в ячейке
- **GIVEN** строка атаки, цитирующая `grep -c '| справка |'` внутри backticks
- **WHEN** файл атаки разбирается просмотрщиком
- **THEN** строка даёт 7 ячеек, черта внутри backticks — текст ячейки

#### Scenario: Design молчит о механизме
- **GIVEN** новый или изменённый сценарий spec, для которого `design.md` не называет механизма (F-07.A, F-08.A)
- **WHEN** скилл проходит сценарий линзой `scenario-run`
- **THEN** строка с опорой «нет: design не называет механизм», тяжесть `блокер`; воздержания нет — ответ выводится из design

#### Scenario: Два механизма на один сценарий
- **GIVEN** сценарий spec, который design покрывает двумя решениями по очереди
- **WHEN** скилл проходит сценарий
- **THEN** по строке на каждую пару «сценарий × механизм», инвариант каждой — исход по своему коду

#### Scenario: Обратная косая перед чертой в цитате кода
- **GIVEN** код образца содержит литерально `\|` (regex в Java)
- **WHEN** скилл цитирует его в ячейке
- **THEN** в ячейке стоит `\\|` — литеральная косая и литеральная черта; парсер просмотрщика различает `\|` и `\\|`, цитата остаётся дословной

## ADDED Requirements

### Requirement: Scenario-run устанавливает область влияния изменения
Атака SHALL сверять перенос сценария `MODIFIED` с мастер-спекой до синхронизации или пригодной базой снимка. За пределами дельты атака SHALL искать сценарии по изменённым стыкам и их потребителям, идти по найденным зависимостям до подтверждённой границы и называть места найденных сценариев и существенные пробелы поиска (F-06.A).

#### Scenario: Живой мастер после синхронизации
- **GIVEN** изменение уже синхронизировано и есть пригодный снимок исходного мастер-сценария, отличающегося от текущего
- **WHEN** атака устанавливает, перенесён ли сценарий `MODIFIED` дословно
- **THEN** использована исходная база снимка, сценарий проходит как изменённый

#### Scenario: Потребитель изменённого стыка вне дельты
- **GIVEN** изменение меняет ключ строки атаки, по которому другая capability сопоставляет ответ человека со строкой, и её сценария нет в дельте
- **WHEN** атака проходит потребителей ключа
- **THEN** проверка включает сценарий той capability по названному месту в мастере и прослеживает влияние до его THEN

#### Scenario: Найдена подтверждённая граница
- **GIVEN** цепь потребителей изменённого входа заканчивается на стыке, где подтверждено прежнее наблюдаемое поведение
- **WHEN** атака определяет область дальнейшей проверки
- **THEN** атака называет стык и опору для прекращения поиска по этой цепочке

#### Scenario: После синхронизации исходной базы нет
<!-- F-09 -->
- **GIVEN** сценарий `MODIFIED` совпадает с живым мастером после синхронизации, а пригодной исходной базы нет
- **WHEN** атака определяет происхождение сценария
- **THEN** атака сообщает о пробеле базы, оставляет перенос неподтверждённым и проверяет существенные риски по условиям допуска к реализации

#### Scenario: Первый снимок сделан после синхронизации и правки дельты
<!-- F-11 -->
- **GIVEN** после синхронизации в дельте правят соседний сценарий и только затем создают первый снимок, в котором проверяемый сценарий совпадает с уже перенесённым
- **WHEN** атака определяет происхождение проверяемого сценария
- **THEN** перенос остаётся неподтверждённым по этому снимку, атака сообщает о пробеле базы и проверяет существенные риски по условиям допуска к реализации

### Requirement: Scenario-run обосновывает сохранение прежнего исхода
Для затронутого стыка `design.md` SHALL называть изменение, сохраняемые входы или свойства и основание их сохранения. Обоснование MAY быть общим для группы сценариев. Атака SHALL сопоставлять проектируемые входы и связи с THEN каждого сценария группы. Сохранение THEN получает справку с опорой на проверенный стык (F-06.A, F-07.A).

#### Scenario: Добавление линзы сохраняет входы прежних сценариев
- **GIVEN** новые строки добавляют линзу, а общее обоснование в `design.md` подтверждает сохранение прежних строк, их ключей и ссылок на журнал
- **WHEN** атака сверяет обоснование и проходит прежние сценарии отображения записи и составления промпта
- **THEN** у каждого такого сценария есть справка о сохранении THEN с опорой на общий стык

#### Scenario: Прежний механизм получает другой вход
- **GIVEN** текст сценария и функция отображения записи прежние, но проектируемая группировка убирает номер записи из поля, которое читает функция
- **WHEN** атака проверяет сохранение исхода
- **THEN** атака называет изменённый вход и потерю текста записи как противоречие THEN

### Requirement: Адресная проверка обосновывает допуск к реализации
Если проектируемый механизм согласуется с THEN, а исход проверяем только на реализации, атака SHALL считать достаточной задачу с привязкой к сценарию, изменённым входом, способом проверки и наблюдаемым THEN. Атака SHALL обозначать результат как ожидаемый. Противоречие механизма или существенный путь регрессии без достаточной проверки SHALL давать блокер (F-08.A).

#### Scenario: Исход проверит адресная задача
- **GIVEN** проектируемый механизм согласуется с THEN, а результат на смешанном наборе строк станет наблюдаемым только на реализации
- **WHEN** задача связывает сценарий, вход со строками двух линз и проверку, что ответ попадает в промпт ровно один раз
- **THEN** атака указывает задачу как достаточный план и обозначает результат как ожидаемый

#### Scenario: Задача проверяет прежний вход
- **GIVEN** проект меняет ключ на новом входе и есть существенный риск потери ответа, а задача проверяет только прежний вход
- **WHEN** атака проверяет задачу
- **THEN** атака ставит блокер и называет пропущенный изменённый вход и его последствие для THEN

#### Scenario: Запланированный тест при известном противоречии
- **GIVEN** проектируемый механизм теряет запись вопреки THEN и задача обещает проверить появление текста записи
- **WHEN** атака проходит сценарий
- **THEN** противоречие даёт блокер с причиной даже при наличии задачи

### Requirement: Изменение мастер-опоры обесценивает вердикт
Вердикт атаки артефактов MUST NOT считаться актуальным, если использованный как опора `scenario-run` блок мастер-спеки изменился, утрачен или не читается. Отчёт SHALL сохранять сведения, позволяющие опознать этот блок и сверить его содержание при проверке свежести, даже если файлы изменения не менялись (F-10.A, F-12.A).

#### Scenario: Изменился использованный блок мастера
<!-- F-10 -->
- **GIVEN** атака артефактов прошла с опорой `scenario-run` на блок мастер-спеки
- **WHEN** после атаки изменяется только этот мастер-блок и проверяется свежесть вердикта
- **THEN** прежний вердикт помечен устаревшим
