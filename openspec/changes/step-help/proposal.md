# Proposal

## Why

`docs/GUIDE.md` описывает шаги, но не отвечает на вопросы, которые возникают по ходу работы: какой шаг сейчас, зачем он, что будет без него и где смотреть результат (F-01…F-04, F-14). `openspec status`, к которому гайд отправляет, знает только о наличии файлов: при открытых развилках он ведёт дальше (F-08), после `specs` называет один из трёх готовых шагов (F-09), а реализации, синхронизации и архива в графе нет (F-13).

Части 2 плагина нужен готовый вывод ядра: тексты шагов обязаны ездить со схемой проекта, потому что версия ядра расходится с версией плагина (F-15, F-20, F-22).

## What Changes

- Новый скрипт `tools/step_help.py` считает, где работа и чей ход, по `openspec status`, счётчикам журнала и прогрессу задач, без утверждения, что шаг выполняется прямо сейчас (F-19, F-23). Он отдаёт JSON и работает без журнала и без изменения (F-33, F-34).
- Новый файл `openspec/schemas/symphysis/steps.md` с текстами шагов, разделами по `id`; тест требует раздел для каждого артефакта схемы (F-20, F-31).
- Страницы получают артефакты схемы, круг просмотрщика, `apply`, `sync` и `archive` (F-27).
- Страница шага показывает, какой шаг сейчас, зачем он, его механики, что будет без него, какие файлы смотреть, команду, предыдущий и следующий шаг (F-28). Пути файлов берутся из `status`, что заблокируется — из графа схемы, что теряется по смыслу — из текста (F-25). Про готовый шаг сказано прямо: файл есть, содержание не проверялось (F-24).
- Панель рядом с карточками показывает либо схему, либо справку; другие шаги открываются листанием и выбором пункта (F-06, F-29, F-32).
- `render-html` встраивает данные справки и время снятия; сбой расчёта страницу не роняет, панель называет причину (F-21, F-34). Пути по умолчанию нет, файл задаёт `--out` (F-30).
- **BREAKING** Страница журнала переименована из `decisions.html` в `symphysis.html`; номер контракта растёт. Записи старых прогонов и архив не меняются (F-35); `decision-scheme` к этому моменту уже в архиве (F-38).
- `install` записывает рядом с инструментами версию symphysis и короткий хеш клона. Справка малозаметно показывает версию форка и версию symphysis, за установкой не следит (F-27, F-36).
- `docs/GUIDE.md` получает строку о справке: что она есть, где открывается и какой командой считается (F-39).

## Capabilities

### New Capabilities

- `step-help`: расчёт текущего шага и чьего хода, тексты шагов, вывод JSON для показа вне страницы.

### Modified Capabilities

- `decision-viewer`: панель показывает схему или справку, страница называется `symphysis.html`, `render-html` встраивает данные справки.
- `decision-journal`: имя страницы, которую собирают из журнала.
- `project-installer`: новый скрипт среди инструментов и файл версии symphysis.
- `plugin-core-contract`: новый вывод для плагина и новый путь страницы, номер контракта растёт; в основных спеках появится с архивом `decision-scheme` (F-38).

## Impact

- Код ядра: новый `tools/step_help.py`, правки `tools/journal_cli.py`, `tools/journal_render.py`, `tools/playground-template.html`, `installer/lib/install.js`, `installer/scripts/sync-payload.js`.
- Тексты: новый `openspec/schemas/symphysis/steps.md`, пять скиллов и заметки перевода `symphysis-viewer`, `docs/GUIDE.md`, `docs/repo-contract.md`.
- Плагин: строка пути в `src/host/core.ts` и его тесты, коммит с `Needs:`. Вкладка справки делается отдельным изменением (F-22).
- Среда: сборке страницы нужен форк `openspec`, скрипт чтит `SYMPHYSIS_OPENSPEC` (F-23). Сборка занимает около 1 с вместо 0,2 с (F-34).
- Пересечение с активным `decision-scheme` по спеке `decision-viewer`: сначала оно архивируется, спеки справки пишутся на новой базе (F-37, F-38).
