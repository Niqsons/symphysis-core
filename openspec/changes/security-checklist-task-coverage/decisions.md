## F-06 Кто доводит «запланировано» до ссылки, если security и tasks можно написать в разном порядке?
<!-- journal:F-06 -->
- вид: развилка
- статус: решён
- адресат: человек
- зависит от: —
- варианты:
  - A. Согласовывать пару при создании второго артефакта. В обычном порядке шаг tasks читает запланированные пункты, оформляет или находит подходящую задачу и добавляет ссылку в security.md. Если tasks уже есть, security сверяет существующие задачи и сразу ссылается на подходящую. Если подходящей задачи ещё нет, пункт остаётся запланированным, а пользователь получает явное указание дополнить tasks и сверить ссылку. Явная зависимость шагов сохраняется в нынешнем виде. Цена — описать два порядка и обработать уже созданные файлы.
    - улика: `openspec/changes/security-checklist-task-coverage/intent.md` «Пока `tasks.md` ещё не написан, в чек-листе стоит «запланировано». На шаге `tasks` появляется ссылка на реальную задачу.»
    - улика: `openspec/schemas/symphysis/schema.yaml` «Опирайся на specs (что строить) и design (как); открытый вопрос design, меняющий задачи, реши с человеком до списка.»
    - улика: `openspec/schemas/symphysis/schema.yaml` «requires: [tasks, security, attack-artifacts]»
  - B. Добавить security к зависимостям tasks. При создании задач шаг всегда имеет на входе чек-лист и в том же проходе заполняет ссылку. Для ранее созданных tasks отдельно сверять их с новым чек-листом. Цена — новое условие готовности tasks для всех изменений, включая чек-листы без запланированных задач.
    - улика: `openspec/changes/security-checklist-task-coverage/intent.md` «Пока `tasks.md` ещё не написан, в чек-листе стоит «запланировано». На шаге `tasks` появляется ссылка на реальную задачу.»
    - улика: `openspec/schemas/symphysis/schema.yaml` «Опирайся на specs (что строить) и design (как); открытый вопрос design, меняющий задачи, реши с человеком до списка.»
