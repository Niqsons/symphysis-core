# Proposal

## Why

Работа с развилками держится на обосновании рекомендации: просьба слова при выборе мимо неё осмысленна, только если есть причина, с которой можно спорить (F-01, F-03, F-16). Сейчас причину можно спрятать, не нарушив ни одной проверки. Скиллы называют поле `text` рядом с `why` без объяснения (F-11), плагин и `decisions.md` показывают `text` вместо причины (F-08, F-09), а страница показывает `why` (F-10). `check` следит только за тем, что `why` не пуст (F-13). Так уже записано 180 рекомендаций в архиве (F-14), а в журнале `reverse-hook` человек решил 12 развилок, не видя причин.

Механику нужно закрепить в ядре, а не только поправить в одной сессии (F-02). Отдельным изменением, раньше `reverse-hook`: ловушка касается всех журналов, а хуку ещё предстоит долгий путь.

## What Changes

- `decisions.md`, карточка и режим проверки плагина всегда показывают `вариант — why`, как уже делает страница (F-04, F-19).
- Импорт из markdown перестаёт писать `text`. У 5 старых составных рекомендаций меняется только начало строки: `B — для процедур…` вместо `B для процедур…`, причина цела (F-15, F-19).
- Поле `text` остаётся необязательным в схеме, с описанием «только старые журналы, показ и поиск его не читают». Новые записи его не пишут, поиск плагина перестаёт его читать (F-18, F-20).
- Скиллы `symphysis-brainstorm`, `symphysis-edge-probe` и `symphysis-consequences` перестают называть `text`; `why` описан как причина выбора этого варианта против других, так же и в `symphysis-prohibition-probe`, который поля не называл (F-05, F-21, F-32).
- Атака считает находкой `why`, который пересказывает вариант (F-21).
- Просьба слова при выборе мимо рекомендации не меняется: карточка просит, «Внести» работает, `check` сигналит (F-22).
- Старые журналы остаются законными, архив не пересобирается (F-06, F-20).
- Требования в спеках и тесты на показ: случай «есть `text`, а причина всё равно видна» (F-07).
- Страховка от возврата ловушки: поле убрано из типа плагина, чтобы компилятор ловил новое чтение, а тест ядра ищет его в `tools/` (F-30). Обе страховки снимаются вместе с полем.
- Режим проверки плагина правится только так, чтобы собрался тип, без новых сценариев и тестов: его позже снимут (F-27, F-29, F-31).

### Modified Capabilities

- `decision-journal`: `decisions.md` пишет рекомендацию как `вариант — why`, импорт не пишет `text`, смысл `why` и поля `text`.
- `decision-viewer`: страница показывает причину и при наличии `text`, поведение закрепляется сценарием.
- `plugin-decision-view`: карточка показывает `вариант — why`, поиск не читает `text`.
- `brainstorm-interview`: `why` записывается как причина выбора этого варианта против других, `text` модель не пишет.
- `artifact-attack`: `why`, пересказывающий вариант, считается находкой.
