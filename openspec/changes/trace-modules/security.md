# Security

Чек-лист относится к структурной оси `trace-modules`: обследованию участвующих repo, чтению README и metadata, аннотациям реализации, снимку и диагностике. Парковки F-46/F-47 разобраны здесь; канон не становится новыми развилками журнала.

Сейчас проверены требования и сценарии проектирования. Реализация ещё не написана: чтение specs и нынешнего resolver не доказывает исполнение новых гарантий; соответствующие негативные тесты должны войти в tasks и пройти при apply.

| Пункт | Применимо / неприменимо — причина | Чем проверено |
| --- | --- | --- |
| Инъекции через содержимое файлов | Применимо: модель анализирует чужие README. Закрывает `module-discovery`: «Объявления обрабатываются как недоверенные данные»; файл не меняет полномочия, корни и порядок работы (F-47). | Прочитан сценарий «Инструкция внутри README не расширяет полномочия»: инструкция прочитать другой корень или скрыть сигнал остаётся данными. Исполнение моделью ещё не проверено; в tasks нужна проба с таким README и следом действий. |
| Пути с `../` | Применимо: пути приходят из объявлений и аннотаций. Закрывает `repository-survey`: «Структурные источники остаются внутри разрешённого корня»; чтение после выхода за выбранный корень запрещено (F-46). | Сценарий «Обход границы через путь или ссылку»; прочитан `roots/roots.py`, `_resolve`: отсекает `..`, абсолютный хвост и результат resolve вне корня. Новая проводка этого resolver ко всем структурным источникам ещё не проверена. |
| Токены и срок их жизни | Неприменимо: изменение не вводит аутентификацию, получение, хранение или обновление токенов; обход локальных repo не получает новые сетевые полномочия. Случайный секрет в README относится к строке о чувствительных данных, а не к новой системе токенов. | Прочитаны proposal, F-17/F-31 и specs: входы — локальная карта, metadata, README и аннотации; операции выдачи токенов и сетевой клиент в объём не входят. |
| Права | Применимо: файл может быть недоступен текущему процессу, сторонний repo остаётся источником чтения. Закрывают `module-discovery`: «Сторонние README остаются входными данными» и «Ошибка источника не стирает доступную структуру». | Сценарии «Нет нужного объявления у клиента», «Нечитаемый README не скрывает соседний модуль» (F-49): нет автоматической правки README, ошибка доступа даёт сигнал и сохраняет соседние модули. Тест ошибки доступа и проверка отсутствия записи ещё предстоят. |
| Бинарные файлы | Применимо к README, который ошибочно содержит бинарные байты. Закрывает `module-discovery`: «Объявления обрабатываются как недоверенные данные»; неподходящий текст не исполняется и не становится модулем. | Сценарии «Бинарный README не становится объявлением» и «Негодная кодировка README не обрывает доступный граф» (F-50); прочитан `roots/roots.py`, `_read_text`: NUL и неверный UTF-8 различаются. Новый сканер ещё не проверен на байтовых фикстурах. |
| Чувствительные данные в журнале, артефактах и журналах прогона | Применимо: локальные пути и посторонний текст README могут быть приватными. Закрывают `trace-snapshot`: «Диагностика и снимок не копируют приватные входные данные» и «Снимок и отчёт лежат в каталоге graph»; `repository-survey`: «Состав компонентов и репозиториев хранится переносимо». Область — новые структурные данные и сообщения; это не обещание очистить весь прежний произвольный текст пользовательского журнала. | Сценарии «Ошибка YAML не раскрывает приватный документ», «Снимок содержит декларацию без полного README», «Абсолютных путей нет». По F-37 сохраняются нормализованные поля и хеши. В tasks нужна проверка JSON, отчёта и перехваченных stdout/stderr на абсолютные пути и секрет-маркер; сейчас проверена только полнота сценариев. |
| Безопасная десериализация YAML | Применимо: frontmatter и metadata — внешние данные. Закрывает `module-discovery`: «Объявления обрабатываются как недоверенные данные»; конструирование произвольных объектов и выполнение команд запрещены (F-47). | Прочитан сценарий «YAML не конструирует исполняемый объект». В tasks нужна отрицательная фикстура с тегом конструктора и утверждением об отсутствии побочного эффекта, наличии сигнала и сохранности соседнего модуля. Безопасность будущего парсера пока не проверена исполнением. |
| Symlink, junction и циклы каталогов | Применимо: обычный строковый префикс не удерживает разрешённый путь в repo. Закрывает `repository-survey`: «Структурные источники остаются внутри разрешённого корня»; отдельно сохраняются исключения `.git`, `node_modules`, `.symphysis` из «Обход не зависит от первого уровня и Git» (F-46/F-32). | Сценарии «Обход границы через путь или ссылку», «Цикл каталогов через ссылку», «Служебный каталог исключён». Прочитан `_resolve` с проверкой после resolve; сканер ещё не проверен на реальных ссылках и на служебном каталоге, достигнутом через ссылку. |
| Подмена локального источника псевдонимом | Применимо: отсутствующий псевдоним нельзя превратить в подкаталог текущего проекта через пустой префикс. Закрывает `repository-survey`: «Repo разрешается через явно названный корень» (F-48). | Сценарий «Неизвестный псевдоним не подменяется пустым префиксом». В consequences воспроизведён нынешний fallback `_resolve` на временной карте; запрет такого fallback для привязки repo должен быть проверен новым тестом после реализации. |
| Новое хранилище персональных данных и сроки хранения | Неприменимо: отдельное хранилище персональных данных, сбор аналитики и новый срок хранения этим изменением не вводятся. Снимок хранит нормализованные структурные декларации и хеши; исходный код и полные README не копируются (F-37). | Прочитаны `trace-snapshot`: «Снимок сохраняет нормализованную структуру и состояния», «Диагностика и снимок не копируют приватные входные данные» и сценарий без полного README. Архивы автоматически не переписываются. |

Границы проверки: сохранность пары декларация/хеш и согласованность снимка с отчётом заданы F-44/F-51; это не утверждение о глобальной блокировке repo. Старые снимки формата 2 и их пригодная base сохраняют прежний смысл по F-23/F-52. Проверки новых гарантий должны использовать обезличенные временные деревья и явную карту `--roots`; личная карта и клиентские README не изменяются.
