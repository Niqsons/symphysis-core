# Последствия: trace-modules

**Состав:** ветки отказа, допущения

Область — повторно используемые resolver, читатели и проверки графа, фильтр экспорта, freeze и список поставки. Обнаружение модулей ещё не реализовано: последствия переноса нынешних веток на README ниже — допущения о предстоящем расширении, а не результаты его запуска. Три файла из code-sites учтены: два разобраны, один исключён; файл поставки добавлен по proposal. F-26 не дал места кода: выбранный владельцем момент анализа оформлен в repository-survey, существующего сканера за этим решением нет.

## Опись

- **Неизвестный псевдоним repo** — `roots/roots.py:113` «if not path.startswith(prefix.replace("\\", "/")):»
  - при отказе: неподходящий префикс пропускается; более короткий, в том числе пустой, ещё может разрешить строку как путь.
  - допущение: привязка repo должна проверять существование названного псевдонима до обычного разрешения файлов; иначе опечатка станет чужим источником.
  - кандидат: F-48; ближайший сценарий: Текущий и внешний репозитории

- **Выход за объявленный корень** — `roots/roots.py:116` «if ".." in tail.split("/") or Path(tail).is_absolute() or tail.startswith("/"):»
  - при отказе: возвращает OUTSIDE_ROOT для недопустимого хвоста; файл не читается.
  - допущение: сканер и аннотации не должны обходить этот вердикт при построении структуры; пределы путей остаются предметом ИБ.
  - кандидат: F-46 (существующая парковка ИБ; проверка путей и ссылок выполняется в security)

- **Junction ведёт вне корня** — `roots/roots.py:121` «return file if file == root or file.is_relative_to(root) else OUTSIDE_ROOT»
  - при отказе: разрешённый путь вне корня возвращается как OUTSIDE_ROOT.
  - допущение: граница repo проверяется после resolve, а не только строковым префиксом; иначе README вне repo окажется его модулем.
  - кандидат: F-46 (существующая парковка ИБ для границ resolver и ссылок)

- **Нечитаемый файл объявления** — `roots/roots.py:186` «return None, VERDICT_UNREADABLE»
  - при отказе: helper отдаёт None с отдельным вердиктом недоступности, а не пустой текст.
  - допущение: если будущий читатель README возьмёт этот helper, он обязан сохранить вердикт; отбрасывание вердикта превратит неизвестный источник в отсутствие модуля.
  - кандидат: F-49; ближайший сценарий: Один недоступный сосед

- **Кодировка объявления и общий отказ артефактов** — `trace/trace_graph.py:379` «raise Refusal(f"{rel}: файл не в UTF-8 ({e.reason}, байт {e.start}): граф не собран") from None»
  - при отказе: общий reader артефактов бросает Refusal и не отдаёт граф; это нынешний исход для файлов изменения, не уже реализованная обработка README.
  - допущение: нельзя автоматически унаследовать общий отказ при подключении README: один негодный источник тогда сотрёт корректные модули и требования.
  - кандидат: F-50; ближайший сценарий: Один недоступный сосед

- **Синтаксически негодный журнал** — `trace/trace_graph.py:398` «raise Refusal(f"decisions.json: журнал не разбирается ({e}): граф не собран") from None»
  - при отказе: отказывает сборке с именем decisions.json.
  - допущение: частичный структурный граф не отменяет отказ по негодному обязательному журналу; иначе ошибки входного JSON будут скрыты расширением.
  - сценарий: Журнал не разбирается

- **Негодная схема журнала** — `trace/trace_graph.py:401` «raise Refusal(f"decisions.json: журнал негоден по схеме, ошибок {len(errors)}: граф не собран",»
  - при отказе: отказывает сборке и передаёт строки ошибок validate_journal.
  - допущение: новая ось не подменяет проверку основного журнала; иначе граф объявит происхождение связей из негодных записей.
  - сценарий: Журнал негоден по схеме

- **Два поддерживаемых формата и один номер читателя** — `trace/trace_graph.py:1066` «if not problems and data["format"] != GRAPH_FORMAT:»
  - при отказе: нынешний reader принимает только GRAPH_FORMAT, остальные номера дают сигнал формы.
  - допущение: в расширении условие должно различать поддерживаемые 2/3 и отвергаемый 1; иначе обещанная совместимость 2 не сработает.
  - сценарий: Прежний поддерживаемый файл; сценарий: Снимок прежнего формата

- **База старого поддерживаемого снимка** — `trace/trace_graph.py:564` «raw = data.get("base") if isinstance(data, dict) and data.get("format") == GRAPH_FORMAT else None»
  - при отказе: при несовпадении format с GRAPH_FORMAT raw становится None, затем база пуста и выбирается живой master.
  - допущение: при выпуске формата 3 нельзя без решения выкинуть пригодную base формата 2; иначе после sync появляются ложные ссылки.
  - кандидат: F-52; ближайший сценарий: Старый снимок и нынешние модули

- **Изменился известный структурный источник** — `trace/trace_graph.py:1079` «return ([f"{rel}: исходник изменён после сборки" for rel in sorted(old.keys() & now.keys()) if old[rel] != now[rel]]»

  - допущение: набор источников должен включить объявления и metadata; без них изменение README оставит ложную свежесть.
  - сценарий: README меняет свежесть

## Исключения

- `upstream/openspec/src/utils/change-metadata.ts` — writeChangeMetadata создаёт новый YAML из очищенного Zod-объекта, readChangeMetadata возвращает типизированную часть без x-расширений. F-36 прямо исключил этот writer из обновления существующего metadata; модель редактирует сырой x-symphysis-components и проверяет diff. Его ветки чтения, неизвестной schema и записи не являются реализацией нового читателя структурных объявлений и не должны заимствоваться как путь обновления. Это не обещание, что typed reader сохраняет расширения. Сохранность чужих данных уже проверяется сценариями «Сохранение посторонних данных» и «Состав metadata изменился после чтения» (F-38).

## Pre-mortem

1. Неизвестный псевдоним внешнего repo разрешился через пустой префикс как подкаталог текущего проекта: граф показывает правдоподобные модули другого источника — кандидат: F-48.
2. Freeze прочитал README дважды: req-graph.json содержит модуль a, report.md уже описывает b, но оба выданы как одна свежая пара — кандидат: F-51.
3. При смене GRAPH_FORMAT с 2 на 3 пригодная base старого снимка отброшена; после sync нынешний master изменил смысл отсечения прежних ссылок MODIFIED, хотя формат 2 объявлен поддерживаемым — кандидат: F-52.

Дополнительный риск поставки не чеканится повторно: код работает в исходном дереве, но новый helper отсутствует в установленной плоской копии. Он уже входит в F-25: проверка установленного инструмента обязательна вместе с настоящими модулями symphysis и межрепозиторной фикстурой.
