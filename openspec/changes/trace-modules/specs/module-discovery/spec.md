# Spec Delta

## Purpose

Чтение явных объявлений модулей и зависимостей в произвольном дереве репозитория: границы, принадлежность файлов и работа с недоступными источниками без изменения клиентских README.

## ADDED Requirements

### Requirement: README явно объявляет имя и род модуля
Обнаружение SHALL распознавать модуль по README.md с валидными name и kind во frontmatter: непустое имя и род «доменный» либо «технический». Имя может отличаться от каталога. Обычный README без объявления MUST NOT становиться модулем только из-за наличия файла; ошибки явного объявления дают сигнал (F-01, F-09, F-18).

#### Scenario: Имя не равно каталогу
- **GIVEN** src/editor/README.md объявляет name: viewer и kind: доменный
- **WHEN** обследуется дерево
- **THEN** обнаружен модуль viewer с границей src/editor

#### Scenario: Обычное описание репозитория
- **GIVEN** README.md содержит описание, но не объявляет name и kind
- **WHEN** обследуется дерево
- **THEN** одно наличие README не создаёт модуль

#### Scenario: Негодный род
- **GIVEN** явное объявление содержит kind: служебный
- **WHEN** объявление прочитано
- **THEN** сигнал называет файл и негодное значение

#### Scenario: UTF-8 BOM и окончания строк не скрывают модуль
<!-- F-40 -->
- **GIVEN** одно валидное объявление README записано в четырёх сочетаниях UTF-8 с BOM или без BOM и LF или CRLF
- **WHEN** выполнено обнаружение модулей
- **THEN** во всех четырёх вариантах обнаружены одинаковые имя и род модуля

### Requirement: Обход не зависит от первого уровня и Git
Обход SHALL читать рабочее дерево объявленного repo на любой глубине, включая корень, без обязательного Git. Служебные .git, node_modules и установленная .symphysis SHALL исключаться; дополнительные исключения задаются переносимо для repo. Имена src/modules не задают привилегированных мест; .gitignore сам по себе не определяет наличие модуля (F-16, F-32).

#### Scenario: Корень и глубокий каталог без Git
- **GIVEN** в дереве без Git объявлены модули в README корня и src/deep/part/README.md
- **WHEN** выполнено обнаружение
- **THEN** обнаружены оба модуля без требования добавить их пути в перечень мест модулей

#### Scenario: Служебный каталог исключён
- **GIVEN** валидные объявления есть в src/ и node_modules/
- **WHEN** выполнено обнаружение
- **THEN** объявление src учитывается, служебное node_modules не входит в состав

#### Scenario: Игнорируемый Git файл
- **GIVEN** валидный README существует в рабочем дереве и не исключён правилами repo, но игнорируется Git
- **WHEN** выполнено обнаружение
- **THEN** наличие объявления не зависит от попадания файла в Git index

### Requirement: Файл относится к ближайшей объявленной границе
Для файла внутри объявленных модулей принадлежность SHALL определяться ближайшим содержащим каталогом с валидным README. Один файл MUST NOT одновременно принадлежать родительскому и вложенному модулю. Файл вне всех объявленных границ не получает выдуманный модуль; расположение модулей symphysis не применяется как правило клиента (F-02, F-18).

#### Scenario: Вложенный модуль клиента
- **GIVEN** корень объявлен модулем base, а src/part объявлен модулем part
- **WHEN** определяется принадлежность src/part/main.py
- **THEN** владелец файла — только part

#### Scenario: Файл вне границ
- **GIVEN** модуль объявлен только в src/one, файл находится в docs/
- **WHEN** определяется принадлежность файла
- **THEN** файл не приписан модулю one или синтетическому модулю корня

### Requirement: Неоднозначное имя модуля не разрешается догадкой
Если несколько README одного repo объявляют одно имя модуля, обнаружение SHALL назвать места конфликта сигналом. Ссылка по такому имени MUST NOT связываться с произвольно выбранным каталогом. Корректные независимые объявления продолжают обрабатываться; одинаковое имя в разных repo не является таким конфликтом (F-18, F-21).

#### Scenario: Повтор внутри repo
- **GIVEN** каталоги a и b одного repo объявляют name: viewer
- **WHEN** обрабатывается ссылка на этот модуль
- **THEN** сигнал содержит оба README; ссылка не назначена одному из них по порядку обхода

#### Scenario: Одно имя разных repo
- **GIVEN** core и plugin объявляют каждый свой viewer
- **WHEN** строится структура
- **THEN** это два различных модуля, а не конфликт имени

### Requirement: Зависимость читается из объявления README
Обнаружение SHALL читать во frontmatter README список логических repo/module, от которых зависит модуль. Направление — от объявляющего модуля к названному. Обычная ссылка в тексте README или импорт в коде MUST NOT автоматически становиться подтверждённой зависимостью; неразрешённая цель даёт сигнал (F-20, F-35).

#### Scenario: Объявленная межрепозиторная зависимость
- **GIVEN** модуль core/viewer явно называет plugin/protocol в списке зависимостей
- **WHEN** обрабатываются объявления
- **THEN** зависимость направлена от core/viewer к plugin/protocol с местом в README

#### Scenario: Только упоминание в описании
- **GIVEN** README содержит обычную ссылку на другой модуль, но зависимости не объявляет
- **WHEN** обрабатывается README
- **THEN** ссылка в прозе сама по себе не создаёт подтверждённую зависимость

#### Scenario: Цель отсутствует
- **GIVEN** объявленная зависимость называет неизвестный repo/module
- **WHEN** собирается граф
- **THEN** сигнал называет цель и место объявления; связь с похожим именем не подставляется

#### Scenario: Цикл объявленных зависимостей сохраняется
<!-- F-41 -->
- **GIVEN** корректные модули a и b явно объявили a → b и b → a
- **WHEN** собран граф и выполнена фильтрованная текстовая выборка диаграммы
- **THEN** граф сохраняет оба ребра, фильтр завершает обход, сам цикл не превращается в запрет выпуска

### Requirement: Сторонние README остаются входными данными
Продукт SHALL читать существующие README сторонних repo и MUST NOT автоматически дописывать в них имя, род или зависимости ради построения графа. GUIDE.md SHALL описывать соглашение обозначения модулей и зависимостей для владельца repo. Применение соглашения к собственным модулям symphysis служит догфудингом, а не миграцией чужих деревьев (F-07, F-25, F-35).

#### Scenario: Нет нужного объявления у клиента
- **GIVEN** сторонний README не содержит декларации зависимости
- **WHEN** выполнены обследование и сборка графа
- **THEN** файл не изменился; продукт не дописал декларацию от имени владельца

#### Scenario: Соглашение доступно владельцу
- **GIVEN** владелец хочет включить свой модуль в граф
- **WHEN** читает GUIDE.md
- **THEN** описаны требуемые объявления README и правила зависимостей без требования раскладки каталогов symphysis

### Requirement: Ошибка источника не стирает доступную структуру
Нечитаемый или негодный источник объявления SHALL давать сигнал с местом и причиной. Доступные корректные модули других источников SHALL оставаться в графе. Недоступный источник MUST NOT выдаваться за подтверждённое отсутствие модулей или за пустой список зависимостей (F-21, F-30).

#### Scenario: Один недоступный сосед
- **GIVEN** один repo с валидными модулями доступен, другой недоступен
- **WHEN** собран граф
- **THEN** модули доступного repo сохранены, недоступность соседа названа отдельно
