# Приёмка trace-modules

Дата итоговой проверки: 2026-11-10. Ветка `feat/trace-modules`, исходное состояние перед реализацией `c6651d852fb84fc2c90a794f2419a21dbf6103ce`.

Реализованы переносимые объявления компонентов/repo, обследование README произвольной глубины, структурные узлы и явные связи реализации/зависимости. Новый снимок имеет format 3; поддерживаемый format 2 читается без дорисовки нынешней структуры. Проверки сохраняют характер сигналов.

## Воспроизведение

Из корня этой рабочей копии в PowerShell:

```powershell
$tracePython = Join-Path $env:LOCALAPPDATA 'Microsoft/WindowsApps/python3.13.exe'
& $tracePython -X utf8 -m pytest
npm --prefix installer test
& $tracePython -X utf8 openspec/changes/trace-modules/verification/installed_acceptance.py
& $tracePython -X utf8 openspec/changes/trace-modules/verification/verify_plan.py
& $tracePython -X utf8 openspec/changes/trace-modules/verification/verify_history.py
node upstream/openspec/bin/openspec.js validate trace-modules --strict
& $tracePython -X utf8 cli/journal.py check openspec/changes/trace-modules/decisions.json --strict --roots openspec/changes/trace-modules/probes/journal-roots.json
& $tracePython -X utf8 trace/trace_graph.py freeze trace-modules --roots openspec/changes/trace-modules/probes/journal-roots.json

git diff --check
```

Версия Python проверки — 3.13.14. xdist: 12 workers из штатного pytest.ini. Источники инструментов вызываются прямо из рабочей копии; установка — только локальным installer/bin/symphysis.js после sync-payload.js. Личная карта и настройки не используются.

## Настоящий репозиторий и установленная копия

[plan-results.json](plan-results.json) подтверждает 16 настоящих модулей из README Symphysis, 34 требования, 94 сценария и 40 задач. Все сценарии ADDED и новые/изменённые сценарии MODIFIED связаны с задачами; у всех 13 Specify есть сценарии со следом пробы. Требование `trace-graph/Граф собирается из файлов изменения` явно реализуют `symphysis-core/trace` и `symphysis-core/roots`. Зависимость trace → roots имеет источник `trace/README.md`; её подтверждают настоящий импорт roots и вызовы resolver в сборщике/helper. Объявлены также прямые зависимости trace → decisions и trace → openspec-run по реальным импортам. Чужие README не правились.

[installed-results.json](installed-results.json) содержит полные вызовы и вывод настоящего установленного инструмента из вложенного cwd вне Git. Два repo имеют одноимённые модули viewer; третий модуль находится глубоко в src. Получены три разных module id, четыре implements (два явно названных модуля, файл и ближайший модуль файла), межрепозиторная зависимость и её происхождение. Неназванный unused.py отсутствует в графе. build/report/freeze/check/отфильтрованный requirementDiagram завершились кодом 0; check не дал сигналов свежести. Хеш установленного helper совпал с исходником, README не изменились, приватный синтетический текст и абсолютный временный корень отсутствуют в JSON/report/snapshot. Проект удаляется штатным TemporaryDirectory, junction в этом стенде нет.

В сохранённых выводах известные пути заменены на `<case>`, `<source>`, `<python>`; разделители путей установленного стенда приведены к `/`. Это только нормализация среды. Точные входные страницы модельных проб и их хеши сохраняются отдельно.

## Модельные подшаги и тела скиллов

Два изолированных прогона модели исполнили изменённые подшаги на установленной копии: initial intent, уточнение repo исследованием, перечитывание metadata после конкурентного добавления repo, перенос одного блока требования и штатная обработка якорей. Во всех шести repo состояния совпали; чужие расширения и конкурентный repo сохранены; JSON-аннотация модуля F-19 не стала ссылкой журнала. README с инструкцией прочитать другой корень/подменить чужое поле остался данными: чужое поле и источники сохранены, недоступность repo не скрыта. Ввод второй стадии зафиксирован аудируемым reader по страницам, полнота и хеши проверены.

Повтор с новой fixture: `setup_model_probe.py`, затем два новых контекста по описанию [repository-survey.md](repository-survey.md) и `verify_model_probes.py`. Точный след и сообщения — [model-trials/results.json](model-trials/results.json), файлы phase1/phase2 и JSONL рядом. Контрольный скрипт проверяет выполненную моделью запись; сам не подставляет ожидаемую metadata.

Предел: это пробы подшагов, полного интервью/research/sync workflow и причинного улучшения качества они не доказывают. Полный native transcript первой стадии и вызовов вне reader не экспортировался. Реальный файловый symlink на этой Windows недоступен из-за привилегий: внутренняя README-file alias проверена подменой результата resolver. Каталожные junction/циклы/выход наружу проверены настоящими ссылками без пропуска.

Payload тел после удаления провенанса: brainstorm — 2834 слова, research — 2351 (подсчёт непустых последовательностей вместе с frontmatter). Это существующие многошаговые тела; новый общий протокол вынесен в `.symphysis/docs/module-declarations.md`, одних числовых ориентиров недостаточно для удаления поведения. Оба прогона дали одинаковую форму metadata и состояний.

## Проверки безопасности

Все 10 строк [security.md](../security.md) имеют фактическое свидетельство либо сохранённую причину неприменимости:

| Область | Результат |
| --- | --- |
| Инструкции внутри README | Две модельные пробы: чужое поле/корни/сигнал недоступности сохранены; предел аудита указан выше. |
| `../`, абсолютные пути | Resolver и тесты аннотаций удерживают входы внутри явно выбранного repo; приватный путь не отражается в диагностике. |
| Токены | Неприменимо: новый auth/network/token lifecycle не вводится. |
| Права | Управляемый PermissionError даёт частичный граф; хеши README до/после совпадают. |
| Бинарные файлы/кодировки | NUL и неверный UTF-8 дают локальный сигнал, корректный сосед сохранён; BOM/LF/CRLF поддержаны. |
| Приватные данные | Отрицательные фикстуры проверяют JSON/report/stdout/stderr; установленный стенд — snapshot и report. |
| YAML | SafeLoader отвергает исполняемый тег без побочного эффекта; дубликат ключа диагностируется. |
| Symlink/junction/циклы | Настоящие Windows junction: внешние байты не читаются, цикл завершается, service alias исключён. File alias — отдельный resolver-тест. |
| Точный псевдоним | Неизвестный alias не превращается в пустой префикс; доступный независимый repo сохранён. |
| Новое хранилище ПД/срок хранения | Неприменимо: отдельное хранилище/сбор/новый срок не вводятся. |

## Ревью и сохранение истории

Независимое ревью всей реализации нашло три P2: переход аннотации к соседнему `###Requirement`, пропуск аннотаций без состава repo и смещение границы через README-file alias. На каждое получен падающий регрессионный тест, исправлено поведение; отдельная проверка сохранила артефактный режим format 2. Повторное ревью исправлений не нашло существенного остатка. HTML-рендер плагина, первичный master graph и store в объём не включались согласно решениям; модельные пределы приняты явно.

Журнал: 172/172 улик сверены. Восемь исчезнувших после реализации цитат перенесены с прежними словами в [baseline-sources.md](baseline-sources.md), проверены по исходному commit; решения, слова владельца и outcome сохранены. Сгенерированные решения/страница/design обновлены, ручные Context, Goals / Non-Goals, Migration Plan сохранены.

`journal.py check --strict` возвращает **2**, а не чистый 0: шесть цитат исходной описи consequences больше не стоят в нынешнем коде. [verify_history.py](verify_history.py) подтверждает каждую в исходном commit и baseline-sources, а также неизменность всей consequences.md. [historical-results.json](historical-results.json) содержит точный перечень. Это объяснённые исторические сигналы; опись не переписана после apply ради зелёной сверки. Новых потерянных улик журнала нет.

Отчёт графа сохраняет три объяснённых сигнала: F-03 не имеет прямой ссылки в тексте требования, хотя его связи реализованы trace-conventions/module-discovery и задачами 3.4/4.x; F-06 — критерий реальной приёмки, закрытый 9.1; требование о границе корня опирается на канон ИБ F-46 без новой развилки владельца. Полная классификация в plan-results.json. Неизвестных ссылок, дублей id, непокрытых задачами новых сценариев и Specify без сценария нет. Отчёт не редактировался вручную и остаётся полным.

Необязательные attack-decisions и attack-artifacts не вызывались. Merge, push, master sync и архивирование в этот шаг не входят.
