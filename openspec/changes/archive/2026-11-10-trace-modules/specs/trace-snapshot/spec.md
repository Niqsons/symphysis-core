# Spec Delta

## ADDED Requirements

### Requirement: Снимок сохраняет нормализованную структуру и состояния
Снимок SHALL сохранять нормализованные объявления, логические repo/module, относительные пути, состояния обследования и доступности, происхождение связей и хеши прочитанных объявлений. Полные README и исходный код не копируются. Историческая структура SHALL читаться из снимка без нынешнего клона; при недоступности живого источника предел проверки явно называется (F-22, F-37).

#### Scenario: Клон после заморозки недоступен
- **GIVEN** снимок содержит структуру и источники repo, клон затем исчез
- **WHEN** читается снимок и проверяется доступность нынешних источников
- **THEN** историческая структура остаётся в снимке; невозможность живой проверки не объявляется отсутствием прежних модулей

#### Scenario: Декларация и её хеш относятся к одной прочитанной версии
<!-- F-44 -->
- **GIVEN** README изменён между извлечением его объявления и вычислением хеша источника
- **WHEN** freeze сохраняет структуру
- **THEN** декларация и хеш относятся к одним прочитанным байтам либо фиксируется невозможность согласованного чтения; смешанная пара старых полей и нового хеша не сохраняется

### Requirement: Диагностика и снимок не копируют приватные входные данные
Переносимые структурные данные, снимок, отчёт и диагностика нового обнаружения MUST NOT копировать абсолютные локальные каталоги, значения личной карты корней или полные тела README и metadata. Источник SHALL называться логическим repo и относительным путём; ошибка разбора — причиной без сырого документа. Объявленные поля и хеши сохраняются по правилам нормализованного снимка (F-46, F-37).

#### Scenario: Ошибка YAML не раскрывает приватный документ
- **GIVEN** личная карта содержит абсолютный каталог, а негодный README содержит строку с секретом вне объявления
- **WHEN** строятся структурный отчёт и диагностические сообщения
- **THEN** названы логический repo, относительный путь и причина; абсолютный каталог, значения карты и сырая строка с секретом не выведены

#### Scenario: Снимок содержит декларацию без полного README
- **GIVEN** README содержит валидные поля модуля и дополнительный приватный текст вне объявления
- **WHEN** freeze сохраняет структуру
- **THEN** снимок содержит нормализованные объявленные поля, происхождение и хеш, но не полный README и не его посторонний приватный текст

### Requirement: Состав README входит в проверку дрейфа
Снимок SHALL фиксировать состав найденных объявлений README в пределах обследования, а проверка SHALL замечать добавление, удаление и перенос такого объявления, не только правку уже известного файла. Проверка живых источников MUST NOT молча подменять ими сохранённую историческую структуру (F-22, F-30, F-37).

#### Scenario: Новый модуль после freeze
- **GIVEN** после заморозки добавлен валидный README в новом каталоге внутри области
- **WHEN** проверен дрейф
- **THEN** назван новый источник, хотя его пути не было в прежнем sources

#### Scenario: Перенос модуля
- **GIVEN** README модуля перенесён в другой каталог
- **WHEN** проверен прежний снимок
- **THEN** изменение состава/размещения обнаружено; прежнее размещение не переписано проверкой

### Requirement: Предыдущий формат читается без дописывания модулей в историю
Снимок формата 2 SHALL читаться как прежний поддерживаемый снимок без структурных сведений. Отсутствие этих сведений MUST NOT считаться результатом «модулей нет». Архивные снимки SHALL NOT автоматически мигрироваться или обогащаться текущими README; формат 1 не становится поддерживаемым вновь только из-за расширения графа (F-22, F-23).

#### Scenario: Старый снимок и нынешние модули
- **GIVEN** архивный формат 2 не содержит структуры, а в нынешнем клоне есть модули
- **WHEN** снимок прочитан новым читателем
- **THEN** файл не переписан, модули не дорисованы задним числом; отсутствие структурных данных явно отличимо от результата обследования

#### Scenario: Поддерживаемая база формата 2 сохраняется после sync
<!-- F-52 -->
- **GIVEN** снимок формата 2 несёт валидную base MODIFIED, а master уже изменён sync
- **WHEN** новый сборщик формата 3 читает прежнюю базу
- **THEN** пригодная base формата 2 сохраняет прежний смысл ссылок; нынешний master не подставляется вместо неё только из-за номера формата

## MODIFIED Requirements

### Requirement: Снимок и отчёт лежат в каталоге graph
Freeze SHALL класть req-graph.json и report.md в openspec/changes/<change>/graph: отсутствующий, неполный или устаревший снимок собирается, свежий обновляет коммиты корней. Свежесть SHALL учитывать и структурные источники. Снимок и отчёт MUST NOT содержать абсолютные пути; отключения снимка настройкой нет. После архивации снимки автоматически не пересобираются (F-05, F-22, F-23, F-37).

#### Scenario: Заморозка
- **GIVEN** изменение с готовыми артефактами
- **WHEN** идёт заморозка
- **THEN** в `graph/` лежат снимок и отчёт, снимок несёт узлы и связи с местом в файле, хеши исходников, коммиты корней и базу мастер-спеки

#### Scenario: Каталог уезжает в архив
- **GIVEN** изменение с `graph/`
- **WHEN** изменение архивируется
- **THEN** снимок и отчёт лежат в `archive/<дата>-<имя>/graph/`

#### Scenario: Снимок без отчёта
<!-- trace-graph/F-100 -->
- **GIVEN** в `graph/` есть снимок, отчёта нет
- **WHEN** выполняется `/opsx:archive`
- **THEN** `graph/` считается неполным и собирается заново

#### Scenario: Абсолютных путей нет
- **GIVEN** `openspec` падает с сообщением, где есть абсолютный путь, а файл корней называет каталоги абсолютными путями
- **WHEN** идёт заморозка
- **THEN** в `req-graph.json` и `report.md` абсолютных путей нет, корни названы префиксами

#### Scenario: README меняет свежесть
- **GIVEN** снимок собран, затем изменилось прочитанное объявление модуля
- **WHEN** freeze вызван до архивации
- **THEN** снимок не считается свежим только по неизменности артефактов изменения; структура и отчёт собраны заново

#### Scenario: Снимок и отчёт описывают одно прочитанное состояние
<!-- F-51 -->
- **GIVEN** README объявляет a при сборке графа и b при следующем чтении для отчёта
- **WHEN** выполняется один freeze
- **THEN** снимок и структурные утверждения отчёта относятся к одному прочитанному состоянию либо freeze явно сообщает несогласованность и не выдаёт пару за свежую
