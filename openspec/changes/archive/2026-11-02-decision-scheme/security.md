# Security

Чек-лист канона ИБ по `specs/` изменения `decision-scheme`: пять пунктов схемы и парковки адресату «ИБ» (F-26, F-115…F-118). Канон в журнал не чеканится, он отмечается здесь. Где проверки ещё нет, так и написано, тест назван кандидатом для `tasks`.

**Главное.** Новая поверхность одна: `scheme.md` рисуется, а файл может прийти из чужой ветки. Её закрывают строгий режим mermaid и CSP. Вопрос о правах агента при пробе (F-118) передан ядру.

| Пункт | Применимо / неприменимо — причина | Чем проверено |
| --- | --- | --- |
| Инъекции через содержимое файлов: подпись `scheme.md` на вкладке (F-26, F-115) | применимо — файл пишут человек и модель, он может прийти из чужой ветки; закрывает требование «Вкладка рисует файл сама и без сети». Скрипты вкладки идут только с `nonce`, строгий режим снимает `click … call` и `javascript:`, CSP блокирует загрузку. `style-src 'unsafe-inline'` нужен mermaid (F-15) и остаётся только на этой вкладке | сценарий «Опасная подпись»; проба плагина `vscode/docs/spike-part1-results.md:100`; кандидат для `tasks`: тот же сценарий в `npm run e2e` |
| Инъекции через содержимое файлов: подпись `scheme.md` на странице из `file://` (F-116) | применимо — закрывает требование «Подписи схемы не ходят в сеть». Без CSP строгий режим не снимает `<img>` и страница идёт по его адресу | сценарий «Картинка с внешним адресом»; `research/F-21-probe/probe.log:39-40`; `research/design-probe/probe.log`, `viol=[]`, `http=[]` |
| CSP страницы и строгий режим mermaid (F-116) | применимо — закрывают требования «Подписи схемы не ходят в сеть» и «Страница не ходит в сеть». `script-src 'unsafe-inline'` нужен самому шаблону, поэтому CSP не заменяет экранирование: текст схемы идёт через `textContent` | сценарии «Кнопки страницы под CSP», «Журнал сети браузера»; проба с настоящими кнопками, `research/design-probe/probe.log` |
| Инъекции через содержимое файлов: текст схемы в разметке страницы | применимо — `</script>` и `<!--` в `scheme.md` могли бы сломать разбор страницы; закрывает `_embed` (`tools/journal_render.py:164`) и своя метка вне проекции | тест-страховка F-89 у `tasks` |
| Пути с `../` | неприменимо — пути из содержимого файлов не берутся: `nodes` сравнивается как строка и путём не становится, вкладка и страница читают `scheme.md` по постоянному имени в каталоге изменения. Путь `<script src>` считает `render-html` из своего `--out`; страница вне проекта тега не получает | чтение `tools/journal_render.py` и `vscode/src/host/project.ts` при реализации; кандидат для `tasks`: `render-html` с `--out` вне проекта |
| Токены и срок их жизни | неприменимо — изменение не хранит и не передаёт токенов, страница и вкладка в сеть не ходят | сценарий «Журнал сети браузера»; чтение спек |
| Права | применимо — инсталлятор кладёт в `.symphysis/tools/` ещё один файл без новых прав, каталог `.symphysis/viewer/` не стирает; вкладка в файл не пишет. Закрывают требования «`install` ставит схему, скиллы и инструменты в проект и сливает конфиг» и «Вкладка не пишет в `scheme.md`». Плагин ничего не обновляет сам: «Плагин не обновляет инструменты сам» | сценарии «Черновики переживают обновление», «Действия на вкладке», «Вызовы процессов при несовпадении» |
| Бинарные файлы | применимо — `scheme.md` может оказаться не текстом: блока в нём нет, вкладка показывает плашку (требование «`scheme.md` — один блок mermaid, и шаги от него не зависят»). Файл mermaid — текст, в git не идёт | сценарии «Файл без схемы», «Файл mermaid не в git ядра» |
| Файл стороннего пакета в поставке: версия и целостность (F-117) | применимо — закрывает требование «`install` ставит схему, скиллы и инструменты в проект и сливает конфиг»: точная версия в `installer/package.json`, целостность держит `installer/package-lock.json`, у плагина свой замок. Пакет дерева зависимостей нужен только при сборке, в поставку идёт один файл и лицензия. Нет файла — поставка не собирается | сценарий «Файла mermaid нет при сборке поставки»; кандидат для `tasks`: тест, что номера версий в плагине и инсталляторе равны (F-53) |
| Проба агента: чтение вне корней проекта, отправка материала внешней модели, сторож исходящего (F-118) | неприменимо к этому изменению — чтение и отправку определяют права агента в конфиге, а не схема и не инструкция; это вопрос к ядру, слово человека записано у F-118. Запись ограничивает требование «Проба агента не правит рабочее дерево» | чтение: в `schema.yaml` и скиллах symphysis прав агента нет; запись — тест на текст инструкции `research` |
