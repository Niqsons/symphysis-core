# Spec Delta

## ADDED Requirements

### Requirement: Подкоманда журнала предлагает места кода
Подкоманда `journal.py` SHALL печатать файлы кода из улик выбранных вариантов решённых развилок, кроме записей проб, с номерами записей, откуда взят каждый файл; подкоманда SHALL NOT менять журнал (F-15.D).

#### Scenario: Только выбранный вариант
- **GIVEN** развилка, решённая вариантом A с уликой `src/Foo.java`, и её вариант B с уликой `src/Bar.java`
- **WHEN** выполняется `journal.py code-sites decisions.json`
- **THEN** в выводе есть `src/Foo.java` с номером записи, `src/Bar.java` нет — предположение: имя подкоманды `code-sites`; решить при реализации

#### Scenario: Открытая развилка, факт и проба не входят
- **GIVEN** открытая развилка, факт с уликой на код и решённая запись пробы с уликой на код
- **WHEN** выполняется `journal.py code-sites decisions.json`
- **THEN** их файлов в выводе нет — предположение: признак записи пробы — префикс вопроса `[...]` или `outcome.kind: проба`; решить при реализации

#### Scenario: Журнал не меняется
- **GIVEN** годный журнал
- **WHEN** выполняется `journal.py code-sites decisions.json`
- **THEN** SHA-256 `decisions.json` не изменился

#### Scenario: Один файл в разном написании
- **GIVEN** улики на один файл в трёх написаниях: `src\Foo.java`, `src/Foo.java` и с другим регистром буквы диска
- **WHEN** выполняется `code-sites`
- **THEN** одна строка с нормализованным путём и тремя номерами записей

#### Scenario: Выбранный вариант без улик
- **GIVEN** решённая развилка с выбранным вариантом без улик
- **WHEN** выполняется `code-sites`
- **THEN** вывод несёт `[..] F-NN: выбранный вариант без улик`, код 0

#### Scenario: Улика вне корня
- **GIVEN** решённая развилка, чья выбранная улика указывает на `../../secret.txt`
- **WHEN** выполняется `code-sites`
- **THEN** пути в списке нет, файл не читается, вывод несёт `[..] F-NN: путь вне корня`

#### Scenario: Что считается файлом кода
- **GIVEN** улики `src/Foo.java`, `docs/plan.md`, `openspec/schemas/x/schema.yaml`, `openspec/changes/y/decisions.json`
- **WHEN** выполняется `code-sites`
- **THEN** в списке `src/Foo.java` и `schema.yaml`; `.md` и файлы каталогов изменений не входят

### Requirement: `check` сигналит расхождение описи со списком мест
Команда `journal.py check` при наличии `consequences.md` SHALL давать строку `[!!]` на каждое место из списка мест кода, чей путь в файле не встречается; файл со строкой `**Причина:**` и отсутствие файла сверки мест SHALL NOT давать (F-75.A, F-128.A). Форму файла скрипт SHALL NOT разбирать сверх этого и цитат `путь:строка «цитата»`. Код выхода SHALL быть 0, с `--strict` 2 (F-25.A, F-15.D). Требование дополняет «Улика сверяется скриптом дословно и остаётся сигналом».

#### Scenario: Место не разобрано
- **GIVEN** `src/Foo.java` в списке мест и `consequences.md`, где этого пути нет
- **WHEN** выполняется `journal.py check decisions.json`
- **THEN** stdout несёт `[!!] consequences.md: src/Foo.java — нет ни разбора, ни исключения с причиной`, код 0

#### Scenario: Строгий режим
- **GIVEN** тот же журнал и файл
- **WHEN** выполняется `journal.py check --strict decisions.json`
- **THEN** код выхода 2

#### Scenario: Место добавлено моделью
- **GIVEN** строки описи по `src/Bar.java`, которого нет в списке мест
- **WHEN** выполняется `journal.py check decisions.json`
- **THEN** по `src/Bar.java` строки `[!!]` нет

#### Scenario: Описи ещё нет
- **GIVEN** изменение без `consequences.md`
- **WHEN** выполняется `journal.py check`
- **THEN** сверки описи нет, строк `[!!]` о ней нет, код 0

#### Scenario: Другое написание пути
- **GIVEN** строка описи `src\Foo.java:270` и место `src/Foo.java`; или те же пути с префиксом корня `calibration/`
- **WHEN** выполняется `journal.py check`
- **THEN** сравнение идёт по пути без `:строка`, с прямыми разделителями и тем же префиксом корня, место закрыто

#### Scenario: Сигнал доходит до symphysis check
- **GIVEN** журнал с сигналом сверки
- **WHEN** выполняется `symphysis check`
- **THEN** сигнал показан строкой `[..] <журнал>: ...`, код выхода не меняется

### Requirement: Повторный номер записи делает журнал негодным
`journal.py check` SHALL считать журнал с двумя записями одного номера негодным, код 1: при повторном номере `apply` молча кладёт слово человека в последнюю запись с этим номером (F-138.A).

#### Scenario: Повторный номер записи
- **GIVEN** журнал с двумя записями `F-02`
- **WHEN** выполняется `journal.py check` или `journal.py apply`
- **THEN** строка `F-02: номер записи повторяется`, код 1; журнал не меняется
