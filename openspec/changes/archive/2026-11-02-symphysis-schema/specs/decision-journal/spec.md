# Spec Delta

## Purpose
Журнал решений изменения: один источник в JSON, рендеры из него, улики с дословной цитатой, слово человека — только через возврат; F-01, F-09, F-10, F-11, F-12, F-17.

## ADDED Requirements

### Requirement: Журнал — JSON-источник, markdown и HTML — рендер из него
Система SHALL хранить журнал решений изменения в `<каталог изменения>/decisions.json` по схеме `journal.schema.json`; `decisions.md` и `decisions.html` SHALL собираться из него командами `render-md` и `render-html` и SHALL NOT редактироваться руками (F-01.B).

#### Scenario: Рендер из годного журнала
- **GIVEN** `decisions.json`, проходящий `check` без ошибок схемы
- **WHEN** выполняется `journal.py render-md decisions.json --out decisions.md`
- **THEN** `decisions.md` содержит каждую запись журнала с её номером, вариантами, рекомендацией под списком вариантов и словом человека

#### Scenario: Негодный журнал не рендерится
- **GIVEN** `decisions.json`, нарушающий схему или правило между записями (факт с вариантами, зависимость на несуществующую запись)
- **WHEN** выполняется `render-md` или `render-html`
- **THEN** команда печатает строки `[!!] <F-NN>: <ошибка>`, возвращает код 1 и файл рендера не пишет

#### Scenario: Повторный рендер без правок даёт тот же файл
- **GIVEN** `decisions.json` без изменений между двумя рендерами
- **WHEN** `render-md` выполняется дважды
- **THEN** оба `decisions.md` совпадают байт в байт — предположение: журнал не решал детерминизм рендера; проверить: тест на два рендера (поле `generated` схемы существует для этого)

### Requirement: Улика сверяется скриптом дословно и остаётся сигналом
Система SHALL сверять каждую улику (`path`, `quote`) с файлом дословно по корням `journal-roots.json` командой `check`, при `--write` SHALL записывать `line`, `found`, `verdict` в журнал, и несверенная улика SHALL оставаться сигналом: код выхода 0 без `--strict`, код 2 с `--strict` (F-12.A, слово человека «сигнал, а не запрет»).

#### Scenario: Цитаты нет дословно
- **GIVEN** улика с `quote`, которой в файле по `path` нет дословно
- **WHEN** выполняется `check --write`
- **THEN** у улики `found: false`, `verdict: «цитаты нет дословно»`, в stdout строка `[!!] <F-NN>: <path> «<quote>» — цитаты нет дословно`, код выхода 0

#### Scenario: Файл вне корней
- **GIVEN** улика с префиксом пути, которого нет в `journal-roots.json`
- **WHEN** выполняется `check`
- **THEN** улика получает вердикт «файла нет» и считается несверенной, код 0

#### Scenario: Строгий режим
- **GIVEN** журнал хотя бы с одной несверенной уликой
- **WHEN** выполняется `check --strict`
- **THEN** код выхода 2, журнал не изменён

### Requirement: Решение появляется только словом человека через возврат
Система SHALL записывать `decision` записи только командой `apply` из промпта возврата просмотрщика (или комментариев md4h командой `apply-md4h`) с датой; `apply` SHALL работать по правилу «всё или ничего»: любая негодная строка промпта называет запись и причину, код 1, журнал не меняется (F-17.D, F-01 находка).

#### Scenario: Промпт с одной негодной строкой
- **GIVEN** промпт возврата, в котором одна строка ссылается на вариант, которого у записи нет
- **WHEN** выполняется `apply decisions.json answers/<дата>.md`
- **THEN** stdout содержит `отказ: <F-NN> — <причина>`, код выхода 1, SHA-256 `decisions.json` не изменился

#### Scenario: Слово внесено дословно с датой
- **GIVEN** строка промпта `- F-NN: B — «слово»`
- **WHEN** выполняется `apply --date 2026-10-30`
- **THEN** у записи `decision = {option: B, word: «слово», date: 2026-10-30}`, прочие поля записи не изменены

### Requirement: Обратимость, адресат парковки и исход — из закрытых списков с причиной
У решённой записи SHALL быть `reversibility.level` из `обратимо | дорого | в одну сторону` с непустым `why` (F-10.A); `parking[].addressee` SHALL быть из `материалы | человек | ИБ` (F-11.D); `outcome` пробы SHALL быть из `Specify | Dismiss | Backstop | Defer`, и `Dismiss` SHALL иметь непустую причину (F-09.C); нарушение SHALL давать код 1 у `check`.

#### Scenario: Отказ без причины
- **GIVEN** запись пробы с `outcome: {kind: проба, value: Dismiss, reason: ""}`
- **WHEN** выполняется `check`
- **THEN** stderr содержит `[!!] <F-NN>: исход Dismiss без причины`, код 1

#### Scenario: Адресат вне списка
- **GIVEN** парковка с `addressee: архитектор`
- **WHEN** выполняется `check`
- **THEN** ошибка схемы с именем записи и полем `parking/0/addressee`, код 1
