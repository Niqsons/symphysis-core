# Spec Delta

## MODIFIED Requirements

### Requirement: Отчёт называет закрытый состав сигналов
Отчёт SHALL называть: критерий без требования; требование и сценарий без задачи; требование без записи (F-83); решение без требования и задачи; неоднозначное имя; неизвестное имя или номер; задачу ни к чему; след, отставший от журнала (F-64); сценарий MODIFIED с прежним именем и другим текстом (F-95); Specify без сценария; Backstop без задачи (F-15). Сигналы графа SHALL идти группами тяжести (F-04, F-27). Решение об объёме SHALL оставаться обычной строкой этого вида (F-65).

#### Scenario: Критерий без требования
- **GIVEN** факт `постановка`, на который не ссылается ни одно требование
- **WHEN** скрипт собирает отчёт
- **THEN** сигнал называет запись и цитату критерия

#### Scenario: Решение об объёме
- **GIVEN** решение об объёме работ, до которого не дошли ни требование, ни задача
- **WHEN** скрипт собирает отчёт
- **THEN** оно названо строкой вида «решение без требования и задачи», отдельной пометки у него нет

#### Scenario: Одно имя у двух требований capability
<!-- F-94 -->
- **GIVEN** одно имя сценария у двух требований capability `demo` и задача с этим именем
- **WHEN** скрипт собирает отчёт
- **THEN** оба сценария считаются закрытыми, сигнал «неоднозначное имя» называет оба требования

#### Scenario: Тяжёлое раньше, чем раннее по файлу
- **GIVEN** сигнал «требование без задачи» на строке 3 спеки и сигнал «неизвестное имя или номер» на строке 40 той же спеки
- **WHEN** скрипт собирает отчёт
- **THEN** «неизвестное имя или номер» стоит в отчёте раньше, в своей группе, а «требование без задачи» — в своей

### Requirement: Шумные виды в отчёт не идут
Отчёт SHALL NOT называть: улику, разошедшуюся с файлом, она остаётся у `check`; сценарий и требование, перенесённые из мастера в MODIFIED без изменения текста; пункт security с известным именем или без имени; решение «Оставить как есть» (F-57, F-64, F-95). След проб после последнего сценария и маркер `<!-- F-NN -->` под заголовком SHALL NOT делать сценарий MODIFIED изменённым: текст сравнивается без HTML-комментариев (F-03, F-26).

#### Scenario: Улика разошлась
- **GIVEN** улика журнала, цитаты которой больше нет в файле
- **WHEN** скрипт собирает отчёт
- **THEN** строки о ней нет, `journal.py check` её называет

#### Scenario: MODIFIED несёт прежний сценарий
- **GIVEN** требование в MODIFIED со сценарием, который уже есть в мастер-спеке с тем же текстом, и без задачи на него
- **WHEN** скрипт собирает отчёт
- **THEN** строки об этом сценарии нет

#### Scenario: Новый сценарий в MODIFIED
- **GIVEN** требование в MODIFIED со сценарием, которого в мастер-спеке нет, и без задачи на него
- **WHEN** скрипт собирает отчёт до `/opsx:sync`
- **THEN** сигнал называет этот сценарий

#### Scenario: Пункт security закрыт доводом
- **GIVEN** пункт security без имени требования, закрытый доводом
- **WHEN** скрипт собирает отчёт
- **THEN** строки о нём нет; пункт с неизвестным именем требования сигнал называет

#### Scenario: Прежнее имя, другой текст
<!-- F-95 -->
- **GIVEN** MODIFIED со сценарием, имя которого есть в мастере, а текст другой, и без задачи на него
- **WHEN** скрипт собирает отчёт до `/opsx:sync`
- **THEN** сигнал называет сценарий, в сохранённом отчёте такие расхождения идут отдельным разделом

#### Scenario: След проб после последнего сценария
- **GIVEN** требование в MODIFIED, чей последний сценарий совпадает с мастером, а за ним в дельте стоит след проб `<!-- проба краёв: … -->`
- **WHEN** скрипт собирает отчёт до `/opsx:sync`
- **THEN** строки «сценарий MODIFIED с прежним именем и другим текстом» об этом сценарии нет

## ADDED Requirements

### Requirement: Группы тяжести сигналов
Часть требования «Отчёт называет закрытый состав сигналов» (F-28). Группы SHALL идти в порядке «что сломано»: «Связь не разрешена» — неизвестное имя или номер, неоднозначное имя; «Опоры нет» — критерий без требования, требование без записи, решение без требования и задачи, след отстал от журнала; «Реализация не закрывает» — требование без задачи, сценарий без задачи, Backstop без задачи, Specify без сценария, задача ни к чему (F-28).

#### Scenario: Три группы по порядку
- **GIVEN** по одному сигналу «задача ни к чему», «требование без записи» и «неоднозначное имя»
- **WHEN** скрипт собирает отчёт
- **THEN** группы идут «Связь не разрешена», «Опоры нет», «Реализация не закрывает», каждая со своей строкой

#### Scenario: Вид вне перечня групп
- **GIVEN** сигнал вида, которого нет ни в одной группе
- **WHEN** скрипт собирает отчёт
- **THEN** тест состава красный: каждый вид закрытого состава стоит ровно в одной группе

### Requirement: Группа показана подзаголовком со счётом
Часть требования «Отчёт называет закрытый состав сигналов» (F-29). Группа SHALL быть подзаголовком третьего уровня раздела «Сигналы графа» с именем группы и счётом строк, внутри группы строки идут по месту в файле; пустая группа SHALL опускаться; расхождения сценариев MODIFIED и требования без базы SHALL оставаться своими разделами (F-29). Строка `[!!] вид: ключ — место` SHALL NOT меняться (F-16).

#### Scenario: Строка сигнала прежняя
- **GIVEN** сигнал внутри группы отчёта
- **WHEN** человек копирует вид и ключ в запись `[сигнал] <вид> · <ключ>` с решением
- **THEN** строка в отчёте имеет форму `[!!] вид: ключ — место`, как без групп, и запись гасит этот сигнал

#### Scenario: Подзаголовок со счётом
- **GIVEN** изменение с двумя сигналами «требование без задачи» и без других сигналов
- **WHEN** скрипт собирает отчёт
- **THEN** раздел «Сигналы графа» несёт один подзаголовок `### Реализация не закрывает (2)` с двумя строками, других подзаголовков нет

#### Scenario: Расхождения остаются своим разделом
- **GIVEN** сигнал «сценарий MODIFIED с прежним именем и другим текстом»
- **WHEN** скрипт собирает отчёт
- **THEN** строка стоит в разделе «Расхождения сценариев MODIFIED», в группах тяжести её нет

#### Scenario: Сигналов графа нет
- **GIVEN** изменение без сигналов графа и с находкой `openspec validate`
- **WHEN** скрипт собирает отчёт
- **THEN** раздел «Сигналы графа» несёт строку «Сигналов графа нет.» без подзаголовков

### Requirement: Группа не ослабляет регламент ответа
Группировка MUST NOT подавать строки нижних групп как необязательные: имена групп не несут слов тяжести, и каждая строка любой группы требует ответа человека или записи `[сигнал]`, как без групп (F-54). Проверка — суждение: человек при чтении отчёта, атака артефактов при сверке ответов с отчётом.

#### Scenario: Ответ на строку нижней группы
<!-- F-54 -->
- **GIVEN** отчёт с группой «Реализация не закрывает»
- **WHEN** человек отвечает на сигналы отчёта
- **THEN** строки этой группы получают ответ или запись `[сигнал]` так же, как строки верхних; судит человек и атака артефактов
