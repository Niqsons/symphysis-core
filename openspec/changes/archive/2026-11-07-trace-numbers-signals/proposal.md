# Proposal

## Why

Граф трассируемости отсекает номера мастер-текста по голому числу (F-07, F-08), а мастер-спеки несут номера чужих журналов с именем журнала и буквой варианта рядом с голыми номерами (F-09, F-33): номер своего журнала с тем же числом пропадает молча, и отчёт даёт «требование без записи» при верной спеке (F-11, критерий F-01). Текст последнего сценария захватывает след проб, которого в мастере нет по правилу синхронизации (F-12, F-13), и неизменённый сценарий читается как изменённый (критерий F-03). Сигналы отчёта идут плоским списком по месту в файле (F-14), а предложение «сигналы по важности» ушло в бэклог без формы (F-17, критерий F-04). Периметр — не плодить новых проблем, старые мастер-спеки, снимки и журналы не переписывать (F-05); решение о хешах у узлов графа принято здесь, чтобы задать форму B-07 и B-08 (F-02, F-06, F-20, F-23).

## What Changes

- Отсечение чужих номеров у требования MODIFIED и у дочернего ADDED идёт по полной ссылке — число, буква варианта, имя журнала перед списком или якорь; ссылка с чужим именем не ссылка этого журнала и не «неизвестный номер»; имя своего изменения — своя ссылка; имя после списка без двоеточия остаётся голым; голое против голого отсекается, как сейчас, и видно сигналом (F-21, F-34, F-36, F-37). Проба на архивных снимках: четыре сигнала intent уходят, ложных связей нет (F-34).
- Якорь записи журнала — `<изменение>/F-NN`: идентичность даёт якорь, проверяемость — хеш (F-06, F-22). Граф читает голую форму и якорь, различая своё и чужое изменение; сегодня косая черта в разборе не граница, а маркер под сценарием с якорем регулярка не принимает (F-32).
- При синхронизации голые `F-NN` блока требования, включая маркеры `<!-- F-NN -->` и комментарии, переписываются в мастере в форму якоря отдельным скриптом; зовёт его модель по строке правила `rules.specs` и подсказке архива, потому что дельту в мастер переносит модель скиллом, а не код форка (F-24, F-30, F-31, F-35). Дельта пишется по-прежнему `(F-NN)`; старые голые номера мастера остаются (F-05).
- **BREAKING** формат снимка: база мастер-спеки хранит ссылки строками вместо чисел, `format` растёт до 2; снимки формата 1 в архиве не пересобираются, проверка их отвергает строкой с номерами версий (F-19, F-25).
- Текст сценария при сверке с мастером берётся без HTML-комментариев тем же правилом, что текст требования: след проб после последнего сценария и маркер `<!-- F-NN -->` сценарий не меняют (F-12, F-26).
- Сигналы графа в отчёте идут группами по тяжести «что сломано» в закреплённом порядке: связь не разрешена, опоры нет, реализация не закрывает; группа — подзаголовок третьего уровня со счётом, внутри по месту в файле; строка `[!!] вид: ключ — место` не меняется, записи `[сигнал]` по ней работают как прежде (F-16, F-27, F-28, F-29).
- Хеши у всех узлов графа: решение «да, хеш содержимого у каждого узла, id остаётся якорем» принято, реализация — изменением B-07 и B-08; в поставку этого изменения не входит (F-23).
- Старый след проб в мастере при замене блока MODIFIED стирается, как и было: конструкция не меняется (F-38).

## Capabilities

### New Capabilities

- `record-anchors`: ссылка на запись журнала несёт якорь изменения — форма `<изменение>/F-NN` (F-22); при синхронизации голые номера блока требования переписываются в мастере в форму якоря скриптом, который зовётся по правилу `rules.specs` и подсказке архива, печатает, что переписал, и повторяем (F-24, F-35); старый текст мастера не переписывается (F-05).

### Modified Capabilities

- `trace-conventions`: требование «Требование называет свои записи журнала» — номер мастер-текста отсекается по полной ссылке, а не по числу; ссылка с чужим именем журнала или якорем другого изменения не ссылка этого журнала; имя своего изменения и якорь своего изменения — своя ссылка; имя после списка без двоеточия — голая ссылка; у дочернего ADDED та же сверка с мастер-текстом родителя (F-21, F-32, F-36, F-37).
- `trace-snapshot`: требование «Снимок несёт базу мастер-спеки» — база хранит ссылки мастера строками, по ним идёт отсечение после `/opsx:sync` (F-25).
- `trace-graph`: требование «Id читаемы, файл несёт версию формата» — `format: 2`, снимок формата 1 проверка отвергает (F-25); требование «Скрипт сам разбирает спеки с номерами строк» — текст сценария без HTML-комментариев, как текст требования (F-26).
- `trace-signals`: требование «Отчёт называет закрытый состав сигналов» — группы по тяжести с закреплённым порядком видов, подзаголовки со счётом, строка сигнала прежняя (F-27, F-28, F-29); требование «Шумные виды в отчёт не идут» — след проб после последнего сценария и маркер под заголовком не делают сценарий MODIFIED изменённым (F-26).

## Impact

- `trace/trace_graph.py`: разбор ссылок (`_REC_REF`, `_record_numbers`) читает букву варианта, имя журнала перед списком и якорь; `master_base`, `known`, `cut`, `put_records` сравнивают ссылки строками; `GRAPH_FORMAT = 2`; `_scenarios` вырезает комментарии правилом `_requirement_body`; `graph_signals` и `build_report` группируют сигналы (F-21, F-25, F-26, F-27–F-29, F-32). Тесты `trace/tests/test_trace_graph.py`, `test_trace_report.py`, `test_trace_snapshot.py`: отсечение по ссылке, формат 2, сценарий со следом, порядок групп.
- Новый скрипт переписывания ссылок при синхронизации с тестами; где он живёт и как попадает в payload (`installer/scripts/sync-payload.js`), решает design (F-35). `openspec/config.yaml`: строка правила `rules.specs` о переписывании и подсказка `operations.archive.guidance` (F-35).
- `docs/GUIDE.md`, разделы «Соглашения в артефактах», «Как скрипт разрешает связи», «Ответ на сигнал»: форма якоря, правило отсечения по ссылке, группы отчёта (F-22, F-27). Требования `onboarding-guide` не меняются.
- Мастер-спеки, архивные снимки формата 1 и журналы прежних изменений не переписываются (F-05, F-25); после архивации снимки скрипт не читает (F-19).
- Плагин `symphysis-vscode` `report.md` не читает; номер контракта не меняется.
- Хеши у узлов и уникальные имена требований — следующее изменение, B-07 и B-08 (F-20, F-23).
