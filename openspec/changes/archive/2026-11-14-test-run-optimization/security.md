# Security

Проверка относится к локальному планировщику и исполнителю тестов из [design.md](design.md). Для F-19 проверяются две границы: какие рабочие деревья и файлы разрешено использовать и как пути и ревизии передаются дочерним процессам. В последней колонке отдельно указаны выполненные проверки существующего кода и проверки, которые предстоят при реализации.

| Пункт | Применимо / неприменимо — причина | Чем проверено |
| --- | --- | --- |
| Инъекции через содержимое файлов | Применимо. Отбор читает README модулей. Требование [«README модулей описывают зависимости для отбора тестов»](specs/module-declaration/spec.md) задаёт данные отбора, а действующее требование [«Объявления обрабатываются как недоверенные данные»](../../specs/module-discovery/spec.md) задаёт границу их интерпретации. Повреждённое объявление обрабатывается по сценарию [«Повреждённый список зависимостей скрывает модуль»](specs/test-impact-selection/spec.md). | Прочитан `read_declaration` с `SafeLoader`. Тест `test_object_yaml_is_rejected_without_side_effect` прошёл. При реализации проверить, что адресный план использует тот же безопасный разбор и что текст README не меняет команды, выбранные корни или порядок запуска. |
| Пути с `../`, абсолютные хвосты и ссылки | Применимо. [«План изменения учитывает рабочее состояние каждого репозитория»](specs/test-impact-selection/spec.md) привязывает сравнение к выбранному корню, а [«План выполняется последовательно и останавливается на первой ошибке»](specs/test-run-execution/spec.md) привязывает контрактные тесты VS Code к выбранному дереву ядра. Для чтения деклараций действует [«Структурные источники остаются внутри разрешённого корня»](../../specs/repository-survey/spec.md). | Тест `test_symlink_escape_service_alias_and_cycle` прошёл. Он проверяет обход README, включая выход за корень и цикл. При реализации проверить границу отдельно при разрешении тестовых путей и непосредственно перед запуском, включая `../`, абсолютный путь вместо относительного, symlink и Windows junction. При отказе проверить, что внешние файлы не читаются и чужой клон не подставляется. |
| Аргументы Git и тестовых процессов | Применимо. Требования [«План коммита сравнивает его с одним родителем»](specs/test-impact-selection/spec.md) и [«План выполняется последовательно и останавливается на первой ошибке»](specs/test-run-execution/spec.md) задают выбранные ревизии и команды групп. F-19 связывает их с проверкой интерпретации аргументов. | Сверены входы и границы в спеках и дизайне. При реализации проверить, что Git-ревизии разрешаются как ревизии, а пути передаются отдельными аргументами штатных команд в выбранном рабочем каталоге. Фикстуры с пробелами, кириллицей, именем с начальным дефисом и невалидной ревизией проверяют, что вход не становится опцией или фрагментом команды. |
| Токены и срок их жизни | Неприменимо к механике отбора и запуска. Она использует локальные рабочие деревья и существующие тестовые команды. Выдача, хранение и обновление токенов не входят в объём изменения. | Прочитаны [proposal.md](proposal.md), [design.md](design.md) и обе спеки выбора и выполнения. Обращение с уже существующими учётными данными в выводе относится к строке о чувствительных данных. |
| Права и недоступные входы | Применимо. [«Невыполненные проверки видны в результате»](specs/test-run-execution/spec.md) требует незавершённого исхода, если дерево или обязательная проверка недоступны. Для объявления действует [«Ошибка источника не стирает доступную структуру»](../../specs/module-discovery/spec.md). | Тест `test_bad_readme_partial_graph_states_and_no_mutation` прошёл с имитацией `PermissionError`. Реальные ACL не менялись. При реализации проверить недоступное дерево и выбранный вход VS Code, исчезнувший до сборки. Планирование и выполнение используют полномочия текущего процесса. |
| Бинарные файлы | Применимо к содержимому README. Для определения влияния прочих изменённых файлов нужен их путь. Действующее требование [«Объявления обрабатываются как недоверенные данные»](../../specs/module-discovery/spec.md) задаёт обработку бинарного объявления, а [«План показывает область и причины выбора»](specs/test-impact-selection/spec.md) задаёт диагностику неполного выбора. | `test_bad_readme_partial_graph_states_and_no_mutation` прошёл с NUL и не-UTF-8. Четыре случая `test_readme_bom_and_eol` прошли с допустимым UTF-8. При реализации проверить, что бинарный README даёт диагностику, а изменение бинарного входа поставки выбирает связанную проверку по пути. |
| Чувствительные данные в журнале, артефактах и журналах прогона | Применимо. [«План показывает область и причины выбора»](specs/test-impact-selection/spec.md) требует показывать корни и причины локально. [«Отчёт указывает проверенное рабочее состояние»](specs/test-run-execution/spec.md) требует различать источник отбора и проверенное дерево. Для диагностик объявления действующая [спека снимка](../../specs/trace-snapshot/spec.md) ограничивает раскрытие сырых входов. | `test_structural_diagnostics_do_not_echo_raw_yaml_or_roots` прошёл для существующего снимка. Новый отчёт требует своей проверки: локальный вывод сохраняет сведения, необходимые для диагностики, а в переносимую сводку и журнал изменения не копируются сырые README, карты корней, окружение и секреты из вывода дочерних процессов. Проверить это на синтетическом маркере в ошибке и stdout/stderr. |
| Очистка браузера и временного профиля | Применимо. Сценарий [«Драйвер превысил таймаут до очистки»](specs/test-run-execution/spec.md) ограничивает отчёт и очистку процессами и профилем этого запуска. | Прочитан существующий драйвер в `tests/fixtures/viewer-browser.mjs`. В [замерах F-11](research/F-11.md) остатки не обнаружены после штатного завершения. При реализации проверить управляемый таймаут и убедиться, что очистка касается только дерева процессов прогона и его временного профиля, а отдельный процесс и соседний профиль сохраняются. |

## Выполненная проверка

На Python 3.13 выполнен адресный запуск существующих тестов с xdist `-n 12`. Временные файлы и профили тестов вынесены за пределы worktree.

```powershell
python3.13 -X utf8 -B -m pytest -q -ra -p no:cacheprovider -n 12 --basetemp <каталог-пробы> trace/tests/test_trace_modules.py -k 'object_yaml_is_rejected_without_side_effect or bad_readme_partial_graph_states_and_no_mutation or readme_bom_and_eol or symlink_escape_service_alias_and_cycle or structural_diagnostics_do_not_echo_raw_yaml_or_roots'
```

Результат — 8 прошли, пропусков нет. Сквозные проверки адресного запуска относятся к реализации B-68.
