# Последствия: test-run-optimization

**Состав:** ветки отказа, допущения

## Опись

- **Подготовка npm-набора инсталлятора** — `installer/package.json:27` «"pretest": "node scripts/build-workflow-carriers.js && node scripts/sync-payload.js",»
  - при отказе: ошибка подготовки прекращает запуск до Node-тестов и возвращает ошибку всей команды npm
  - допущение: исполнитель использует штатный npm-вход и учитывает ненулевой исход подготовки как отказ группы. Прямой запуск Node-тестов без подготовки может проверить старый payload
  - сценарий: Первая группа завершилась ошибкой

- **Запуск Python из теста инсталлятора** — `installer/test/config.test.js:45` «const direct = (p) => spawnSync("python", ["-X", "utf8", script(p), "--project", p], { encoding: "utf8" });»
  - при отказе: дочерний запуск разрешает `python` по PATH и может выбрать другой интерпретатор, если прежняя обёртка больше не задаёт порядок поиска
  - допущение: при удалении обёртки раздельная команда сохраняет выбранную среду Python, иначе проверка конфигурации может выполниться в другой среде или упасть на зависимости
  - сценарий: Тесты инсталлятора требуют Python

- **Ошибка Node-набора внутри pytest** — `installer/test/test_installer.py:32` «assert r.returncode == 0, r.stdout + r.stderr»
  - при отказе: прежняя обёртка передаёт ненулевой результат Node как ошибку pytest
  - допущение: после разделения ненулевой исход по-прежнему прерывает последовательность, иначе VS Code может стартовать после красного инсталлятора
  - сценарий: Первая группа завершилась ошибкой

- **Границы коллекции pytest** (`pytest.ini`): веток отказа в конфигурации не найдено, искал: `^    viewer/tests`, `^    installer/test`, `^addopts`. Конфигурация задаёт общие пути сбора и число воркеров. Последствия разделения коллекции проверяются по сторожу путей ниже.

- **Сторож путей pytest** — `tests/test_pytest_testpaths.py:39` «assert strays(ROOT / "pytest.ini", files) == []»
  - при отказе: тест обнаруживает файл вне testpaths, а фильтры двух отдельных запусков в этой проверке не участвуют
  - допущение: наличие пути в testpaths после разделения недостаточно для подтверждения покрытия полного прогона
  - кандидат: F-22; ближайший сценарий: Полная проверка перед выпуском или по слову владельца

- **Браузерная группа без Node** — `viewer/tests/test_viewer_browser.py:39` «pytestmark = [pytest.mark.skipif(node is None, reason="нет node: драйвер браузера не запустить"),»
  - при отказе: весь браузерный файл пропускается
  - допущение: исполнитель отличает пропуск обязательной группы от успешного результата pytest
  - сценарий: Обязательная проверка пропущена

- **Браузерная группа без Chrome** — `viewer/tests/test_viewer_browser.py:40` «pytest.mark.skipif(chrome is None, reason="нет Chrome; путь задаётся SYMPHYSIS_CHROME"),»
  - при отказе: весь браузерный файл пропускается с причиной о Chrome
  - допущение: причина попадёт в незавершённый итог и сохранится при полном выпускном прогоне
  - сценарий: Обязательная проверка пропущена

- **Браузерная группа без Mermaid** — `viewer/tests/test_viewer_browser.py:41` «pytest.mark.skipif(not MERMAID.is_file(), reason="нет файла mermaid: npm ci в installer")]»
  - при отказе: весь файл пропускается, хотя pytest и Chrome доступны
  - допущение: доступность самостоятельного npm-набора и доступность файла Mermaid для браузерного pytest проверяются по фактическому результату группы
  - сценарий: Обязательная проверка пропущена

- **Внешний таймаут браузерного драйвера** — `viewer/tests/test_viewer_browser.py:66` «capture_output=True, text=True, encoding="utf-8", timeout=120)»
  - при отказе: ожидание процесса Node завершается таймаутом, драйвер может не дойти до очистки Chrome и профиля
  - допущение: ошибка прогона и отсутствие остаточных процессов — два разных наблюдения. Без второй проверки повтор может начать работу при остаточной нагрузке
  - кандидат: F-21; ближайший сценарий: Проверка очистки профилей под нагрузкой

- **Ошибка очистки внутри драйвера** — `tests/fixtures/viewer-browser.mjs:317` «if (!(await removeProfile())) code = 1;»

  - допущение: отдельная браузерная команда сохраняет ошибку драйвера, иначе результат очистки станет зелёным при оставшемся профиле
  - сценарий: Проверка очистки профилей под нагрузкой

- **Некорректный список зависимостей** — `trace/trace_modules.py:100` «raise DeclarationError('негодный список dependencies')»
  - при отказе: парсер отклоняет декларацию целиком, а обнаружение записывает диагностический сигнал и сохраняет только успешно прочитанные модули
  - допущение: при частичном графе известный путь сам по себе не подтверждает, что учтены его потребители. Сигнал F-17 относится к другой ветке, где декларация модуля сохранилась
  - кандидат: F-20; ближайший сценарий: Изменение общей зависимости

- **Неразрешённая цель корректной зависимости** — `trace/trace_modules.py:358` «issue(source, 'зависимость не разрешена: ' + dep['repo'] + '/' + dep['module'])»
  - при отказе: граф выдаёт сигнал с источником связи, сохраняет объявляющий модуль и продолжает строиться по разрешённым связям
  - допущение: продолжение отбора с сигналом соответствует принятому выбору. Сигнал нельзя потерять при показе плана
  - кандидат: F-17; ближайший сценарий: Изменение общей зависимости

- **Отсутствующий каталог при сборке тестов VS Code** — `vscode/build.mjs:26` «for (const dir of ["test/unit", ...modules].filter((d) => fs.existsSync(d))) {»

  - допущение: исполнитель сверяет запланированные входы с фактическими. Иначе частичная сборка может выдать зелёный итог без выбранной группы
  - кандидат: F-23; ближайший сценарий: Обязательная проверка пропущена

## Исключения

- `skills-store/tools/pick_tests.py` — сравнительный пример раздельных Git-режимов. Его обработчики превращают ошибку Git в пустой список и при переименовании пропускают старый путь. План B-68 требует отличать ошибку от пустого сравнения и учитывать оба пути. Эта реализация не служит источником входных путей.
- `viewer/viewer_render.py` — импорт `journal_render` подтверждает зависимость viewer от decisions. Команда выбора получает эту связь из декларации README. Отказы рендера схемы и шаблона остаются поведением самих тестов просмотрщика.

## Pre-mortem

1. После отделения браузерного pytest часть тестов проходит сторож путей, но выпадает из обоих вызовов из-за фильтров. Обе команды могут дать зелёный результат при неполной коллекции — кандидат: F-22
2. Повреждённый список dependencies убирает из карты потребителя. Правка известного модуля даёт правдоподобный адресный план без его тестов — кандидат: F-20
3. После таймаута Node остаются процессы Chrome или занятый профиль. Следующий прогон стартует с лишней нагрузкой даже при двух воркерах — кандидат: F-21
