# Последствия: global-user-install

**Состав:** ветки отказа, допущения

Скрипт состава выполнен один раз: обе части включены, водитель описи выключен; сигналов `[!!]` нет. Работа выполнена в главной нити. Это опись существующего кода до реализации; она не утверждает, что global уже работает.

`code-sites` предложил 0 мест: выбранные варианты журнала не дали списка исполняемых файлов. Поиск расширен вручную по `install`, `targets`, `ensureContinue`, `default_roots`, `project_roots`, `_default_project`, `compute`, `_mermaid_src`, `render-html`, `getSchemaDir`, `openspec new change`, `.symphysis/tools`, `.symphysis/docs`, `openspec/schemas`.

## Исключения

Нет исключённых мест из `code-sites`: исходный список пуст. Все добавленные места описи разобраны. Разбор ограничен ветками, связанными с новым размещением, проектным контекстом и готовностью клиентского пути; он не является аудитом всех алгоритмов ядра.

## Проверенные соседние зависимости

- `settings/symphysis_config.py:153–159` содержит опасный для внешнего runtime fallback, но `installer/bin/symphysis.js:117` уже передаёт `--project`. F-25 фиксирует этот факт: dispatcher должен сохранить передачу выбранного store по F-10. Сам синтаксис настроек, умолчания при нечитаемом YAML и линзы здесь не меняются; нового решения о прямом низкоуровневом вызове без контекста не требуется.
- `openspec-run/openspec_run.py:133–163` получает рабочий корень параметром `root`, передаёт его в `Popen(cwd=root)`; расположение кода не выбирает store. Поиск исполняемого форка, его таймаут и снятие дерева процессов остаются существующим контрактом. ## Pre-mortem

1. CLI symphysis отказывает несовместимому store, но штатная нативная команда клиента создаёт изменение раньше этой проверки. Пользователь проходит обычный путь, а гарантия F-15 к нему не применяется; запуск текущего форка без декларации создал каталог изменения — кандидат: F-23.
2. Runtime перенесён к пользователю, старая проектная карта сохранена байт в байт, но `src/` больше не используется либо `<root>/..` указывает на родителя runtime. Проверка решений теряет улики или получает неверную область чтения, хотя данные store не переносились — кандидат: F-20.
3. Установка проверяет выбранную группу клиентов через `.some(hasContinue)`: рабочий Claude скрывает отсутствие workflow второго клиента. Наличие глобальных symphysis skills выглядит успехом, а путь до архивации из второго клиента обрывается при продолжении — кандидат: F-21.

Дополнительные причины вне тройки: недоступные HTML-ресурсы на другом диске (F-22); проектная схема, перехватившая выбор global-поставки (F-24); невалидный planning config с потерей либо неприменением правил при global-инициализации (F-26). Каждая имеет собственный кандидат ветки в описи и не создаётся вторично как pre-mortem.
