## MODIFIED Requirements

### Requirement: Тексты шагов лежат в `steps.md`, раздел на шаг
`openspec/schemas/symphysis/steps.md` выбранной поставки SHALL нести раздел `## <id>` на каждый артефакт схемы и на `viewer`, `apply`, `sync`, `archive`, в порядке показа (step-help/F-20, step-help/F-27, step-help/F-31; F-10). Раздел SHALL содержать название и подразделы «Зачем», «Механики», «Если пропустить», «Что смотреть», «Команда». Тест ядра SHALL падать на шаге без раздела и на разделе без шага (step-help/F-20).

#### Scenario: Новый артефакт без текста
- **GIVEN** в `schema.yaml` добавлен артефакт, раздела в `steps.md` нет
- **WHEN** выполняется тест ядра
- **THEN** тест красный и называет `id` артефакта

#### Scenario: Раздел без подраздела
- **GIVEN** раздел `## design` без подраздела «Если пропустить»
- **WHEN** выполняется тест ядра
- **THEN** тест красный и называет раздел и подраздел

#### Scenario: Старая схема в проекте
- **GIVEN** проект, для которого в выбранной поставке `steps.md` нет или нет раздела шага
- **WHEN** выполняется `step_help.py`
- **THEN** код 0, данные шага из графа на месте, тексты шага пусты, а вывод говорит, что текста нет

### Requirement: У шага есть поле `skills`
У каждого шага вывод SHALL нести поле `skills`: скиллы из текста шага, `name`, `path` и `base` (step-help/F-46, step-help/F-56). Поиск SHALL идти сначала в проекте: `.claude/skills`, `.opencode/skills`, `.agents/skills`; затем в явном каталоге установки, а без него — в выбранной resolver поставке (F-10, F-13). `base` SHALL быть `project` или `install`; абсолютного пути SHALL NOT быть (step-help/F-51). Не найден — `path` равен `null`.

#### Scenario: Скилл в проекте
- **GIVEN** в тексте шага `` `symphysis-brainstorm` ``, файл `.claude/skills/symphysis-brainstorm/SKILL.md`
- **WHEN** выполняется `step_help.py --change demo`
- **THEN** у шага запись с этим именем, путём от корня и `base` `project`, его путь есть и в `file_links`

#### Scenario: Порядок каталогов
- **GIVEN** файл скилла есть в `.claude/skills` и в `.opencode/skills`
- **WHEN** выполняется `step_help.py --change demo`
- **THEN** путь из `.claude/skills`, запись одна

#### Scenario: Скилла нет
- **GIVEN** скилл назван, файла нигде нет
- **WHEN** выполняется `step_help.py --change demo`
- **THEN** запись с этим именем, `path` равен `null`, код 0

#### Scenario: Шаг без скиллов
- **GIVEN** в тексте шага скилл не назван
- **WHEN** выполняется `step_help.py --change demo`
- **THEN** поле `skills` — пустой список

#### Scenario: Схема без текстов
- **GIVEN** проект, где в выбранной поставке `steps.md` нет
- **WHEN** выполняется `step_help.py`
- **THEN** код 0, у шагов `skills` пуст

#### Scenario: Скилл выбранной global-поставки
- **GIVEN** store без local runtime, названный скилл есть только в выбранной global-поставке
- **WHEN** справка рассчитывается без `--install-dir`
- **THEN** запись скилла несёт путь относительно выбранной установки и `base` `install`, без абсолютного пути пользователя

### Requirement: Каталог установки задаётся необязательным аргументом
`step_help.py` SHALL принимать необязательный `--install-dir <каталог>` для поиска скиллов после проекта (step-help/F-46, step-help/F-62). Без аргумента fallback SHALL идти только в выбранную resolver поставку (F-10, F-13). Сохранение аргумента само SHALL NOT поднимать номер контракта (step-help/F-35). Каталога нет — не сбой: скилл SHALL считаться не найденным. Аргумент SHALL NOT выбирать исполняемый runtime, менять корень store и файлы вывода.

#### Scenario: Скилл только в установке
- **GIVEN** файла скилла нет в проекте, он есть в каталоге установки
- **WHEN** выполняется `step_help.py --install-dir <каталог>`
- **THEN** путь от каталога установки, `base` `install`, строки каталога в выводе нет

#### Scenario: Проект важнее
- **GIVEN** файл скилла есть и в проекте, и в каталоге установки
- **WHEN** выполняется `step_help.py --install-dir <каталог>`
- **THEN** `base` `project`

#### Scenario: Каталога нет
- **GIVEN** `--install-dir` указывает на несуществующий каталог
- **WHEN** выполняется `step_help.py`
- **THEN** код 0, `path` равен `null`, `error` пуст

#### Scenario: Без аргумента
- **GIVEN** файл скилла только в каталоге установки, который не принадлежит выбранной поставке
- **WHEN** выполняется `step_help.py`
- **THEN** `path` равен `null`

#### Scenario: Явный каталог не переключает runtime
- **GIVEN** resolver выбрал поставку для store, а `--install-dir` указывает другой каталог скиллов
- **WHEN** справка рассчитывается с этим аргументом
- **THEN** каталог участвует только в поиске скиллов после проекта; исполняемый runtime, тексты шагов и рабочий store остаются выбранными resolver

## ADDED Requirements

### Requirement: Источники справки принадлежат выбранной поставке
Тексты шагов, версия symphysis и общие справочные ресурсы SHALL браться из поставки, выбранной resolver для рабочего store. В global-режиме проектная копия этих файлов SHALL NOT требоваться. Выбор global-поставки SHALL NOT менять корень store, расчёт шага по его файлам или значения проектных настроек (F-10, F-13).

#### Scenario: Справка без локальных копий runtime
- **GIVEN** store без local runtime и совместимая global-поставка с текстами шагов и файлом версии
- **WHEN** справка рассчитывается для изменения этого store
- **THEN** показаны шаг по файлам store, тексты и версия выбранной global-поставки; отсутствие проектной копии runtime не выдаётся за отсутствие текста справки

#### Scenario: Два store с одинаковым именем изменения
- **GIVEN** два store с одноимёнными изменениями используют одну global-поставку, но имеют разные готовые артефакты
- **WHEN** справка рассчитывается отдельно для каждого store
- **THEN** текущие шаги вычислены по каждому store; тексты и версия общей поставки не объединяют их состояние

### Requirement: Разрешение скиллов справкой не меняет нативную discovery клиента
Порядок поиска скиллов справкой SHALL описываться как разрешение ссылок symphysis. Справка SHALL NOT выдавать этот порядок за нативный приоритет local/global скиллов или агентов клиента, объединять конфликтующие установки либо автоматически исправлять их. Наличие обеих установок не становится поддерживаемым режимом из-за доступной ссылки (F-10, F-13).

#### Scenario: Нативный приоритет отличается от поиска справки
- **GIVEN** в store есть local-поставка, у пользователя есть global-поставка, а нативная discovery клиента имеет другой порядок
- **WHEN** справка разрешает ссылку на скилл
- **THEN** ссылка не утверждает, какой файл фактически загрузил клиент; клиентские файлы и конфликты не изменены
