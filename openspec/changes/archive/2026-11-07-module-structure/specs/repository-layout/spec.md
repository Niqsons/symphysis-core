# Spec Delta

## Purpose

Как устроен корень репозитория symphysis: какие каталоги первого уровня — модули, какие — контур разработки, где лежат модули и их тесты и что сверяет тест структуры.

## ADDED Requirements

### Requirement: README корня называет каждый каталог первого уровня
`README.md` в корне каждого репозитория SHALL называть компонент и репозиторий, как компонент выпускается и где контракт с другим компонентом, и каждый каталог первого уровня с пометкой — модуль или контур разработки. У каталога контура разработки README модуля SHALL NOT быть (F-22).

#### Scenario: Каталог без пометки
- **GIVEN** в корне ядра каталог первого уровня, которого README корня не называет
- **WHEN** выполняется тест структуры
- **THEN** тест красный и называет каталог

#### Scenario: Контур разработки с README модуля
- **GIVEN** `docs/` помечен в README корня контуром разработки, а в `docs/README.md` стоит frontmatter модуля
- **WHEN** выполняется тест структуры
- **THEN** тест красный и называет `docs/`

#### Scenario: Каталоги корня вне git
<!-- F-51 -->
- **GIVEN** в корне ядра есть `.symphysis/` и `upstream/`, которых нет в git
- **WHEN** выполняется тест структуры
- **THEN** тест их не требует: в счёт идут каталоги, которые знает git

### Requirement: Корень плагина описывает репозиторий, README пакета — отдельный файл
В плагине корневой `README.md` SHALL описывать репозиторий; README пакета `.vsix` SHALL быть отдельным файлом, который упаковка передаёт `vsce` как README пакета, и в `.vsix` SHALL оказаться только он (F-38).

#### Scenario: Пакет несёт README пакета
- **GIVEN** собранный `.vsix`
- **WHEN** тест упаковки читает его README
- **THEN** это текст README пакета, без frontmatter модуля и без описания каталогов репозитория

### Requirement: Модуль — каталог на своём месте
Каталог модуля SHALL лежать на первом уровне ядра или в `src/` плагина; модуль схемы — каталог `openspec/schemas/symphysis/`, место которого задаёт OpenSpec (F-12, F-17, F-31).

#### Scenario: Модуль не на своём месте
- **GIVEN** каталог с README модуля на втором уровне ядра вне `openspec/schemas/symphysis/`
- **WHEN** выполняется тест структуры
- **THEN** тест красный и называет каталог

### Requirement: Файл принадлежит одному модулю
Файл модуля SHALL лежать в каталоге своего модуля, и модули SHALL NOT вкладываться друг в друга: файл принадлежит одному модулю (F-03, F-37).

#### Scenario: Вложенный модуль
- **GIVEN** каталог с README модуля внутри каталога другого модуля
- **WHEN** выполняется тест структуры
- **THEN** тест красный и называет оба модуля

#### Scenario: Файл хука в каталоге своего модуля
<!-- F-52 -->
- **GIVEN** `hook.py` лежит в каталоге модуля `hook` плагина
- **WHEN** собирается `.vsix`
- **THEN** в пакете он лежит по пути `hook/hook.py`, который читает код

### Requirement: Тесты модуля лежат в его каталоге
Тесты модуля SHALL лежать в его каталоге; сквозные тесты плагина SHALL оставаться в `test/e2e/`, общие фикстуры — в общем месте для тестов (F-23).

#### Scenario: Тест модуля находится общей командой
- **GIVEN** тест модуля `decisions` в его каталоге
- **WHEN** выполняется `python -X utf8 -m pytest` в корне ядра
- **THEN** тест найден и запущен

#### Scenario: Юнит-тест модуля плагина собирается
<!-- F-62 -->
- **GIVEN** юнит-тест модуля плагина лежит в каталоге модуля в `src/`
- **WHEN** выполняется `npm test`
- **THEN** тест собран и запущен

### Requirement: Тест структуры в каждом репозитории
В каждом репозитории SHALL быть тест структуры: он сверяет README корня и README модулей с файлами по требованиям этой capability и `module-declaration`; расхождение — красный тест с именем каталога (F-25).

#### Scenario: Новый каталог без описания
- **GIVEN** в корне плагина появился каталог первого уровня без строки в README корня
- **WHEN** выполняется `npm test`
- **THEN** тест структуры красный и называет каталог

### Requirement: README корня не называет каталог, которого нет
README корня MUST NOT называть каталог первого уровня, которого в корне нет: тест структуры SHALL сверять строки README корня с каталогами корня в обе стороны (F-22, F-56; проверка — тест).

#### Scenario: Строка о каталоге, которого нет
<!-- F-56 -->
- **GIVEN** README корня называет `scripts/`, а каталога в корне нет
- **WHEN** выполняется тест структуры
- **THEN** тест красный и называет строку README корня

### Requirement: Общий файл не копируется в модули
Непустой файл с одинаковым содержимым MUST NOT лежать в двух модулях: тест структуры SHALL сравнивать хеши файлов модулей (F-03, F-57; проверка — тест).

#### Scenario: Копия в двух модулях
<!-- F-57 -->
- **GIVEN** непустой файл с одним содержимым лежит в модулях `decisions` и `viewer`
- **WHEN** выполняется тест структуры
- **THEN** тест красный и называет оба пути
<!-- требование из F-57; пробами не проходило -->

### Requirement: Тесты модулей не уходят пользователю
Файлы каталогов тестов модулей MUST NOT попадать в payload, пакет npm `@niqsons/symphysis` и `.vsix`: тест состава payload и тест упаковки SHALL проверять список файлов (F-23, F-58; проверка — тест).

#### Scenario: Тесты модуля схемы
<!-- F-58 -->
- **GIVEN** у модуля схемы есть каталог тестов в его каталоге
- **WHEN** собирается payload и выполняется `symphysis install`
- **THEN** в payload и в `openspec/schemas/symphysis/` проекта нет файлов этого каталога
