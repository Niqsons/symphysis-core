# Proposal

## Why

Калибровка на случае camunda-bid показала, что схема на сложной задаче
не окупается: на одной модели ваниль OpenSpec дала полноту выше, symphysis —
ниже при времени 3–5× и расходе 6–7× (F-01). Пункты сверх ванили дали только
пробы, и те выборкой (F-02); атака артефактов меряет наличие и происхождение,
не следование spec → design, и выдала 84 справки без находок (F-03);
конструкция прошла в design из следствий факта без варианта и «почему» (F-04);
критерии черновика заказчика не защищены и отступление от них невидимо
в поставке (F-05). Слово владельца: атаки должны быть включаемы, а не
обязательны (F-06). Возврат к брейншторму после просмотрщика в схеме уже есть —
это основание, не правка (F-14).

Почему сейчас: правки идут до повторного замера, замер — плечо P-чел на том
же случае с оградой (F-10.C, F-11.B). Первый прогон схемы на изменении без
парковок и первая атака журнала с просмотрщиком дали ещё три дефекта схемы
по ходу этого изменения: тупик `research` (F-16), источник факта «постановка»
(F-17), режим «атака» просмотрщика (F-18).

## What Changes

- **Атаки включаемы.** Признак `optional` у артефакта в форке OpenSpec:
  `attack-decisions` и `attack-artifacts` выходят из цепочки `requires`,
  `isPlanningComplete` их не ждёт; атака вызывается по имени словом человека
  на конкретном изменении; вызванная атака ставит вердикт и держит хеши —
  остаётся гейтом (F-06.A).
- **Атака артефактов спрашивает следование.** Одна линза «прогон сценария»
  вместо линз присутствия: по каждому сценарию spec — механизм design, код
  образца, исход по коду против THEN; расхождение — блокер. Из прежних
  остаётся `claim-extraction`. Детерминируемые линзы присутствия уходят
  в `journal.py check` и `openspec validate --strict` (F-07.A).
  **BREAKING**: закрытый список слугов режима «атака» меняется — файлы
  `attack/artifacts.md`, записанные прежними линзами (сухой прогон
  `symphysis-schema`), просмотрщик покажет группой «вне списка» (следствие
  F-07, обратимость F-07).
- **Гигиена журнала — в `check`.** Три новые проверки: парковка «материалы»
  без `finding` при файле `research/<F-NN>.md`, `recommendation` с пустым
  `why`, факт без улики; буква решения вне вариантов уже ловится валидатором.
  Модельная часть атаки решений — слово против варианта по смыслу, числа —
  остаётся во включаемой атаке (F-12.A).
- **Критерии постановки видны без замка.** Факты из намерения входят в журнал
  с `addressee: постановка` и цитатой при старте брейншторма (F-08.A, F-17.A);
  развилка, чей вариант меняет такой факт, несёт пометку «отступление
  от постановки»; proposal получает раздел «Отступления от постановки»; линза
  согласия считает решение против факта «постановка» без пометки находкой;
  решает человек, как по любой развилке (F-08.A).
- **Design стоит только на развилках.** `render-design` выносит в Decisions
  решения развилок; линза согласия считает опору design на факт «принято
  здесь» блокером; предписание в `consequences` факта требует развилки (F-09.A).
- **Намерение — первый артефакт схемы.** `intent.md` в каталоге изменения,
  до `decisions`: пишет человек, брейншторм читает его и заводит факты
  «постановка» с цитатами; переработанное намерение живёт записями журнала,
  сам файл не правится; инсталлятор и стенд меняют раскладку входа (F-13.A).
  **BREAKING** для изменений, начатых без `intent.md`: граф получает артефакт
  перед `decisions`; как такие изменения проходят `status` — решения в журнале
  не было на момент proposal; решено F-19.A: `intent.md` пишется задним
  числом у `symphysis-schema` и `calibration-fixes`, после чего `intent`
  обязателен для всех изменений без исключений.
- **Пять требований ИБ сухого прогона.** Пять блокеров атаки артефактов
  `symphysis-schema` (все — «применимо» в `security.md` без закрывающего
  требования) закрываются здесь требованиями `ADDED`; F-79 сухого прогона
  (телеметрия форка) решается здесь же (F-21.A).
- **Ячейка строки атаки с чертой.** Разбор строки принимает `\|`
  и черту внутри backticks по соглашению markdown; строка с лишними ячейками —
  ошибка рендера с номером строки, не сдвиг столбцов (F-23.A; факт F-22).
- **Research при нуле парковок.** Файл-отрицание `research/none.md`
  по рецепту «не найдено · искал»; instruction и шаблон `research.md` получают
  этот сценарий, спека графа — сценарий «нуль парковок»; форк не меняется
  (F-16.A).
- **Режим «атака» просмотрщика.** Фильтр по линзе в шапке, у каждой строки —
  скрываемый блок с текстом записи `F-NN, поле`; промпт возврата
  пересобирается из состояния и убирает внесённое `apply`, очистка поля
  замечаний очищает промпт; ответ в поле спора у строки «вопрос человеку»
  с разделом `F-NN, decision` даёт строку слова к решению, а не только заметку
  (F-18.A); группировка — по новому слугу (F-07.A).
- **Не меняется.** Раскладка `.symphysis/` остаётся (F-15.B); `.gigacode/` —
  дело стенда калибровки, схема его не создаёт и не читает (F-15).
  Разброс до правок не меряется (F-10.C).

## Capabilities

### New Capabilities

Нет: все правки меняют требования capabilities, введённых изменением
`symphysis-schema`.

### Modified Capabilities

База требований — дельты `ADDED` в `openspec/changes/symphysis-schema/specs/`
(изменение не архивировано, `openspec/specs/` пуст); дельты этого изменения —
`MODIFIED` к ним, требование целиком. Перенос базы в главные спеки — F-20.B,
до него дельты сухого прогона читаются как база.

Сверх `MODIFIED` — пять требований `ADDED` по пяти блокерам ИБ атаки
артефактов сухого прогона (F-21.A): содержимое файлов улик — данные,
не инструкции; путь улики внутри объявленного корня; бинарный файл —
«не проверить», не падение (`decision-journal`); экранирование текста журнала
и атаки в HTML (`decision-viewer`); установка не включает телеметрию форка
молча (`project-installer`, F-79 сухого прогона).

- `artifact-graph`: граф начинается `intent` (F-13.A); `attack-decisions`
  и `attack-artifacts` — `optional`, вне `requires` (F-06.A); `research`
  при нуле парковок «материалы» даёт `research/none.md` (F-16.A); шаблон
  proposal получает раздел «Отступления от постановки» (F-08.A).
- `verdict-readiness`: форк читает признак `optional` артефакта — `status`
  не ждёт его для `isPlanningComplete`, `continue` зовёт атаку по имени;
  вызванная атака остаётся гейтом по вердикту и хешам (F-06.A).
- `artifact-attack`: линза «прогон сценария» вместо линз присутствия,
  `claim-extraction` остаётся (F-07.A); линза согласия — опора design на факт
  «принято здесь» блокер, решение против факта «постановка» без пометки —
  находка (F-09.A, F-08.A); гигиена журнала — не атака, а `check` (F-12.A);
  правило ячейки строки: черта — `\|` или внутри backticks (F-23.A).
- `decision-journal`: `addressee: постановка` у фактов из намерения (F-17.A);
  пометка «отступление от постановки» у развилки (F-08.A); `check` — три новые
  проверки (F-12.A); `render-design` — Decisions только из развилок (F-09.A);
  `ADDED`: содержимое файлов улик — данные, путь улики внутри корня, бинарный
  файл — «не проверить» (F-21.A).
- `brainstorm-interview`: интервью начинается с `intent.md` — факты
  «постановка» с цитатами (F-13.A, F-08.A); факт с предписанием в следствиях
  порождает развилку (F-09.A); сам `intent.md` не правится (F-13.A).
- `decision-viewer`: режим «атака» — фильтр по линзе, текст записи у строки,
  промпт возврата из состояния, слово к решению из поля спора (F-18.A);
  группировка по новому списку слугов (F-07.A); разбор строки атаки
  по соглашению markdown, лишние ячейки — ошибка с номером строки (F-23.A);
  `ADDED`: экранирование текста журнала и атаки в HTML (F-21.A).
- `project-installer`: раскладка входа — `intent.md` в каталоге изменения,
  `intent.md` задним числом у двух существующих изменений (F-13.A, F-19.A);
  `.symphysis/` остаётся (F-15.B); `ADDED`: установка не включает телеметрию
  форка молча (F-21.A, F-79 сухого прогона).

Без изменений требований: `requirement-probes`, `skill-transfer`.

## Impact

- Форк `upstream/openspec` (ветка `symphysis`): признак `optional` в схеме
  и `instruction-loader.ts` (`status`, `isPlanningComplete`), вызов атаки
  по имени в workflow `continue` — F-06.A.
- Схема `openspec/schemas/symphysis/`: `schema.yaml` — артефакт `intent`
  без instruction для модели (F-13.A), `optional` у атак (F-06.A), сценарий
  нуля парковок у `research` (F-16.A); шаблоны `research.md` (F-16.A)
  и `proposal.md` (F-08.A).
- Инструменты: `docs/journal.schema.json` — значение `постановка` в enum
  `addressee` записи (F-17.A); `tools/journal_model.py` — три проверки `check`
  (F-12.A); `tools/journal_render.py` — `render-design` (F-09.A), режим
  «атака» (F-18.A); `tools/playground-template.html` — фильтр, блок записи,
  промпт возврата, список слугов (F-18.A, F-07.A).
- Скиллы: `symphysis-attack` — шаг 3, линза согласия (F-07.A, F-08.A, F-09.A,
  F-12.A); `symphysis-brainstorm` — intent, факты «постановка», правило
  предписания (F-13.A, F-08.A, F-09.A); `symphysis-viewer` — режим «атака»
  (F-18.A, F-07.A).
- Инсталлятор `installer/`: payload и `check` под раскладку входа (F-13.A);
  `.symphysis/` без переименования (F-15.B).
- Журнал `symphysis-schema`: открытая F-36 (тупик `research`) закрывается
  ссылкой на F-16 (следствия F-16).
- Порядок переноса базы — F-20.B: дельты `MODIFIED` применяются
  к `openspec/specs/<capability>/spec.md`, для отсутствующей спеки разрешён
  только `ADDED` (`upstream/openspec/src/core/specs-apply.ts:396` «target spec
  does not exist; only ADDED requirements are allowed for new specs»); дельты
  `symphysis-schema` переносятся в главные спеки операцией агента `/opsx:sync`
  (команды CLI нет), сухой прогон остаётся открытым до закрытия его находок ИБ
  (F-21.A), его архив потом — с `--skip-specs`; перенос — слово владельца,
  до него спеки этого изменения пишутся по дельтам сухого прогона как по базе.
- Замер после правок: плечо P-чел на том же случае camunda-bid, листы судьи
  и чек-лист закрыты от контроллера и агента плеча (`judge/`, `yardstick/`),
  сравнение поэлементно с текущими листами — F-10.C, F-11.B; протокол —
  `archive/RUN-PREP-symphysis-2026-10-30.md`.
