# Proposal

## Why

На предупреждение атаки сегодня реакции нет: строки `предупреждение` идут человеку списком и при `passed`, остаются в файле атаки, а тело скилла говорит «механизма «прочитано» у предупреждения пока нет» и относит флаг к отдельному изменению (F-04). Владелец выбрал вариант B развилки Р4 ревью: заметка `notes[]` «предупреждение прочитано: `<раздел>`» через «Замечания к схеме», страница показывает флаг, сверяя заметки с файлом атаки, контракт таблицы не меняется (F-01, F-02, F-03). Путь уже проложен спорами: `apply` пишет «Замечания к схеме:» одной заметкой с датой (F-05), страница сверяет `notes[]` с файлом атаки подстрокой и собирает строку замечаний через « · » (F-06). Цена по хешу известна: заметка меняет хеш журнала без новых записей, состав вердикта называет это словами «записей не добавлено: журнал изменён иначе», повтор атаки обновляет только хеш (F-08) — изменение `attack-stale-scope` влито перед этим ради того.

## What Changes

- Заметка «предупреждение прочитано: <раздел>» становится известной формой: раздел дословно из столбца «Раздел» таблицы атаки (`F-12, options.B` у журнала, `design.md, Decisions` у артефактов); флаг ложится на все строки `предупреждение` файла с этим разделом (F-13, F-07). Флаг есть только у строк тяжести `предупреждение`, включая «по спеке не выводится»; у блокеров и справок его нет (F-12).
- Страница в режиме «атака»: переключатель «прочитано» на карточке строки `предупреждение`; отметка живёт в хранилище браузера рядом со спорами; при сборке промпта каждая отметка даёт текст «предупреждение прочитано: <раздел>» в строке «Замечания к схеме:» через « · »; после `apply` отметка уходит из состояния по подстроке в `notes[]`, и флаг на карточке берётся из журнала (F-14, F-06). Слово из чата главная нить пишет той же строкой в файл ответа и вносит `apply` (F-14). Заметка, у которой в файле атаки нет строки с таким разделом, флага не даёт и остаётся в разделе «Заметки» журнала и в режиме «проверка» (F-16).
- Скилл атаки: итог по-прежнему перечисляет все строки `предупреждение`, у прочитанных — пометка «(прочитано)» по заметкам `notes[]` с тем же разделом; при повторе по составу прежние строки не трогаются, флаг переживает повтор, пока раздел на месте; строки «механизма пока нет» и «отдельное изменение» из тела снимаются (F-15, F-04).
- Контракт с плагином: форма заметки записывается в `docs/repo-contract.md` в перечень значений, которые плагин разбирает, рядом с меткой «(добавлен человеком»; номер контракта не растёт — новое значение в свободном тексте заметки, плагин без него ничего не теряет (F-17, F-09). Переключатель и флаг в плагине — его сессия, коммит с `Needs:` не нужен (F-17, F-11).
- Не меняются: столбцы таблицы атаки и frontmatter файлов атаки (F-03), грамматика строк `apply` (F-05, F-09); `journal.py check` и `step_help.py` флаги не считают (F-15); хеш в вердикте остаётся байтовым, повтор атаки идёт по составу (F-08).

## Capabilities

### New Capabilities

- `warning-read-flag`: флаг «прочитано» у предупреждения атаки — форма заметки `notes[]` и опознание строки по разделу дословно, какие строки несут флаг, что значит заметка без строки, место формы заметки в контракте с плагином без роста номера (F-12, F-13, F-16, F-17).

### Modified Capabilities

- `decision-viewer`: новое требование — режим «атака» несёт переключатель «прочитано» у строк `предупреждение`, собирает отметки в строку «Замечания к схеме:» промпта возврата и после пересборки показывает флаг по заметкам журнала; внесённые отметки уходят из состояния браузера (F-14, F-12, F-16).
- `artifact-attack`: требование «Вердикт атаки держат блокеры» — список предупреждений в итоге несёт пометку «(прочитано)» по заметкам журнала с тем же разделом; строки прочитанных предупреждений при повторе по составу не трогаются (F-15).

## Impact

- Ядро, модуль `viewer/`: `viewer/playground-template.html` — состояние `attackState` (отметки рядом со спорами), карточка строки, сборка промпта, уборка внесённого после `apply`, флаг по `notes[]`; тесты `viewer/tests/test_viewer_prompt.py` (строка промпта и уборка) и `viewer/tests/test_viewer_page.py`; тело `viewer/skills/symphysis-viewer/SKILL.md` — шаг 5, строка о флаге рядом со спорами по атаке (F-14).
- Модуль `attack/`: `attack/skills/symphysis-attack/SKILL.md` — шаги 5 и 7, «Границы», «Приёмка» (F-15, F-04); `attack/attack-table.md`, раздел «Что считает страница» — строка о флаге (общий файл скиллов атаки и просмотрщика). Парсер `attack/attack_table.py` и расчёт `attack/attack_scope.py` не меняются (F-03, F-15).
- `docs/repo-contract.md` — строка в перечне значений, которые плагин разбирает; номер контракта прежний (F-17). `docs/GUIDE.md` — абзацы о шагах атаки: предупреждение можно отметить прочитанным на странице, отметка уходит в `notes[]`.
- Инсталлятор: новых файлов модулей нет; payload пересобирается `scripts/sync-payload.js` из уже перечисленных `viewer/playground-template.html`, `attack/attack-table.md` и тел скиллов.
- Плагин `symphysis-vscode`: переключатель и флаг — отдельной работой в его репозитории по строке контракта (F-17, F-11).
- Побочное, уже учтённое: каждая внесённая отметка меняет хеш журнала, вердикт `attack-decisions` становится `stale` с составом «записей не добавлено: журнал изменён иначе»; повтор атаки обновляет хеш без новых строк (F-08).
