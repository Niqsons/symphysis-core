# Spec Delta

## Purpose
Сборка `.vsix` плагина: по собранному файлу видно, из какого коммита он собран, а работоспособность проверяется настоящей установкой, в том числе для промежуточных сборок.

## ADDED Requirements

### Requirement: Собранный файл называет версию и коммит
Сборка `.vsix` SHALL нести версию из `package.json` и короткий хеш коммита плагина в имени файла и в манифесте, и эта версия SHALL быть видна в окне расширений (F-10, F-30).

#### Scenario: Сборка из коммита
- **GIVEN** плагин версии 0.2.0 на коммите с коротким хешем H
- **WHEN** выполняется `npm run package`
- **THEN** имя файла и манифест содержат 0.2.0 и H

#### Scenario: Окно расширений
- **GIVEN** установленный пакет
- **WHEN** человек смотрит расширение в окне расширений
- **THEN** видна версия с хешем — предположение: VS Code показывает хеш в поле версии; проверить: настоящей установкой

### Requirement: Промежуточная сборка проверяется установкой, без шагов выпуска про `main`
Новая сборка вместе с пакетом правок SHALL проходить `npm run e2e:vsix`, в состав пакета SHALL входить файл mermaid. Эта сборка промежуточная: версия 0.2.0, без тега и без слияния в `main` плагина. Шаги выпуска 1 и 2 из контракта для неё SHALL NOT применяться (F-09, F-55).

#### Scenario: Проверка сборки
- **GIVEN** собранный `.vsix` с пакетом правок
- **WHEN** выполняется `npm run e2e:vsix`
- **THEN** пакет ставится в чистый VS Code, вкладка схемы и журнал работают, состав пакета совпадает с ожидаемым

#### Scenario: Ядро ещё не в `main`
- **GIVEN** коммиты плагина с `Needs:` на коммиты ядра, которых нет в `main` ядра
- **WHEN** собирается промежуточная сборка
- **THEN** сборка и проверка проходят на ядре из ветки изменения
