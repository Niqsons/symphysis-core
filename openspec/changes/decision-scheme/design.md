## Migration Plan

Порядок — по зависимостям, шаги исполняет `tasks.md`.

1. Ядро, затем плагин: коммит плагина называет `Needs:` (F-19). Промежуточная сборка проверяется на ядре из ветки изменения (F-55).
2. `implementation-consequences` правит те же файлы: `docs/journal.schema.json`, `schema.yaml`, `sync-payload.js`, `install.js`. Работа в своём worktree конфликта не даёт, он возникнет при вливании. Её ядро вливается первым, эта ветка приводится к новому `main`. Вливание только по слову человека.
3. Инструменты проектов: новый `.vsix` на старых инструментах просит обновить их, команда `symphysis install --force`; черновики `.symphysis/viewer/` остаются (F-20, F-31).
4. Журналы не мигрируют: без `nodes` они годны (F-114). Страницы в git показывают прежнюю вшитую схему, пока их не пересоберут. Изменения без `scheme.md` видят плашку (F-05).
5. Этот журнал: пока инструменты здесь не обновлены, `nodes` запрещён схемой, записи изменения остаются без него.
6. Откат: ядро откатывается коммитом, лишний файл mermaid в `.symphysis/tools/` ничему не мешает, а без него страница показывает текст (F-39). Плагин откатывается установкой прежнего `.vsix` с `--force`.
