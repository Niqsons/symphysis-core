# Proposal

## Why

Замер после правок калибровки вернул P-чел почти к уровню ванили, но правило §4 не изменилось (F-09, записка `docs/analysis/calibration-fixes-measure-2026-11-01.md`). Наблюдённые потери P — поведение переиспользуемого кода, а не края требований (F-06), и механизма, который ищет такие ветки, в схеме нет: разведка GSD веток отказа не выписывает (F-01), а линза `scenario-run` идёт от сценария и ветку без сценария не видит (F-05). Владелец выбрал шаг, который закрывает этот разрыв, и назвал критерии готовности: новые прогоны трёх плеч на Opus 5.5 (F-20, F-27), реализованные механики (F-21), сборка, установка и пошаговое руководство (F-22).

Почему сейчас: исследование показало, что критерий F-22 на другой машине сегодня невыполним. Форка нет нигде, кроме этого диска (F-28), а на чистой установке нет команды `/opsx:continue`, хотя `check` отвечает `ok` (F-29). Стенд привязан к Fable, на которой новых прогонов больше не будет (F-10, F-30).

## What Changes

- **Шаг последствий.** Новый артефакт `consequences` между `specs` и `design`, файл `consequences.md` (F-13.A). Строка описи несёт ветку отказа из кода с цитатой и допущение нашей конструкции о ней (F-14.C).
- **Что разбирается.** Скрипт предлагает файлы кода из улик выбранных вариантов решённых развилок, модель выбирает, дополняет и исключает с причиной (F-15.D). Расхождение со списком — сигнал `[!!]`, не стоп (F-25.A).
- **Как доходит до человека.** Опись остаётся в файле, в журнал идут только ветки без сценария, кандидатами с исходами проб (F-16.A). В конце шага — три причины провала всего изменения, тоже кандидатами (F-17.A).
- **Проба краёв.** Каждое требование получает строку по всем восьми категориям, сырой список сохраняется, текст объясняет задачу подробнее (F-18.B). Покрытие — сигнал, не стоп (F-25.A).
- **Выбор перед запуском.** Файл `symphysis.yaml` в корне проекта с умолчанием «всё включено»: ветки отказа, допущения, проба краёв (F-24.A, слова владельца к F-14 и F-18). Настройка личная: файл живёт вне git, каждый пользователь решает сам, с каким инструментарием работать и как его настраивать (F-94.E).
- **Установка.** `install` ставит workflow `continue`, `check` проверяет наличие команды (F-32.A). `install` создаёт `symphysis.yaml`, если файла нет, и не перезаписывает его (F-24.A); добавляет `symphysis.yaml` в `.gitignore` проекта, повторный запуск строку не дублирует (F-94.E). Инструменты журнала получают первую зависимость, PyYAML (F-110.B).
- **Выпуск.** Скрипт сборки кладёт тарбол форка рядом с исходниками в `vendor/`, установка идёт из клона репозитория (F-31.A, F-36.A).
- **Руководство.** `docs/GUIDE.md` проводит учебный проект по всем шагам OpenSpec, шаги после `tasks.md` описаны короче (F-34.A).
- **Прогоны.** Шаг последствий на копиях `c3-p1` и `c3-p2` на Fable (F-19.A, F-26.B), затем три плеча на Opus 5.5: ваниль, чистый промпт, P-чел (F-20, F-26.B). Роль человека на Opus 5.5 (F-33.A). Механики стенда правятся в `skills-factory` (F-30, F-37). Итог записывается, каким бы ни вышел; P-чел ниже ванили означает, что правки не помогли (F-27).

## Capabilities

### New Capabilities

- `consequence-inventory`: шаг последствий — состав строки описи, выбор мест кода, кандидаты в журнал, pre-mortem, файл при нуле механизмов.
- `project-settings`: личный файл `symphysis.yaml` вне git — что выбирается перед запуском шага, умолчания, поведение при выключенном составе.
- `onboarding-guide`: пошаговое руководство — установка из клона, учебный проект, все шаги OpenSpec.

### Modified Capabilities

- `artifact-graph`: артефакт `consequences` в графе и зависимость от него у `design`.
- `requirement-probes`: пол пробы краёв по восьми категориям, сырой список, выключение пробы.
- `decision-journal`: подкоманда, предлагающая места кода, и сверка описи и покрытия сигналом.
- `project-installer`: установка workflow `continue` и его проверка, создание `symphysis.yaml` и его строка в `.gitignore` проекта, тарбол форка в выпуске.

## Impact

- **Схема:** `openspec/schemas/symphysis/schema.yaml`, новый шаблон `consequences.md`, instruction `design` и `specs`.
- **Скиллы:** новый скилл шага последствий, `skills/symphysis-edge-probe` (текст, шаблон, сырой список).
- **Инструменты:** `tools/journal*.py` — список мест кода, сверка и чтение `symphysis.yaml` пакетом PyYAML; строка «пакетов не требуют» в `installer/README.md` перестаёт быть верной (F-110.B).
- **Инсталлятор:** `installer/lib/install.js`, `installer/lib/check.js`, скрипт сборки, `vendor/`. Шаг `install` правит глобальный конфиг OpenSpec так же, как уже делает с телеметрией (F-32.A), при `profile: core` переводит профиль в `custom` с шестью workflow и `continue` (F-79.A); кастомный профиль форк сам больше не пополняет, это касается других проектов на машине. Ещё `install` правит `.gitignore` проекта (F-94.E).
- **Форк OpenSpec:** не меняется (F-13.A, F-32.A).
- **Документы:** `docs/GUIDE.md`, `installer/README.md`.
- **Вне репозитория:** `skills-factory`, ветка стенда: водитель, сборка плеч, правила судейства (F-37). Прогоны расходуют Fable на двух копиях и Opus 5.5 на трёх плечах; судейство трёх листов — за владельцем.
