## Причины блокеров

Блокеров 12, причин шесть. Строки выше не перечитывались и не переоценивались; это группировка для читателя.

1. **Установка из клона.** `installer/node_modules/` и `installer/payload/` вне git, а путь пользователя в спеке и в задаче 7.2 не собирает ни то, ни другое. На чистом клоне `node installer/bin/symphysis.js install` падает. После `git pull` тот же разрыв молчит: `install --force` кладёт прежний payload, `check` сверяет с ним же и отвечает `ok`. Строки «Установка на чистой машине», «Обновление до новой версии».
2. **Список workflow через `config set` на Windows.** `runOpenspec` склеивает аргументы в строку оболочки, кавычки JSON теряются, форк отказывает, установка читает отказ как «форка нет» и выходит с кодом 0. Тесты идут по ветке `.js` без оболочки и этого не увидят. Строки «Чистая установка», «Список человека сохраняется», «Профиль core на чистой установке».
3. **Побочные правки `config set`.** Вызов форка вписывает значения по умолчанию, а при включённой телеметрии ещё `noticeSeen` и `anonymousId`. Сценарий обещает различие только в трёх правках. Строка «Конфиг до и после».
4. **Кто такой «настроенный клиент».** Форк этого наружу не отдаёт, в инсталляторе карты клиентов нет, журнал и строка предположений способа не называют. Строки «Форка нет или клиент не настроен», «Команды нет», «Команда у настроенного клиента», «Клиент не настроен».
5. **Скилл как третий читатель `symphysis.yaml`.** Вопрос F-51 называет чтение моделью, план покрывает только Python и JS. Строка «Значение не из true и false», механизм «чтение скиллом».
6. **Режим «только допущения».** Формы строки без пути в задаче 4.2 нет, а сверка идёт по пути. Строка «Только допущения».
