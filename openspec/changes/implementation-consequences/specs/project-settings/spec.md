# Spec Delta

## Purpose
Файл настроек проекта `symphysis.yaml`: что человек выбирает до запуска шага, какие значения действуют по умолчанию и как виден выключенный состав.

## ADDED Requirements

### Requirement: `symphysis.yaml` в корне проекта задаёт выбор перед запуском шага
Файл `symphysis.yaml` в корне проекта, вне `.symphysis/`, SHALL задавать три выбора: ветки отказа, допущения, проба краёв; отсутствие файла или ключа SHALL означать «включено» (F-24.A, слова владельца к F-14 и F-18, F-23).
<!-- проба краёв: форма=text, исходы: F-50 открыт, F-51 открыт -->
<!-- проба запретов: исходы: F-94 открыт; канон — F-103 → security.md -->

#### Scenario: Файла нет
- **GIVEN** проект без `symphysis.yaml`
- **WHEN** начинается шаг `consequences` или проба краёв
- **THEN** ветки отказа, допущения и проба краёв считаются включёнными

#### Scenario: Ключа нет
- **GIVEN** `symphysis.yaml`, где задан только выключенный выбор допущений
- **WHEN** начинается шаг `consequences`
- **THEN** допущения выключены, ветки отказа включены — предположение: ключи `consequences.failure_branches`, `consequences.assumptions`, `edge_probe.enabled` со значениями `true | false`; решить при реализации

#### Scenario: Файл переживает обновление установки
- **GIVEN** `symphysis.yaml` с правками человека
- **WHEN** выполняется `symphysis install --force`
- **THEN** файл не изменён, а каталог `.symphysis/` обновлён

### Requirement: Шаг читает выбор в начале и человека не спрашивает
Скилл шага SHALL читать `symphysis.yaml` в начале шага и SHALL NOT задавать человеку вопрос о составе; правка файла после начала шага SHALL действовать со следующего запуска шага (F-24.A).
<!-- проба краёв: форма=stateful, исходы: кандидатов нет -->
<!-- проба запретов: исходы: F-95 открыт -->

#### Scenario: Запуск шага без вопроса
- **GIVEN** проект с `symphysis.yaml` и изменение, у которого готовы `specs`
- **WHEN** запускается шаг `consequences`
- **THEN** шаг идёт с выбором из файла, вопроса о составе человеку нет

#### Scenario: Правка во время шага
- **GIVEN** идущий шаг, начатый при включённых допущениях
- **WHEN** человек выключает допущения в `symphysis.yaml`
- **THEN** идущий шаг дописывает опись с допущениями; следующий запуск шага идёт без них
<!-- проба краёв, без кандидата: idempotency, concurrency — сценарий «Правка во время шага»: значение читается один раз за запуск -->

### Requirement: Выключенный состав назван в артефакте шага
Шаг, часть которого выключена настройкой, SHALL называть это в своём артефакте (F-24.A); предположение: след выключенной пробы краёв — комментарий шаблона под требованием; решить при реализации.

#### Scenario: Выключена колонка описи
- **GIVEN** `symphysis.yaml`, где допущения выключены
- **WHEN** шаг `consequences` пишет `consequences.md`
- **THEN** файл называет, что допущения выключены настройкой

#### Scenario: Выключена проба краёв
- **GIVEN** `symphysis.yaml`, где проба краёв выключена
- **WHEN** завершается шаг `specs`
- **THEN** под каждым требованием стоит `<!-- проба краёв: выключена настройкой -->`
