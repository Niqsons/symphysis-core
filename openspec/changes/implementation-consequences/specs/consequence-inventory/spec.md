# Spec Delta

## Purpose
Шаг последствий схемы `symphysis`: опись веток отказа переиспользуемого кода и допущений о них, выбор мест разбора и вывод непокрытого человеку через журнал решений.

## ADDED Requirements

### Requirement: Опись лежит в файле, строка несёт ветку отказа и допущение о ней
Шаг `consequences` SHALL писать всю опись в `<каталог изменения>/consequences.md`; строка описи SHALL называть механизм, ветку отказа из кода в виде `путь:строка «цитата»`, что код делает при этом отказе, и допущение конструкции изменения об этой ветке (F-13.A, F-14.C, F-16.A).

#### Scenario: Строка при настройках по умолчанию
- **GIVEN** журнал с решённой развилкой, чей выбранный вариант несёт улику на файл кода, и проект без выключенных колонок описи
- **WHEN** выполняется шаг `consequences`
- **THEN** в `consequences.md` есть строка с именем механизма, `путь:строка «цитата»`, действием кода при отказе и допущением конструкции об этой ветке

#### Scenario: Строку можно проверить по коду
- **GIVEN** строка описи с `путь:строка «цитата»`
- **WHEN** читатель открывает файл по этому пути
- **THEN** цитата стоит в файле дословно, и в ней видна сама ветка отказа, а не её пересказ

#### Scenario: Файл без веток отказа
- **GIVEN** файл из списка мест без веток отказа
- **WHEN** модель пишет опись
- **THEN** строка «<механизм> (`<путь>`): веток отказа не найдено, искал: <шаблоны>» без цитаты, сверка по этому пути считает место разобранным

#### Scenario: Цитаты нет в файле дословно
- **GIVEN** строка описи с цитатой `a || b`, которой в файле нет дословно
- **WHEN** выполняется `journal.py check`
- **THEN** `[!!] consequences.md: <путь> «a || b» — цитаты нет дословно`, код 0; разбор строки держит `||` и апостроф, номер строки не сверяется

### Requirement: Строка описи не выдаёт пересказ за ветку отказа
Строка описи, называющая ветку отказа при включённых ветках, MUST NOT быть без `путь:строка «цитата»`; строка «веток отказа не найдено» края F-38 ветку не называет; судит человек или атака, форму строки скрипт не разбирает (F-90.A, F-38.A, F-128.A).

#### Scenario: Строка без цитаты
- **GIVEN** строка `**Состав:**` файла с ветками отказа и строка описи, называющая ветку без `путь:строка «цитата»`
- **WHEN** человек читает опись или идёт атака `symphysis-attack`
- **THEN** строка признана нарушением требования; судит человек или атака
<!-- требование из F-90; пробами не проходило -->

### Requirement: Состав строки описи следует настройкам проекта
Шаг `consequences` SHALL писать в строке описи только колонки, включённые в `symphysis.yaml`: ветку отказа, допущение или обе (F-14.C и слово владельца к нему, F-24.A).

#### Scenario: Только ветки отказа
- **GIVEN** `symphysis.yaml`, где допущения выключены, а ветки отказа включены
- **WHEN** выполняется шаг `consequences`
- **THEN** строка описи несёт механизм, `путь:строка «цитата»` и действие кода при отказе; колонки допущения в файле нет

#### Scenario: Только допущения
- **GIVEN** `symphysis.yaml`, где ветки отказа выключены, а допущения включены
- **WHEN** выполняется шаг `consequences`
- **THEN** строка описи несёт механизм, путь файла и допущение конструкции о нём; колонок ветки и цитаты в файле нет, сверка закрывает место по пути

### Requirement: Места разбора предлагает скрипт, выбирает модель
Шаг `consequences` SHALL начинаться со списка мест кода из подкоманды журнала и SHALL оставлять выбор модели: разобрать место из списка, дополнить список найденным самой или исключить место строкой с причиной в `consequences.md`; скрипт SHALL NOT ограничивать этот выбор (F-15.D, F-25.A).

#### Scenario: Модель исключает место
- **GIVEN** место `src/Foo.java` в списке, которое модель считает не относящимся к изменению
- **WHEN** модель пишет опись
- **THEN** `consequences.md` несёт строку исключения с этим путём и причиной, разбора этого места нет, шаг не останавливается

#### Scenario: Модель дополняет список
- **GIVEN** файл `src/Bar.java`, которого нет в списке, но на который опирается конструкция изменения
- **WHEN** модель пишет опись
- **THEN** в `consequences.md` есть строки по этому файлу, и сверка со списком на него не сигналит

### Requirement: Исключение места несёт довод о конкретном файле
Шаг `consequences` MUST NOT исключать место из разбора без довода о конкретном файле; судит человек, читая раздел исключений, или атака, скрипт этого не судит (F-91.B).

#### Scenario: Шаблонная причина исключения
- **GIVEN** все места исключены одной шаблонной причиной, сверка не сигналит
- **WHEN** человек читает раздел исключений или идёт атака `symphysis-attack`
- **THEN** исключение без довода о конкретном файле признано нарушением требования; судит человек или атака
<!-- требование из F-91; пробами не проходило -->

### Requirement: В журнал идут только ветки без сценария
Шаг `consequences` SHALL сверять каждую строку описи со сценариями `specs/` и SHALL заводить кандидат журнала только на строку без сценария: на ветку, а при описи из одних допущений на допущение (F-16.A, F-43.A). Кандидат SHALL нести исходы Specify, Dismiss, Backstop, Defer и улику: на строку кода или, у допущения без цитаты, на строку требования; решение SHALL появляться только словом человека через `apply` (F-07).

#### Scenario: Ветка со сценарием
- **GIVEN** строка описи, на ветку которой в `specs/` есть сценарий
- **WHEN** шаг сверяет ветку со сценариями
- **THEN** строка описи называет этот сценарий, записи журнала по ветке нет

#### Scenario: Ветка без сценария
- **GIVEN** строка описи, на ветку которой сценария нет
- **WHEN** шаг сверяет ветку со сценариями
- **THEN** в журнале появляется запись `kind: развилка`, `status: открыт`, `addressee: человек` с четырьмя вариантами исходов, уликой `path` и `quote` на код и `decision: null`; строка описи называет её номер

#### Scenario: Исход Specify доходит до спеки
- **GIVEN** кандидат шага с решением человека Specify
- **WHEN** скилл шага зеркалит исход
- **THEN** `outcome` равен `{kind: проба, value: Specify, reason: <слово дословно>}`, а в `specs/` появляется сценарий на эту ветку

#### Scenario: Сценарий задевает ветку, но не называет её исход
- **GIVEN** сценарий, чей THEN не называет исход этой ветки
- **WHEN** шаг сверяет ветку со сценариями
- **THEN** ветка считается без сценария и идёт кандидатом, строка описи называет ближайший сценарий

#### Scenario: Опись только из допущений
- **GIVEN** опись только из допущений
- **WHEN** шаг сверяет допущения со сценариями
- **THEN** допущение без сценария идёт кандидатом журнала с теми же четырьмя исходами

### Requirement: Шаг заканчивается тремя причинами провала изменения
В конце шага `consequences` SHALL быть раздел pre-mortem о провале всего изменения: норма — три наиболее вероятные причины, меньше — со строкой почему, больше — остальные без записей журнала (F-46.A). Каждая из трёх SHALL быть кандидатом журнала с исходами Specify, Dismiss, Backstop, Defer или ссылкой на совпавшего кандидата описи (F-17.A, F-47.A).

#### Scenario: Причины становятся кандидатами
- **GIVEN** написанная опись
- **WHEN** шаг завершается
- **THEN** `consequences.md` несёт раздел с тремя причинами и номером записи журнала у каждой, в журнале три открытых кандидата

#### Scenario: Причина о всём изменении
- **GIVEN** изменение с шестью механизмами в описи
- **WHEN** модель пишет раздел pre-mortem
- **THEN** причин три на всё изменение, троек причин на каждый механизм нет

### Requirement: Причина провала верна только для этого изменения
Раздел pre-mortem MUST NOT нести причину, верную для любого изменения; судит человек в просмотрщике, подставляя в неё другое изменение (F-93.B).

#### Scenario: Причина подходит другому изменению
- **GIVEN** кандидат pre-mortem в просмотрщике
- **WHEN** человек подставляет в причину другое изменение
- **THEN** причина, оставшаяся верной, признана нарушением требования; судит человек
<!-- требование из F-93; пробами не проходило -->

### Requirement: Шаг без механизмов или без состава оставляет файл с причиной
Когда разбирать нечего или все колонки описи выключены, шаг `consequences` SHALL писать `consequences.md` с этой причиной, и артефакт SHALL считаться сделанным (F-13.A, F-24.A).

#### Scenario: Нуль механизмов
- **GIVEN** пустой список мест кода, и модель ничего не добавила
- **WHEN** выполняется шаг `consequences`
- **THEN** `consequences.md` называет, что механизмов нет и что искалось, как `research/none.md`; в `status --json` `consequences` — `done`, `design` — `ready`

#### Scenario: Все колонки выключены
- **GIVEN** `symphysis.yaml`, где ветки отказа и допущения выключены
- **WHEN** выполняется шаг `consequences`
- **THEN** `consequences.md` называет причину «все колонки выключены настройками», строк описи нет; в `status --json` `design` — `ready`; сверки мест нет (F-128.A)
