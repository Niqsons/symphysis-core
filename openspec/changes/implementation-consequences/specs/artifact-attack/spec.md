# Spec Delta

## MODIFIED Requirements

### Requirement: Строка атаки валидна только с линзой, тяжестью, инвариантом и опорой
Скилл `symphysis-attack` SHALL писать в `attack/<цель>.md` таблицу, где строка — одно утверждение цели с разделом, линзой из закрытого списка, инвариантом (кроме строк покрытия), тяжестью из `блокер | предупреждение | справка` и опорой `есть | нет | по спеке не выводится`; невыводимое SHALL получать тяжесть `предупреждение` и путь `вопрос человеку`; `status: passed` SHALL ставиться только при нуле строк `блокер`, строки `предупреждение` вердикт не держат (F-25.B, F-131.A). Линз атаки артефактов SHALL быть две: `scenario-run` — по каждой паре «сценарий spec × механизм design» строка называет механизм, цитирует код образца `путь:строка`, выводит исход по коду и сравнивает с THEN, расхождение — `блокер`, механизм не назван — `блокер` с опорой «нет: design не называет механизм»; и `claim-extraction`; линзы присутствия SHALL быть сняты, их детерминируемая часть — в `journal.py check` и `openspec validate --strict` (F-07.A, F-32.E, F-33.E). Линзы атаки журнала SHALL быть `context-compliance` (слово против варианта по смыслу; опора design на факт — `блокер`; решение против факта `постановка` без пометки «отступление» — находка), `claim-authority`, `claim-extraction`, `coverage`; гигиену журнала (факт без улики, пустое `why`, парковка без `finding`, буква вне вариантов) атака SHALL NOT репортить — её ловит `check` (F-12.A, F-09.A, F-08.A). Ячейка строки SHALL NOT содержать символ черты иначе как `\|` или внутри backticks; литеральная обратная косая перед литеральной чертой пишется как `\\|` (F-23.A, F-34.E).

#### Scenario: Одна строка предупреждения
- **GIVEN** таблица атаки с 53 строками `справка` и одной `предупреждение`
- **WHEN** скилл ставит вердикт
- **THEN** frontmatter несёт `status: passed`, строка итога в `notes[]` журнала — «…предупреждений 1… — passed», итог человеку называет эту строку

#### Scenario: Невыводимое
- **GIVEN** сценарий spec, опирающийся на край с исходом Defer в журнале
- **WHEN** скилл пишет строку `scenario-run`
- **THEN** опора — «по спеке не выводится», тяжесть — `предупреждение`, чем закрыть — `вопрос человеку`

#### Scenario: Сценарий не следует из механизма
- **GIVEN** сценарий spec «переменной нет — инцидент», решение design «новая оценка по образцу `NULLABLE_DATE_TIME_RESULT_TYPES`» и код образца `case NULL -> Either.right(Optional.empty());`
- **WHEN** скилл проходит сценарий линзой `scenario-run`
- **THEN** строка с цитатой кода `путь:строка`, исход «пустое значение без инцидента», опора «нет», тяжесть `блокер`, `status: gaps_found`

#### Scenario: Гигиена журнала не в атаке
- **GIVEN** журнал с фактом без улики
- **WHEN** скилл атакует `decisions.json`
- **THEN** строки об этом факте в таблице нет; `journal.py check` даёт код 1 с именем записи

#### Scenario: Черта в ячейке
- **GIVEN** строка атаки, цитирующая `grep -c '| справка |'` внутри backticks
- **WHEN** файл атаки разбирается просмотрщиком
- **THEN** строка даёт 7 ячеек, черта внутри backticks — текст ячейки

#### Scenario: Design молчит о механизме
- **GIVEN** сценарий spec, для которого `design.md` не называет механизма
- **WHEN** скилл проходит сценарий линзой `scenario-run`
- **THEN** строка с опорой «нет: design не называет механизм», тяжесть `блокер`; воздержания нет — ответ выводится из design

#### Scenario: Два механизма на один сценарий
- **GIVEN** сценарий spec, который design покрывает двумя решениями по очереди
- **WHEN** скилл проходит сценарий
- **THEN** по строке на каждую пару «сценарий × механизм», инвариант каждой — исход по своему коду

#### Scenario: Обратная косая перед чертой в цитате кода
- **GIVEN** код образца содержит литерально `\|` (regex в Java)
- **WHEN** скилл цитирует его в ячейке
- **THEN** в ячейке стоит `\\|` — литеральная косая и литеральная черта; парсер просмотрщика различает `\|` и `\\|`, цитата остаётся дословной

### Requirement: Понижение тяжести только с названной причиной
Скилл `symphysis-attack` MUST NOT ставить строке тяжесть ниже тяжести её линзы без причины в ячейке тяжести; причина SHALL называть решённую запись журнала, собственное суждение модели тяжесть SHALL NOT снижать (F-136.B); каждое понижение SHALL быть видно читателю в режиме «атака» просмотрщика (F-54.E; проверка — суждение: наличие причины проверяется по тексту ячейки, её основание судит человек в просмотрщике).

#### Scenario: Понижение без причины
- **GIVEN** строка линзы `context-compliance` (тяжесть источника — блокер) с тяжестью `предупреждение` и без причины в скобках
- **WHEN** человек читает режим «атака»
- **THEN** строка показана как понижение без причины; достаточность названной причины у соседних строк судит человек

#### Scenario: Понижение своим суждением
- **GIVEN** строка с опорой «нет», и записи журнала, снижающей её тяжесть, нет
- **WHEN** скилл ставит тяжесть
- **THEN** тяжесть — `блокер`; со словом человека в записи F-NN ячейка несёт `предупреждение (решено человеком в F-NN)`

## ADDED Requirements

### Requirement: Вердикт атаки держат блокеры
Скилл `symphysis-attack` SHALL ставить `status: passed` при нуле строк `блокер`; строки `предупреждение` SHALL идти человеку списком, SHALL NOT держать `apply` и при `apply` SHALL читаться заметками к задачам (F-131.A).

#### Scenario: Только предупреждения
- **GIVEN** таблица атаки без блокеров, с двумя предупреждениями
- **WHEN** атака ставит вердикт
- **THEN** frontmatter несёт `status: passed`, итог атаки называет предупреждения списком

#### Scenario: Есть блокер
- **GIVEN** таблица атаки с одним блокером и без предупреждений
- **WHEN** атака ставит вердикт
- **THEN** frontmatter несёт `status: gaps_found`
