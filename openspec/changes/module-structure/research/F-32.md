# F-32 · Как README модуля уживается с README пакета: `installer/README.md` — README пакета npm, корневой README плагина — README `.vsix`?

## Найдено

`vsce` 4.0.0 берёт README по пути из `--readme-path`, кладёт его в пакет как `extension/readme.md` и frontmatter не трогает; другой путь работает, только если корневой `README.md` не идёт в пакет.

- `vscode/node_modules/@vscode/vsce/out/main.js:98` «.option('--readme-path <path>', 'Path to README file (defaults to README.md)')»: путь README задаётся флагом.
- `vscode/node_modules/@vscode/vsce/out/package.js:745` «file = { ...file, originalPath: !isInMemoryFile(file) ? file.localPath : undefined, path: 'extension/readme.md' };»: в пакете файл README всегда ложится как `extension/readme.md`.
- `openspec/changes/module-structure/research/F-32-probe/vsce.txt:8` «name: symphysis-vscode»: при frontmatter в корневом README он стоит в `extension/readme.md` пакета как есть (строки 7–10 следа).
- `openspec/changes/module-structure/research/F-32-probe/vsce.txt:15` «ERROR  The following files have the same case insensitive path, which isn't supported by the VSIX format:»: с `--readme-path` при нынешнем `.vscodeignore` корневой `README.md` и README по флагу сталкиваются, пакет не собирается.
- `openspec/changes/module-structure/research/F-32-probe/vsce-3.txt:5` «файлы readme в пакете: ['extension/readme.md']»: без строки `!README.md` в `.vscodeignore` и с `--readme-path` в пакете один README — файл по флагу.
- `openspec/changes/module-structure/research/F-32-probe/web.txt:11` «"Add a `README.md` file to the root of your extension with the content you want to show on the extension's Marketplace page."»: документация VS Code называет страницей Marketplace README пакета.

Упаковка плагина и тесты держатся за корневой `README.md`; e2e читает `readme.md` установленного пакета.

- `vscode/package.mjs:19` «const flags = ["--no-update-package-json", "--no-dependencies", "--skip-license", "--allow-missing-repository"];»: упаковка `--readme-path` не передаёт.
- `vscode/.vscodeignore:3` «!README.md»: в пакет идёт корневой `README.md`.
- `vscode/test/unit/package-readme.test.ts:9` «const REPO_README = path.resolve(__dirname, "..", "..", "README.md");»: юнит-тест проверяет корневой `README.md`.
- `vscode/test/unit/package-readme.test.ts:17` «assert.ok(ignore.includes("!README.md"), ".vscodeignore не пропускает README.md");»: юнит-тест требует строку `!README.md` в `.vscodeignore` — третий случай пробы её снимает.
- `vscode/test/e2e/vsix-scenario.ts:32` «assertReadme(readReadme(path.join(ext!.extensionPath, "readme.md")));»: e2e проверяет `readme.md` установленного пакета — путь в исходнике ему безразличен.

npm кладёт в пакет README из корня пакета всегда.

- `openspec/changes/module-structure/research/F-32-probe/npm-pack.txt:3` «README в пакете: ['README.md']»: в пакет `@niqsons/symphysis` идёт `installer/README.md`.
- `openspec/changes/module-structure/research/F-32-probe/web.txt:5` «"Certain files are always included, regardless of settings:"»: документация npm о файлах, которые пакет несёт всегда…
- `openspec/changes/module-structure/research/F-32-probe/web.txt:6` «элемент списка: "`README`"»: …и README среди них.
- `openspec/changes/module-structure/research/F-32-probe/web.txt:7` «"`README` & `LICENSE` can have any case and extension."»: README берётся по имени в любом регистре и с любым расширением.

  искал: `front`, `front.?matter` в `vscode/node_modules/@vscode/vsce/out/package.js`
- не найдено: как страница пакета npm и вкладка расширения VS Code показывают frontmatter README

- Условия: копия собранного плагина (`package.json` без `vscode:prepublish`, `.vscodeignore`, `out/extension.js`, `hook/hook.py`, `media/`) во временный каталог; `node vscode/node_modules/@vscode/vsce/vsce package 0.0.0-probe` с флагами `vscode/package.mjs`; случай 1 — frontmatter в корневом README; случай 2 — README пакета в `docs/package-readme.md`, корневой README — описание репозитория, `--readme-path docs/package-readme.md`; случай 3 — как случай 2, но `.vscodeignore` без строки `!README.md`. README пакета прочитан из `.vsix` (`extension/readme.md`). Для npm — `npm pack --dry-run --json --ignore-scripts` в `installer/`. Путь временного каталога заменён на `<временный каталог>`; деревья ядра и плагина не менялись.
- След: `research/F-32-probe/vsce.txt`, `research/F-32-probe/vsce-3.txt`, `research/F-32-probe/npm-pack.txt`, `research/F-32-probe/web.txt`

## Вопросы, которые открылись

- README плагина: оставить корневой `README.md` README пакета и писать описание репозитория в другом файле, или перенести README пакета (`--readme-path` в `vscode/package.mjs`, без `!README.md` в `vscode/.vscodeignore`, правка `vscode/test/unit/package-readme.test.ts:9` и `:17`) и освободить корень под описание репозитория — развилка второго круга.
- README модуля `installer`: npm берёт README из корня пакета всегда (`research/F-32-probe/web.txt:5`), поэтому README модуля и README пакета — один файл; нести ли в нём frontmatter, если показ frontmatter на странице npm не проверен.
- Как показ frontmatter выглядит на самом деле — проверка глазами человека: установить `.vsix` из случая 1 в VS Code и открыть вкладку расширения; страница npm — после публикации или в локальном реестре.
