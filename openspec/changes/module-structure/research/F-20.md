# F-20 · Как код модулей находит друг друга и свои файлы в исходнике?

## Найдено

Свои файлы код находит от `ROOT` — каталога над тем, где лежит `journal_model.py`; исключения — файл версии рядом с `step_help.py` и скиллы клона в `skills/`. Ещё три места от `__file__` — путь `journal.py` для команды пересборки (`tools/journal_cli.py:170`), хук гейта имён рядом с установщиком (`tools/hooks/install_hooks.py:15`), файл mermaid только из установки (`tools/journal_render.py:232`) — выбранным вариантом не задеты, кроме первого (связка ниже).

- `tools/journal_model.py:21` «ROOT = Path(__file__).resolve().parent.parent»: `ROOT` — каталог над каталогом кода.
- `tools/journal_model.py:22` «SCHEMA_PATH = ROOT / "docs" / "journal.schema.json"»: схема журнала — в `docs/` под `ROOT`, не рядом с кодом.
- `tools/journal_render.py:21` «TEMPLATE_PATH = ROOT / "tools" / "playground-template.html"»: шаблон страницы — в `tools/` под `ROOT`.
- `tools/journal_apply.py:27` «ROOTS_PATH = ROOT / "tools" / "journal-roots.json"»: файл корней — в `tools/` под `ROOT`.
- `tools/step_help.py:279` «INSTALL_SKILL_DIRS = (*PROJECT_SKILL_DIRS, "skills")  # R16: в клоне ядра скиллы лежат в `skills/`, в установке — как в проекте»: справка ищет скиллы клона ядра в каталоге `skills/`.
- `tools/step_help.py:136` «return Path(__file__).resolve().with_name(VERSION_FILE).read_text(encoding="utf-8-sig").strip() or None»: файл версии — рядом с `step_help.py`.

Исходник запускают на месте документы проекта, тесты ядра и тесты плагина; правило архивации зовёт установленную копию.

- `CLAUDE.md:33` «`tools/journal.py render-html` из шаблона `tools/playground-template.html`.»: страница плана собирается исходным `journal.py`.
- `docs/repo-contract.md:106` «python tools/hooks/install_hooks.py --pre-commit»: хуки ставятся из исходника.
- `openspec/config.yaml:29` «до выбора синхронизации вызови `python .symphysis/tools/trace_graph.py freeze <имя>`»: правило архивации зовёт установленную копию графа.
- `tests/conftest.py:13` «sys.path.insert(0, str(ROOT / "tools"))»: тесты ядра импортируют код из `tools/`; путь `ROOT / "tools"` стоит ещё в 22 файлах `tests/`.
- `tests/test_flag_help.py:13` «TOOLS = sorted((ROOT / "tools").glob("*.py"))»: тест справки перебирает все скрипты одного каталога.
- `vscode/test/e2e/harness.mjs:18` «if (/^(journal.*\.(py|json)|step_help\.py|openspec_run\.py|playground-template\.html)$/.test(f)) fs.copyFileSync(path.join(SYMPHYSIS, "tools", f), path.join(tools, f));»: тесты плагина копируют ядро из `tools/` клона по именам; так же `vscode/test/e2e/demo.mjs:16`, `vscode/test/unit/fixture-project.ts:20`, `vscode/test/unit/step-help.test.ts:107`.

`<root>` — это `ROOT` выполняемой копии: у исходника корень репозитория, у установки `.symphysis`.

- `tools/journal_apply.py:33` «"""`<home>` и `~` — домашний каталог; `<root>` — ROOT (каталог над `tools/`), хвост»: `<root>` раскрывается в `ROOT` той копии, что выполняется.
- `tools/journal_apply.py:36` «return (ROOT / value[len("<root>"):].lstrip("/\\")).resolve()»: хвост после `<root>` разрешается от `ROOT`.
- `tools/journal-roots.json:2` «"docs/": "<root>/docs",»: файл корней исходника написан от корня репозитория — `<root>` здесь репозиторий.
- `vscode/test/unit/fixture-project.ts:23` «fs.writeFileSync(path.join(tools, "journal-roots.json"), JSON.stringify({ "": "<root>/.." }), "utf8");»: у установленной копии `<root>` — `.symphysis`, проект — `<root>/..`.
- `tools/symphysis_config.py:148` «"""Корень проекта без параметра: пустой префикс файла корней (у установленной копии это проект»: настройки различают корень проекта и `ROOT` установки через файл корней.

Связка с выбранным вариантом A — что он задевает, без выбора:

- При модулях первого уровня (F-17 A) `tools/journal_model.py:21` даёт `ROOT` = корень репозитория и из каталога модуля: `<root>` исходника не меняется.
- «Рядом с кодом» совпадает в обеих раскладках для файлов, которые установка кладёт в `.symphysis/tools/`: шаблон (`tools/journal_render.py:21`), файл версии (`tools/step_help.py:136`), `journal.py` для пересборки (`tools/journal_cli.py:170`). Схема журнала лежит в установке в `.symphysis/docs/` (`tools/journal_model.py:22`) — у неё «рядом с кодом» в исходнике и путь в установке расходятся.
- Файл корней исходника (`tools/journal_apply.py:27`, `tools/journal-roots.json:2`) — файл разработки этого репозитория, не модуля: «рядом с кодом» его не найдёт.
- Скиллы клона в `skills/` (`tools/step_help.py:279`) при скиллах в модулях (F-18 A) по этому пути не найдутся.
- Точки запуска: `CLAUDE.md:33`, тесты ядра (`tests/conftest.py:13`, 23 файла с `ROOT / "tools"`) и четыре места плагина называют `tools/`; хуки (`docs/repo-contract.md:106`) остаются в `tools/hooks/`; правило архивации (`openspec/config.yaml:29`) зовёт установку и раскладкой исходника не задето.
