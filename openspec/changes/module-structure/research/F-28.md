# F-28 · Как схема становится модулем, если её каталог задаёт OpenSpec?

## Найдено

Форк читает из каталога схемы только `schema.yaml` и шаблоны по имени; лишний `README.md` вывода не меняет.

- `upstream/openspec/src/core/artifact-graph/resolver.ts:214` «const schemaPath = path.join(schemaDir, 'schema.yaml');»: схему форк берёт из одного файла каталога.
- `upstream/openspec/src/core/artifact-graph/instruction-loader.ts:272` «const templatesDir = path.join(schemaDir, 'templates');»: шаблоны артефактов — только из `templates/`.
- `upstream/openspec/src/core/artifact-graph/instruction-loader.ts:273` «const templatePathOnDisk = path.join(templatesDir, templatePath);»: шаблон берётся по имени, а не перебором каталога.
- `openspec/changes/module-structure/research/F-28-probe/diff.txt:1` «diff without-readme.txt with-readme.txt: 0 строк»: с `README.md` в каталоге схемы вывод `openspec schemas`, `status` и `instructions` тот же, что без него.
- `openspec/changes/module-structure/research/F-28-probe/with-readme.txt:8` «symphysis (project)»: с `README.md` схема по-прежнему находится как схема проекта.
- `openspec/schemas/symphysis/steps.md:1` «# Тексты шагов схемы symphysis»: в каталоге схемы уже лежит файл, который форк не читает.

Каталог схемы уходит к пользователю целиком, без фильтра, и целиком сверяется `check`.

- `installer/scripts/sync-payload.js:9` «const DIRS = ["openspec/schemas/symphysis"];»: payload берёт каталог схемы целиком.
- `installer/lib/install.js:162` «copyTree(res, root, path.join(payloadDir, "openspec", "schemas", "symphysis"), t.schemaDir, force, () => true, { schemaDir: t.schemaDir });»: установка копирует каталог схемы с фильтром `() => true` — любой файл.
- `installer/lib/check.js:94` «const schemaSrc = path.join(payloadDir, "openspec", "schemas", "symphysis");»: `check` перебирает каждый файл каталога схемы payload.
- `installer/lib/check.js:97` «if (!fs.existsSync(to)) findings.push(`${rel(root, to)}: нет файла`);»: файл каталога схемы, которого нет в проекте, `check` называет расхождением.
- `installer/test/check.test.js:626` «assert.ok(r.findings.includes("схема: байты отличаются от payload: openspec/schemas/symphysis/steps.md"), JSON.stringify(r.findings));»: сверка байт уже покрывает файл каталога схемы, который не `schema.yaml`.

`openspec/config.symphysis.yaml` идёт в payload отдельным путём; инсталлятор и тесты знают этот путь, форк файл не читает.

- `installer/scripts/sync-payload.js:11` «"openspec/config.symphysis.yaml",»: в payload файл идёт отдельной строкой списка, не каталогом схемы.
- `installer/lib/install.js:189` «const oursBytes = fs.readFileSync(path.join(payloadDir, "openspec", "config.symphysis.yaml"));»: инсталлятор читает его по этому пути и сливает с `openspec/config.yaml` проекта.
- `installer/test/install.test.js:89` «const ours = fs.readFileSync(path.join(payloadDir, "openspec", "config.symphysis.yaml"), "utf8");»: тест инсталлятора знает тот же путь.
- `installer/test/payload.test.js:13` «"openspec/config.symphysis.yaml",»: тест состава payload называет файл отдельной строкой.

Если файл ляжет в `openspec/schemas/symphysis/`: `copyTree` строки `installer/lib/install.js:162` скопирует его в каталог схемы проекта как обычный файл, а чтение `installer/lib/install.js:189` и тесты `installer/test/install.test.js:89`, `installer/test/payload.test.js:13` укажут на прежний путь. Форк в каталоге схемы читает только `schema.yaml` и `templates/`.

## Проба

- Условия: копия `openspec/config.yaml`, `openspec/schemas/` и `openspec/changes/module-structure/` во временный каталог; форк `openspec` из `PATH`, `OPENSPEC_TELEMETRY=0`; вызовы `openspec schemas`, `openspec status --change module-structure`, `openspec instructions decisions --change module-structure` — сначала без `README.md`, затем с `README.md` (frontmatter `name`, `kind` и заголовок) в `openspec/schemas/symphysis/`. Из вывода фильтром `sed '/^- /d'` снят спиннер; фильтр снимает и строки списков — одинаково в обоих выводах. Путь временного каталога заменён на `<временный каталог>`.
- След: `research/F-28-probe/without-readme.txt`, `research/F-28-probe/with-readme.txt`, `research/F-28-probe/diff.txt`
