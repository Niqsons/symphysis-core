# Security

| Пункт | Применимо / неприменимо — причина | Чем проверено |
| --- | --- | --- |
| Инъекции через содержимое файлов | применимо — требование `module-declaration` «README модуля несёт имя и род во frontmatter»: тест структуры разбирает frontmatter README. Содержимое README — данные: разбор только двух скалярных полей `name` и `kind`, без загрузчика YAML, исполняющего теги | тест структуры читает frontmatter безопасным разбором и красный на теге YAML (задача `tasks`); сценарий «README без frontmatter» |
| Пути с `../` | применимо — требования `module-declaration` «README модуля описывает вложенные каталоги первого уровня» и «README модуля не называет каталог, которого нет»: ссылка README вида `../соседний/` ведёт за каталог модуля и не должна засчитываться его вложенным каталогом | тест структуры нормализует путь ссылки и засчитывает только каталоги внутри модуля (задача `tasks`); сценарии «Каталог появился без описания», «Ссылка на удалённый каталог» |
| Токены и срок их жизни | неприменимо — изменение переносит файлы и пишет README, токенов не вводит, не хранит и не передаёт | чтение `proposal.md` и `specs/`: ни одно требование не называет токен, ключ или учётные данные |
| Права | неприменимо — изменение не меняет, кто и куда пишет: установка пишет те же `.symphysis/` и `openspec/schemas/symphysis/` (F-19), тест структуры только читает дерево | чтение `specs/project-installer/spec.md` и `specs/repository-layout/spec.md`; сценарий «Установка без README схемы» |
| Бинарные файлы | применимо — требование `repository-layout` «Общий файл не копируется в модули»: тест сравнивает файлы модулей, среди них бинарные и большие (`media/icon.svg`, сборки страниц) | тест структуры считает хеш по байтам, без декодирования текста (задача `tasks`); сценарий «Копия в двух модулях» |
| Чувствительные данные в журнале, артефактах и журналах прогона | применимо — требования `repository-layout` «README корня называет каждый каталог первого уровня» и `module-declaration` «README модуля описывает вложенные каталоги первого уровня»: README корня и модулей — публикуемые тексты, в них не должно быть абсолютных путей машины разработчика и имён из рабочих задач (парковка F-59) | гейт имён `check_names.py` хука `tools/hooks/gate_hook.py` на каждом коммите; чтение README при ревью изменения |
| Состав поставки: файлы разработки уходят пользователю | применимо — требования `repository-layout` «Тесты модулей не уходят пользователю» и `project-installer` «README модуля схемы в проект не ставится» | тест состава payload и тест упаковки; сценарии «Тесты модуля схемы», «Установка без README схемы», «Сверка не ждёт README» |
