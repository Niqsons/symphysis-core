# Proposal

## Why

Владелец принял определения компонента и модуля (F-02) и описание модуля в репозитории (F-03): модуль — каталог с README, файл принадлежит одному модулю. Репозитории symphysis этому не соответствуют (F-04): README есть только у `installer/`, модули ядра лежат вперемешку в `tools/` и `skills/`, `journal_render.py` стоит в двух модулях. Критерий готовности — F-01; в объёме оба компонента, ядро и плагин (F-29). Совместимость с прежними установками не держится (F-14, F-15).

## What Changes

- Ядро делится на модули — каталоги первого уровня рядом с `installer/` (F-17); состав модулей, скиллы и водители в модуле своей механики — F-18; фасад CLI `journal.py` — отдельный технический модуль (F-33); корни улик и поиск цитат вместе с `ROOT` — технический модуль (F-34); общие файлы скиллов — F-35. Делимые файлы `journal_render.py` и `journal_apply.py` режутся по функциям (F-27).
- Плагин делится на модули в `src/<модуль>/` (F-31) с добавленными модулями для файлов, не вошедших в первый список (F-43); циклы типов между `protocol`, `search` и `scheme` снимаются (F-44).
- У каждого модуля обоих репозиториев — README с именем и родом во frontmatter, описанием и вложенными каталогами первого уровня ссылками (F-16, F-21, F-39).
- README корня каждого репозитория описывает компонент и каждый каталог первого уровня — модуль или контур разработки (F-22); в плагине корень освобождается под README репозитория, README пакета — отдельный файл (F-38).
- Тесты модуля живут в его каталоге (F-23); тест структуры в каждом репозитории сверяет README с файлами (F-25).
- Установка остаётся плоской: `.symphysis/tools/` и `.symphysis/docs/`, номер контракта с плагином прежний (F-19); код находит свои файлы рядом с собой (F-20, F-40, F-41); схема журнала в установке переезжает в `.symphysis/tools/` (F-41).
- Модуль схемы: README каталога схемы к пользователю не уходит (F-36), `config.symphysis.yaml` переезжает в каталог схемы (F-37).
- Справка о шаге находит скиллы клона ядра в каталогах модулей (F-42).
- Требования мастер-спек называют установленный путь или имя скрипта без каталога исходника (F-26).
- **BREAKING** для контура разработки: каталога исходников `tools/` с кодом ядра больше нет — тесты плагина, берущие ядро из `tools/` клона, перестают его находить (F-09), а настройка плагина `symphysis.toolsPath`, указывающая на `<клон>/tools`, — тоже; настройка на `<клон>` находит ядро через установку клона в себя (F-45); `tools/` остаётся каталогом инструментов разработки (F-22). Установленные проекты переустанавливаются (F-14, F-15).

## Capabilities

### New Capabilities

- `module-declaration`: как модуль объявляет себя — README каталога модуля с именем и родом во frontmatter, описанием и вложенными каталогами первого уровня ссылками (F-03, F-21, F-39).
- `repository-layout`: как устроен корень репозитория — README корня называет каждый каталог первого уровня как модуль или контур разработки, файл принадлежит одному модулю, тесты модуля лежат в его каталоге, тест структуры в каждом репозитории сверяет README с файлами (F-22, F-23, F-25, F-38).

### Modified Capabilities

- `decision-viewer`: требования «Просмотрщик — один HTML из своего шаблона с тремя режимами», «`render-html` встраивает снимок справки, сбой страницу не роняет», «Скилл просмотрщика знает о внесении кнопкой» называют шаблон, скрипт справки и скилл без каталога исходника (F-26).
- `step-help`: требования «Скрипт считает текущий шаг и чей ход» и «Справка не становится гейтом и не меняет файлы» (сценарий «Скиллы о скрипте не знают») называют скрипт и скиллы без каталога исходника (F-26).
- `trace-graph`: требование «Граф собирается из файлов изменения» называет скрипт графа без каталога исходника (F-26).
- `requirement-probes`: требование «Текст пробы объясняет задачу подробнее» называет скилл пробы краёв без каталога исходника (F-26).
- `skill-transfer`: требование «Скилл несёт копию источника с copyright notice и перечень смысловых отличий» называет скиллы без каталога `skills/` (F-26).
- `plugin-core-contract`: требование «Заданный `SYMPHYSIS_ROOT` без ядра — падение, а не пропуск» опознаёт ядро клона не по `tools/journal.py` (F-09, F-26).
- `project-installer`: новое требование — README модуля схемы в проект не ставится (F-36).

## Impact

- Ядро: перенос `tools/*.py`, `tools/playground-template.html`, `docs/journal.schema.json`, `skills/`, `agents/`, `tests/` по модулям (F-17, F-18, F-23, F-33–F-35, F-41); `installer/scripts/sync-payload.js` собирает payload из модулей с прежними путями установки, пропускает README схемы, берёт `config.symphysis.yaml` и схему журнала по новым местам (F-19, F-36, F-37, F-41); точки входа и `tests/conftest.py` находят каталоги модулей (F-20); `tools/step_help.py` ищет скиллы клона в модулях (F-42); `pytest.ini` (F-23); README корня и модулей (F-21, F-22); пути исходников в `CLAUDE.md`, `docs/GUIDE.md`, `docs/skills-canon.md` (F-17, F-18); хуки гейта имён и `tools/allowed-*.txt` не переезжают (F-22).
- Плагин `symphysis-vscode`: перенос `src/` по модулям (F-31, F-43, F-44), точки входа `build.mjs`, `--readme-path` в `package.mjs`, `.vscodeignore` и юнит-тест `test/unit/package-readme.test.ts` (F-38), копирование ядра в четырёх тестах (F-09); коммиты плагина несут `Needs:` на коммиты ядра (F-29). Номер контракта не меняется (F-19).
- Улики прежних журналов с путями `tools/…` и `vscode/src/…` остаются как есть (F-24).
- Установка в самом ядре переустанавливается `symphysis install --force` (F-14).
