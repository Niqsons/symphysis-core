## Методика

- Из корня ядра выполняется `python3.13 -X utf8 -B -m pytest -p no:cacheprovider -vv -ra --color=no --basetemp=<каталог>/pytest --junitxml=<каталог>/results.xml`. `-n 12` берётся из действующего `pytest.ini`. TAP вложенного `node --test` пишется в отдельный файл через `NODE_OPTIONS`.
- Из корня VS Code выполняется `npm test` через установленный npm CLI. Эта команда включает сборку unit-тестов. Повтор со штатным репортёром Node использует обычный для плагина Python 3.14.0 с PyYAML 6.0.3. Выпускной `e2e:vsix` относится к отдельной проверке полного режима.
- Каждая команда получает отдельные `TEMP`, `TMP` и `TMPDIR`. Замер длительности включает подготовку внутри команды. Дочерние процессы измеряются выборочно примерно раз в две секунды, поэтому пики являются нижней оценкой. Остатки процессов прогона и профилей просмотрщика проверяются после выхода и через три секунды.
- Предельное ожидание команды — 900 секунд. Время ожидания внутри тестов учитывается отдельно по результатам и диагностике.

## Наблюдения

Полный pytest на локальной правке занял 660,03 с. Прошли 2187 тестов pytest, упали 2, пропущены 3. Вложенный запуск инсталлятора прошёл 560 из 560 тестов за 524,60 с. Из 84 браузерных тестов двух файлов прошли 82, включая сценарий с шестью драйверами. В изолированной серии F-11 измерялся один файл с 79 тестами.

`test_panel_starts_below_a_wrapped_header` и `test_switching_keeps_the_place` завершились ошибкой удаления профиля через 20 с. В обоих случаях Chrome удерживал `lockfile` с ошибкой `EBUSY`. Через три секунды после завершения pytest остались два каталога профилей. Процессы Chrome с путями этих профилей к тому времени отсутствовали.

Первый замер процессов включил шесть процессов AMD и консоли, созданных до старта pytest. Это ложные совпадения при повторном использовании PID предка. Перед двумя следующими замерами добавлена сверка времени создания процесса и родителя. Пик всех потомков первого замера приблизительный. Пик браузерных процессов — 95, зарегистрировано 12 воркеров xdist.

В случае общей настройки pytest прошёл за 632,64 с, в совместном случае — за 634,82 с. В каждом прошли 2189 тестов pytest, включая все 84 браузерных, и 560 тестов инсталлятора. Через три секунды после выхода в обоих случаях не обнаружено процессов прогона и профилей. Все три прогона pytest собрали те же 2192 случая, включая обёртку инсталлятора. Состав 560 тестов внутри инсталлятора тоже совпал.

Во всех трёх запусках пропущен `test_check_plan_journal_all_found` из-за отсутствующего корня улик `md4h/`. Тесты `test_build_on_this_very_change_gives_nodes_of_every_kind` и `test_this_very_change_has_links_of_every_kind_of_this_portion` пропущены, поскольку изменение `trace-graph` уже в архиве.

В первом замере VS Code было 671 прохождение, 6 падений и 0 пропусков за 39,48 с. Общая переменная `NODE_OPTIONS` переключила вложенный тест соседнего клона на TAP, хотя он проверяет строки штатного репортёра. Ещё пять отказов пришли из тестов поиска Python: они получили путь к исполняемому файлу Microsoft Store.

Первый повтор со штатным репортёром и виртуальной средой Python 3.13 остановлен через 221,20 с. Вызовы Python через её Windows launcher выполнялись десятки секунд, один тест завершился ошибкой, итогового счётчика нет. После остановки не обнаружено процессов прогона и профилей. Повтор со штатным Python 3.14 прошёл все 677 тестов. Оба диагностических запуска сохранены отдельно.
