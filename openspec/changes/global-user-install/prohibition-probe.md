# Проба запретов: global-user-install

По каждому требованию рассмотрены продуктовые и инженерные превращения. Инженерная корректность (пустой ввод, повтор, гонка, неверный путь исполнения) отсеяна в пробу краёв/опись. Общий канон путей и полномочий вынесен отдельно в ИБ. Новых особенных продуктовых запретов сверх принятых решений не оставлено.

- client-installation/Установленные скиллы обнаруживаются выбранным клиентом: скрыть часть набора и объявить один проверенный клиент доказательством всех; оба исхода прямо запрещены нормой; новых кандидатов запрета нет.
- client-installation/Поддерживаемые агенты исполняют скилл в нативном формате: считать чужой preload загрузкой skill; норма это прямо исключает; полномочия/инъекции вынесены в канон; новых кандидатов запрета нет; канон — F-19 → security.md.
- client-installation/Проверка различает наличие файлов и готовность клиента: выдать скопированные файлы за обнаружение моделью; это уже MUST NOT и отдельный сценарий; новых кандидатов запрета нет.
- client-installation/Нативные коллизии смешанной установки остаются пользователю: автоматически исправлять discovery другого клиента; F-13 и сама норма запрещают такой исход; новых кандидатов запрета нет.
- decision-viewer/Ресурсы страницы берутся из выбранной поставки: подтянуть ресурсы другой поставки и незаметно сменить scope; запрет и два сценария уже есть; новых кандидатов запрета нет.
- decision-viewer/Снимок справки global runtime относится к store журнала: показать сведения не того store как результат текущего; норма и сценарий запрещают подмену; новых кандидатов запрета нет.
- decision-viewer/Ссылки на скиллы страницы используют выбранную поставку: под видом ссылки уйти к другой поставке или сетевому ресурсу; ограничения и сценарий уже названы; новых кандидатов запрета нет.
- decision-viewer/Общий runtime не объединяет состояние страниц разных store: перенести невнесённое слово в чужой журнал; принадлежность и сохранение состояния прямо определены; новых кандидатов запрета нет.
- onboarding-guide/Руководство различает local и global установки: навязать global как обязательный для local или назвать CLI полной установкой; это исключено текстом; новых кандидатов запрета нет.
- onboarding-guide/Руководство ведёт клонированный store до архивации: обещать флоу без указания store и места артефактов; оба сценария требуют эту информацию; новых кандидатов запрета нет.
- onboarding-guide/Руководство разделяет обновление scope и смену режима: обещать автоматическую миграцию всех проектов/менеджер версий; ограничения явно названы; новых кандидатов запрета нет.
- onboarding-guide/Руководство описывает явную миграцию и границу смешанной установки: назвать resolver гарантией native priority; сценарий mixed и текст исключают такое обещание; новых кандидатов запрета нет.
- plugin-core-contract/Контракт ядра предоставляет единое разрешение поставки для хостов: вынудить хост независимо угадывать другую поставку; требование общего resolver исключает это; новых кандидатов запрета нет.
- plugin-core-contract/Разрешение runtime не меняет рабочий store вызовов хоста: использовать каталог runtime как cwd данных; норма сохраняет корень выбранного store; новых кандидатов запрета нет.
- plugin-core-contract/Контракт разрешения сообщает несовместимость выбранной поставки: выдать несовместимость за пустой журнал; это запрещено конкретно, ошибки остаются видимыми; новых кандидатов запрета нет.
- plugin-core-contract/Контракт сохраняет проектную принадлежность черновиков: сместить черновики/курсоры пользователя в общий runtime; это прямо запрещено нормой; новых кандидатов запрета нет.
- project-installer/Local остаётся самостоятельной полной установкой: превратить local в устаревшую или неполную установку; прямой запрет и сценарий без global; новых кандидатов запрета нет.
- project-installer/Global-инициализация настраивает выбранный store отдельно от runtime: незаметно создать второй planning root или скопировать runtime в global-store; оба исхода исключены; новых кандидатов запрета нет.
- project-installer/Global-инициализация сохраняет проектное состояние: перенести личные данные в общую поставку или другой store; сохранение и разделение прямо описаны; новых кандидатов запрета нет.
- project-installer/Проверка global не требует локальной копии runtime: исправлять проект при check или ставить local по ошибке global; оба сценария сохраняют read-only проверку; новых кандидатов запрета нет.
- runtime-resolution/Dispatcher и хосты используют единый выбор поставки: развести CLI и хост на разные runtime; это запрещённый исход единого выбора; новых кандидатов запрета нет.
- runtime-resolution/Resolver предпочитает local при наличии обеих установок: включить смешанную поддержку под видом fallback; норма и сценарий не разрешают global ресурс для local; новых кандидатов запрета нет.
- runtime-resolution/Ресурсы принадлежат выбранной поставке: подменить отсутствующий ресурс другой поставкой и выдать его своим; это уже прямой MUST NOT; новых кандидатов запрета нет.
- runtime-resolution/Расположение runtime не определяет рабочий store: превратить каталог runtime в общий корень чтения; это запрещено нормой; обход путей вынесен в канон; новых кандидатов запрета нет; канон — F-18 → security.md.
- runtime-resolution/Global-вызов проверяет совместимость store: тихо мигрировать данные или подобрать другую версию; оба исхода запрещены; отсутствие декларации — край F-15; новых кандидатов запрета нет.
- step-help/Тексты шагов лежат в `steps.md`, раздел на шаг: потерять тексты с global и назвать это отсутствием текста у store; MODIFIED покрывает выбранную поставку; новых кандидатов запрета нет.
- step-help/У шага есть поле `skills`: выдать относительный путь за доказательство native выбора; границу дополнительно определяет S5; новых кандидатов запрета нет.
- step-help/Каталог установки задаётся необязательным аргументом: аргументом справки переключить runtime/store; запрет и отдельный сценарий уже есть; новых кандидатов запрета нет.
- step-help/Источники справки принадлежат выбранной поставке: считать общее хранилище текстов общим состоянием двух store; конкретный сценарий исключает это; новых кандидатов запрета нет.
- step-help/Разрешение скиллов справкой не меняет нативную discovery клиента: переписать настройки клиента из операции справки; прямой запрет и сценарий уже есть; новых кандидатов запрета нет.
- user-installation/Пользовательская установка содержит общий продукт: выпустить global, который тайно требует проектную копию runtime; норма требует достаточности общей поставки; новых кандидатов запрета нет.
- user-installation/Local и global являются самостоятельными режимами: навязать совместную установку для работоспособности любого режима; прямой SHALL NOT; новых кандидатов запрета нет.
- user-installation/У пользователя одна активная global-поставка: навязать пользователю менеджер версий или переименовать runtime каждого store в global; это исключено одним active; новых кандидатов запрета нет.
- user-installation/Установка сохраняет границы собственных файлов: перезаписать пользовательские/чужие файлы и назвать обновлением; явный MUST NOT, область путей вынесена в канон; новых кандидатов запрета нет; канон — F-17 → security.md.
- user-installation/Смена режима выполняется явно для выбранного store: мигрировать другие store либо чинить mixed без отдельного действия; прямой запрет; изменение плана — край F-16; новых кандидатов запрета нет.

Дополнительно проверялось предполагаемое автоматическое смешение глобальных Claude/OpenCode agents: оно не подтверждено проверенными исходниками OpenCode 2.2.5. Compatibility discovery относится к skills, agent plugin читает config entries; этот ложный кандидат не вынесен человеку. Различие нативных форматов уже покрывает C2.
