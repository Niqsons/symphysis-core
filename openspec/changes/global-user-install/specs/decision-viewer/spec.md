## ADDED Requirements

### Requirement: Ресурсы страницы берутся из выбранной поставки
`render-html` SHALL брать шаблон, справочные ресурсы и mermaid из одной поставки, выбранной resolver symphysis для рабочего store. В global-режиме отсутствие проектной копии runtime SHALL NOT само по себе лишать страницу рисунка схемы. Границы local/global и local-приоритет resolver SHALL сохраняться; ресурсы другой поставки SHALL NOT примешиваться автоматически (F-10, F-13).

#### Scenario: Глобальная установка без локального mermaid
- **GIVEN** store с `scheme.md`, совместимая global-поставка с mermaid и отсутствие local runtime в store
- **WHEN** для журнала этого store собирается и открывается HTML-страница
- **THEN** доступны рисунок схемы, оба предметных режима, обе раскладки решений и промпт возврата; проектная копия runtime для этого не требуется

#### Scenario: Отсутствующий ресурс не подменяется другой поставкой
- **GIVEN** выбранная local-поставка без файла mermaid и global-поставка с ним
- **WHEN** собирается страница журнала выбранного store
- **THEN** выбранной остаётся local; схема показана текстом по прежнему правилу, mermaid из global автоматически не используется

### Requirement: Снимок справки global runtime относится к store журнала
При общем runtime снимок справки SHALL рассчитываться для store, определённого по журналу, и пользоваться ресурсами выбранной для него поставки. Время снятия, команда пересборки и данные шага SHALL относиться к этому store. Каталог runtime и каталог вызова другого проекта SHALL NOT подменять store журнала (F-10).

#### Scenario: Общий runtime обслуживает журнал другого store
- **GIVEN** два store с одноимёнными изменениями, одна global-поставка и вызов из второго store для журнала первого
- **WHEN** `render-html` встраивает снимок справки
- **THEN** шаг, файлы и команда пересборки относятся к первому store; расположение runtime не меняет этот выбор

### Requirement: Ссылки на скиллы страницы используют выбранную поставку
При global-установке справка страницы SHALL разрешать названные скиллы в выбранной поставке и давать доступ к найденным телам без обязательной проектной копии. Ненайденный скилл SHALL оставаться ненайденным, а не связываться с другой поставкой. Разрешение ресурсов SHALL сохранять запрет абсолютных путей в файле страницы и сетевых запросов (F-10, F-13).

#### Scenario: Скилл находится только в global-поставке
- **GIVEN** store без local runtime, выбранная global-поставка содержит названный в тексте шага скилл
- **WHEN** человек открывает справку собранной страницы и переходит к этому скиллу
- **THEN** доступно тело скилла выбранной поставки; файлу страницы не требуется проектная копия runtime, в его содержимом нет абсолютного пути пользовательской установки

### Requirement: Общий runtime не объединяет состояние страниц разных store
Выбор global runtime SHALL NOT переносить журналы, ответы и черновики в пользовательскую поставку или объединять состояние разных store. Пересборка страницы после совместимого обновления runtime SHALL сохранять невнесённое слово человека для того же журнала; показ страницы другого store SHALL NOT выдавать его за слово для другого журнала (F-03, F-10, F-11).

#### Scenario: Одноимённые изменения не разделяют черновик
- **GIVEN** два store с одноимёнными изменениями используют одну global-поставку, для первого журнала сохранено невнесённое слово человека
- **WHEN** человек открывает страницу второго журнала
- **THEN** слово первого не появляется в промпте второго; первый черновик не перенесён в runtime и остаётся доступным у первого журнала

#### Scenario: Обновление runtime не очищает черновик страницы
- **GIVEN** у журнала сохранён черновик, а активная global-поставка совместимо обновлена
- **WHEN** страница этого журнала пересобрана и открыта снова
- **THEN** невнесённое слово доступно для того же журнала; обновление runtime само не меняет журнал и не вносит слово
