# Native-приёмка: фактическое состояние, 2026-11-09

Проверяется контур разработки на Windows, отдельно от требований к установке продукта.
Тестовая Windows-учётная запись — `test-user`; действующие настройки и credentials владельца
не используются как фикстуры. Временные данные клиентов находятся на X.

Владелец исключил Claude из этой приёмки: «На Claude работу не тестируем.»
OpenCode IDE отложен в отдельную сессию, B-64 и задачи 9.2–9.4 остаются открытыми.
Native OpenCode CLI проверяется через подписку OpenCode Go по отдельному разрешению владельца.

## Первая попытка модельной проверки OpenCode

Первый helper остановился на проверке метаданных local-сессии до отправки prompt:
`modelSubmitted=false`. Процесс завершён, все 390 исходных файлов и защищённые деревья
store/source/unprepared остались неизменными. Global по правилу последовательного запуска
не начинался. Результат не засчитывается как модельная проверка.

В квитанции записан только общий RuntimeError; точный этап по ней восстановить нельзя.
Следующий helper сохраняет именованные этапы, HTTP-статусы без тел ответов и отдельные
результаты проверки источника skill и параметров сессии. Исходная неуспешная квитанция
сохраняется. Схема поля model сверена с исходниками OpenCode 2.2.5; менять её наугад
оснований нет. Для чтения registry используется ожидание стабильных результатов,
как в уже прошедшем сборщике discovery.

Повтор с диагностикой остановился на `session_readback`: provider/ID модели, agent,
permissions и cwd совпали, а клиент добавил `variant`. Причина установлена в исходниках
[OpenCode 2.2.5](https://github.com/anomalyco/opencode/blob/v2.2.5/packages/core/src/session/info.ts#L24):
при чтении сессии отсутствующий variant становится строкой `default`. Строгое сравнение
всего словаря модели было ошибкой тестового helper. Исправление принимает только ожидаемые
provider/ID и документированный default, сохраняя остальные проверки. Этот повтор также
завершился до prompt, сохранил все 390 файлов и завершил собственный процесс.

Третья ревизия helper завершила **local и global успешно**. В каждой свежей сессии
`opencode-go/glm-5.2` выполнила `pwd`, `symphysis preflight --json`, native `skill` с ID
`symphysis-brainstorm` и `symphysis resource skill symphysis-brainstorm`.
Все восемь вызовов завершены; чужих инструментов или моделей в журнале нет.

Native tool result совпал с полным ожидаемым skill frame побайтово: 32 424 bytes local,
32 418 global. Вывод dispatcher — 32 878 bytes, одинаковый канонический SHA в двух режимах.
После результата skill последовал новый ответ модели, итоговый JSON соответствует
проверенным действиям; оба session idle outcome — succeeded. Все 390 исходных файлов
и защищённые деревья store/source/unprepared сохранены, оба собственных процесса завершены.
В global модель запускалась из pointer-source без проектной runtime-копии.

Исходящий запрос содержал только проверенные учебные данные и поставляемые инструкции.
Права ограничены native skill и тремя точными shell-командами; edit, execute/Code Mode,
subagent и прочие действия не разрешались. Обычная история клиента осталась в его собственном
защищённом тестовом хранилище; в отчёт экспортированы metadata и хеши, а не auth/raw debug.

## Native research-driver OpenCode: частичный результат

На двух новых независимых local/global стендах подготовлен change `native-driver-canary`
с синтетической парковкой F-01, включённым research driver и каноническими путями brief,
research и report. Это тестовые данные, не решение владельца. Подготовка: 12/12 CLI-проверок,
198 файлов снимка, полный names/hash gate и отдельная проверка публичного Mermaid.

Local-запуск выполнил настоящий native `subagent` с установленным research-driver.
Проверены связь parent/child, agent, модель, cwd и точное наследование permissions.
Дочерняя модель получила полные канонические driver doc и research skill, прочитала brief
и источник, записала ровно `research/F-01.md` и `briefs/.../report.md` и вернула полный
сохранённый отчёт родителю. 198 исходных файлов сохранены, процесс завершён.

Приёмка **не прошла**. Во второй находке закрывающая кавычка цитаты заменена обратной;
report при этом сообщает «Сигналы: нет». Это реальные дефекты результата. Ещё несколько
вызовов инструментов отклонены, а проверка параметров preflight не получила подтверждения.
Его вывод совпал по SHA с ожидаемыми 171 bytes ready для нужных store/scope/generation;
параметры команды и cwd ещё не восстановлены. По одним хешам параметров нельзя отличить
дефект вызова от слишком узкого сравнения каталога в helper. Нужна диагностика через API собственной сохранённой
сессии. Ошибки инструментов сами по себе не объявляются нарушением договора отчёта.

Global и отрицательная проверка неподготовленного store после local-отказа не запускались.
Исходная неуспешная квитанция и оба первоначальных артефакта сохранены; повторное
использование результата не превращает его в PASS. Привязка тела native agent к child
подтверждена registry/session и исходниками клиента; полная system wire trace не снималась.

### Диагностика и исправление результата

Ограниченный контроллер под test-user восстановил параметры собственной сессии через
native API. Первый вызов был `symphysis preflight` из канонического каталога change;
helper ошибочно допускал только cwd store. Отклонённые чтения касались каталога изменения
и `research/none.md`; отсутствие ещё не созданного F-01.md было отдельной штатной пробой.
Чтений за пределами проверенного стенда не зафиксировано.

По проверенному замечанию тот же водитель перечитал источник и артефакты, выполнил
`preflight --change native-driver-canary --json` до корректирующей записи и исправил
одну кавычку. Семь новых вызовов завершены успешно; полный вывод preflight совпал
побайтово с отдельным CLI-запуском и подтвердил store/scope/generation.
Все проверки артефактов прошли, report остался прежним; исходные 198 файлов сохранены.
Первоначальный FAIL не переписан в PASS: это отдельное подтверждённое исправление.

Отдельная модельная сессия на неподготовленном store выполнила один preflight и получила
blocked с диагностикой; записи не было, оба отчёта остались неизменны. Прямой CLI вернул
exit 2, а native PowerShell — exit 1. Его 739 bytes (JSON и notice exit 1) точно совпали
с результатом CLI и оболочки. Условие helper, требовавшее только native exit 2, было
слишком узким. Контроллер штатно закрыт, собственный процесс завершён.

### Найденный пробел F-23 и исправление реализации

Bare preflight не выбирает metadata существующего change по cwd. Новый изолированный
CLI-стенд воспроизвёл store default symphysis и change metadata spec-driven: bare вызов
из change cwd вернул exit 0/ready/symphysis, явный `--change` — exit 2/blocked/spec-driven
с `schema-source-conflict`. Все 74 файла пробы сохранены. Поэтому первоначальная запись
водителя после bare guard не подтверждает изменение-специфичную защиту.

`installer/lib/agent-renderers.js` теперь требует прочитать непустое строковое brief.change
и передать значение одним экранированным аргументом `preflight --change` до любой записи;
нет имени или команда отказала — возврат причины без записи. Текст brief не становится
командой или кодом. Общий проектный bare preflight сохраняет прежнюю семантику.

Регрессия сначала упала, после исправления 8/8 renderer-тестов прошли для пяти водителей
и трёх форматов. Полный installer Node-прогон: 549 passed, 5 failed, 0 skipped;
все пять config-ошибок вызваны отсутствующим явным путём к форку в очищенном test env.
Повтор config.test.js с закреплённым SYMPHYSIS_OPENSPEC: 8/8 passed, 0 skipped.
Исходные файлы между прогонами не менялись, все пять падений закрыты; покрыты 554 уникальных
теста. Единого полного зелёного прогона не было, исходная красная квитанция сохранена.
Исправленный пролог ещё требует свежего native-прогона, включая отказ по чужой metadata.

### Свежий native-прогон после исправления

Новый стенд содержит 209 исходных файлов и три случая: local, global и отдельный
store с несовместимой metadata изменения. Native registry всех трёх случаев
подтвердил точное исправленное тело research-driver. В отрицательном случае
завершились parent и настоящий child, но экспорт результата упал с AttributeError:
адаптер сборщика не передал константу DRIVER функции оформления строки subagent.
Причина отдельно воспроизведена offline без клиента и модельных запросов.

Повторная проверка целостности сохранила все 209 файлов; research/report не созданы.
Контроллер штатно остановлен, все три собственных процесса завершены. Само отсутствие
файлов ещё не доказывает правильный guard: итог по завершённой сессии будет извлечён
через native API исправленным сборщиком без повторного модельного запроса. Исходная
неуспешная квитанция сохранена; новая native-приёмка пока не засчитана.

### Восстановленный результат и проверка исправленного пролога

Исправленный сборщик восстановил только фиксированную пару собственных foreign-сессий
через native API, без нового prompt и без чтения DB. Перед регистрацией совпали agent,
model, cwd, точные permissions и parent ID. Получены полный brief, явный
`preflight --change native-driver-canary --json`, JSON blocked с диагностикой и
ненулевым native exit. Вызовов write/edit нет; оба выхода отсутствуют, 209 исходных
файлов сохранены. Квитанция проверяет наличие diagnostics, но не конкретный код:
точную причину несовместимости отдельно подтверждает ранее выполненная CLI-проба.

Свежие local и global водители затем успешно выполнили исследование. В обоих случаях
полные brief и source прочитаны, канонические driver doc и research skill получены;
успешный guard с явным change находится в более раннем сообщении, чем обе записи.
Цитаты, жанр, вопрос, дословная копия brief и форма обоих выходов прошли проверку;
сохранённый отчёт целиком вернулся родителю. Local выполнил 11 ожидаемых вызовов,
global — 10, без ошибок и сигналов. Global работал из pointer-source без проектного
runtime. В защищённых store/source/unprepared добавлены ровно два разрешённых выхода
для каждого режима; все 209 исходных файлов неизменны. Новые native caches за пределами
этих деревьев этим утверждением не перечисляются.

Повторы в fresh parent/child с оставленными готовыми выходами остановились на лимите
240 секунд. Guard, brief/source/resources получены, но были лишние отклонённые чтения
внутри публичного стенда; новых записей не было, прежние выходы побайтно сохранены.
Это самостоятельный непройденный сценарий повторного входа. Причина timeout не
установлена; последовательность «лишнее чтение вызвало задержку» журналом не доказана.
Для сравнения формы в одинаковом начальном состоянии сохранены квитанции и хешированные
копии выходов; после проверки точных собственных leaf-путей сняты только четыре
сгенерированных выхода. Все 209 исходных файлов, brief/source, carrier и код сохранены.
Контролируемые повторы с пустыми выходами завершились в обоих режимах: форма,
цитаты, guard до записей и полный возврат отчёта прошли. Для каждого режима есть
два завершённых запуска с тем же brief; у всех четырёх отчётов совпали пять разделов.
В каждом контролируемом повторе один лишний запрос чтения каталога был отклонён,
содержимое не получено. Это сохранённый сигнал соблюдения роли; `mandatoryPassed`
проверяет обязательные результаты и не означает отсутствие таких сигналов.
Непройденные повторы с готовыми выходами сохранены отдельно. Контроллер штатно
закрыт, три собственных сервера завершены, PID и lock отсутствуют; 209 файлов целы.

Отдельные native local/global проверки неподготовленного store прошли: каждая модель
вызвала ровно один preflight, получила blocked и завершилась без других инструментов.
Защищённые деревья и оба прежних отчёта не изменены; native exit 1 и его уведомление
распознаны отдельно от прямого CLI exit 2. Полный intent→archive этим не проверен.

### Независимая инфраструктурная CLI-матрица

На новом публичном seed Git-store и двух настоящих локальных клонах прошли **26/26
проверок**, 37 команд с ожидаемыми кодами выхода. Подтверждены global install без
неявного init, отказы до объявления store без записи, init/check обоих store,
pointer-source и маршрутизация нового change только в выбранный store, update preview
без записи и изоляция update A/B. Повтор install/init/update побайтно идемпотентен;
неподготовленный store и pointer сохранены, установлены восемь охраняемых workflow.
Исходники и Git-status ядра до/после каждого прогона совпали, финальный names gate — exit 0.

Это CLI-запуски текущего пользователя, без native клиента, модели или IDE. После падения
перенесённой копии Git до продуктовых действий использован read-only системный Git на C;
конфиги, клоны, runtime и временные данные остались на X. Красный результат сохранён.
Обновление той же версии 0.1.0 не выдано за миграцию между релизами; 10.5 целиком
остаётся открытой до полного пути change→archive с client logs.

В первом стенде некорректная slash-форма ComSpec вызвала создание пустых каталогов
в batch-пробах Python. Адресное A/B с тем же PATH воспроизвело причину: с обратными
слешами побочного эффекта нет. Исправлено только тестовое окружение. Новая CLI-матрица
повторила **26/26 проверок, 37 команд** с дополнительным контролем отсутствия этих
каталогов. Старые квитанции сохранены; код продукта не менялся.

Перед первым запуском отдельный публичный стенд полного workflow подготовлен: 42/42 CLI-проверки, 242
исходных файла по хешам, семь skills и восемь workflow-команд с точными телами,
два настоящих клона, drivers выключены явно. Intent и ответы тестовой персоны
не приписываются настоящему владельцу. На момент подготовки change и его будущие
результаты ещё не были созданы; дальнейший native-запуск описан ниже.

### Первый запуск полного workflow, 2026-11-10

В native OpenCode CLI модель получила два публичных входа тестовой персоны и
выполнила настоящие `opsx-new` и `opsx-continue` для intent. Native command API
вернул HTTP 204; сохранённые развёрнутые тела команд, выбранная модель и привязка
сессии совпали с проверенными носителями. Preflight и адресные status/instructions
предшествовали записи. Change создан только в выбранном store; `intent.md`
побайтно совпал с исходным файлом: 1737 байт, SHA-256
`eae0f8867e6c901c2a930e33db506a61e433fad8265f6436743b1547cbf34e42`.

Шаг decisions не завершён. Одна попытка прервана ошибкой наблюдения стенда:
открытый Root монитором `progress.json` мешал атомарной замене файла. Это отдельно
воспроизведено на синтетическом файле; даже share-delete не устранил блокировку
на используемом диске. После прекращения чтения активного progress две попытки
дошли до лимита 240 секунд без записи новых файлов. Причина этих timeout не
установлена. Все неуспешные квитанции сохранены отдельно от успешных.

Модель получила полный brainstorm skill, terms, journal-cli и шаблон журнала.
Запрос выдуманного `resource doc journal.schema.json`, чтения каталогов runtime
и дополнительные команды вне точного списка были отклонены без содержимого.
JSON-schema установлен среди tools; ресурс с таким doc-id не публикуется.
Это не доказывает, что именно отклонённые вызовы вызвали timeout.

Независимая сверка также нашла пропуск тестового стенда: обязательный на первом
круге `scheme.md` отсутствовал среди разрешённых записей. Это отдельный дефект

## Блокер Codex

Явная проба Windows MXC завершилась до выполнения синтетических read/write canary:
клиент сообщил, что механизм недоступен. Процесс завершён, fallback не использовался,
системные функции и ACL не менялись. Модель в этой пробе не запускалась.

Нельзя считать read-only или workspace-write доказательством запрета чтения вне стенда.
Полный Codex intent→archive остаётся непроверенным до подходящего ограниченного режима.
Отдельный запрос без файловых инструментов также не подготовлен: в штатном CLI/app-server
этой версии не найден подтверждённый запрет всех встроенных инструментов. Отключение shell
оставляет `apply_patch` при поддержке моделью. Запрет всех инструментов через Rust host
ToolPolicy не является обычным параметром установленного клиента. Основания — исходники
закреплённой версии: [сборка инструментов](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/core/src/tools/spec_plan.rs#L1427)
и [host ToolPolicy](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/ext/extension-api/src/tool_policy.rs#L6).
