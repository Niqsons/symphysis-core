# Spec Delta

## MODIFIED Requirements

### Requirement: `view-json` отдаёт номер контракта
Вывод `journal.py view-json` SHALL содержать номер контракта, целое число. Номер SHALL расти при смене контракта и SHALL NOT расти от нового поля (`docs/repo-contract.md`; журнал `decision-scheme`: F-08). Смена значения адресата `материалы` → `агент` — смена контракта: номер SHALL стать 4, коммит ядра называет смену в `Why:`, а плагин догоняет своим коммитом с `Needs:` на коммит ядра (F-03, F-04, F-09, F-10, F-19).

#### Scenario: Вывод содержит номер
- **GIVEN** годный `decisions.json`
- **WHEN** выполняется `journal.py view-json`
- **THEN** в выводе есть поле с номером контракта

#### Scenario: Новое поле номер не поднимает
- **GIVEN** журнал с полем `nodes` у записи
- **WHEN** выполняется `journal.py view-json`
- **THEN** номер контракта прежний, а поле `nodes` в выводе есть

#### Scenario: Новое значение адресата поднимает номер
- **GIVEN** ядро, в котором адресат парковки и записи — `агент`, а `материалы` читается только у старых журналов
- **WHEN** выполняется `journal.py view-json` и `step_help.py`
- **THEN** в обоих выводах `contract` равен 4; плагин с `EXPECTED_CONTRACT = 3` просит поставить новый `.vsix` и решений не вносит, пока его коммит с `Needs:` на коммит ядра не выпущен

## ADDED Requirements

### Requirement: Номер контракта не растёт без записи в договоре
`CONTRACT` MUST NOT быть выше наибольшего N в абзацах «С номера N» файла `docs/repo-contract.md`: смена номера без абзаца о ней — расхождение кода с договором двух репозиториев; проверяет тест, который читает файл и сравнивает числа (F-26).

#### Scenario: Номер выше последнего абзаца
<!-- F-26 -->
- **GIVEN** `CONTRACT = 4` в `journal_render.py`, а в `docs/repo-contract.md` последний абзац — «С номера 3 …»
- **WHEN** выполняется тест договора
- **THEN** тест красный и называет оба числа; с абзацем «С номера 4 …» — зелёный
