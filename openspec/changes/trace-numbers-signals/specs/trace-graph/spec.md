# Spec Delta

## MODIFIED Requirements

### Requirement: Скрипт сам разбирает спеки с номерами строк
Скрипт SHALL сам разбирать заголовки `### Requirement:`, `#### Scenario:` и секции дельты и SHALL знать номер строки каждого узла (F-40). Текст сценария SHALL браться без HTML-комментариев тем же правилом, что текст требования (F-03, F-26). Тест SHALL сверять счётчики разбора с `openspec show --json` на фикстурах, расхождение с OpenSpec даёт красный тест (F-14, F-40).

#### Scenario: Узел несёт пометку дельты
- **GIVEN** спека с секциями `## ADDED Requirements` и `## MODIFIED Requirements`
- **WHEN** скрипт собирает граф
- **THEN** каждое требование несёт пометку своей секции и номер строки заголовка

#### Scenario: Счётчики разошлись с OpenSpec
- **GIVEN** фикстура, где разбор скрипта и `openspec show --json` дают разное число сценариев
- **WHEN** идёт тест сверки
- **THEN** тест красный и называет фикстуру

#### Scenario: След проб после последнего сценария
- **GIVEN** требование, за последним сценарием которого стоят `<!-- проба краёв: … -->` и `<!-- проба запретов: … -->`
- **WHEN** скрипт разбирает спеку
- **THEN** текст сценария кончается его последней строкой THEN, комментарии в текст не входят, а маркер `<!-- F-NN -->` под заголовком сценария тоже не текст
<!-- проба краёв: форма=text, io, исходы: F-47 Dismiss -->
<!-- проба запретов: исходы: нет -->

### Requirement: Id читаемы, файл несёт версию формата
Узлы SHALL нести читаемые id: `req:capability/имя`, `scn:capability/требование/имя`, `rec:F-NN`, `task:N.M`, `cap:имя`, `sec:<текст пункта>`, `branch:<путь>:<строка>` (F-70, F-131). Файл SHALL нести `format: 2` — база мастер-спеки хранит ссылки строками (F-25) — и кандидат связи `source` (F-23, F-70). Снимок другой версии проверка SHALL отвергать строкой, называющей обе версии; снимки формата 1 в архиве не пересобираются (F-19, F-25).

#### Scenario: Одно имя в двух capability
- **GIVEN** требование с одним именем в двух capability
- **WHEN** скрипт собирает граф
- **THEN** это два узла с разными id

#### Scenario: Переименование меняет id
- **GIVEN** требование переименовано в спеке
- **WHEN** скрипт собирает граф
- **THEN** узел несёт новый id, старого в графе нет

#### Scenario: Две ветки одного механизма
- **GIVEN** две ветки одного механизма на разных строках файла
- **WHEN** скрипт собирает граф
- **THEN** это два узла `branch:` с разными id

#### Scenario: Снимок прежнего формата
- **GIVEN** `graph/req-graph.json` с `format: 1`
- **WHEN** идёт проверка файла графа
- **THEN** строка называет «формат 1, а скрипт читает 2», код выхода прежний
<!-- проба краёв: форма=numeric-range, text, io, исходы: нет -->
<!-- проба запретов: исходы: нет -->
