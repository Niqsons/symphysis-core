# Spec Delta

## Purpose
Отчёт сигналов графа: что он называет, как соединён с `openspec validate`, когда его показывают человеку и как записывается ответ на сигнал.

## ADDED Requirements

### Requirement: Одна команда отчитывается и за граф, и за validate
Скрипт графа SHALL сам запускать `openspec validate --json` и выводить его находки вместе с сигналами графа одним отчётом. Форк OpenSpec для этого SHALL NOT меняться (F-05, F-07, F-32).

#### Scenario: Находка validate в отчёте
- **GIVEN** требование без сценария
- **WHEN** скрипт собирает отчёт
- **THEN** отчёт несёт находку `openspec validate` рядом с сигналами графа

#### Scenario: Находок нет
- **GIVEN** изменение, где `openspec validate` чист и сигналов графа нет
- **WHEN** скрипт собирает отчёт
- **THEN** отчёт говорит, что сигналов нет, код 0

### Requirement: Сигналы не останавливают работу
Сигнал SHALL только называть зазор и SHALL NOT менять код выхода скрипта; решает человек: реализовать или принять (F-31).

#### Scenario: Отчёт с сигналами
- **GIVEN** изменение с требованием без задачи
- **WHEN** скрипт собирает отчёт
- **THEN** сигнал назван, код 0

### Requirement: Отчёт называет закрытый состав сигналов
Отчёт SHALL называть: критерий без требования; требование и сценарий без задачи; решение без требования и задачи; неоднозначное имя; неизвестное имя или номер; задачу ни к чему; след, отставший от журнала (F-64). Решение об объёме SHALL оставаться обычной строкой этого вида (F-65).

#### Scenario: Критерий без требования
- **GIVEN** факт `постановка`, на который не ссылается ни одно требование
- **WHEN** скрипт собирает отчёт
- **THEN** сигнал называет запись и цитату критерия

#### Scenario: Решение об объёме
- **GIVEN** решение об объёме работ, до которого не дошли ни требование, ни задача
- **WHEN** скрипт собирает отчёт
- **THEN** оно названо строкой вида «решение без требования и задачи», отдельной пометки у него нет

### Requirement: Шумные виды в отчёт не идут
Отчёт SHALL NOT называть: улику, разошедшуюся с файлом, она остаётся у `check`; сценарий и требование, перенесённые из мастера в MODIFIED; пункт security с известным именем или без имени; решение «Оставить как есть» (F-57, F-64).

#### Scenario: Улика разошлась
- **GIVEN** улика журнала, цитаты которой больше нет в файле
- **WHEN** скрипт собирает отчёт
- **THEN** строки о ней нет, `journal.py check` её называет

#### Scenario: MODIFIED несёт прежний сценарий
- **GIVEN** требование в MODIFIED со сценарием, который уже есть в мастер-спеке, и без задачи на него
- **WHEN** скрипт собирает отчёт
- **THEN** строки об этом сценарии нет

#### Scenario: Новый сценарий в MODIFIED
- **GIVEN** требование в MODIFIED со сценарием, которого в мастер-спеке нет, и без задачи на него
- **WHEN** скрипт собирает отчёт до `/opsx:sync`
- **THEN** сигнал называет этот сценарий

#### Scenario: Пункт security закрыт доводом
- **GIVEN** пункт security без имени требования, закрытый доводом
- **WHEN** скрипт собирает отчёт
- **THEN** строки о нём нет; пункт с неизвестным именем требования сигнал называет

### Requirement: Сигнал о решении следует его исходу
Запись с исходом Specify без сценария и запись с исходом Backstop без задачи SHALL давать сигнал, исходы Dismiss и Defer SHALL молчать (F-64). Связь Specify со сценарием SHALL считаться по точному совпадению с комментарием `<!-- F-NN -->` под заголовком сценария (F-45).

#### Scenario: Specify с комментарием
- **GIVEN** запись F-12 с исходом Specify и сценарий с `<!-- F-12 -->` под заголовком
- **WHEN** скрипт собирает отчёт
- **THEN** сигнала о F-12 нет

#### Scenario: Specify без комментария
- **GIVEN** запись F-12 с исходом Specify, сценария с её номером нет
- **WHEN** скрипт собирает отчёт
- **THEN** сигнал называет F-12

#### Scenario: Dismiss
- **GIVEN** запись с исходом Dismiss без требования и задачи
- **WHEN** скрипт собирает отчёт
- **THEN** строки о ней нет

### Requirement: Сигнал называет запись, снявшую исход
Рядом с сигналом «Specify без сценария» отчёт SHALL называть запись, у которой эта запись стоит в `depends_on`: вероятная причина, почему сценария нет (F-11, F-46). Этот случай SHALL проверяться фикстурой в тестах (F-69).

#### Scenario: Исход снят позже
- **GIVEN** запись F-12 с исходом Specify без сценария и решённая запись F-30 с `depends_on: [F-12]`
- **WHEN** скрипт собирает отчёт
- **THEN** строка о F-12 несёт «снято F-30?»

### Requirement: Отчёт показывается перед реализацией и в её конце
Инструкция `apply` SHALL велеть модели показать отчёт человеку перед первой задачей и в конце реализации, когда отмечена последняя задача (F-48, F-78).

#### Scenario: Перед первой задачей
- **GIVEN** изменение без отмеченных задач
- **WHEN** начинается `/opsx:apply`
- **THEN** человек видит отчёт до первой правки кода

#### Scenario: После последней задачи
- **GIVEN** отмечена последняя задача `tasks.md`
- **WHEN** модель заканчивает реализацию
- **THEN** человек видит отчёт на текущих файлах

### Requirement: Ответ на сигнал записывается в журнал
Ответ человека на сигнал SHALL быть записью журнала с префиксом `[сигнал]`, исходами Specify, Dismiss, Backstop, Defer и `outcome.kind: проба`. Запись SHALL заводиться только на сигнал, о котором человек решил что-то записать; скрипт SHALL находить её и этот сигнал больше не поднимать (F-30, F-47).

#### Scenario: Человек принял зазор
- **GIVEN** сигнал о требовании без задачи и запись `[сигнал]` об этом требовании с исходом Dismiss через `apply`
- **WHEN** скрипт собирает отчёт
- **THEN** этого сигнала в отчёте нет

#### Scenario: Человек ничего не записал
- **GIVEN** тот же сигнал и записи `[сигнал]` нет
- **WHEN** скрипт собирает отчёт
- **THEN** сигнал назван снова
