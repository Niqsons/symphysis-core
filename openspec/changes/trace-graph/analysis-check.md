# Сверка реализации с разбором

Разбор: `docs/analysis/requirements-traceability-graph-of-symphysis.md`. Он остаётся опорой как есть и не правится (F-56.A). Здесь по строке на каждый из 29 разделов (`##` и `###`): что реализовано, что отступило, что вне поставки (F-38), что не про реализацию. Реализовано значит «со ссылкой на место»: команда `tools/trace_graph.py`, файл, решение журнала `F-NN`; места проверены чтением кода и `--help` подкоманд, не по памяти.

Исходы:

- **реализовано** — где именно;
- **отступило** — от чего и каким решением журнала (`F-NN`, номер решения Т из разбора);
- **вне поставки** — F-38: снимок корня, сверка снимков, первичный сбор, связи между корнями, хранители, модули, вид в плагине, поле графа в `view-json`;
- **не про реализацию** — методика, замеры, вопросы без механики;
- **отступление без записи** — разбор описывает механику, реализация сделала иначе, записи журнала нет. Список таких мест в конце файла; записи заводит контроллер с владельцем;
- **расхождение с решением** — запись есть, реализация с ней расходится; отдельный раздел в конце файла.

Каждое место ниже стало развилкой для человека (F-56.A): пункты 1–5 — записи F-151–F-155. Решения владельца, 2026-11-06: F-151 A, F-152 A, F-153 A, F-154 B — отступление принято, правок нет; F-155 B — три строки в бэклоге ядра. Место в разборе дано строкой файла.

1. **Рёбра графа, которых нет в реализации.** Разбор рисует и перечисляет (диаграмма строки 94–114, таблица строки 128–133), граф их не строит: запись журнала зависит от записи (`depends_on`, строка 131, в коде только для подсказки «снято F-NN?» в отчёте); запись связана с узлом схемы (`nodes`, строка 130); запись опирается на файл кода (улика, строка 129), цитата критерия `intent.md` (строка 106); отчёт `research/F-NN.md` к записи (строка 109); ветка описи к кандидату журнала и к цитате кода (строки 103–104, 133; id ветки несёт `путь:строка`, но узла кода и связи нет). Связь требования с записью по следу пробы — не здесь, а в разделе «Расхождение с решением журнала» ниже: о ней запись есть. Спека `trace-graph` «Граф несёт связи артефактов с местом в файле» перечисляет семь связей без этих. Частично прикрывают F-64 и F-122 (улики остаются у `check`), но решения «эти связи в граф не входят» нет.
2. **Состав снимка.** Разбор называет в снимке «сигналы с исходами, вердикт атаки» (строки 308, 320, 364). Сигналы с исходами владелец отдал отчёту рядом со снимком: F-74.A, `graph/report.md` — это решено. Без записи остаётся вердикт атаки: его нет нигде в `graph/`. Поля `change`, `schema`, `state` из условной формы тоже не написаны: F-139 перечисляет поля снимка, но довода об отказе от этих трёх не даёт.
3. **Пустой граф без узла `change`.** Разбор (строки 266, 286–297): у только что созданного изменения один узел «изменение». Реализация и спека: граф пуст (сценарий «Только что созданное изменение»).
4. **Критерий без требования без решения рядом.** Разбор (строки 220, 238–239): отчёт ставит рядом с критерием решение, расхождение уже принято (`рядом: F-22 выбрано A «Оставить как есть»`). `graph_signals` печатает цитату критерия и место, решения рядом нет.
5. **Предложения Claude без решения владельца и без записи** (строки 687, 688, 690): метка доверия снимка («собран, не проверен», «проверен атакой», «устарел»); отложенная проверка (отказ от атаки при выпуске пишется как Defer); группировка и порядок сигналов по важности. В реализации ни одного нет. Слабее остальных пунктов: это предложения, но F-56.A требует запись на каждое отступление.

## Расхождение с решением журнала

Решение есть, реализация с ним расходится. Решение не меняется; расхождение — новая развилка для человека со ссылкой на решение.

1. **След пробы как связь требования с записью, F-82.B.** Разбор (строка 128) и вопрос F-82 исходят из того, что номер в следе пробы даёт связь `traces`. Владелец выбрал B: «две связи с разными `at` допустимы» — номер в тексте требования и номер в следе дают две связи. Граф даёт одну: `traces` строится только из текста требования (`tools/trace_graph.py`, `put_records`), `_requirement_body` комментарии отбрасывает, номера следа идут только в сигналы «след отстал» и «Specify без сценария». Спека `trace-graph` «Граф несёт связи артефактов с местом в файле» связи по следу тоже не называла. Решено F-156.A, 2026-11-06: связь по следу реализуется, спека называет след, задача 2.10.

- Раздел «Показ» разбора рисует `requirementDiagram` и `flowchart`. Реализован только `requirementDiagram` (F-54), это не отступление.
- Исходы в нескольких строках составные («реализовано; отступило; ...»), потому что разделы смешанные. В Т1–Т21 исход одиночный.
