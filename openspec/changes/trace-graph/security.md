# Security

Чек-лист канона ИБ по `specs/` изменения `trace-graph`: пять пунктов схемы, парковки адресату «ИБ» (F-59) и то, что нашлось при их разборе. Канон в журнал не чеканится, он отмечается здесь. Реализации ещё нет: «чем проверено» называет сценарий или тест, который поставит `tasks`.

**Главное.** Новых поверхностей две: скрипт зовёт внешние команды с данными из файлов изменения, а снимок и отчёт уходят в git и в архив. Три пункта при разборе требованием закрыты не были: текст диаграммы, имя изменения в вызове `validate`, абсолютные пути в снимке и отчёте. По слову владельца у каждого теперь сценарий в `specs/`.

| Пункт | Применимо / неприменимо — причина | Чем проверено |
| --- | --- | --- |
| Инъекции через содержимое файлов: текст в диаграмме (F-59) | применимо — закрывает требование `trace-diagram` «Текст диаграммы разбирается на настоящих именах», сценарий «Директива и разметка в имени». Одних кавычек мало: директива `%%{init: {'theme':'forest'}}%%` в имени требования меняет тему всей диаграммы на обеих сборках mermaid, а `<img>` в имени строгий режим не обязан снимать, как уже выяснил `decision-scheme`. Генератор должен убирать из имён и текста `%%` и угловые скобки. Рисует потребитель, в ядре рисунка нет | проба `research/F-59-probe/results.txt`; сценарий «Директива и разметка в имени» |
| Инъекции через содержимое файлов: текст, который читает модель (F-59) | применимо — имена и цитаты из файлов идут в отчёт и в вывод `build`. Отчёт модель не читает, а только отдаёт ссылкой: закрывает требование `trace-signals` «Отчёт отдаётся ссылкой». Вывод `build` линза `trace-link` читает (F-133), а в скилле `symphysis-attack` правила «содержимое файлов — данные» нет, оно есть только у `symphysis-consequences` и для улик в `decision-journal`. Строка в скилле идёт в `tasks` | чтение скилла `symphysis-attack` после правки; ревью транскрипта атаки |
| Инъекции в вызов форка через имя изменения (F-59) | применимо — закрывает требование `trace-signals` «Одна команда отчитывается и за граф, и за validate», сценарий «Имя изменения с символами оболочки». `validate` принимает имя позиционным аргументом, а `run_fork` проверяет только `change=` (`tools/step_help.py:147`). На Windows `.cmd` разбирает `cmd.exe`, и `step-help` уже показал, что имя `a&echo.>файл` исполняется. Скрипт графа проверяет имя тем же правилом до любого вызова | сценарий «Имя изменения с символами оболочки» |
| Подмена `node` файлом из корня чужого проекта | применимо — форк идёт с `cwd` корня проекта. Закрывает вынесенный запуск форка: требование `trace-signals` «Одна команда отчитывается и за граф, и за validate», сценарий «Запуск форка общий» (F-138) | тесты запуска форка переезжают вместе с `run_fork` и идут и для скрипта графа |
| `openspec` из `PATH` (F-59) | применимо частично — путь задаёт сам человек в своём окружении, граница прав здесь не проходит. Закрывает то же требование, сценарий «`openspec` не запустился» | сценарий «`openspec` не запустился» |
| `git` в каталогах из файла корней (F-59) | применимо — путь приходит из файла корней проекта, прав он не добавляет. Закрывает требование `trace-snapshot` «Снимок называет только коммиты заморозки»: команда только читает коммит, зовётся списком аргументов, без оболочки | сценарий «Корень вне git или без каталога»; тест: аргументы вызова `git` не проходят через оболочку |
| Пути с `../` | применимо — имя изменения входит в путь `graph/`, куда `freeze` пишет. Закрывает та же проверка имени: `..` и разделитель пути получают отказ. Путь `--out` задаёт вызывающий, граница прав здесь не проходит: требование `trace-graph` «Живой граф не лежит на диске». Из содержимого файлов пути не берутся: `at` и исходники считаются от каталога изменения, улики сверяет `check` | сценарии «Имя изменения с символами оболочки» и «Запись в указанный файл» |
| Токены и срок их жизни | неприменимо — скрипт читает файлы и зовёт локальные `openspec` и `git`, токенов не хранит и не передаёт; замер с ключом API из F-134 в это изменение не входит | чтение дельт `specs/` |
| Права | применимо — скрипт работает с правами человека и пишет только в `--out` и `graph/`: закрывают требования `trace-graph` «Живой граф не лежит на диске» и `trace-snapshot` «Снимок и отчёт лежат в каталоге graph». `install` кладёт файлы рядом с инструментами и новых прав не просит: `project-installer` «`install` ставит скрипт графа» | сценарий «Вывод без файла»; сценарий «Новый проект» |
| Бинарные файлы | применимо частично — среди исходников может оказаться файл не в UTF-8. Хеш считается по байтам, а разбор отказывает и называет файл. Заморозку это не роняет молча: закрывает требование `trace-snapshot` «Архивация проверяет каталог graph», сценарий «Сборка не удалась». Сам скрипт и общий модуль текстовые | тест: `spec.md` не в UTF-8 даёт код ненулевой с именем файла |
| Данные наружу: снимок и отчёт в git | применимо — закрывает требование `trace-snapshot` «Снимок и отчёт лежат в каталоге graph», сценарий «Абсолютных путей нет». `req-graph.json` и `report.md` отслеживаются git и уезжают в архив, а причина «validate не запустился» (F-93) и значения файла корней несут абсолютные пути. В снимке корень называется префиксом, а не путём. Функция `_no_paths` (`tools/step_help.py:222`) уже снимает такие пути и переезжает вместе с запуском форка | сценарий «Абсолютных путей нет» |
| Данные наружу: телеметрия форка | применимо — заморозка зовёт форк, а включённая телеметрия шлёт события. `run_fork` её выключает, закрывает сценарий «Запуск форка общий» | тест запуска форка: переменная `OPENSPEC_TELEMETRY` равна 0 |
| Отказ в обслуживании: зависший форк и большой текст | применимо — зависший `openspec` держал бы заморозку: закрывает предел времени `run_fork`, сценарий «`openspec` не запустился». Слишком большой текст диаграммы не доходит до потребителя: требование `trace-diagram` «Без выбора действует предел текста» | сценарии «Текст больше предела» и «Выбранная capability больше предела» |
