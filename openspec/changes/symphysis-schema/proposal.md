# Proposal

## Why

Конвейер проектирования на сильной модели нужен в рамке OpenSpec с механиками
GSD, а не как форк одного из них: рамка держит граф артефактов и состояние
в файлах, GSD даёт интервью, пробы и слой проверки (F-06, F-23, F-25).
Ванильный OpenSpec считает артефакт готовым по наличию файла (F-20) — гейт,
вызываемый дисциплиной исполнителя, не держит (F-02.D отвергнут). Решения
человека и улики без скрипта сверки теряются молча (F-12, F-27.B отвергнут).
Изменение вводит схему `symphysis`: журнал решений как первый артефакт графа
(F-04), исследование по парковкам (F-05), атаку с вердиктом, по которому
форк считает готовность (F-02, F-03, F-13), скиллы интервью, проб и атаки
(F-06, F-25), просмотрщик (F-17, F-26) и установщик в проект (F-15, F-16).
Граница «скрипт — детерминированное, модель — суждение» принята F-27.A;
ставка «соглашения вместо скриптов» измеряется сухим прогоном на самой схеме
(F-19).

## What Changes

- Журнал решений `decisions.json` — источник; `decisions.md` и `decisions.html` —
  рендер из него (F-01); у записи — обратимость с причиной (F-10), парковка
  с адресатом из трёх (F-11), исход из двух лексик (F-09); улика — путь
  и дословная цитата, сверяет скрипт, несверенная — сигнал, не стоп (F-12).
- Граф схемы: `decisions` → `research` (жанры из пяти, отрицания по рецепту,
  F-05.C) → `attack-decisions` → `proposal` → `specs` → `design`/`security`
  → `tasks` → `attack-artifacts` (F-04, F-13).
- Форк OpenSpec в двух точках: готовность вердикт-артефакта по `status`
  во frontmatter и шаг вердикта в workflow `continue` (F-02.B, F-03.C);
  пин upstream, выпуски разбираются до втягивания (F-03, F-21).
- Скиллы: `symphysis-brainstorm` (перспективы GSD, круг кончается словом
  человека — F-06.D, F-07.B), `symphysis-edge-probe` (форму называет модель,
  человек правит — F-08.D, F-22), `symphysis-prohibition-probe` (текстовая
  проба, канон — адресату ИБ, F-24, F-11.D), `symphysis-attack` (слой
  проверки GSD: линзы, тяжесть, инвариант, воздержание, хеши — F-25.B),
  `symphysis-viewer` (свой шаблон и три режима — F-26.B). Текст на русском,
  копии GSD с copyright notice и перечнем смысловых отличий (F-14.A).
- Просмотрщик: возврат решений промптом из HTML и комментариями md4h
  к рендеру; HTML на диск не пишет (F-17.D, F-01 находка).
- Установщик `@niqsons/symphysis`: npm-пакет, `install`/`check`, схема
  в проект `openspec/schemas/symphysis/` (F-15.C, F-16.B).
- Сухой прогон схемы на самой себе до обкатки (F-19.A); дневник со
  временем и ходами, отчёт сравнивает с ванильным OpenSpec числом (F-27).

Ломающих изменений нет: схема новая, ванильные схемы проекта не трогаются.

## Capabilities

### New Capabilities

- `decision-journal`: журнал решений как источник (JSON) с рендерами,
  уликами «путь и цитата», сверкой-сигналом, обратимостью, парковкой
  с адресатом, двумя лексиками исходов и двумя каналами возврата слова
  человека — F-01, F-09, F-10, F-11, F-12, F-17.
- `artifact-graph`: граф артефактов схемы `symphysis` — журнал первым,
  исследование по парковкам с жанрами, атака журнала и артефактов,
  `apply` только после `tasks` и вердикта — F-04, F-05, F-13.
- `verdict-readiness`: готовность вердикт-артефакта по `status: passed`
  во frontmatter в форке OpenSpec; `status` показывает `verdict`;
  `continue` при `mismatch` зовёт атаку, не переписывает файл; пин
  upstream — F-02, F-03, F-13, F-20, F-21.
- `brainstorm-interview`: интервью по пяти перспективам GSD порциями;
  вопрос, ответ на который есть в файлах, человеку не задаётся; круг
  кончается счётом и словом человека, отказ записывается — F-06, F-07.
- `requirement-probes`: проба краёв по закрытой таксономии восьми категорий
  с формой от модели и проба запретов текстом; четыре исхода, Dismiss только
  с причиной; канон — парковка адресату ИБ — F-08, F-09, F-11, F-22, F-24.
- `artifact-attack`: атака цели с FORCE stance — строка с линзой, тяжестью,
  инвариантом и опорой; воздержание «по спеке не выводится»; вердикт по счёту;
  хеши целей обесценивают вердикт — F-13, F-25.
- `decision-viewer`: просмотрщик из одного HTML по своему шаблону, три режима
  (решения · проверка · атака), промпт возврата, `apply` всё-или-ничего;
  вывод модели — развилка, не строка поставки — F-17, F-18, F-26.
- `skill-transfer`: механики GSD переносятся текстом на русском: копия
  источника с copyright notice, перечень мест, где смысл инструкции
  изменён; классификатор краёв и движок запретов не портируются —
  F-14, F-22, F-24.
- `project-installer`: npm-пакет ставит схему, скиллы и инструменты журнала
  в проект и сверяет установку; гейт называет, не чинит; форк не ставит,
  версию проверяет — F-15, F-16.

### Modified Capabilities

Нет: в `openspec/specs/` проекта спецификаций ещё нет.

## Impact

- Схема: `openspec/schemas/symphysis/` (schema.yaml, 9 шаблонов);
  `openspec/config.symphysis.yaml` → `openspec/config.yaml` проекта.
- Скиллы: `skills/symphysis-{brainstorm,edge-probe,prohibition-probe,attack,viewer}/`
  с `references/` и `TRANSLATION-NOTES.md`.
- Инструменты: `tools/journal.py` и модули `journal_model`, `journal_apply`,
  `journal_render`, `journal_cli`; `tools/playground-template.html`;
  `docs/journal.schema.json`; `tools/journal-roots.json`.
- Форк: `upstream/openspec`, ветка `symphysis`, `1.15.0-symphysis.1`
  (`schema.ts`, `state.ts`, `frontmatter.ts`, `instruction-loader.ts`,
  `continue-change.ts`, `UPSTREAM.md`).
- Установщик: `installer/` (`bin`, `lib`, `scripts/sync-payload.js`, тесты).
- Зависимости: Node ≥ 20, `py -3.13` с `jsonschema`; клиент агента
  с каталогом скиллов (`.claude/skills` по умолчанию, F-16 следствие).
- Документы: `docs/plan-flexible-pipeline.md`, `docs/plan-implementation*.md`,
  `docs/dry-run-journal.md`, `docs/dry-run-report.md`.
