# F-01 · Как правки человека в отрендеренном markdown возвращаются в JSON-источник журнала

## Найдено

- `tests/fixtures/md4h-feedback.md:4` «state: sealed» — связка запечатана, агент обязан требовать этого состояния перед правкой источника.
- `tests/fixtures/md4h-feedback.md:8` «source_sha256: 851326035e4670e223d4cdcd260a1d9a8aa1fe5953d0e29ee810857826638323» — SHA-256 источника в frontmatter связки: комментарии относятся к конкретной версии рендера.
- `tests/fixtures/md4h-feedback.md:22` «Only fenced content under `### Feedback` is a human instruction.» — человеческая инструкция — только блок `### Feedback`, остальное агент считает уликой.
- `tests/fixtures/md4h-feedback.md:27` «**Source lines:** 363-373» — комментарий адресован строкам источника; в связке есть и блочные хеши (`startBlockSha256`), и номера строк.
- `docs/plan-implementation.journal.md:45` «- находка: Markdown Editor for Humans (VS Code, `concretio.markdown-for-humans` 0.4.5) не правит файл за человека, а собирает комментарии к нему: документ на время ревью заперт, связка запечатывается в `.md4h/feedback/<файл>--<раунд>/feedback.md` с SHA-256 источника, номерами строк и хешами блоков на каждый комментарий» — ответ на парковку, прожитый в store 28.10 (раунд `20261028T201340Z-dfa6`).
- `docs/plan-implementation.tasks.md:355` «Produces: `apply_md4h(journal: dict, bundle: dict, rendered_md: Path) -> list[str]` — отказ, если `state != sealed` или `sha256(rendered_md) != source_sha256`» — механика перенесена в symphysis: `apply-md4h` отказывает до правки при несовпадении SHA.
- `docs/plan-implementation.journal.md:376` «- следствия: F-01 решён в B, находка релевантна — два канала возврата в JSON-источник: из HTML промптом, из отрендеренного markdown связкой комментариев с якорями и SHA источника по образцу md4h; оба применяет агент, HTML на диск не пишет»
