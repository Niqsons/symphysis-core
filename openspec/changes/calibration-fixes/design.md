## Context

Состояние: схема `symphysis` версии 1 и её девять capabilities живут
дельтами `ADDED` неархивированного сухого прогона `symphysis-schema`,
`openspec/specs/` пуст (F-20); форк OpenSpec `1.15.0-symphysis.1` считает
вердикт-артефакт готовым по `status` во frontmatter (F-06, улики A);
инструменты журнала и просмотрщик лежат в `.symphysis/` и остаются там
(F-15.B); вход изменения пока `.gigacode/input/draft.md` стенда калибровки,
в схеме артефакта для него нет (F-13). Калибровка на camunda-bid дала факты
F-01…F-05 ниже; по ходу самого этого изменения добавились F-14, F-16…F-23
и F-61 — тупик `research`, дефекты просмотрщика и парсера, порядок переноса
базы. Мотивация — `proposal.md`, раздел Why; здесь она не пересказывается.

Ограничения подхода: решает человек, модель излагает (правило схемы и слово
F-05 о журнале); граница «скрипт — детерминированное, модель — суждение»
(F-27 плана, на него встают F-12.A и F-20.B); решения design стоят только
на развилках (F-09.A), поэтому ниже нет конструкций из фактов; дельты
`MODIFIED` этого изменения применимы только после переноса базы операцией
агента `/opsx:sync` по слову владельца (F-20.B); два изменения в репозитории
начаты без `intent.md` и получают его задним числом до правки схемы (F-19.A);
пять блокеров ИБ сухого прогона закрываются здесь требованиями `ADDED`
(F-21.A); правка общего шаблона просмотрщика — часть этого изменения,
потому что оно само о схеме и инструментах (F-18 следствия, F-07 delivery).

## Goals / Non-Goals

Goals — границы того, что этот дизайн достигает:

- Атаки включаемы: признак `optional` у `attack-decisions` и `attack-artifacts`
  в форке, вызов по имени, вызванная атака — гейт по вердикту и хешам, чужой
  хеш — `stale` (F-06.A, F-26.E, F-29.E, F-30.E, F-31.E); невызванная атака
  видна в `status` (F-52.E).
- Атака артефактов спрашивает следование spec → design линзой `scenario-run`,
  читает и не исполняет, понижает тяжесть только с причиной (F-07.A, F-32.E,
  F-33.E, F-53.E, F-54.E); гигиена журнала — три проверки `check` (F-12.A,
  F-35.E).
- Постановка видна без замка: `intent.md` первым артефактом, факты
  `addressee: постановка`, пометка отступления, раздел в proposal, слово
  к выбору необязательно (F-13.A, F-17.A, F-08.A, F-24.E, F-28.E, F-43.E,
  F-44.E, F-55.E).
- Design — проекция решений развилок, не фактов (F-09.A, F-37.E, F-38.E).
- Research при нуле парковок — файл-отрицание `none.md`, убираемый при первой
  парковке (F-16.A, F-27.E).
- Режим «атака» просмотрщика: фильтр по линзе без скрытия блокеров, текст
  записи у строки, честный промпт возврата, разбор ячейки по соглашению
  markdown (F-18.A, F-23.A, F-45.E…F-48.E, F-56.E).
- Пять требований ИБ сухого прогона: данные, не инструкции; путь внутри корня
  с нормализацией и разрешением ссылок; бинарный файл — «не проверить»;
  экранирование HTML; телеметрия выключена по умолчанию (F-21.A, F-39.E…F-42.E,
  F-49.E, F-51.E, F-57.E).
- Тексты исходов кандидата пробы конкретны для требования (F-61.A).

Non-Goals — что этот дизайн не делает:

- Не меняет раскладку `.symphysis/` и не трогает `.gigacode/` стенда (F-15.B,
  F-15 question).
- Не меряет разброс до правок и не заводит второй случай калибровки: замер —
  после правок, плечо P-чел на camunda-bid с оградой (F-10.C, F-11.B).
- Не архивирует `symphysis-schema` и не копирует его дельты как `ADDED`:
  перенос базы — операция агента по слову владельца, архив сухого прогона —
  потом с `--skip-specs` (F-20.B).
- Не нормализует регистр и пробелы в значениях `addressee` (F-36 Dismiss,
  слово человека: «попробуем без нормализации»).
- Не делает `intent` необязательным и не вводит условия по дате изменения
  в форк (F-19.A против B и C).
- Не возвращает замок на постановку из GSD (F-08.B отвергнут).

## Decisions

### F-06 Как сделать атаки включаемыми, а не обязательными (слово владельца 2026-10-31)?

- **Выбрано:** A. Признак `optional` у артефакта в форке OpenSpec: `attack-decisions` и `attack-artifacts` выходят из цепочки `requires`, `isPlanningComplete` их не ждёт; атака вызывается по имени (`/opsx:continue <изменение> attack-artifacts`) словом человека на конкретном изменении; вызванная атака ставит вердикт и держит хеши как сейчас — включённая атака остаётся гейтом.
- **Обратимость:** дорого — Контракт форка со схемой: признак `optional` живёт в `schema.yaml` и в `instruction-loader.ts` (status, continue), на него встают скиллы атаки; откат — правка форка, схемы и скиллов, а изменения, прошедшие без вызванной атаки, вердикта задним числом не получат.
- **Улики выбранного:** upstream/openspec/src/core/artifact-graph/instruction-loader.ts:628 «isPlanningComplete: isComplete,»
- **Улики выбранного:** upstream/openspec/src/core/artifact-graph/instruction-loader.ts:171 «Fork (symphysis, C3): verdict state, only for artifacts whose schema entry»
- **Улики выбранного:** skills/symphysis-attack/SKILL.md:166 «`status: passed` ставится, только когда в таблице нет ни одной строки»
- **Отвергнуто:** B. Настройка проекта в `openspec/config.yaml` (например `symphysis: attacks: on | off`): схема одна, `continue` и `status` читают флаг; включение — на проект, не на изменение.
- **Отвергнуто:** C. Две схемы — `symphysis` с атаками и `symphysis-lite` без них; выбор при `openspec new change --schema`. — маловероятно: Две схемы с одним отличием — долг на каждую следующую правку схемы: инкапсуляция, не копии.

### F-07 Что должна спрашивать атака артефактов, когда её зовут: линзы присутствия, как сейчас, или следование spec → design?

- **Выбрано:** A. Заменить: одна линза «прогон сценария» — для каждого сценария spec атака называет механизм design, цитирует код образца, выводит исход по коду и сравнивает с THEN; расхождение — блокер. Из прежних остаётся claim-extraction (пути существуют). Линзы присутствия, которые детерминируемы (покрытие по именам, задача без файлов, парковка без находки), уходят в `journal.py check` и `openspec validate --strict`; остальные снимаются.
- **Обратимость:** дорого — Зависимая система — просмотрщик режима «атака»: закрытый список слугов в `tools/playground-template.html` и парсер строк; файлы `attack/*.md`, записанные с новым слугом «прогон сценария», при откате станут строками «вне списка» и невалидными.
- **Улики выбранного:** calibration/c3-p1/project/.gigacode/materials/camunda-zeebe-root/zeebe/engine/src/main/java/io/camunda/zeebe/engine/processing/common/ExpressionProcessor.java:279 «case NULL -> Either.right(Optional.empty());»
- **Улики выбранного:** calibration/c3-p1/project/openspec/changes/camunda-bid/specs/call-activity-business-id/spec.md:154 «#### Scenario: Переменной нет — инцидент, после исправления дочерний создан»
- **Улики выбранного:** docs/analysis/silent-mechanics-review-2026-10-31.md:34 «Ни одна не спрашивает «даёт ли механизм design исход сценария spec».»
