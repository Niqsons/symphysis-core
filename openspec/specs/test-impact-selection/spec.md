# test-impact-selection Specification

## Purpose

Определять и объяснять набор проверок Symphysis по изменениям в ядре и VS Code, чтобы проверять затронутое поведение при разработке и интеграции.

## Requirements

### Requirement: План изменения учитывает рабочее состояние каждого репозитория
В режиме изменения команда SHALL сравнивать каждый выбранный репозиторий с явно указанной для него базой и учитывать зафиксированные изменения, индекс, рабочее дерево и новые файлы. При удалении учитывается прежний путь, при переименовании — оба пути (test-run-optimization/F-09).

#### Scenario: Два репозитория и правки поверх коммитов
- **GIVEN** для ядра и VS Code указаны разные базы, в ядре есть коммит и правка в индексе, а в VS Code есть незаписанная правка и новый файл
- **WHEN** строится план изменения
- **THEN** каждый из этих путей учитывается при сравнении с базой своего репозитория

#### Scenario: Удаление и перенос между модулями
- **GIVEN** один файл удалён, а другой перенесён между модулями
- **WHEN** строится план изменения
- **THEN** отбор учитывает прежний путь удалённого файла и оба пути перенесённого

### Requirement: План коммита сравнивает его с одним родителем
В режиме отдельного коммита команда SHALL выбирать пути по сравнению этого коммита с его родителем. Для merge-коммита родитель SHALL быть указан явно. При удалении учитывается прежний путь, при переименовании — оба пути (test-run-optimization/F-09).

#### Scenario: Отдельный коммит и посторонние правки
- **GIVEN** указан обычный коммит, а в рабочем дереве есть правка другого файла
- **WHEN** строится план коммита
- **THEN** изменение этого файла не входит в сравнение коммита

#### Scenario: Не выбран родитель merge-коммита
- **GIVEN** указан merge-коммит без родителя сравнения
- **WHEN** запрашивается план
- **THEN** команда сообщает, что требуется явно указать родителя, и не выдаёт готовый план

#### Scenario: Сравнение с выбранным родителем
- **GIVEN** у merge-коммита различаются изменения относительно двух родителей
- **WHEN** запрашивается план с указанием одного из родителей
- **THEN** учитываются пути, изменившиеся относительно выбранного родителя

### Requirement: План включает проверки затронутых модулей и потребителей
Команда SHALL выбирать тесты затронутых модулей и их прямых и транзитивных потребителей по `dependencies` в README, а также связанные общие, сквозные и упаковочные проверки ядра, инсталлятора и VS Code (test-run-optimization/F-04, test-run-optimization/F-07, test-run-optimization/F-08).

#### Scenario: Изменение общей зависимости
- **GIVEN** модуль A зависит от B, B зависит от C, а D с этой цепочкой не связан
- **WHEN** изменяется исходный файл C
- **THEN** план включает применимые проверки A, B и C, а сама эта цепочка не добавляет тесты D

#### Scenario: Изменение ядра требует проверки VS Code
- **GIVEN** правка ядра затрагивает интерфейс, который проверяет сквозной тест VS Code
- **WHEN** строится план для этой правки
- **THEN** план включает связанную проверку VS Code, даже если в VS Code нет изменённых файлов

#### Scenario: Изменение источника поставки
- **GIVEN** изменился входной файл поставки с проверкой состава пакета
- **WHEN** строится план для этой правки
- **THEN** план включает связанную проверку пакета

#### Scenario: Потребители модуля с удалённым README
<!-- test-run-optimization/F-16 -->
- **GIVEN** файл перенесён в другой модуль, README прежнего модуля удалён тем же изменением, а его прежние связи доступны
- **WHEN** строится план изменения
- **THEN** в план входят применимые проверки прежних потребителей наряду с проверками нового модуля

#### Scenario: Прежние связи недоступны
<!-- test-run-optimization/F-16 -->
- **GIVEN** файл перенесён, README прежнего модуля удалён и прежние связи нельзя восстановить
- **WHEN** строится план изменения
- **THEN** команда расширяет план до применимого полного набора и указывает недоступность прежних связей причиной расширения

### Requirement: План показывает область и причины выбора
Команда SHALL показывать корни участвующих репозиториев, базы сравнения, выбранные группы и причину выбора каждой группы. При читаемом сравнении с неизвестным путём или изменённой общей настройкой план SHALL расшириться до применимого полного набора с указанием причины (test-run-optimization/F-06, test-run-optimization/F-09, test-run-optimization/F-10).

#### Scenario: Неизвестный путь
- **GIVEN** Git вернул путь, область влияния которого команда определить не смогла
- **WHEN** строится план
- **THEN** план показывает применимый полный набор и называет путь причиной расширения

#### Scenario: Изменение общей настройки
- **GIVEN** изменилась общая настройка тестового набора
- **WHEN** строится план
- **THEN** план показывает расширенный набор и называет настройку причиной выбора

#### Scenario: Пустое сравнение и ошибка Git
- **GIVEN** сравнение одного входа успешно и не содержит изменений, а для другого входа Git вернул ошибку
- **WHEN** запрашиваются планы для обоих входов
- **THEN** первый результат сообщает о пустом сравнении, а второй называет ошибку и сообщает о незавершённом построении плана

#### Scenario: Повреждённый список зависимостей скрывает модуль
<!-- test-run-optimization/F-20 -->
- **GIVEN** путь правки известен, а неверный формат `dependencies` в README исключил модуль из обнаружения
- **WHEN** команда строит план для затронутой области
- **THEN** она указывает повреждённый README и, если из-за пропуска модуля нельзя подтвердить полноту отбора, расширяет план до применимого полного набора
