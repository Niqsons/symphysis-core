# decision-viewer Specification

## Purpose
Просмотрщик журнала: один HTML по своему шаблону с тремя режимами, все развилки показаны целиком, слово человека возвращается промптом; F-17, F-18, F-26.

## Requirements

### Requirement: Просмотрщик — один HTML из своего шаблона с тремя режимами
`render-html` SHALL собирать `decisions.html` из `decisions.json` по шаблону `tools/playground-template.html` в один файл с режимами «решения», «проверка» (только чтение) и «атака» (строки `attack/*.md`, переданных `--attack`); состояние человека SHALL жить в browser storage; страница SHALL собирать промпт возврата кнопкой и SHALL NOT писать на диск (F-26.B, F-17.D).

#### Scenario: Сборка с атакой
- **GIVEN** годный `decisions.json` и `attack/decisions.md` с валидной таблицей
- **WHEN** выполняется `render-html decisions.json --out decisions.html --attack attack/decisions.md`
- **THEN** код 0, `decisions.html` — один файл с переключателем трёх режимов и хешем журнала в шапке

#### Scenario: Битый файл атаки
- **GIVEN** `attack/decisions.md`, строка таблицы которого даёт не 7 ячеек
- **WHEN** выполняется `render-html … --attack attack/decisions.md`
- **THEN** stderr называет файл и строку, код 2, HTML не пишется

### Requirement: Все варианты и рекомендация показаны целиком
Карточка записи SHALL показывать все варианты, включая помеченные «маловероятно» с причиной, рекомендацию под списком вариантов, антиподы, зависимости, парковки, улики с вердиктом сверки и поле «оспорить» у факта; вариант, добавленный человеком, SHALL быть помечен; вывод модели, на который опирается артефакт, SHALL сначала становиться записью с вариантами и показываться здесь (F-26.B главное правило, F-17.D).

#### Scenario: Маловероятный вариант виден
- **GIVEN** запись с вариантом `unlikely: «причина»`
- **WHEN** открывается карточка записи
- **THEN** вариант присутствует в списке с пометкой «маловероятно» и причиной, рекомендация стоит ниже последнего варианта

### Requirement: Режим «атака» группирует строки по линзам и держит слуг вне списка отдельно
Режим «атака» SHALL показывать по каждому файлу атаки шапку с целями и хешами (хеш `decisions.json` сверяется с журналом), счётчики по тяжести и по линзе, строки в порядке линза → тяжесть по таблице `symphysis-attack`; слуг вне закрытого списка SHALL попадать в группу «вне списка» как невалидная строка; спор человека у строки SHALL уходить в промпт возврата строкой «Замечания к схеме:» и в `notes[]`, не в файл атаки (F-26 следствия).

#### Scenario: Слуг вне списка
- **GIVEN** строка атаки с линзой `style`
- **WHEN** страница собирает режим «атака»
- **THEN** строка показана в группе «вне списка» с пометкой невалидности, в счётчике линз её нет
