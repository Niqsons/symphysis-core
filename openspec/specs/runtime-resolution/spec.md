# runtime-resolution Specification

## Purpose
Определяет единый выбор поставки symphysis и её ресурсов независимо от рабочего store, его данных и расположения исполняемого кода.

## Requirements

### Requirement: Dispatcher и хосты используют единый выбор поставки
Единая команда symphysis SHALL разрешать рабочий store, выбранную поставку и её ресурсы. Скиллы SHALL использовать эту команду для обращения к общим инструментам, а IDE-хосты SHALL получать выбор поставки через тот же resolver. Для одного store и одной установки эти пути обращения SHALL NOT выбирать разные поставки (global-user-install/F-10).

#### Scenario: Команда и хост обращаются к одной поставке
- **GIVEN** выбран store с одной установленной для него поставкой symphysis
- **WHEN** скилл обращается к инструменту через команду symphysis, а IDE-хост запрашивает runtime этого store
- **THEN** оба обращения выбирают одну и ту же поставку при сохранении рабочего store

### Requirement: Resolver предпочитает local при наличии обеих установок
Если для выбранного store обнаружены local и global установки, resolver symphysis SHALL выбирать local без объединения ресурсов двух поставок. Этот выбор SHALL NOT означать поддержку смешанной работы или обещание изменить нативный приоритет скиллов и агентов клиента (global-user-install/F-13, global-user-install/F-14).

#### Scenario: Local имеет приоритет resolver
- **GIVEN** для store обнаружены local и global поставки
- **WHEN** resolver выбирает runtime symphysis
- **THEN** выбрана local-поставка; её недостающий ресурс не подменяется ресурсом global-поставки

### Requirement: Ресурсы принадлежат выбранной поставке
Инструменты, схема, шаблоны, общие документы и справка SHALL разрешаться из выбранной поставки, а не из случайной соседней установки. Недоступность ресурса выбранной поставки SHALL быть названа пользователю; другой runtime MUST NOT выдаваться за ресурс этой поставки (global-user-install/F-03, global-user-install/F-10, global-user-install/F-11).

#### Scenario: У выбранной поставки отсутствует ресурс
- **GIVEN** в выбранной поставке нет нужного шаблона, а в другой установке он есть
- **WHEN** инструмент запрашивает этот шаблон
- **THEN** отсутствие ресурса выбранной поставки названо, шаблон другой установки не используется как её собственный

#### Scenario: Проектная схема перехватывает выбор global runtime
<!-- global-user-install/F-24 -->
- **GIVEN** выбран global runtime, но одноимённая проектная схема перехватывает нативный выбор OpenSpec
- **WHEN** проверяется установка или запускается документированный клиентский путь
- **THEN** несогласованный источник схемы явно назван, смешанное выполнение не продолжается и конфликтующий файл не удаляется автоматически

#### Scenario: JSON-схема журнала доступна именованным ресурсом
- **GIVEN** выбранная local или global поставка содержит JSON-схему журнала
- **WHEN** вызывается `symphysis resource doc journal.schema.json`
- **THEN** возвращается полная JSON-схема выбранной поставки, совпадающая со схемой для `journal check`; другая установка не подставляется вместо выбранной

### Requirement: Расположение runtime не определяет рабочий store
Рабочий корень инструментов SHALL соответствовать выбранному store независимо от расположения runtime. Улики, настройки, журналы, ответы и черновики SHALL разрешаться в контексте этого store и его карты корней. Нахождение кода вне store MUST NOT превращать каталог установки или его родителя в корень проектных данных (global-user-install/F-03, global-user-install/F-06, global-user-install/F-10).

#### Scenario: Два store имеют одинаковое имя изменения
- **GIVEN** два store используют общий runtime и содержат изменения с одинаковым именем
- **WHEN** инструмент вызывается для изменения первого store
- **THEN** без явной связи в его карте корней данные второго store не читаются и не меняются, результаты и черновики остаются у первого

#### Scenario: Runtime лежит рядом с несколькими store
- **GIVEN** общий runtime расположен вне выбранного store, а у его родителя есть другие проекты
- **WHEN** инструмент разрешает корни улик выбранного store
- **THEN** родитель runtime не становится общим корнем чтения улик вследствие одного расположения кода

#### Scenario: Карты корней двух store сохраняют проектную семантику
<!-- global-user-install/F-20 -->
- **GIVEN** два store имеют собственные карты корней с проектными значениями `<root>` и разными префиксами `src/`
- **WHEN** общий runtime проверяет улики каждого store без ручной передачи `--roots`
- **THEN** используются карта и проектная база выбранного store, префиксы не теряются и не подменяются соседним store либо runtime

### Requirement: Global-вызов проверяет совместимость store
Store SHALL объявлять совместимость с global-поставкой. При несовместимости проверка и команда symphysis SHALL отказывать с понятным явным действием пользователя, не мигрируя данные автоматически и не подбирая скрыто другую версию runtime (global-user-install/F-11).

#### Scenario: Обновлённая поставка несовместима со store
- **GIVEN** активная global-поставка несовместима с объявленной совместимостью выбранного store
- **WHEN** пользователь проверяет установку либо вызывает команду для этого store
- **THEN** получен отказ с причиной и явным действием, данные store не мигрированы и другая версия не выбрана автоматически

#### Scenario: У store нет декларации совместимости
<!-- global-user-install/F-15 -->
- **GIVEN** у старого клонированного store нет декларации совместимости с global-поставкой
- **WHEN** global check или команда symphysis обращается к этому store
- **THEN** операция со store не выполняется, названа неподтверждённая совместимость и необходимость явной инициализации либо миграции

#### Scenario: Клиентский путь проверяет совместимость до записи
<!-- global-user-install/F-23 -->
- **GIVEN** global-store без декларации совместимости либо с несовместимой декларацией
- **WHEN** пользователь начинает документированный клиентский путь создания или продолжения изменения
- **THEN** интеграция проверяет совместимость до первого изменяющего действия этого пути, отказывает с явной инициализацией либо миграцией и не меняет данные store
