# client-installation Specification

## Purpose
Определяет обнаружение установленных скиллов и поддерживаемых агентов symphysis нативными клиентами отдельно для local и global режимов.

## Requirements

### Requirement: Установленные скиллы обнаруживаются выбранным клиентом
Установка выбранного режима для Claude Code, Codex или OpenCode SHALL делать поставляемый набор скиллов symphysis доступным самому клиенту в его нативной discovery. Пользователь и агент SHALL видеть набор, начиная с `symphysis-brainstorm`, без ручного поиска файлов другого клиента. Поддержка одного клиента SHALL NOT считаться доказательством поддержки остальных (global-user-install/F-02, global-user-install/F-03, global-user-install/F-08).

#### Scenario: Global-скиллы доступны после клонирования store
- **GIVEN** для выбранного поддерживаемого клиента выполнена global-установка, затем клонирован store без local-поставки
- **WHEN** открывается свежая сессия клиента и выполняется документированная инициализация store
- **THEN** клиент обнаруживает весь поставляемый набор скиллов symphysis, и агент может вызвать `symphysis-brainstorm` без ручного поиска его тела

#### Scenario: Local-скиллы доступны без global
- **GIVEN** для выбранного поддерживаемого клиента выполнена local-установка в проект без global-поставки
- **WHEN** открывается свежая сессия клиента в этом проекте
- **THEN** клиент обнаруживает поставляемый набор скиллов symphysis выбранной local-установки

### Requirement: Поддерживаемые агенты исполняют скилл в нативном формате
Тела агентов symphysis, поставляемые для выбранного клиента, SHALL обнаруживаться и загружаться в поддерживаемом им формате. Вызванный водитель SHALL получать нужное тело скилла способом этого клиента; наличие Claude-поля предварительной загрузки в чужом формате SHALL NOT считаться загрузкой скилла (global-user-install/F-03, global-user-install/F-08).

#### Scenario: Водитель Codex получает нужный скилл
- **GIVEN** установлен поддерживаемый водитель symphysis для Codex и подготовлен его brief
- **WHEN** Codex загружает и вызывает водителя
- **THEN** тело агента принимается нативным механизмом Codex, а водитель получает инструкции нужного скилла без предположения о Claude-предварительной загрузке

#### Scenario: Водитель OpenCode не зависит от формата Claude
- **GIVEN** установлен поддерживаемый водитель symphysis для OpenCode и подготовлен его brief
- **WHEN** OpenCode загружает и вызывает водителя
- **THEN** клиент принимает тело в своём формате, водитель получает нужный скилл без трактовки полей Claude как нативных настроек OpenCode

### Requirement: Проверка различает наличие файлов и готовность клиента
Проверка выбранной установки SHALL различать целостность поставки, наличие клиентских носителей и подтверждённую доступность скиллов и поддерживаемых агентов клиенту. Само наличие файла на диске MUST NOT выдаваться за подтверждение обнаружения в сессии; недостающая проверка SHALL быть названа как неподтверждённая (global-user-install/F-02, global-user-install/F-08, global-user-install/F-10).

#### Scenario: Файлы скопированы без проверки discovery
- **GIVEN** файлы клиентской интеграции существуют, но обнаружение выбранным клиентом не проверено
- **WHEN** пользователь получает результат проверки установки
- **THEN** наличие файлов указано отдельно, а доступность клиенту не объявлена подтверждённой только на этом основании

#### Scenario: Готовность workflow проверяется для каждого выбранного клиента

- **GIVEN** для установки выбраны два клиента, у одного есть необходимый workflow `continue`, у другого его нет
- **WHEN** выполняется установка или проверка
- **THEN** отсутствие workflow названо для второго клиента и готовность первого не выдаётся за готовность второго

### Requirement: Нативные коллизии смешанной установки остаются пользователю
При наличии local и global копий скиллов или агентов symphysis SHALL NOT обещать единый нативный приоритет для всех клиентов или автоматически исправлять их конфликты. Диагностика SHALL отделять выбор resolver symphysis от нативной discovery; разрешение конфликтов смешанной установки остаётся пользователю (global-user-install/F-13, global-user-install/F-14).

#### Scenario: Нативный выбор отличается от resolver
- **GIVEN** обе установки присутствуют, resolver symphysis выбрал local, а клиент обнаружил глобальный скилл либо обе копии
- **WHEN** пользователь проверяет эту установку
- **THEN** нативный выбор не выдаётся за выбор resolver, конфликт не исправляется автоматически и не объявляется поддерживаемой смешанной работой
