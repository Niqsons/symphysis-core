# project-settings Specification

## Purpose
Личный файл настроек `symphysis.yaml` в корне проекта, вне git: что человек выбирает до запуска шага, какие значения действуют по умолчанию и как виден выключенный состав.

## Requirements

### Requirement: `symphysis.yaml` в корне проекта задаёт выбор перед запуском шага
Файл `symphysis.yaml` в корне проекта, вне `.symphysis/`, SHALL задавать выборы вложенными ключами: `consequences.failure_branches`, `consequences.assumptions`, `edge_probe.enabled` и `attack.<слуг линзы>` на каждую линзу атаки; отсутствие файла или ключа SHALL означать «включено» (F-24.A, F-110.B, F-61, F-63, F-132, слова владельца к F-14 и F-18, F-23).

#### Scenario: Файла нет
- **GIVEN** проект без `symphysis.yaml`
- **WHEN** начинается шаг `consequences` или проба краёв
- **THEN** ветки отказа, допущения и проба краёв считаются включёнными

#### Scenario: Ключа нет
- **GIVEN** `symphysis.yaml`, где задан только `consequences.assumptions: false`
- **WHEN** начинается шаг `consequences`
- **THEN** допущения выключены, ветки отказа включены

#### Scenario: Файл переживает обновление установки
- **GIVEN** `symphysis.yaml` с правками человека
- **WHEN** выполняется `symphysis install --force`
- **THEN** файл не изменён, а каталог `.symphysis/` обновлён

#### Scenario: Значение не из true и false
- **GIVEN** непустое значение не из `true | false`; пустое значение равно отсутствию ключа (F-109.A)
- **WHEN** файл читают `symphysis check` и скрипт настроек
- **THEN** выбор считается включённым, оба дают `[!!] symphysis.yaml: недопустимое значение <значение>`; у `symphysis check` код 2, у скрипта код 0, с `--strict` 2

#### Scenario: Линзы по умолчанию
- **GIVEN** проект без `symphysis.yaml`
- **WHEN** скилл атаки узнаёт состав скриптом настроек
- **THEN** все линзы обоих файлов атаки включены

#### Scenario: Выключена одна линза
- **GIVEN** `symphysis.yaml`, где выключена одна линза
- **WHEN** выполняется скрипт настроек
- **THEN** вывод называет эту линзу выключенной, остальные включёнными

#### Scenario: Новая установка называет линзы
- **GIVEN** проект без `symphysis.yaml`
- **WHEN** выполняется `symphysis install --project <каталог>`
- **THEN** созданный файл несёт ключ каждой линзы, все включены

#### Scenario: Неизвестная линза
<!-- F-108 -->
- **GIVEN** ключ линзы с неизвестным слугом
- **WHEN** выполняются `symphysis check` и скрипт настроек
- **THEN** `[!!] symphysis.yaml: неизвестная линза <имя>`, этот ключ ни одной линзы не выключает

### Requirement: `symphysis.yaml` читает один скрипт
Файл `symphysis.yaml` SHALL читать только скрипт `.symphysis/tools/symphysis_config.py`, пакетом PyYAML, беря значения текстом; `symphysis config` и `symphysis check` SHALL звать этот скрипт и передавать его строки, сами файл MUST NOT разбирать (F-135.B, F-110.B, F-51.A, F-113, F-118.A). Сомнение в чтении SHALL решаться во включённую сторону сигналом, а не остановкой команд журнала (F-24.A, F-25.A).

#### Scenario: Значения читаются текстом
- **GIVEN** файл случаев со значениями `no`, `off`, `False`, `"false"`, `выкл`, пустым значением, табом в отступе и повторённым ключом
- **WHEN** тест читает каждый случай скриптом настроек
- **THEN** состав и сигнал совпадают с записанными в файле случаев; `no` и `off` не выключают выбор; `"false"` читается как `false`

#### Scenario: Нет пакета PyYAML
- **GIVEN** Python без PyYAML и `symphysis.yaml` с выключенной пробой краёв
- **WHEN** выполняется `python .symphysis/tools/symphysis_config.py`
- **THEN** `[!!] symphysis.yaml: нет пакета PyYAML — выполнить: python -m pip install pyyaml`, все выборы считаются включёнными, код 0, с `--strict` 2

#### Scenario: Прочие команды журнала без пакета
- **GIVEN** Python без PyYAML
- **WHEN** выполняются `journal.py apply`, `render-md`, `render-html`
- **THEN** они работают как прежде: журнал настройки не читает (F-128.A)

#### Scenario: Файл не разбирается
- **GIVEN** `symphysis.yaml` с табом в отступе
- **WHEN** выполняются скрипт настроек и `symphysis check`
- **THEN** оба дают `[!!] symphysis.yaml: не разбирается`, все выборы считаются включёнными; у скрипта код 0, с `--strict` 2, у `symphysis check` код 2

#### Scenario: Плоская запись вместо вложенной
- **GIVEN** `symphysis.yaml` со строкой `edge_probe: false` или `consequences: false`
- **WHEN** выполняется `symphysis check`
- **THEN** выбор включён, `[!!] symphysis.yaml: <ключ> — нужен вложенный ключ`, код 2

#### Scenario: Модель узнаёт состав скриптом
- **GIVEN** `symphysis.yaml` со значением `edge_probe.enabled: no`
- **WHEN** скилл в начале шага зовёт `python .symphysis/tools/symphysis_config.py`
- **THEN** вывод называет пробу краёв включённой и несёт сигнал о недопустимом значении; сам файл скилл не разбирает (F-118.A)

#### Scenario: Человек смотрит состав
- **GIVEN** проект с `symphysis.yaml`
- **WHEN** выполняется `symphysis config --project <каталог>`
- **THEN** вывод — строки скрипта настроек дословно; у `journal.py` подкоманды настроек нет (слово человека к F-118)

#### Scenario: Скрипт недоступен
- **GIVEN** Python не отвечает или в проекте нет `.symphysis/tools/symphysis_config.py`
- **WHEN** выполняется `symphysis config --project <каталог>`
- **THEN** `[!!]` называет причину и что выполнить, код 2; состав не показан, инсталлятор файл не разбирает

### Requirement: `symphysis.yaml` — личная настройка и в git не идёт
Файл `symphysis.yaml` SHALL жить вне git проекта: каждый пользователь сам решает, с каким инструментарием работать и как его настраивать; выбор одного человека MUST NOT становиться настройкой всей команды (F-94.E).

#### Scenario: Выбор одного человека не доходит до другого
- **GIVEN** два клона одного проекта после `install`, в первом проба краёв выключена
- **WHEN** человек первого клона коммитит и пушит свою работу, а второй её забирает
- **THEN** `symphysis.yaml` в коммит не попал, состав во втором клоне прежний
<!-- требование из F-94; пробами не проходило -->

### Requirement: Шаг читает выбор в начале и человека не спрашивает
Скилл шага SHALL узнавать состав скриптом настроек в начале шага и SHALL NOT задавать человеку вопрос о составе; правка файла после начала шага SHALL действовать со следующего запуска шага (F-24.A, F-118.A).

#### Scenario: Запуск шага без вопроса
- **GIVEN** проект с `symphysis.yaml` и изменение, у которого готовы `specs`
- **WHEN** запускается шаг `consequences`
- **THEN** шаг идёт с выбором из файла, вопроса о составе человеку нет

### Requirement: Выключенный состав назван в артефакте шага
Шаг, часть которого выключена настройкой, SHALL называть это в своём артефакте (F-24.A); предположение: след выключенной пробы краёв — комментарий шаблона под требованием; решить при реализации.

#### Scenario: Выключена колонка описи
- **GIVEN** `symphysis.yaml`, где допущения выключены
- **WHEN** шаг `consequences` пишет `consequences.md`
- **THEN** файл называет, что допущения выключены настройкой

#### Scenario: Выключена проба краёв
- **GIVEN** `symphysis.yaml`, где проба краёв выключена
- **WHEN** завершается шаг `specs`
- **THEN** в блоке каждого требования стоит `<!-- проба краёв: выключена настройкой -->`

#### Scenario: Всё включено
- **GIVEN** всё включено
- **WHEN** шаг пишет `consequences.md`
- **THEN** файл называет состав «ветки отказа, допущения» той же строкой, что и при выключенных
