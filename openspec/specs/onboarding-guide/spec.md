# onboarding-guide Specification

## Purpose
Пошаговое руководство `docs/GUIDE.md`: установка из клона репозитория и учебный проект, проведённый через все шаги OpenSpec настоящими командами.

## Requirements

### Requirement: Руководство ведёт установку из клона репозитория
Файл `docs/GUIDE.md` на русском SHALL вести установку из клона репозитория: клон, `npm i -g` тарбола форка из `vendor/`, выключение телеметрии до других команд форка, `python -m pip install pyyaml`, `npm --prefix installer ci`, `npm i -g ./installer`, инициализация проекта, `symphysis install`, `check` (F-31.A, F-36.A, F-34.A, F-22, F-110.B, F-114.A, F-117.A, F-125.A).

#### Scenario: Установка на чистой машине
- **GIVEN** машина с Node и Python, без symphysis и без форка, с доступом к репозиторию и к реестру npm или зеркалу
- **WHEN** человек выполняет шаги установки из `docs/GUIDE.md`
- **THEN** `openspec --version` совпадает с пином, `check` печатает `check: ok` с кодом 0, в проекте есть `/opsx:continue`

#### Scenario: Шаг для разработчика
- **GIVEN** чистый клон без `upstream/openspec`
- **WHEN** разработчик собирается запускать тесты инсталлятора
- **THEN** `docs/GUIDE.md` называет шаг получения и сборки форка из ветки `openspec-fork` и отличает его от установки для пользователя

#### Scenario: Реестр npm недоступен
- **GIVEN** реестр npm или индекс pip недоступен
- **WHEN** шаг установки форка или пакета падает
- **THEN** `docs/GUIDE.md` называет эту причину и настройку зеркала, повтор после настройки ставит недостающее

#### Scenario: Обновление до новой версии
- **GIVEN** установленный проект и клон с новой версией
- **WHEN** человек выполняет раздел «Обновление»
- **THEN** `git pull`, `npm --prefix installer ci`, `npm i -g` нового тарбола, `openspec update`, `symphysis install --force`, затем `check: ok`; `symphysis.yaml` и файл корней не тронуты

#### Scenario: Телеметрия до других команд форка
- **GIVEN** чистая машина сразу после `npm i -g` тарбола форка
- **WHEN** читатель выполняет следующую команду руководства
- **THEN** в конфиге `telemetry.enabled: false` и нет `anonymousId`; команда дана отдельно для PowerShell и bash (F-117.A)

#### Scenario: Глобальный конфиг и `XDG_CONFIG_HOME`
- **GIVEN** читатель с заданной `XDG_CONFIG_HOME`, в которой лежат другие программы
- **WHEN** он читает раздел установки
- **THEN** руководство называет: запись идёт только в `<XDG_CONFIG_HOME>/openspec/config.json`, соседние каталоги не трогаются, путь показывает `openspec config path`, а переменная, заданная не во всех оболочках, даёт два конфига (F-122)

#### Scenario: Команда установки на Windows
- **GIVEN** читатель на Windows
- **WHEN** копирует команду установки
- **THEN** `docs/GUIDE.md` даёт её отдельно для PowerShell и bash, с относительным путём и предупреждением о `\` в Git Bash

### Requirement: Читатель узнаёт о глобальном эффекте до шага
Файл `docs/GUIDE.md` MUST NOT оставлять читателя узнавать о глобальном эффекте постфактум: что меняют `npm i -g`, `pip install` и запись в глобальный конфиг, написано до шага; судит владелец чтением при прохождении (F-97.B и слово человека).

#### Scenario: Глобальный эффект назван до шага
- **GIVEN** текст `docs/GUIDE.md` с шагами `npm i -g`, `pip install` и правкой глобального конфига
- **WHEN** владелец читает его при прохождении
- **THEN** руководство называет, что меняется, до команды; судит владелец
<!-- требование из F-97; пробами не проходило -->

### Requirement: Учебный проект идёт настоящими командами и выводами
Файл `docs/GUIDE.md` SHALL вести один маленький учебный проект; приведённые команды и выводы SHALL быть взяты из настоящего прохождения, а читатель SHALL мочь повторить его сам (F-34.A).

#### Scenario: Повтор читателем
- **GIVEN** машина после установки по `docs/GUIDE.md`
- **WHEN** читатель выполняет команды учебного проекта в указанном порядке
- **THEN** каждая команда отрабатывает, и читателю не нужны файлы вне учебного проекта и репозитория

#### Scenario: Прохождение проверяет руководство
- **GIVEN** готовый текст `docs/GUIDE.md`
- **WHEN** проводится прохождение по нему на Opus 5.5 или Sonnet 5.5
- **THEN** расхождение команды с текстом правит текст, и вывод в тексте взят из этого прохождения

#### Scenario: Сравнение вывода с руководством
- **GIVEN** блок вывода в руководстве
- **WHEN** читатель сравнивает его со своим
- **THEN** вывод CLI совпадает с точностью до путей, заменённых на `<каталог>`; артефакты модели помечены «пример, у читателя будет иначе»

### Requirement: В руководстве нет рабочих имён и материалов замеров
Файл `docs/GUIDE.md` MUST NOT нести имена и код из рабочих задач, выдержки из замеров и адрес клона с токеном (F-98.A, F-104).

#### Scenario: Адрес без токена
- **GIVEN** шаг клона в `docs/GUIDE.md`
- **WHEN** тест ищет в файле адрес с учётными данными
- **THEN** находок нет, руководство называет хранилище учётных данных

#### Scenario: Гейт имён по руководству
- **GIVEN** готовый `docs/GUIDE.md`
- **WHEN** тест прогоняет по файлу гейт имён и ищет выдержки из замеров
- **THEN** находок нет
<!-- требование из F-98; пробами не проходило -->

### Requirement: Руководство покрывает все шаги OpenSpec
Файл `docs/GUIDE.md` SHALL описывать все шаги OpenSpec от установки до архивации, включая шаг `consequences` и выбор в `symphysis.yaml`; шаги после `tasks.md` SHALL быть в тексте и MAY быть описаны короче (F-34 и слово владельца к нему, F-24.A).

#### Scenario: Шаги после tasks
- **GIVEN** `docs/GUIDE.md`
- **WHEN** читатель доходит до готового `tasks.md`
- **THEN** руководство не обрывается: дальше описаны реализация, синхронизация спек и архивация

#### Scenario: Выбор перед запуском
- **GIVEN** `docs/GUIDE.md`
- **WHEN** читатель доходит до шага `consequences`
- **THEN** руководство показывает `symphysis.yaml`, называет три выбора с умолчанием «включено» и говорит, что файл личный и в git не идёт (F-94.E)

#### Scenario: Учебный проект несёт свой код
- **GIVEN** учебный проект
- **WHEN** читатель доходит до шага `consequences`
- **THEN** в проекте есть небольшой кусок кода, на который опирается решение журнала, и шаг показывает хотя бы одну строку описи и одного кандидата; этот кусок — проверка шага при прохождении (слово человека к F-58)

#### Scenario: Граница всех шагов
- **GIVEN** `docs/GUIDE.md`
- **WHEN** читатель ищет шаг
- **THEN** описаны workflow, которые ставит установка: семь профиля `core`; об остальных одна строка: они есть и как их добавить

### Requirement: Руководство называет проверенных клиентов
Файл `docs/GUIDE.md` SHALL показывать установку для Claude Code и параметр `--skills-dir` для других клиентов и SHALL называть, что opencode этим прохождением не проверен (F-34, следствие решения).

#### Scenario: Другой клиент
- **GIVEN** читатель с клиентом, отличным от Claude Code
- **WHEN** он читает раздел установки
- **THEN** руководство показывает `--skills-dir`, как узнать установленных клиентов (`where.exe` в PowerShell, `which` в bash), и прямо говорит, что прохождение шло только на Claude Code (F-115.D)
