# plugin-agent-hook Specification

## Purpose
Хук клиента сообщает агенту о том, что случилось вне чата: о внесённом кнопкой и о правке `scheme.md`. Плагин ставит его сам и снимает выключателем.

## Requirements

### Requirement: «Внести» пишет событие
После успешного `apply` «Внести» SHALL дописывать в `.symphysis/viewer/events.jsonl` одну строку JSON: изменение, файл ответа от корня проекта, хеш журнала до и после, отчёт `apply` (F-15, F-32, F-33). Отказ `apply` события SHALL NOT давать. Каталог `.symphysis/viewer/` исключает себя из git, как и черновики.

#### Scenario: Внесено
- **GIVEN** журнал открыт, черновик с решением
- **WHEN** человек нажимает «Внести», `apply` проходит
- **THEN** в `events.jsonl` новая строка с изменением, файлом `answers/`, двумя хешами и отчётом

#### Scenario: Отказ `apply`
- **GIVEN** промпт, который `apply` отвергает
- **WHEN** человек нажимает «Внести»
- **THEN** строки в `events.jsonl` нет, журнал не тронут

#### Scenario: Событие не записалось
- **GIVEN** `apply` прошёл, запись в `events.jsonl` упала
- **WHEN** человек нажимает «Внести»
- **THEN** журнал внесён, к отчёту добавлено предупреждение, что агенту надо сказать самому

#### Scenario: Ни одна сессия не обращалась
- **GIVEN** в `.symphysis/viewer/` нет ни одного курсора сессии
- **WHEN** человек нажимает «Внести»
- **THEN** к отчёту добавлено: ни одна сессия агента ещё не обращалась через хук в этом проекте, агенту в другом каталоге надо сказать самому

### Requirement: Хук печатает непрочитанные события этой сессии
При обращении к агенту скрипт хука SHALL печатать события, которых эта сессия ещё не видела; курсор SHALL быть свой у каждой сессии (F-32). Новая сессия SHALL вставать в конец файла и прошлых событий не видеть (F-50). Поле `prompt` со входа SHALL NOT никуда записываться (F-52). Новостей нет — вывод SHALL быть пуст.

#### Scenario: Две сессии
- **GIVEN** две сессии уже обращались к агенту, затем внесено одно событие
- **WHEN** обе обращаются снова
- **THEN** каждая видит это событие один раз

#### Scenario: Новая сессия
- **GIVEN** в `events.jsonl` три старых события
- **WHEN** новая сессия обращается впервые
- **THEN** этих событий в выводе нет

#### Scenario: Продолжение сессии
- **GIVEN** сессия видела событие и была продолжена с тем же номером
- **WHEN** она обращается снова без новых событий
- **THEN** вывод пуст

#### Scenario: Текст запроса не сохраняется
- **GIVEN** запрос с заметной строкой
- **WHEN** срабатывает хук
- **THEN** тест не находит этой строки ни в одном файле `.symphysis/viewer/`

#### Scenario: Длинный вывод
- **GIVEN** непрочитанных событий на 30 000 символов
- **WHEN** сессия обращается
- **THEN** вывод не длиннее 9 000 символов: самые новые события целиком и строка «ещё N событий в `.symphysis/viewer/events.jsonl`», курсор в конце

#### Scenario: Курсор дальше конца файла
- **GIVEN** курсор сессии дальше конца `events.jsonl`
- **WHEN** сессия обращается
- **THEN** файл читается с начала, новые события показаны, курсор в конце

#### Scenario: Неполная последняя строка
- **GIVEN** последняя строка `events.jsonl` без перевода строки
- **WHEN** сессия обращается
- **THEN** эта строка не показана, курсор перед ней, следующее обращение показывает её целиком

#### Scenario: Сессия без скилла
- **GIVEN** сессия без загруженного скилла просмотрщика
- **WHEN** хук печатает событие
- **THEN** строка сама говорит: человек внёс решения кнопкой, журнал изменён, ответ лежит в названном файле `answers/`, перечитай журнал перед записью, этот промпт вносить не надо

### Requirement: Хук сообщает об изменении `scheme.md` по хешу
Скрипт SHALL сверять хеш `scheme.md` каждого активного изменения с тем, что видела эта сессия, и печатать строку с именем изменения, если хеш другой (F-32). Первое обращение сессии SHALL только запоминать хеш. Запись самого агента отличить нельзя: лишняя строка допустима (Р20 части 1). Строка SHALL быть только сигналом: схема не источник истины, а удобное представление для человека, поэтому работа агента SHALL NOT прерываться (слово к F-74).

#### Scenario: Первое обращение
- **GIVEN** активное изменение со `scheme.md`
- **WHEN** сессия обращается впервые
- **THEN** строки о схеме нет, хеш запомнен

#### Scenario: Правка между обращениями
- **GIVEN** сессия обращалась, затем `scheme.md` изменения `demo` сохранён с другим содержимым
- **WHEN** сессия обращается снова
- **THEN** вывод называет `demo`; следующее обращение без правки этой строки не даёт

#### Scenario: Сохранение без правки
- **GIVEN** файл перезаписан тем же содержимым
- **WHEN** сессия обращается снова
- **THEN** строки о схеме нет

#### Scenario: Файл появился в работающей сессии
- **GIVEN** на первом обращении `scheme.md` у `demo` не было
- **WHEN** файл появился и сессия обращается снова
- **THEN** вывод называет `demo`

#### Scenario: Только сигнал
- **GIVEN** вывод называет изменившийся `scheme.md`
- **WHEN** тест читает строку
- **THEN** код выхода 0, запрос дошёл до модели, в строке сказано об изменении, а просьбы остановиться или приказа действовать нет

### Requirement: Хук не останавливает запрос человека
Хук MUST NOT останавливать запрос человека ни при каком сбое: падение скрипта, файла скрипта нет, путь к Python мёртв (F-52, F-69). Код выхода 2 блокирует запрос у Claude Code, а Python сам выходит с ним без файла, поэтому записи SHALL быть устроены так, чтобы этого кода клиент не получил. Оболочка opencode SHALL ловить всё: необработанное исключение там тоже останавливает запрос.

#### Scenario: Файла скрипта нет у Claude Code
- **GIVEN** запись на месте, `.symphysis/viewer/` снят, например `git clean -fdX`
- **WHEN** человек отправляет запрос
- **THEN** запрос доходит до модели

#### Scenario: Скрипт вышел с кодом 2
- **GIVEN** скрипт на месте и выходит с кодом 2
- **WHEN** человек отправляет запрос
- **THEN** запрос доходит до модели

#### Scenario: Скрипт упал
- **GIVEN** файл журнала событий с битой строкой или нет прав на запись курсора
- **WHEN** человек отправляет запрос
- **THEN** запрос доходит до модели, причина видна только в следе скрипта

#### Scenario: Python переехал
- **GIVEN** запись указывает на путь, которого больше нет
- **WHEN** человек отправляет запрос
- **THEN** запрос доходит до модели

#### Scenario: Сбой в оболочке opencode
- **GIVEN** файла скрипта нет, путь к Python мёртв или вызов упал
- **WHEN** человек отправляет запрос в opencode
- **THEN** запрос доходит до модели

### Requirement: Плагин ставит хук сам там, где он нужен
При активации и при появлении инструментов плагин SHALL ставить хук без действия человека, если в корне папки есть `openspec/`, найдены инструменты и есть след клиента (F-47, F-60, F-65, F-76): `.claude/`; `.opencode/` или `opencode.json(c)`. Инструменты по настройке и в `tools/` считаются только при `schema: symphysis` в `openspec/config.yaml` (F-75, F-98). Предположение: при `-g` проект называет эту схему; решить на этапе `-g` (F-92). Выбор клиентов придёт позже (F-58).

#### Scenario: Проект с журналом и следом Claude Code
- **GIVEN** `openspec/`, `.symphysis/tools/`, `.claude/`
- **WHEN** плагин активируется
- **THEN** запись Claude Code есть, файла opencode нет

#### Scenario: Оба следа
- **GIVEN** `openspec/`, инструменты, `.claude/` и `.opencode/`
- **WHEN** плагин активируется
- **THEN** записи есть у обоих клиентов

#### Scenario: Нет следа клиента
- **GIVEN** `openspec/` и инструменты, ни одного следа
- **WHEN** плагин активируется
- **THEN** плагин ничего не пишет

#### Scenario: Проект без `openspec/`
- **GIVEN** задан `symphysis.toolsPath`, в проекте `.claude/`, но нет `openspec/`
- **WHEN** плагин активируется
- **THEN** плагин ничего не пишет

#### Scenario: Инструменты по настройке
- **GIVEN** `openspec/` со `schema: symphysis` в `openspec/config.yaml`, `.claude/`, инструменты только по `symphysis.toolsPath`
- **WHEN** плагин активируется
- **THEN** запись Claude Code есть

#### Scenario: Python не найден
- **GIVEN** плагин не нашёл Python
- **WHEN** плагин активируется
- **THEN** плагин ничего не пишет, причину называет то же место, что и просмотрщик

#### Scenario: Две папки в рабочей области
- **GIVEN** две папки, условие выполнено только у одной
- **WHEN** плагин активируется
- **THEN** запись появляется только в этой папке

#### Scenario: Проект на обычном OpenSpec
- **GIVEN** `openspec/` без `schema: symphysis` в `openspec/config.yaml`, инструменты только по `symphysis.toolsPath`
- **WHEN** плагин активируется
- **THEN** плагин ничего не пишет

#### Scenario: Инструменты поставлены при открытом окне
- **GIVEN** плагин активирован без инструментов
- **WHEN** появились `.symphysis/tools/journal.py` и `openspec/`
- **THEN** условие проверяется снова, хук встаёт без перезагрузки окна

#### Scenario: Чужой `tools/journal.py`
- **GIVEN** `tools/journal.py` чужого проекта, `openspec/` без `schema: symphysis`, `.claude/`
- **WHEN** плагин активируется
- **THEN** плагин ничего не пишет

#### Scenario: Причина называется один раз
- **GIVEN** хук не поставлен, человеку показано предупреждение с файлом и причиной
- **WHEN** плагин активируется снова с той же причиной
- **THEN** второго предупреждения нет; при новой причине оно показано снова

### Requirement: Скрипт хука приходит из пакета плагина
Скрипт хука SHALL лежать в `.symphysis/viewer/` и SHALL приходить из пакета плагина: при активации плагин SHALL заменять файл, если он отличается от пакетного (F-31, F-63). Инсталлятор ядра этот каталог SHALL NOT стирать. Один скрипт SHALL обслуживать обоих клиентов (F-68).

#### Scenario: Скрипта нет
- **GIVEN** условие установки выполнено, файла скрипта нет
- **WHEN** плагин активируется
- **THEN** файл появился и совпадает с пакетным

#### Scenario: Файл подменён
- **GIVEN** файл скрипта отличается от пакетного
- **WHEN** плагин активируется
- **THEN** файл заменён пакетным

#### Scenario: Файл совпадает
- **GIVEN** файл совпадает с пакетным
- **WHEN** плагин активируется
- **THEN** время изменения файла прежнее

### Requirement: Запись Claude Code лежит в `.claude/settings.local.json`
Плагин SHALL дописывать запись `UserPromptSubmit` в `.claude/settings.local.json` без оболочки: `command` — абсолютный путь к настоящему исполняемому файлу Python, путь скрипта через `${CLAUDE_PROJECT_DIR}` (F-31, F-48, F-52). Чужие настройки и хуки SHALL сохраняться. Вторую запись плагин SHALL NOT добавлять. При активации путь SHALL сверяться и переписываться, если Python переехал (F-57).

#### Scenario: Файла нет
- **GIVEN** `.claude/` без `settings.local.json`
- **WHEN** плагин активируется
- **THEN** файл создан, в нём одна запись

#### Scenario: Чужие настройки и хуки
- **GIVEN** в файле разрешения и чужой хук `UserPromptSubmit`
- **WHEN** плагин активируется
- **THEN** они на месте без изменений, запись плагина рядом; при запросе срабатывают оба

#### Scenario: Повторная активация
- **GIVEN** запись плагина уже есть, Python тот же
- **WHEN** плагин активируется снова
- **THEN** файл байт в байт прежний

#### Scenario: Python переехал
- **GIVEN** в записи путь к Python, которого больше нет, плагин нашёл другой
- **WHEN** плагин активируется
- **THEN** путь в записи новый, запись одна

#### Scenario: Путь с пробелом и кириллицей
- **GIVEN** проект в каталоге с пробелом и кириллицей
- **WHEN** человек отправляет запрос
- **THEN** хук срабатывает, его вывод виден модели

#### Scenario: Файл настроек не разбирается
- **GIVEN** файл настроек не разбирается как JSON, например в нём комментарий
- **WHEN** плагин активируется
- **THEN** файл байт в байт прежний, записи нет, человеку один раз названы файл и причина

#### Scenario: Пустой файл настроек
- **GIVEN** файл настроек нулевой длины
- **WHEN** плагин активируется
- **THEN** он считается пустыми настройками, запись плагина в нём

### Requirement: Файл opencode лежит в `.opencode/plugins/`
Плагин SHALL класть `.opencode/plugins/symphysis-hook.js` и SHALL NOT править `opencode.json` (F-49). Файл SHALL быть оболочкой над тем же Python-скриптом: хук `prompt` кладёт новое запись `instructions.entry` с ключом `symphysis`, новых событий нет — запись снимается (F-67, F-68). Предположение: Desktop и фоновый сервис грузят файл так же, как CLI, а работающий сервер подхватывает новый файл; проверить при реализации (F-49).

#### Scenario: Установка
- **GIVEN** `openspec/`, инструменты, `.opencode/` без файла плагина
- **WHEN** плагин активируется
- **THEN** файл есть, `opencode.json` не менялся

#### Scenario: Новые события
- **GIVEN** файл на месте, внесено событие
- **WHEN** человек отправляет запрос в сессии opencode
- **THEN** модель видит событие, слова запроса не изменены

#### Scenario: Новых событий нет
- **GIVEN** запись `symphysis` есть с прошлого обращения, новых событий нет
- **WHEN** человек отправляет запрос
- **THEN** запись снята

#### Scenario: Та же сессия
- **GIVEN** сессия opencode видела событие и продолжена с тем же номером
- **WHEN** человек отправляет запрос без новых событий
- **THEN** события в инструкциях нет

#### Scenario: Файл совпадает с нужным
- **GIVEN** файл плагина уже написан с тем же путём к Python
- **WHEN** плагин активируется
- **THEN** файл байт в байт прежний и не перезаписан

#### Scenario: Чужой файл с тем же именем
- **GIVEN** `symphysis-hook.js` без метки этого плагина
- **WHEN** плагин активируется
- **THEN** файл не тронут, запись opencode не ставится, причина названа

### Requirement: Файлы хука спрятаны от git
Файлы, которые плагин создаёт для хука, SHALL быть записаны строками в `.git/info/exclude`: путь к нему SHALL давать сам git, а `git` SHALL разрешаться абсолютным путём без каталогов рабочей области (F-66). Рабочее дерево SHALL NOT менять ничего, кроме самих файлов хука. Строки человека плагин SHALL NOT трогать.

#### Scenario: Обычный репозиторий
- **GIVEN** репозиторий с чистым `git status`, след Claude Code
- **WHEN** плагин активируется
- **THEN** `git status` по-прежнему чист

#### Scenario: Worktree
- **GIVEN** проект открыт в рабочем дереве `git worktree`
- **WHEN** плагин активируется
- **THEN** строки в файле, который назвал git, `git status` чист

#### Scenario: Проект без git
- **GIVEN** каталог без репозитория
- **WHEN** плагин активируется
- **THEN** запись ставится, про git ничего не требуется и не говорится

#### Scenario: `git` не найден
- **GIVEN** есть `.git`, а `git` не найден
- **WHEN** плагин активируется
- **THEN** файлов хука нет: спрятать их нечем; причина названа

#### Scenario: Повторная активация
- **GIVEN** строки уже есть
- **WHEN** плагин активируется снова
- **THEN** строк не прибавилось

#### Scenario: Такая же строка человека
- **GIVEN** человек сам написал в `.git/info/exclude` ту же строку
- **WHEN** хук снимается
- **THEN** его строка на месте

#### Scenario: Файл настроек отслеживается git
- **GIVEN** `.claude/settings.local.json` отслеживается git
- **WHEN** плагин активируется
- **THEN** файл не тронут, записи Claude Code нет, причина названа

#### Scenario: Два рабочих дерева
- **GIVEN** хук стоит в двух рабочих деревьях `git worktree`
- **WHEN** его снимают в одном
- **THEN** строки `exclude` остаются, пока файлы хука есть в другом

#### Scenario: Файл opencode отслеживается git
- **GIVEN** `.opencode/plugins/symphysis-hook.js` отслеживается git
- **WHEN** плагин активируется
- **THEN** файл не тронут, запись opencode не ставится, причина названа

### Requirement: Выключатель снимает хук
Настройка `symphysis.hook.enabled`, по умолчанию включена, SHALL управлять хуком (F-61). Выключено: плагин SHALL снимать свою запись, свой файл opencode и свои строки exclude и больше их не ставить. Чужие настройки и хуки SHALL оставаться. Файл настроек, в котором не осталось ничего, плагин SHALL удалять: иначе он останется виден git. Действует сразу в открытых проектах, в остальных при следующей активации.

#### Scenario: Выключение
- **GIVEN** хук стоит у обоих клиентов, файл настроек создан плагином
- **WHEN** человек выключает настройку
- **THEN** файла настроек нет, файла opencode нет, строк exclude нет, `git status` как до установки

#### Scenario: Чужое остаётся
- **GIVEN** в файле настроек разрешения и чужой хук
- **WHEN** человек выключает настройку
- **THEN** они на месте, записи плагина нет

#### Scenario: Активация при выключенной настройке
- **GIVEN** настройка выключена, условие установки выполнено
- **WHEN** плагин активируется
- **THEN** записи нет, а старая запись этого проекта снята

#### Scenario: Включение снова
- **GIVEN** настройка выключена, хук снят
- **WHEN** человек включает настройку
- **THEN** запись снова на месте без перезагрузки окна

#### Scenario: Запись удалена руками
- **GIVEN** настройка включена, человек удалил запись руками
- **WHEN** плагин активируется
- **THEN** запись снова на месте: снять её насовсем можно только настройкой

#### Scenario: Чужой файл opencode
- **GIVEN** `symphysis-hook.js` без метки этого плагина
- **WHEN** человек выключает настройку
- **THEN** файл на месте

#### Scenario: Файл настроек не разбирается при снятии
- **GIVEN** в файле запись плагина, файл не разбирается как JSON
- **WHEN** человек выключает настройку
- **THEN** файл байт в байт прежний, причина названа; клиент такой файл не читает, запись снимется при первой активации после починки

#### Scenario: Выключение в одном проекте
- **GIVEN** `symphysis.hook.enabled` равен `false` только в настройках рабочей области
- **WHEN** плагин активируется в этом проекте и в другом
- **THEN** в этом записи нет, в другом хук стоит

### Requirement: Пакет плагина не выходит без описания хука
Пакет плагина MUST NOT выходить без описания хука: в `.vsix` SHALL быть `README.md`, называющий, что плагин пишет в проекте (`.claude/settings.local.json`, `.opencode/plugins/`, `.git/info/exclude`, `.symphysis/viewer/`), настройку `symphysis.hook.enabled` и как убрать хук руками, в том числе после удаления плагина (F-82, F-87). Тест упаковки SHALL читать собранный пакет.

#### Scenario: Описание в пакете
- **GIVEN** собранный `.vsix`
- **WHEN** тест упаковки читает его `README.md`
- **THEN** в нём названы записи плагина, `symphysis.hook.enabled` и как убрать хук руками

#### Scenario: Описания нет
- **GIVEN** сборка без `README.md` или без этих строк
- **WHEN** выполняется тест упаковки
- **THEN** тест красный и называет, чего нет
