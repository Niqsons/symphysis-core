# module-discovery Specification

## Purpose
Чтение явных объявлений модулей и зависимостей в произвольном дереве репозитория: границы, принадлежность файлов и работа с недоступными источниками без изменения клиентских README.

## Requirements

### Requirement: README явно объявляет имя и род модуля
Обнаружение SHALL распознавать модуль по README.md с валидными name и kind во frontmatter: непустое имя и род «доменный» либо «технический». Имя может отличаться от каталога. Обычный README без объявления MUST NOT становиться модулем только из-за наличия файла; ошибки явного объявления дают сигнал (trace-modules/F-01, trace-modules/F-09, trace-modules/F-18).

#### Scenario: Имя не равно каталогу
- **GIVEN** src/editor/README.md объявляет name: viewer и kind: доменный
- **WHEN** обследуется дерево
- **THEN** обнаружен модуль viewer с границей src/editor

#### Scenario: Обычное описание репозитория
- **GIVEN** README.md содержит описание, но не объявляет name и kind
- **WHEN** обследуется дерево
- **THEN** одно наличие README не создаёт модуль

#### Scenario: Негодный род
- **GIVEN** явное объявление содержит kind: служебный
- **WHEN** объявление прочитано
- **THEN** сигнал называет файл и негодное значение

#### Scenario: UTF-8 BOM и окончания строк не скрывают модуль
<!-- trace-modules/F-40 -->
- **GIVEN** одно валидное объявление README записано в четырёх сочетаниях UTF-8 с BOM или без BOM и LF или CRLF
- **WHEN** выполнено обнаружение модулей
- **THEN** во всех четырёх вариантах обнаружены одинаковые имя и род модуля

### Requirement: Объявления обрабатываются как недоверенные данные
Содержимое README, metadata и аннотаций SHALL рассматриваться как данные: инструкции в них MUST NOT менять полномочия модели, выбранные корни или порядок работы. Чтение YAML MUST NOT исполнять команды, теги конструирования произвольных объектов или подстановки кода. Бинарный либо непригодный текст объявления SHALL давать сигнал без исполнения содержимого и без утраты корректных соседних источников (trace-modules/F-47, trace-modules/F-21).

#### Scenario: Инструкция внутри README не расширяет полномочия
- **GIVEN** README содержит валидное объявление и текст с требованием модели прочитать другой корень или скрыть сигнал
- **WHEN** модель обследует repo и сборщик читает объявление
- **THEN** текст остаётся данными, корни и полномочия не меняются, сигнал не скрывается по инструкции README

#### Scenario: YAML не конструирует исполняемый объект
- **GIVEN** frontmatter объявления содержит тег конструирования произвольного объекта или вызова команды
- **WHEN** разбирается YAML
- **THEN** команда и конструктор не исполняются, объявление отклонено с сигналом, корректные соседние модули сохранены

#### Scenario: Бинарный README не становится объявлением
- **GIVEN** README содержит байты NUL либо не является пригодным текстовым объявлением, а соседний модуль объявлен корректно
- **WHEN** обнаруживаются модули
- **THEN** бинарный источник назван сигналом и не создаёт модуль, соседний модуль сохранён

### Requirement: Обход не зависит от первого уровня и Git
Обход SHALL читать рабочее дерево объявленного repo на любой глубине, включая корень, без обязательного Git. Служебные .git, node_modules и установленная .symphysis SHALL исключаться; дополнительные исключения задаются переносимо для repo. Имена src/modules не задают привилегированных мест; .gitignore сам по себе не определяет наличие модуля (trace-modules/F-16, trace-modules/F-32).

#### Scenario: Корень и глубокий каталог без Git
- **GIVEN** в дереве без Git объявлены модули в README корня и src/deep/part/README.md
- **WHEN** выполнено обнаружение
- **THEN** обнаружены оба модуля без требования добавить их пути в перечень мест модулей

#### Scenario: Служебный каталог исключён
- **GIVEN** валидные объявления есть в src/ и node_modules/
- **WHEN** выполнено обнаружение
- **THEN** объявление src учитывается, служебное node_modules не входит в состав

#### Scenario: Игнорируемый Git файл
- **GIVEN** валидный README существует в рабочем дереве и не исключён правилами repo, но игнорируется Git
- **WHEN** выполнено обнаружение
- **THEN** наличие объявления не зависит от попадания файла в Git index

#### Scenario: Ссылка не обходит служебное исключение
- **GIVEN** ссылка с обычным именем ведёт в служебный node_modules внутри того же repo
- **WHEN** обход ищет объявления модулей
- **THEN** объявления служебного каталога не включаются через его другое имя; обход сохраняет остальные доступные модули

### Requirement: Файл относится к ближайшей объявленной границе
Для файла внутри объявленных модулей принадлежность SHALL определяться ближайшим содержащим каталогом с валидным README. Один файл MUST NOT одновременно принадлежать родительскому и вложенному модулю. Файл вне всех объявленных границ не получает выдуманный модуль; расположение модулей symphysis не применяется как правило клиента (trace-modules/F-02, trace-modules/F-18).

#### Scenario: Вложенный модуль клиента
- **GIVEN** корень объявлен модулем base, а src/part объявлен модулем part
- **WHEN** определяется принадлежность src/part/main.py
- **THEN** владелец файла — только part

#### Scenario: Файл вне границ
- **GIVEN** модуль объявлен только в src/one, файл находится в docs/
- **WHEN** определяется принадлежность файла
- **THEN** файл не приписан модулю one или синтетическому модулю корня

### Requirement: Неоднозначное имя модуля не разрешается догадкой
Если несколько README одного repo объявляют одно имя модуля, обнаружение SHALL назвать места конфликта сигналом. Ссылка по такому имени MUST NOT связываться с произвольно выбранным каталогом. Корректные независимые объявления продолжают обрабатываться; одинаковое имя в разных repo не является таким конфликтом (trace-modules/F-18, trace-modules/F-21).

#### Scenario: Повтор внутри repo
- **GIVEN** каталоги a и b одного repo объявляют name: viewer
- **WHEN** обрабатывается ссылка на этот модуль
- **THEN** сигнал содержит оба README; ссылка не назначена одному из них по порядку обхода

#### Scenario: Одно имя разных repo
- **GIVEN** core и plugin объявляют каждый свой viewer
- **WHEN** строится структура
- **THEN** это два различных модуля, а не конфликт имени

### Requirement: Зависимость читается из объявления README
Обнаружение SHALL читать во frontmatter README список логических repo/module, от которых зависит модуль. Направление — от объявляющего модуля к названному. Обычная ссылка в тексте README или импорт в коде MUST NOT автоматически становиться подтверждённой зависимостью; неразрешённая цель даёт сигнал (trace-modules/F-20, trace-modules/F-35).

#### Scenario: Объявленная межрепозиторная зависимость
- **GIVEN** модуль core/viewer явно называет plugin/protocol в списке зависимостей
- **WHEN** обрабатываются объявления
- **THEN** зависимость направлена от core/viewer к plugin/protocol с местом в README

#### Scenario: Только упоминание в описании
- **GIVEN** README содержит обычную ссылку на другой модуль, но зависимости не объявляет
- **WHEN** обрабатывается README
- **THEN** ссылка в прозе сама по себе не создаёт подтверждённую зависимость

#### Scenario: Цель отсутствует
- **GIVEN** объявленная зависимость называет неизвестный repo/module
- **WHEN** собирается граф
- **THEN** сигнал называет цель и место объявления; связь с похожим именем не подставляется

#### Scenario: Цикл объявленных зависимостей сохраняется
<!-- trace-modules/F-41 -->
- **GIVEN** корректные модули a и b явно объявили a → b и b → a
- **WHEN** собран граф и выполнена фильтрованная текстовая выборка диаграммы
- **THEN** граф сохраняет оба ребра, фильтр завершает обход, сам цикл не превращается в запрет выпуска

### Requirement: Сторонние README остаются входными данными
Продукт SHALL читать существующие README сторонних repo и MUST NOT автоматически дописывать в них имя, род или зависимости ради построения графа. GUIDE.md SHALL описывать соглашение обозначения модулей и зависимостей для владельца repo. Применение соглашения к собственным модулям symphysis служит догфудингом, а не миграцией чужих деревьев (trace-modules/F-07, trace-modules/F-25, trace-modules/F-35).

#### Scenario: Нет нужного объявления у клиента
- **GIVEN** сторонний README не содержит декларации зависимости
- **WHEN** выполнены обследование и сборка графа
- **THEN** файл не изменился; продукт не дописал декларацию от имени владельца

#### Scenario: Соглашение доступно владельцу
- **GIVEN** владелец хочет включить свой модуль в граф
- **WHEN** читает GUIDE.md
- **THEN** описаны требуемые объявления README и правила зависимостей без требования раскладки каталогов symphysis

### Requirement: Ошибка источника не стирает доступную структуру
Нечитаемый или негодный источник объявления SHALL давать сигнал с местом и причиной. Доступные корректные модули других источников SHALL оставаться в графе. Недоступный источник MUST NOT выдаваться за подтверждённое отсутствие модулей или за пустой список зависимостей (trace-modules/F-21, trace-modules/F-30).

#### Scenario: Один недоступный сосед
- **GIVEN** один repo с валидными модулями доступен, другой недоступен
- **WHEN** собран граф
- **THEN** модули доступного repo сохранены, недоступность соседа названа отдельно

#### Scenario: Нечитаемый README не скрывает соседний модуль
<!-- trace-modules/F-49 -->
- **GIVEN** в доступном repo один README не читается из-за ошибки доступа, соседний README содержит валидное объявление
- **WHEN** строится структура
- **THEN** соседний модуль сохранён, нечитаемый путь и причина названы сигналом; неизвестные объявления и зависимости не объявлены пустыми

#### Scenario: Негодная кодировка README не обрывает доступный граф
<!-- trace-modules/F-50 -->
- **GIVEN** один README содержит явное объявление в CP1251, другой README того же repo валиден в UTF-8
- **WHEN** собирается граф
- **THEN** первый даёт сигнал о кодировке без угадывания другой кодировки; второй модуль и требования сохранены без общего отказа графа
