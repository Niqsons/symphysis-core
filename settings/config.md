# Состав шага из личной настройки

Общий файл скиллов `symphysis-*`: как шаг узнаёт свой состав — какие части включены личным
`symphysis.yaml` проекта. Справка скрипта — `symphysis config --help`.

## Вызов

```bash
symphysis config
```

Вывод — одна строка состава и, возможно, строки сигналов:

```text
[..] symphysis.yaml: ветки отказа вкл, допущения вкл, проба краёв вкл, водители: атака вкл, пробы выкл, опись выкл, исследование вкл
[!!] symphysis.yaml: <что не так>
```

Какая часть нужна шагу, говорит тело скилла: описи — «ветки отказа» и «допущения», пробе
краёв — «проба краёв». Часть «водители» — у скиллов с разделом «Водитель»: «атака» —
`symphysis-attack`, «пробы» — `symphysis-edge-probe` и `symphysis-prohibition-probe`,
«опись» — `symphysis-consequences`, «исследование» — `symphysis-research`.

## Правила

- После успешного preflight скилл MUST позвать `symphysis config` один раз, до расчёта шага, и дальше идти по напечатанному
  составу; второй вызов в том же запуске бесполезен: правка файла действует со следующего
  запуска шага.
- Скилл MUST NOT читать и MUST NOT править `symphysis.yaml`: значение `no` там выбор не
  выключает, а модель прочла бы его как выключение, и шаг пошёл бы по чужому составу.
- Скилл MUST NOT спрашивать человека о составе: состав — его личная настройка, вопрос о ней
  повторял бы уже сделанный выбор.
- Если под составом есть строка `[!!]` (недопустимое значение, файл не разбирается, нет пакета
  PyYAML) — шаг идёт по напечатанному составу: при сомнении скрипт считает выбор включённым,
  и строка это уже учитывает; файл не чинится; строку `[!!]` скилл MUST передать человеку в итоге
  дословно, иначе человек не узнает, что его настройка не прочитана.
- Отказ dispatcher, preflight, выбора store, совместимости, busy или получения ресурса —
  остановка без записи файлов; скилл MUST передать диагностику человеку. Такой отказ MUST NOT
  превращаться в состав по умолчанию: непроверенная поставка не исполняет шаг.
- Если после успешного preflight сам расчёт состава не запустился — скилл MUST считать части шагов включёнными,
  а водителей — по умолчанию (атака и исследование вкл, пробы и опись выкл) и назвать это
  в итоге.
- Если у скилла водитель «вкл» и у клиента есть субагенты — главная нить MUST написать brief
  и позвать водителя по разделу «Водитель» тела; если «выкл», или у клиента нет субагентов,
  или в каталоге агентов клиента нет тела `symphysis-<скилл>-driver` —
  те же такты идут в главной нити по тому же телу, brief и отчёт не пишутся: водитель без
  brief невоспроизводим, а главная нить без водителя теряет только изоляцию контекста.
- Состав шага SHOULD стоять в выходном файле шага строкой `**Состав:**` при любом выводе: без
  неё по файлу не отличить «всё включено» от «настройки не читали».
