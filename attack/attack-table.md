# Таблица атаки

Общий файл скиллов `symphysis-attack` (пишет файлы `attack/decisions.md`, `attack/artifacts.md`)
и `symphysis-viewer` (показывает их в режиме «атака»). Норма одна: как строка пишется и как её
читает парсер `symphysis journal render-html --attack`.

## Столбцы

Семь столбцов в этом порядке; заголовок — как в шаблоне артефакта:

| Утверждение | Раздел | Линза | Инвариант | Тяжесть | Опора есть / нет | Чем закрыть |
| --- | --- | --- | --- | --- | --- | --- |

- **Утверждение** — одно утверждение цели: цитата или пересказ с номером строки; у `scenario-run` —
  сценарий `<файл>, <требование> / <сценарий>`.
- **Раздел** — у журнала `<F-NN>, <поле>`; у артефактов `<файл>, <место>`; у `scenario-run` —
  механизм design (решение `F-NN` или раздел).
- **Линза** — slug из закрытого списка своего файла, латиницей: у журнала `context-compliance`,
  `claim-authority`, `claim-extraction`, `coverage`; у артефактов `scenario-run`,
  `claim-extraction`, `trace-link`, `rule-compliance`. Slug не из списка — группа «вне списка», строка невалидна: в счётчике линз
  её нет, в счётчике тяжести есть.
- **Инвариант** — нарушенное свойство, не правка: «у задачи есть проверка», а не «добавь
  проверку»; у строк покрытия («чисто», «не пройдено») — `—`.
- **Тяжесть** — `блокер | предупреждение | справка`. По опоре: у «нет» — тяжесть линзы; у «по спеке
  не выводится» — всегда `предупреждение`; у «есть» — `справка`. Иная — только по слову человека,
  причина в скобках в той же ячейке: либо `<тяжесть> (<обоснование>)`, внесённое `apply` строкой
  о тяжести (понижение блокера, повышение предупреждения, у «по спеке не выводится» тоже), либо
  `предупреждение (решено человеком в F-NN)` по записи журнала — она остаётся годной; без причины
  страница показывает «понижение без причины». У `rule-compliance` тяжесть
  линзы при опоре «нет» двух видов: `блокер` у пропавшего условия мастер-текста, сомнения в нём
  и требования, которого в мастер-спеке нет; `предупреждение (правило составления)` у прочих правил —
  причина в скобках постоянная, это тяжесть линзы, не понижение, слова человека она не требует;
  страница показывает её «понижено: правило составления», голое `предупреждение` у такой строки —
  «понижение без причины».
  У `context-compliance` для двух выбранных антиподов тяжесть линзы —
  `предупреждение (оба антипода выбраны)` с постоянной причиной в скобках. Слово человека
  о тяжести не требуется. Страница показывает «понижено: оба антипода выбраны».
- **Опора** — `есть: путь:строка «цитата»` (у журнала — только цитата или решённая `F-NN`),
  `нет: <на чём держится>`, либо `по спеке не выводится`.
- **Чем закрыть** — путь, не предписание: у журнала `исследование | вопрос человеку | правка
  записи`; у артефактов `правка артефакта | запись журнала | вопрос человеку`; у обоих `повторить
  атаку по разделу`; нечего закрывать — `—`.

Строка без линзы, тяжести или инварианта невалидна: парсер её отвергает, вердикт по ней
не считается.

## Мастер-опоры

Если `scenario-run` использует блок мастер-спеки как опору, автор отчёта MUST записать
идентификаторы и SHA-256 блока в отдельное верхнеуровневое поле `master_supports` frontmatter.
Поле — однострочный JSON-массив. Элемент содержит `capability`, `requirement`, необязательное
`scenario` и `sha256`. В массив идут только блоки, на которые опираются строки атаки.
Найденный при поиске соседний блок сам по себе опорой не становится, иначе его правка даст ложный `stale`.

`capability` — логическое имя, включая вложенное `identity/user-auth`; требование и сценарий
именуются заголовками. Путь выводится из выбранного корня планирования и `openspec/specs/`.
Абсолютные имена, компоненты `..` и выход по ссылке за выбранный корень или каталог мастер-спек
отклоняются до чтения. Метаданные MUST содержать только идентификаторы и отпечатки, иначе отчёт
скопирует исходный текст или абсолютный путь. Цели `targets[]` продолжают именовать файлы внутри изменения.

Отпечаток вычисляется по строгому UTF-8 с удалением BOM только в начале файла и заменой CRLF/CR
на LF. Блок начинается исходным заголовком и заканчивается перед следующим заголовком того же
или высшего уровня вне fenced-блока кода, либо в конце файла. Разделительные пустые строки,
комментарии и пробелы входят в отпечаток; блок требования включает сценарии. Используй
`master_support` из `attack_master` при чтении используемого блока и сохрани полученный объект,
иначе свёртка пробелов или хеш всего файла изменит область опоры. Перед оценкой строки сверь,
что `master_block` того же модуля даёт блок с сохранённым отпечатком; оценивай прочитанный блок.

Для воспроизводимой записи автор MUST получить `symphysis resolve --json` с теми же селекторами,
сохранить доверенный stdout в UTF-8 в `<resolve.json>` и взять корень из `store.root`, инструменты
из `runtime.toolsRoot`. Значения полей отчёта источником этих путей не служат. В `<used-blocks.json>`
сохрани массив объектов `master_support`, полученных при чтении только использованных блоков,
включая исходный `sha256`. Рецепт перед записью сверяет сохранённые отпечатки с текущими блоками;
если блок изменился в ходе атаки, повтори проход по изменившейся опоре. Иначе отчёт присвоит новой
версии блока вывод, сделанный по прежнему содержимому.
Сохрани рецепт в `<write-master-supports.py>` в каталоге запуска и выполни
`python -I <write-master-supports.py> <resolve.json> <имя изменения> <used-blocks.json>`.
Иначе ручная запись отпечатков не воспроизводится при проверке свежести.

```python
import json
import os
import sys
import tempfile
from pathlib import Path

try:
    resolved = json.loads(Path(sys.argv[1]).read_text(encoding="utf-8-sig"))
    if resolved.get("status") != "ready":
        raise ValueError("runtime unavailable")
    planning_root = Path(resolved["store"]["root"]).resolve()
    changes = (planning_root / "openspec/changes").resolve()
    change = (changes / sys.argv[2]).resolve()
    report = (change / "attack/artifacts.md").resolve()
    if not changes.is_relative_to(planning_root) or change.parent != changes or not report.is_relative_to(change):
        raise ValueError("report outside selected change")
    sys.path.insert(0, str(Path(resolved["runtime"]["toolsRoot"]).resolve()))
    from attack_master import master_support, set_master_supports, validate_master_support
    used = json.loads(Path(sys.argv[3]).read_text(encoding="utf-8-sig"))
    if not isinstance(used, list):
        raise ValueError("used blocks must be a list")
    supports = [validate_master_support(selection) for selection in used]
    for support in supports:
        current = master_support(planning_root, support["capability"], support["requirement"], support.get("scenario"))
        if current != support:
            raise ValueError("used master block changed")
    updated = set_master_supports(report.read_bytes().decode("utf-8"), supports).encode("utf-8")
    with tempfile.NamedTemporaryFile(dir=report.parent, delete=False) as draft:
        draft.write(updated)
    try:
        os.replace(draft.name, report)
    finally:
        Path(draft.name).unlink(missing_ok=True)
except (OSError, UnicodeError, ValueError, TypeError, KeyError, IndexError):
    raise SystemExit("master-support metadata could not be written") from None
```

`set_master_supports` заменяет поле с сохранением остальных байтов отчёта, включая `targets[]`.
Ошибка чтения, неоднозначное имя или негодный блок не дают отпечатка. Автор MUST устранить
ошибку перед записью `passed` с этой опорой, иначе незаписанная опора выпадет из свежести.
Отчёт прежнего формата без поля проверяется по своим локальным целям.

## Строки покрытия

- Раздел журнала без находок — `| чисто | <раздел> | coverage | — | справка | есть | — |`.
- Раздел, до которого проход не дошёл, — `| не пройдено | <раздел> | coverage | — | блокер | нет | повторить атаку по разделу |`.
- Раздел строки покрытия у журнала — одна запись: `F-NN` или `F-NN, все поля`; диапазон
  `F-01–F-10` в разделе не пишется: состав устаревшего вердикта считается по номерам,
  стоящим в столбце дословно, и записи внутри диапазона считались бы не атакованными.
- У артефактов покрытие держит `scenario-run`: сценарий, до которого проход не дошёл, —
  `| <файл>, <требование> / <сценарий> | — | scenario-run | — | блокер | нет: не пройдено | повторить атаку по разделу |`.
- У `rule-compliance` строка покрытия — на файл цели: файл без находок линзы —
  `| чисто | <файл> | rule-compliance | — | справка | есть | — |`; файл, до которого проход не дошёл, —
  `| не пройдено | <файл> | rule-compliance | — | блокер | нет: не пройдено | повторить атаку по разделу |`.
  Ненаписанная цель строк `rule-compliance` не даёт, `consequences.md` вне `targets[]` — не цель.
- Цели нет (файл не написан) — у журнала строка «не пройдено» в разделе с именем файла;
  у артефактов строка `claim-extraction` с именем файла, опора `нет: файла нет`, `блокер`.

## Правило ячейки

- Черта в ячейке — только `\|` или внутри backticks; голая черта вне backticks — разделитель
  столбцов, и строка рассыпается.
- Цитата кода — в backticks. Литеральная обратная косая перед литеральной чертой в цитате кода
  пишется `\\|`: внутри backticks `\\|` читается как `\|`; вне backticks `\\` — литеральная
  косая, следующая черта — разделитель. Литеральная обратная косая в цитате кода пишется `\\`.
- Пустых ячеек нет: нет содержимого — `—`.
- Не семь ячеек, незакрытый backtick или пустая ячейка — ошибка парсера с файлом, строкой
  и столбцом, `render-html --attack` даёт код 2 и страницу не пишет. Чинит файл атаки тот, кто
  его писал: скилл `symphysis-attack`.
- Показ экранирован: разметка только `` `код` `` в `<code>`; `<b>` и прочие теги видны текстом.

## Что считает страница

- Счётчики тяжести «блокеров N · предупреждений N · справок N» — по всему файлу, вне фильтра по
  линзе: блокер виден при любом фильтре.
- Группировка строк — линза → тяжесть; фильтр по линзе прячет группы, но не счётчики.
- Раздел строки вида `F-NN, поле` с существующей записью — у строки блок перехода к карточке
  записи; ссылка — переход, не слияние сущностей.
- Строки атаки `apply` не меняет по спору: её закрывает правка цели и повторная атака; исключение — ячейка
  тяжести и `status` файла по строке о тяжести.
- Кнопки тяжести: «понизить» у `блокер`, «повысить» у `предупреждение`; у `справка` и строк покрытия
  («не пройдено», «нет: файла нет») кнопки нет. Обоснование — в своём скрытом поле, не в поле спора; кнопка
  берёт его при нажатии, нажатая без текста — «нет обоснования, строки о тяжести не будет»; повторное нажатие
  снимает отметку и обоснование. Отметка уходит в промпт возврата строкой над «Замечания к схеме:»:
  `- тяжесть: <путь файла атаки> · <раздел> · «<утверждение>» → <тяжесть> — «<обоснование>»`. `apply` пишет
  в ячейку `<тяжесть> (<обоснование>)`, пересчитывает `status` файла атаки (`passed` при нуле `блокер`);
  журнал не меняется; после `apply` строка из промпта уходит.
- Флаг «прочитано» — только у строк `предупреждение`: переключатель на карточке; отметка уходит в промпт
  возврата текстом «предупреждение прочитано: <раздел>» в строке «Замечания к схеме:» и ложится заметкой
  `notes[]`; флаг сверяется с заметками по разделу дословно, текст — отдельный сегмент заметки через « · »;
  у флага из журнала переключатель неактивен; строка остаётся на месте, тяжесть, счётчики и вердикт
  от флага не меняются.
