# symphysis-brainstorm

Брейншторм: намерение человека и материалы изменения → интервью по пяти перспективам →
журнал решений `decisions.json` с развилками, фактами и парковками → круг просмотрщика →
счёт круга. Изменение здесь — единица работы схемы, каталог `openspec/changes/<имя>/`;
решение — выбранный человеком вариант развилки, не проектное решение модели.

## Вход

- До первого изменяющего действия модель MUST выполнить `symphysis preflight --change <имя>`;
  селекторы `--project` и `--store`, если нужны, стоят перед подкомандой и одинаковы
  у всех вызовов. Отказ preflight или получения ресурса — остановка без записи файлов.
- Ссылки вида `symphysis resource ...` — команды: модель MUST прочитать их вывод
  целиком; это инструкции выбранной поставки, а не пути внутри store.
- `<каталог изменения>` — `openspec/changes/<имя>/`; термины — `symphysis resource doc terms.md`.
- Обследование repo и запись metadata — `symphysis resource doc module-declarations.md`.
- `<каталог изменения>/intent.md` — намерение человека и критерии готовности; читается
  первым и не правится.
- `<каталог изменения>/scheme.md` — схема решения, один блок mermaid `flowchart TD`; нужна
  человеку, шаги от неё не зависят.
- `<каталог изменения>/decisions.json` — журнал; шаблон уже лежит там (`title`, `source`,
  `intro`, `records: []`); ключи английские, значения русские.
- До первой записи журнала модель MUST прочитать целиком вывод
  `symphysis resource doc journal.schema.json`: схема задаёт обязательные поля и типы,
  иначе `check` отвергнет запись. Отказ команды — остановка без записи журнала.
- Материалы изменения — запрос человека, каталог изменения, файлы и каталоги, которые назвал
  человек, код и документы проекта по именам и литералам из `intent.md`.
- Круг — один проход по пяти перспективам; вопросы человеку идут порциями по 2–3, порция
  кончается ответом человека. Второй круг — в конце шага `research`, после отчётов.
- Команды и коды `journal.py` — `symphysis resource doc journal-cli.md`; круг просмотрщика — скилл
  `symphysis-viewer`.

## Выход

- Записи `decisions.json`: факты постановки, развилки с вариантами, уликами и одной
  рекомендацией, факты с уликами, парковки с адресатом; `title` и `intro` журнала.
- `scheme.md` на первом круге, если файла не было.
- `answers/<дата>-criteria.md` — ответ человека о критериях, если `intent.md` их не несёт.
- Строка `notes[]` «круг N закончен: …» на каждый круг; строка о конце брейншторма.
- Человеку: вопросы порциями в чат, ссылка на страницу после круга, вопрос «Начать новый круг?».

## Инварианты

1. **Решает человек, не модель.** Модель читает материалы, формулирует развилки
   с вариантами и уликами, пишет факты с цитатами и одну рекомендацию; `decision` MUST
   появляться только из слова человека через `apply`. Числового гейта ясности нет: круг
   кончается счётом новых решений и фактов и словом человека; иначе выбор модели уходит
   в артефакты, минуя человека.
2. **Вопрос, ответ на который лежит в материалах, человеку не задаётся.** Материалы MUST
   быть прочитаны до первого вопроса, найденное — записано фактом с уликой; вопрос, ответ
   на который уже в файлах, тратит порцию и учит человека не читать вопросы.
3. **Развилка решается в `symphysis.html` или в плагине, но решить человек может и в чате.**
   Слово из чата MUST вноситься тем же `apply`, дословно; запретить человеку писать в чат
   нельзя. Порядок показа и внесения — скилл `symphysis-viewer`.
4. **`intent.md` не правится.** Переработанное намерение живёт записями журнала, файл
   остаётся словами человека на входе: иначе сверить решения с постановкой будет не с чем.
5. **Находка с конструкцией — развилка, не предписание.** Если из находки напрашивается
   конструкция («по образцу X», «требует новой …») — модель MUST писать две записи:
   факт-наблюдение с цитатой и развилку с вариантами (образец X, иной путь, маловероятные
   с причиной) и одной рекомендацией; в факте — наблюдение, не предписание
   в `consequences`: design стоит на решении развилки, опору на факт атака считает блокером.

## Порядок

### 1. Прочитай намерение

Первым — `<каталог изменения>/intent.md`. Каждый критерий готовности из раздела «Критерии
готовности» — факт `addressee: постановка` (значение строчными, без пробелов): `question` —
`«Критерий готовности: <критерий>»`, одна улика: `path` — `openspec/changes/<имя>/intent.md`
(от корня проекта, как у всех улик), `quote` — строка критерия дословно; `status: решён`.
Факты постановки — первые записи журнала, по одному на критерий.

#### Состояния `intent.md`

- **`intent.md` пуст** (0 байт или одна строка заголовка): форк засчитывает `intent`
  по существованию файла, а читать нечего — сначала спроси намерение и сохрани ответ
  дословно по шаблону `intent.md` (слова — в «Намерение», критерии — в «Критерии
  готовности»), затем круг. Это единственная запись в `intent.md`; дальше он не правится.
- **Критериев ноль** — в `intent.md` их нет (раздела нет, он пуст, в нём одна мотивация)
  и фактов `addressee: постановка` в журнале нет: первый вопрос человеку в чат — «назови
  критерии готовности»; в `notes[]` — строка «намерение без критериев» с датой. Ответ
  сохраняется как есть в `<каталог изменения>/answers/<дата>-criteria.md`: каждый
  названный критерий — факт `постановка` с цитатой из этого файла; ответ «Без критериев
  готовности» — тоже факт `постановка` с этой цитатой: критерии заполнены. Факты постановки
  в журнале уже есть (критерии названы в `answers/<дата>-criteria.md`) — вопрос не задаётся,
  второй строки `notes[]` нет: `intent.md` не правится, и без журнала второй круг спросил бы
  снова. Строка «Без критериев готовности» в самом `intent.md` — заполненные критерии:
  вопроса нет, факт — по ней.
- **Второй круг** перечитывает `intent.md`: факт постановки с той же цитатой второй раз
  не заводится. Текст критерия изменился — новый факт только по слову человека: спроси
  в чат, заводить ли его.
<!-- src: F-13.A, F-17.A, F-24.E, F-43.E, F-44.E -->

#### Обследуй исходные repo

После чтения intent главная нить MUST выполнить протокол `symphysis resource doc module-declarations.md`
и сообщить результат по каждому участвующему repo: иначе круг не отличит отсутствие модулей
от отсутствия анализа. Повторный круг MUST уточнить состав и состояния по новым материалам
research, сохранив прежние записи и чужие поля metadata.
<!-- src: trace-modules/F-26, F-29–F-31, F-36, F-38–F-39 -->

### 2. Проверь схему решения

На первом круге, после `intent.md`: `<каталог изменения>/scheme.md`, один блок mermaid
`flowchart TD`; схема нужна человеку, шаги от неё не зависят.

- Файла нет, сценарий в `intent.md` есть: составь файл по сценарию и дай на него ссылку
  в чат.
- Файла нет и сценария нет: предложи своё видение сценария и задай вопросы; файл и ссылка —
  после составления.
- Файл есть: не меняй его и дай на него ссылку. Файл человека и файл оборвавшегося круга
  не различаются.
- Файл есть и противоречит `intent.md` (узел схемы или стрелка идёт против критерия
  готовности или сценария): спроси об этом человека в чат, файл не правь.
- Перед записью проверь ещё раз: файл появился, пока схема составлялась, — не перезаписывай,
  покажи свой вариант в чате.

Дальше файл меняется только по слову человека: он правит его сам и сам об этом говорит.
Просит поправить — правишь файл и даёшь ссылку. При закрытии круга о схеме не спрашивай
и утверждения файла не жди.
<!-- src: F-01, F-22, F-57, F-58, F-102; F3 владельца: противоречие схемы и intent.md -->

### 3. Прочитай материалы

Затем выполни запрос данных: прочитай запрос человека, каталог изменения, файлы и каталоги,
которые назвал человек, и найди в коде и документах проекта то, что названо в `intent.md`
по именам и литералам.

- Найденным считается то, что отвечает на критерий готовности, узел схемы или вопрос
  перспективы (шаг 4): такое идёт в журнал сразу фактом с уликой — путь и дословная цитата,
  не из памяти. Остальное прочитанное в журнал не пишется.
- Заполни `title` (`«Журнал решений: <изменение>»`) и `intro`: от какого корня считаются пути
  улик, какие материалы читались.
<!-- src: spec-phase.md:542; F5, F6, F7 владельца -->

### 4. Пройди перспективы по порядку

Перспектива без вопросов к этому изменению пропускается молча.

- **Исследователь (Researcher)** — текущее состояние: что уже есть в материалах изменения
  по теме; разница между сегодня и целью; что сломано или чего нет — откуда работа.
- **Упрощатель (Simplifier)** — минимальный объём: простейшая версия, решающая основную
  задачу; что останется, если срезать половину; что сделает изменение успешным без приятных
  мелочей.
- **Хранитель границ (Boundary Keeper)** — периметр: что в этом изменении точно не делается;
  какие соседние задачи тянет решить, а не надо; что включает в себя готовый результат.
- **Аналитик отказов (Failure Analyst)** — края, ломающие требования: худшее, если требования
  поняты неверно; как выглядит сломанная версия; из-за критики чего будет отвергнут
  артефакт (атака — скилл `symphysis-attack`).
- **Закрывающий (Seed Closer)** — остаток: развилка решения открыта — можно решить сейчас;
  о чём пожалеешь, если не решить до планирования.
<!-- src: spec-phase.md:28-51 вопросы перспектив; F8, F9, F10 владельца -->

### 5. Направь каждый вопрос

- **Ответ в материалах изменения** — человека не спрашивай: прочитай и запиши факт
  с уликой. Не прочитать сейчас (материалов нет, объём велик) — парковка `агент`: бриф
  исследованию, его ведёт агент исследования (артефакт `research`).
- **Выбор между вариантами** — развилка: запись с вариантами, уликами, одной рекомендацией;
  развилка решается в `symphysis.html` или в плагине, в чате сам выбор не предлагай, пока
  человек об этом не попросил.
- **Знает только человек, и это не выбор** (чего он хочет, что главное, что включает
  в себя готовый результат) — вопрос в чат, порцией. Ответ — развилка с одним вариантом или
  с вариантами, которые ответ назвал; слово человека дословно — в `apply` строкой
  `- F-NN: A — «слово»`: безальтернативная развилка тоже пишется как решение.
- **Канон ИБ** (инъекции, пути, токены, права, чувствительные данные) — парковка `ИБ`;
  записью журнала не становится, его закрывает чек-лист `security.md`.
- **Новая возможность, не уточнение этого изменения** — парковка `человек` в запись
  развилки, где всплыла: «новая возможность: …». Проверка: уточняет ли это, *как* сделать
  запланированное, или добавляет то, что могло бы быть своим изменением. Объём изменения
  в записях не растёт.

### 6. Запиши запись

Формат — JSON-схема из раздела «Вход»; `check` сверяет по ней.

#### Развилка

`kind: развилка`, `status: открыт`, `addressee: человек`:

- `question` — конкретная серая зона этого изменения, не категория («интерфейс»,
  «поведение» — нет; «что видит человек на пустом журнале» — да).
- `options[]` — все варианты (вариант — один из ответов развилки), включая маловероятные
  с `unlikely: причина` (без причины `check` отвергнет); у каждого `evidence[] {path,
  quote}` — путь от корня проекта и дословная строка файла; `text` варианта несёт всё, что
  человеку нужно для выбора: что будет при выборе, цена, различие по обратимости.
- `recommendation {option, why}` — одна, пишется после вариантов: человек находит её под
  списком, не первой строкой; `why` — причина выбора этого варианта против других, а не
  пересказ варианта: без неё выбор мимо рекомендации не с чем сравнить.
- `depends_on` — записи, без решения которых выбор здесь — догадка; `antipodes` — варианты
  других развилок, несовместимые с вариантом этой; `consequences` — что следует из решения.
- `decision: null` — его напишет `apply`.
- Вариант «ничего не менять» начинается словами «Оставить как есть»: по этому началу
  `render-design` ставит у решения пометку «конструкция не меняется».
- `nodes` — необязательный список идентификаторов узлов `scheme.md`, к которым относится
  запись; идентификатор дословно, как в схеме; подходящего узла нет — поля нет, это
  не дефект; `apply` поле не пишет, поменять просит человек в чате.

#### Отступление от постановки

Вариант, чьё наблюдаемое поведение противоречит сценарию факта `addressee: постановка`,
несёт поле `options[].deviation: F-NN` — номер этого факта. Пометка у варианта, не у записи:
при выборе видно, какой вариант отступает. Уточнение без противоречия (вариант сужает
критерий, сценарий факта остаётся верным) — без поля. Решает человек, как по любой развилке:
пометка — видимость, не замок; `check` годен и при выборе отступающего варианта, а развилку,
чей выбранный вариант несёт `deviation`, proposal назовёт в разделе «Отступления от постановки».
<!-- src: F-08.A, F-28.E, F-55.E -->

#### Запись, снимающая решение

Развилка, которая снимает прежнее решение (например, срез снимает исход Specify), называет
снятую запись в `depends_on`. Формат журнала не меняется. `outcome` снятой записи
не переписывается: он зеркалит слово человека. По этой связи скрипт графа показывает
подсказку «снято F-NN?»; без неё сигнал о снятом сценарии остаётся ложным.
<!-- src: F-46 изменения trace-graph -->

#### Факт

`kind: факт`, `options: []`, `addressee: агент` (факт из `intent.md` — `addressee:
постановка`, шаг 1): `question` — утверждение; `evidence[]` на записи — путь и цитата,
взятая из прочитанного файла, не по памяти; `status: решён`, когда улика есть. Факт без
улики не пишется — это парковка `агент`. `consequences` — какие записи на нём стоят.

#### Парковка

Элемент `parking[]` записи: `addressee` из трёх — `агент | человек | ИБ`, `text` —
вопрос с границами (что выяснить, где читать). Запись без решения с парковкой —
`status: припаркован`. Ответ агента исследования приходит файлом `research/<F-NN>.md`:
во втором круге внеси его в `finding`, цитаты — уликами.

### 7. Сверь после каждой записи

`check`, затем `render-md` (`symphysis resource doc journal-cli.md`). Код 1 — журнал негоден по
схеме или правилам (факт с вариантами, зависимость на несуществующую запись, антипод без
варианта): исправь до следующего шага. Строка `[!!]` «цитаты нет дословно» — сигнал, не стоп:
обычно это пересказ — открой файл и возьми строку как есть; «файла нет» — проверь путь.
<!-- src: F-12 сигнал, не стоп; F18 владельца: коды в общем файле -->

### 8. Проведи круг просмотрщика

Когда порции круга кончились:

- До показа сверь попарно новые варианты между собой и с уже выбранными, отвергнутые
  не смотри; несовместимая пара — поле `antipodes` у обоих вариантов. Антипод бывает только
  между разными записями: варианты одной развилки и так исключают друг друга, такой антипод
  `check` отвергнет кодом 1. Сверка идёт всегда и в этом же контексте, субагента для неё
  не заводи: он сверит имена, а не смысл.
- Круг просмотрщика — скилл `symphysis-viewer`, «Порядок»: сборка и проверка страницы,
  передача человеку, внесение слова промптом из чата или кнопкой плагина, парковка
  адресату `человек`, пересборка.
- После выбора сверь выбранные за круг решения между собой и с прежними решениями, тоже
  в этом же контексте. Находка — новая развилка об этом расхождении; пара, по которой
  развилка уже заведена, новой записи не даёт. Тексты вариантов, рекомендации и `decision`
  прежних записей сверка не меняет: решает человек.

### 9. Оцени обратимость

У каждой записи с `decision` и `reversibility: null` оцени, чего стоит отменить решение:
`level` — `обратимо | дорого | в одну сторону`, `why` — назови миграцию, контракт или
зависимую систему, не «трудно менять». Причина обязательна при любом уровне. Где варианты
различаются по обратимости, это MUST стоять в `text` варианта — до выбора: после выбора
человек узнал бы о цене поздно.

### 10. Закрой круг

Круг закончен, когда перспективы пройдены и круг просмотрщика (шаг 8) прошёл: развилка без
решения не закрывает круг, пока человек её не видел. Сосчитай за круг: K — новых решений
(записей, получивших `decision`), M — новых фактов, D — новых развилок, оставшихся без
решения, P — парковок `агент`, A — пары антиподов, найденные сверкой; ноль значит
«смотрел, таких нет». Закрой круг строкой `notes[]`:
`{date, text: «круг N закончен: решений K, фактов M, открытых развилок D, парковок агенту P, антиподов A»}`.
Дальше — первое подходящее:

- P > 0 — круг закрыт, вопрос о новом круге не задаётся: его задаст instruction `research`
  в конце шага `research`, после отчётов: закроет парковки находками и позовёт этот скилл.
- K = 0 и M = 0 — брейншторм закончен, только если и D = 0: `notes[]` ← «круг N без новых
  решений и фактов — брейншторм закончен». При D > 0 человек видел развилки и не решил ни
  одной — молча не заканчивай, спроси «Начать новый круг?».
- иначе спроси человека в чате: **«Начать новый круг?»** «Нет» — `notes[]` ←
  «брейншторм закончен по решению человека» с датой. «Да» — круг N+1 с шага 1 по открытым
  записям и находкам.

Числа кругов скилл не ограничивает: открытое без решения подхватят атака и Open Questions.
Строка о конце брейншторма новому кругу не мешает: человек просит ещё круг — идёт круг N+1,
прежняя строка остаётся, в конце новая. Номер круга N — число строк «круг … закончен»
в `notes[]` плюс один.

## Коды и сигналы

Коды и маркеры `journal.py` — `symphysis resource doc journal-cli.md`. Особенное для брейншторма:

- `check` код 1 «антипод внутри одной развилки» → убрать `antipodes` у вариантов одной
  записи (шаг 8).
- `check` код 1 «факт с вариантами» → у факта `options: []`.
- `check` строка `[!!]` «парковка человеку без finding» → разбирается в круге просмотрщика
  (скилл `symphysis-viewer`, шаг 6).
- Ответ человека на вопрос порции в чате → развилка с одним вариантом и строка `apply`,
  не правка JSON.

## Границы

- Показ развилок, внесение слова, парковка адресату `человек` — скилл `symphysis-viewer`.
- Исследование парковок `агент` — артефакт `research`, второй круг — после его отчётов.
- Атака журнала — скилл `symphysis-attack`; пробы требований — `symphysis-edge-probe`,
  `symphysis-prohibition-probe`; требования, proposal, design стоят на решённых записях
  позже, брейншторм их не пишет.
- `intent.md` — слова человека на входе; пустой файл заполняется его ответом дословно,
  дальше файл не правится.
- Схема решения — создаётся один раз, дальше по слову человека; скилл не надзирает за
  схемой: не спрашивает о её обновлении и не ждёт утверждения.
- Числа ясности нет: критерия «достаточно ясно» нет, есть счёт новых решений и фактов
  и слово человека.
- В субагенте скилл не исполняется: интервью без контекста чата и прежних решений
  вырождается в вопросы, ответы на которые уже есть.

## Приёмка

- `decision` появляется только из `apply`; слово дословно, с датой.
- Улика — не пересказ: `check` находит путь и цитату; несверенная помечена, не замолчана.
- Рекомендация одна на развилку, после всех вариантов; в чате отдельно от вариантов
  не озвучена.
- Маловероятный вариант стоит в записи с `unlikely` и причиной, не удалён.
- Парковка адресована: адресат из трёх; текст называет, что выяснить и где.
- Круг кончается счётом: строка `notes[]` с K, M, D, P и A на каждый круг; числа кругов скилл
  не ограничивает.
- Новый круг — по слову: вопрос «Начать новый круг?» задан, и когда круг дал лишь открытые
  развилки; не задан при парковках `агент` и когда круг не дал ничего нового; отказ
  записан дословной строкой.
- Схема не мешает: файл создан один раз, дальше по слову человека; при закрытии круга о нём
  нет вопроса.
- Антиподы сверены до показа и после выбора, в том же контексте; в строке круга их число,
  находка — новая развилка.
- Первые записи круга 1 — факты `addressee: постановка` с цитатой из `intent.md`, по одному
  на критерий; `intent.md` байт в байт прежний; нуль критериев — вопрос «назови критерии
  готовности» и строка `notes[]`; второй круг не заводит факт с той же цитатой.
- Вариант против сценария факта постановки несёт `deviation: F-NN`; уточнение — без поля;
  выбор отступающего варианта законен.
- Конструкция — развилкой: «по образцу X», «требует новой …» — факт-наблюдение и развилка
  с вариантами и рекомендацией.
- У решённой записи `reversibility` с `level` и `why`, называющим контракт или систему.
