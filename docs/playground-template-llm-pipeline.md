# Шаблон playground: проектирование LLM-конвейера

Описание шаблона для форка плагина playground (F-18.B) в его же
манере: когда применять, раскладка, элементы управления, состояние,
промпт на выходе, чем заполнять. Первый инстанс —
`docs/plan-implementation.html`, собранный из
`docs/plan-implementation.journal.json` командой `cli/journal.py render-html`
по шаблону `viewer/playground-template.html`. Круг 1 обратной связи
человека (2026-10-29) внесён; что изменилось — в конце.

## Когда применять

Когда человек проектирует конвейер из шагов и артефактов, где решения
зависят друг от друга, часть решений несовместима, а факты надо
отделять от выбора. Шаблоны плагина не подходят: `design-playground`
и `data-explorer` крутят параметры одного объекта; `concept-map`
рисует граф, но не знает статусов и улик; `document-critique` даёт
статусы approve/reject по предложениям, но не знает ни зависимостей,
ни антиподов; `diff-review` и `code-map` — про код. Ни один
не читает внешних данных и не возвращает ничего, кроме промпта.

## Раскладка

```
+----------------+------------------------------------+------------------+
| Оглавление     |  Журнал: карточки записей          | Схема работы     |
| (фикс. панель) |  F-02 · развилка · решено: B · П4  | (фикс. панель)   |
| ● F-01 вопрос… |  вопрос                             |  ┌ 1 Брейншторм  |
| ● F-02 вопрос… |  зависит от: [F-01 ×] [+ зависимость]  │ 2 Исследов. ◄┐|
| ● F-20 факт…   |  ( ) A. вариант — улики «…» сверено |  │ 3 Второй круг│|
|                |  (•) B. вариант — в журнале · антипод  ◇ новое? ─да─┘ |
| все / открытые |  ( ) C. вариант — маловероятно: …   |  │ 4 Гриль       |
|                |  рекомендация: A — почему (под списком)│ 5 Просмотрщик |
| улик сверено   |  слово в журнале: «…»               |  │ 6 → OpenSpec  |
| N из M         |  [слово человека] [добавить вариант]| ┌◇ вердикт gaps┘|
|                |  ▸ парковка — доп. вопрос (1)       | └ готово к apply |
|                |  F-20 · факт · улики — спор — [оспорить] Рамка·Инстал. |
+----------------+------------------------------------+  Э5 Сухой прогон |
| ═══ ручка: высота панели тянется ═══                 | клик = фильтр    |
|  Возврат: промпт из изменений, слов, парковок [Скопировать]            |
+-------------------------------------------------------+------------------+
```

Три колонки: слева оглавление, по центру решения, справа схема; обе
боковые панели фиксированы (`position: sticky`) и видны при любой
прокрутке решений. Нижняя панель возврата тянется за ручку, высота
запоминается в браузере. Один HTML, без библиотек.

## Вход: журнал решений

Данные — журнал по формату `plan-flexible-pipeline.md`, раздел «Журнал
решений», с добавками: `маловероятно:` у варианта, `антиподы:`
у записи, `улики:` у факта (и у развилки — как находки), `парковка:`,
`находка:`, `спор:`, пометка «(добавлен человеком)» у варианта
из просмотрщика. Скрипт рендера превращает журнал в JSON и встраивает
в HTML. Запись:

```json
{
  "id": "F-02", "question": "…", "kind": "развилка|факт",
  "status": "открыт|припаркован|решён", "addressee": "…",
  "depends_on": ["F-01"], "delivery": "П4",
  "options": [{"letter": "A", "text": "…", "added": false,
               "evidence": [{"path": "…", "line": 165, "quote": "…", "found": true}],
               "unlikely": "причина или null"}],
  "antipodes": [{"option": "B", "other": "F-03.A"}],
  "recommendation": {"option": "A", "why": "…"},
  "decision": {"option": "B", "word": "…", "date": "2026-10-29"},
  "parking": [{"addressee": "агент", "text": "…", "finding": "…"}],
  "finding": "…", "dispute": "…", "consequences": "…"
}
```

`parking` — список (пустой, если парковки нет): шаблон показывает каждый элемент.
`finding` на записи — находки парковок через « · ».

Улика без номера строки в журнале получает строку от скрипта: он ищет
цитату грепом по файлу. Не найденная цитата помечается в HTML —
сигнал, а не блок (F-12).

## Элементы управления

| Решение | Элемент | Правило |
| --- | --- | --- |
| выбор варианта | radio на карточке | один вариант на развилку; факт не выбирается; решение из журнала показано выбранным, другой выбор помечается «изменено» |
| слово человека | textarea под вариантами | дословно, уходит в промпт как «почему» |
| парковка | раскрывающийся блок: вопрос + адресат + «припарковать» | дополнительный вопрос, не снимает решения; вопросов может быть несколько; подсказка объясняет, зачем парковка и кто адресат |
| зависимость | чипы `зависит от` с «×», поле `F-NN` + «+ зависимость» | человек снимает зависимость из журнала или добавляет свою; и то и другое уходит в промпт |
| вариант, которого нет | поле «добавить вариант» | получает следующую букву, помечен «добавлен человеком» |
| развилка, которой нет | кнопка «добавить развилку» | id `F-N1…`, уходит в промпт первой |
| факт неверен | textarea «оспорить» | факт остаётся закрытым, спор уходит в промпт |
| фильтр | клик по блоку схемы; «только открытые» | записи своей поставки; второй клик снимает |
| переход | оглавление слева | клик прокручивает к карточке; точка — статус |

## Правила, которых нет в других шаблонах

- **Антиподы.** Пары `F-02.B ↔ F-03.A` из журнала, в обе стороны,
  без дублей. Выбор варианта, антипод которого уже выбран,
  не проходит: карточка называет, что выбрано и где. Невыбранные
  антиподы выбранных решений показаны серыми.
- **Предпосылки.** Развилка с нерешённой `зависит от` помечается
  жёлтым и называет, чего ждёт; выбор не запрещён.
- **Маловероятное видно.** Вариант с `маловероятно:` показан наравне
  с остальными, с причиной; его можно выбрать.
- **Рекомендация под списком.** Не первой строкой и не диалогом:
  её надо найти, тогда выбор осознанный (заметка человека, круг 1).
- **Факт — не выбор.** Факт закрыт уликами; его можно оспорить словом.
- **Парковка — не отмена решения.** Решение по развилке и вопрос
  на парковке живут рядом; адресаты — агент, человек, ИБ.
- **Состояние — в браузере по умолчанию.** `localStorage` под ключом
  инстанса; экспорт и импорт JSON — для переноса между браузерами.
  На диск HTML не пишет. Решения из журнала — не состояние браузера:
  сброс их не трогает.

## Схема работы

Блок-схема SVG без внешних библиотек: прямоугольники — шаги
и артефакты, ромбы — развилки конвейера («новое?» после второго
круга, «вердикт» после атаки), пунктир — возвраты. Узлы несут
список поставок; клик фильтрует записи. Пока узлы и рёбра вшиты
в шаблон; по итогам кругов обратной связи они переезжают в журнал
или в заголовок плана, чтобы шаблон не знал конкретного конвейера.

## Состояние

```javascript
const state = {
  decisions: { "F-02": { choice: "C", word: "…", parked: [{ text: "…", addressee: "ИБ" }] } },
  added:     { "F-05": [{ letter: "D", text: "…" }] },
  deps:      { "F-05": { add: ["F-07"], remove: ["F-04"] } },
  newForks:  [{ id: "F-N1", question: "…", options: "…", word: "…" }],
  disputes:  { "F-20": "…" },
  notes:     "замечания к схеме"
};
```

`choice` хранится только когда отличается от решения в журнале.

## Промпт на выходе

Строки, которые агент вставляет в журнал без переписывания:

```
Решения по журналу plan-implementation.journal.md, 2026-10-29:
- F-02: C (было B) — «слово человека»
- F-03: к решению C — «уточнение без смены варианта»
- F-05: добавлен вариант D. текст
- F-05: зависимость добавлена F-07
- F-05: зависимость снята F-04
- F-09: припарковано → ИБ — «вопрос»
- F-20: факт оспорен — «слово»
Новые развилки:
- F-N1: вопрос — варианты: …
Замечания к схеме: …
```

Только изменённое, добавленное, припаркованное и оспоренное; решения
из журнала, оставленные как есть, в промпт не попадают.

Промпт вносит в JSON `cli/journal.py apply <журнал.json> <промпт>` — всё
или ничего, отказ называет запись; сам `apply` не рендерит, после него
`render-md` и `render-html`.

## Чем заполнять

Не сочинять HTML под задачу: шаблон фиксирован, меняются данные.
`cli/journal.py render-html <журнал.json> --out <html>` читает журнал, сверяет
улики, встраивает JSON и пишет HTML.

## Чего шаблон не делает

- не решает развилки и не меняет рекомендации;
- не пишет на диск — возврат только промптом или экспортом JSON;
- не сверяет улики сам — это делает скрипт рендера до сборки;
- не заменяет журнал: HTML — просмотр и ввод, источник — файл.

## Круг 1 обратной связи — внесено 2026-10-29

- адресат «архитектор» снят; подсказка, зачем парковка;
- парковка не снимает решение, вопросов на парковке несколько;
- схема — блок-схема с развилками вместо линейного списка; оглавление
  слева;
- антиподы без дублей;
- зависимости правит человек;
- решения из журнала показаны решёнными, изменение помечается.

Открыто к следующему кругу: F-17 — не заменит ли md4h-связка
комментариев возврат промптом (ждёт F-01).

## Круг 2 обратной связи — внесено 2026-10-29

- схема справа фиксированной панелью, вертикальная блок-схема;
  оглавление слева, решения по центру; нижняя панель с ручкой
  высоты;
- состояние браузера чистится от того, что уже внесено в журнал:
  слово к решению, парковка, спор, совпадающий выбор;
- F-01 решён в B: источник журнала — JSON; возврат из HTML — промпт,
  из markdown — комментарии с якорями по образцу md4h. Шаблон
  принимает JSON напрямую, парсер markdown становится обратным
  рендером (Э1).
