# Контракт связанных репозиториев

Действует для двух проектов: ядра `symphysis` и плагина `symphysis-vscode`. На другие репозитории не распространяется, у них свои правила пуша.

## Раскладка

| Что | Где |
| --- | --- |
| схема, скиллы, инструменты журнала, страница, инсталлятор | `symphysis`, удалённый `Niqsons/symphysis-core` |
| плагин VS Code | `symphysis-vscode`, удалённый `Niqsons/symphysis-vscode` |
| механики замера: раннеры, водитель, сборка плеч, правила судейства | `skills-factory` |
| замеры: прогоны, листы, эталон | только на диске |
| копии исходников доноров, `upstream/` | не публикуются; упоминать источник в текстах можно |
| наши правки форка OpenSpec | ветка `openspec-fork` в `symphysis-core`, оставлена по слову человека |

## Подпись коммита

Коммит из работы над другим проектом несёт `From:` с проектом и веткой и `Why:` с причиной для той стороны. Родной коммит подписи не несёт.

Подпись стоит в последнем абзаце сообщения, вместе с `Co-Authored-By`. Отдельным абзацем git её не видит.

```
feat(journal): view-json: данные журнала для показа вне страницы

From: symphysis-vscode feat/part1-viewer
Why: плагину нужны данные журнала без разбора HTML страницы
Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

Список таких коммитов:

```
git log --format='%h %s | %(trailers:key=From,valueonly,separator=)'
```

## Обратная ссылка

Коммит плагина, которому нужен коммит ядра, несёт `Needs: symphysis <хеш>`.

Тесты плагина идут по рабочему дереву `../symphysis`, а не по этому хешу. Поэтому перед выпуском плагина проверяется, что хеш достижим из `main` ядра:

```
git -C ../symphysis merge-base --is-ancestor <хеш> main
```

## Что входит в контракт ядра с плагином

- грамматика строк `apply`: плагин сам пишет эти строки, и они попадают в журнал;
- вывод `view-json`;
- коды выхода `journal.py`;
- пути файлов изменения;
- списки линз;
- когда появятся: `scheme.md` и хук.

**Что считается сменой.** Новое поле сменой не считается. Удаление, переименование и смена смысла считаются.

**Что делать при смене.** Номер контракта растёт, а коммит ядра называет смену в `Why:`. Ядро лежит в `.symphysis/tools/` каждого проекта, и его версия расходится с версией плагина. Поэтому `view-json` отдаёт номер контракта, а плагин при несовпадении просит обновиться.

## Логика и показ

Ядро отвечает за правила записи: `apply`, `check`, схему журнала и вывод. Показ и сборка промпта у страницы и у плагина свои: перенос в ядро означал бы запуск Python на каждый символ. Совпадение проверяет контрактный тест.

На странице доступны все виды слова. Удобства, такие как поиск, фильтры и оглавление атаки, есть только в плагине.

Выпуск — отдельный тег в `main`: `v1.x.x` и далее.

## Рабочее дерево

- В `git add` идут только свои файлы.
- Своя ветка — свой worktree. В общем дереве ветку не переключают.
- Паузу объявляет только человек: сессии не видят друг друга.
- Операции над всей историей идут только во время паузы.

## Пуш

- Перед пушем проходит гейт имён.
- Агент пушит рабочие ветки.
- `main`, перезапись истории и первый пуш ядра из локального репозитория — только по слову человека.

## Где живёт текст

В этом файле, в `main` ядра: иначе его видно не на всех ветках. `CLAUDE.md` обоих проектов ссылается сюда, копий нет.
