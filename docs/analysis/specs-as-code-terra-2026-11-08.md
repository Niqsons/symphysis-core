# Specs skills-as-code: Astra-автор и два запуска Terra

Дата: 2026-11-08. По запросу владельца отдельная Astra создала новый скилл specs
с максимальным доступным усилием; затем два свежих субагента Terra выполнили одну
задачу текущим способом и по новому скиллу. Условия сравнения подтверждены владельцем:
текущий способ против нового скилла, один запуск на сторону.

## Вывод владельца и состояние изменения

После результатов владелец зафиксировал 2026-11-08:

> тогда мой текущий вывод такой, что в openspec скиллах можно вносить правки, а не переписывать их целиком. но внесение каждой порции правок необходимо проверять.

> работа над текущим изменением приостановлена, до появления триггеров о необходимости изменения.

Изменение `fork-symphysis-flow` приостановлено. Дальнейшие правки скиллов выполняются
порциями при появлении необходимости, с проверкой каждой порции. Конкретный перечень
триггеров возобновления не задан. Прототип ниже остаётся материалом эксперимента.

## Результат

Новый скилл в этом запуске не обеспечил выполнение задания: Terra создала только
одну из четырёх дельт и честно назвала результат частичным. Текущий способ создал
все четыре файла, но независимая проверка обнаружила проблемы ссылок и точности
формулировок. Считать меньший расход нового скилла экономией при том же качестве нельзя.

| Результат | Текущий continue → specs | Новый symphysis-specs |
| --- | --- | --- |
| Создано файлов из четырёх | 4/4 | 1/4 |
| Требований | 15 | 1 |
| Сценариев | 42 | 3 |
| Строгая проверка CLI | проходит | проходит для частичного изменения |
| Требования до 500 знаков | да | да, в единственном файле |
| RENAMED исследования | есть | не создан |
| Сохранены имена старых сценариев | да, у всех MODIFIED | да, у единственного MODIFIED |
| Входные файлы и журнал не менялись | да | да |
| Полнота авторства по proposal | достигнута по файлам; есть замечания содержания | не достигнута |
| Обе последующие пробы | не выполнялись по заданию | не выполнялись по заданию |

CLI принимает изменение уже с одним корректным файлом: `specs` — glob-артефакт.
Новая инструкция помогла Terra отличить это `done` от полноты задания, но не довести
создание остальных файлов до конца. Принятие решений человеком и последующие этапы
не имитировались. После первых финальных ответов исправлений и повторов не было.

## Токены и время

Числа взяты из локальных `token_count` и `token_usage_record` соответствующих
дочерних сессий Codex. Итоги двух независимых записей расхода совпали. Это сообщённый
сервисом расход, а не оценка длины текста через количество символов.

| Метрика | Текущий способ | Новый скилл |
| --- | ---: | ---: |
| Весь вход за все обращения | 452 235 | 258 875 |
| Из входа — кэшированный | 416 128 | 225 280 |
| Из входа — некэшированный | 36 107 | 33 595 |
| Выход, включая размышления | 5 213 | 1 794 |
| Из выхода — reported reasoning tokens | 231 | 95 |
| Всего вход + выход | 457 448 | 260 669 |
| Обращений модели к инструментам | 12 | 7 |
| Время отдельной сессии | 117,379 с | 61,575 с |

Кэшированный вход уже входит во весь вход; токены размышлений уже входят в выход.
Эти строки нельзя складывать повторно. Весь вход суммирует контекст на повторных
обращениях модели, поэтому сотни тысяч не означают такой размер уникальных исходников.
Цены, денежная стоимость и производительность на единицу результата не оценивались.

У нового запуска на 43% меньше полного счётчика токенов и на 59% меньше reported
reasoning, но создано только 1/4 необходимых файлов. Гипотезу «более ясная инструкция
даёт меньше размышлений при том же результате» этот опыт не подтверждает и не опровергает:
одинаковый результат не получен.

Стоимость авторства Astra учитывается отдельно, вне двух колонок исполнения:
модель `gpt-6-astra`, effort `ultra`, 869,692 с, 22 обращения к инструментам;
1 184 949 входных токенов, из них 1 145 344 кэшированных и 39 605 некэшированных;
32 272 выходных, из них 10 279 reasoning; всего 1 217 221 токен.

## Как подготовлен опыт

Автор Astra получил только общие правила `writing-skill-bodies`, канон symphysis,
схему, шаблон, config, глоссарий и текущую инструкцию continue. Proposal и тестовое
архивное изменение ему не предоставлялись. Автор не запускал других агентов.

После его финального ответа тело зафиксировано по SHA-256
`e54dc982d4b8dcd86899fbd0a19916df09e15547a16edf0914e80448418fd57d`.
Тестовое содержимое после просмотра результатов в него не вносилось. Автор сообщил
о статических проверках и 12 проверках счётчика; основная нить отдельно проверила
структуру тела, наличие ресурсов и запуск справки счётчика. Поведенческая проверка
ограничена результатами двух Terra ниже и не объявляется успешной.

Оба исполнителя — `gpt-6.1-terra`, effort `medium`, свежий контекст без истории
разговора. Одинаковые входы, разрешения и реальные инструменты CLI. Среди 79 общих
файлов исходно различается только строка вызова в brief; пакеты инструкций различаются
намеренно. Старый способ — установленный `openspec-continue-change`, адресованный
артефакту specs. Новый — `symphysis-specs` и его счётчик длины.

Задание остановлено после авторства дельт, до edge-probe и prohibition-probe, одинаково
для обеих сторон. Это явное ограничение опыта, а не изменение продуктовых настроек.
Глобальная установка команды, форк и основной рабочий проект не менялись.

Границы чтения/записи заданы brief; отдельная изоляция файловой системы процессов
не настраивалась. Сиды, температура и политика кэша интерфейсом субагентов не раскрыты.
Подсказок, корректирующих сообщений и обратной связи во время запусков не было.

## Исторические входы

Взято архивное изменение `parking-addressee-agent` — переименование адресата
«материалы» в «агент». Его реальный proposal затрагивает четыре capability, включая
подсказку просмотрщика и контракт плагина, поэтому пример шире одной замены в тексте.

- Proposal: коммит `457eae5`.
- Мастер-спеки: первый родитель `8ddebc4d6dfcc6588c405c5057881ce52f1e46ea`, до реализации
  и синхронизации изменения.
- Журнал: из того же коммита proposal, только F-01–F-21. Исключены F-22–F-26 и заметки
  позднейших проб, чтобы исполнители не получили готовые дополнительные решения.
- Готовые дельты из архива не копировались исполнителям. Исходный код проекта не
  предоставлялся: предмет авторства задают proposal, принятые основания и мастер-контракт.
- Настоящий CLI `1.16.1+symphysis.5` вызывается одинаковым запускателем с локальными
  XDG-каталогами и отключёнными телеметрией/проверкой обновлений. До старта в обеих
  копиях specs имел `ready`; инструкции CLI получались успешно.

Длинные мастер-требования требуют деления с сохранением сценариев родителя. Основание
для деления F-20 и переименования F-21 оставлены в журнале, чтобы не заставлять модель
выдумывать решения. Следующие вопросы после проб, например F-25, не были частью входа.

## Проверка качества

Рубрика, проверщик и подробный перечень сохраняемых условий записаны до запусков
Terra. Проверялись четыре capability, грамматика, WHEN/THEN и ссылки у требований,
длина прозы, разрешимость MODIFIED относительно базы, RENAMED, сохранение старых имён
сценариев и неизменность защищённых входов. Неизменённая фикстура эти критерии проваливает.
Имена сценариев сами по себе не доказывают сохранение смысла; содержание просмотрено
дополнительно основной нитью.

У текущего способа обнаружены замечания:

1. Унаследованные номера квалифицированы именами capabilities как именами изменений:
   например `decision-journal/F-10.A` и `artifact-graph/F-37`. В зафиксированной истории
   нет журналов изменений `decision-journal`, `brainstorm-interview`, `artifact-graph`
   и `plugin-core-contract`. Входы не дают оснований превращать capability в namespace
   журнала. CLI такие семантические ошибки ссылок не отверг.
2. В MODIFIED исследования исчезло явное условие «находки из прочитанного файла»:
   остался формат `путь:строка «цитата»`. Сохранённые сценарии не восстанавливают
   это условие явно. Это ослабление формулировки относительно мастер-текста.
3. Подсказка адресата говорит, что ответ ищет «агент»; proposal прямо называет агента
   исследования. Уточнение роли в этом месте не перенесено с прежней точностью.

У нового способа главный дефект — отсутствие трёх capabilities. Единственный файл
`plugin-core-contract/spec.md` проходит проверку и сохраняет два старых сценария,
добавляя сценарий номера 4. Это корректная частичная работа, не завершённое авторство.

## Усечение вывода: установленное и предположение

В собственном финале Terra нового способа сослалась на усечённое чтение журнала и
мастер-спек. Технические записи инструментов подтверждают три ответа с маркером
`truncated`: два включали чтение самого нового SKILL.md, один — мастер-спек.
У текущего способа такой ответ был один, при чтении журнала и мастер-спек; исполнитель
после него продолжил и создал весь набор.

Новое тело — 57 401 байт, 238 строк; текущее — 14 200 байт, 153 строки. Некоторые
новые строки длинные, поэтому одно чтение «всех строк» не гарантирует получение текста
в лимит ответа инструмента. Новое тело требует полной проверки входов и остановки
зависимой работы при неполном чтении, но не задаёт конкретного способа дочитать
усечённый ответ диапазонами. Связка объёма текста, способа чтения и этого правила —
кандидат на причину остановки. Один запуск причинную связь не доказывает.
