# Проверка терминов на чистом контексте, 2026-11-06

Правило — `docs/skills-canon.md`, раздел 7 (слово владельца, F3 раунда `e745`): термин стоит
в теле без определения, если модель понимает его на чистом контексте; не понят или значительно
расходится — в `terms.md`. Проверка выполнена 2026-11-06; это единственный источник состава
`terms.md` на сегодня.

## Метод

- 37 терминов-кандидатов из канона с нашими определениями по телам скиллов и глоссарию пакета —
  `skills-factory/runner/evals/terms-symphysis-2026-11-06.json`. Определения писал агент; они
  мерило судьи и подлежат сверке владельцем.
- Промпт один на все термины: «Ты исполняешь инструкцию одного шага проектирования программного
  обеспечения: требования, решения, проверка артефактов. В инструкции встречается термин «X» без
  определения. Что он значит в таком контексте? Ответь в два предложения. Если не знаешь или
  термин в таком контексте тебе незнаком, так и скажи.»
- Пять плеч, по три повтора, 555 ячеек, ошибок 0: `ollama/glm-5.2` и `ollama/deepseek-v4.1-flash` —
  чистый вызов API ollama.com; `opencode/glm-5.2` и `opencode/deepseek-v4.1-flash` — `opencode run
  --standalone` с тем же провайдером; `claude/sonnet` — `claude -p --model sonnet`. Плечи клиентов —
  «обычный вызов» по слову владельца, но изолированный от этой машины (ниже).
- Судья — `claude -p --model sonnet`, один вызов на термин со всеми 15 ответами; вердикт из четырёх:
  «совпадает», «частично» (общий смысл верный, ключевой элемент нашего определения отсутствует),
  «расходится» (другая вещь), «не знает» (термин назван незнакомым; верная догадка с такой оговоркой
  тоже «не знает»). Доводы судьи — по ячейке в `grades.jsonl`.
- Скрипты — `skills-factory/runner/tools/term_check.py`, `term_grade.py`; ответы и вердикты
  дословно — `skills-factory/runner/runs/20261106-terms-symphysis/` (на диске, в git не идут:
  `docs/repo-contract.md`, «замеры: только на диске»).

### Изоляция клиентов: три ловушки

Первые два прогона клиентских плеч были загрязнены, ответы сохранены рядом как
`answers.contaminated-*.jsonl` и `answers.before-pwd-fix.jsonl`:

1. Каталог запуска лежал внутри репозитория skills-factory — deepseek через opencode процитировал
   файл с нашими определениями, Sonnet — `SHARED-RULES.md`. Теперь каталог — `%TEMP%\term-check`,
   скрипт отказывает, если каталог внутри git.
2. Python `subprocess` ставит `cwd`, но не переменную `PWD`; opencode берёт каталог проекта из `PWD`
   и искал файлы (`rg`, `git --work-tree`) в каталоге запуска скрипта. Теперь `PWD` равен каталогу
   запуска.
3. Оба клиента грузят пользовательские скиллы и агентов из `~/.claude`: Sonnet цитировал описание
   скилла `writing-skill-bodies`, написанного в тот же день. У `claude` помогли
   `--setting-sources project --disable-slash-commands` («скиллы: нет»), у opencode — только
   `"tools": {"skill": false}` в `opencode.json` каталога запуска: подмена `HOME`, `USERPROFILE`,
   `HOMEDRIVE`, `HOMEPATH` скиллы не прячет. Копировать `.credentials.json` в отдельный
   `CLAUDE_CONFIG_DIR` классификатор Claude Code запретил, и это верно.

Диагностика перед любым таким замером: спросить клиента «перечисли доступные скиллы и выполни
`pwd`» и посмотреть `cwd=` у `rg.exe` в `~/.local/share/opencode/log`.

Правило итога: термин идёт в `terms.md`, если хотя бы одна ячейка «не знает» или «расходится».
По этому правилу — **все 37 терминов**. Сводные числа по 555 ячейкам: «совпадает» 13, «частично»
119, «расходится» 110, «не знает» 313.

Почему «не знает» так много: промпт просил сказать «не знаю», модели оговаривают почти каждый
ответ, а судья по своему правилу считает оговорённую догадку за «не знает». Для состава глоссария
это консервативно и приемлемо: ни один термин не опознан как устоявшийся. Но опасность терминов
различается, и её видно по другому признаку — уверенно ли модель подставляет другое значение.

## Сверка и деление по опасности

Сверено человеком-агентом по первому повтору всех пяти плеч (185 ответов) и по доводам судьи у
спорных терминов; вердикты судьи держатся, расхождений с чтением не нашлось. Деление — вывод
агента, не слово владельца.

### Группа B — знает иначе: уверенно подставляет другое значение

Самая опасная: модель не чувствует пробела и глоссарий не откроет.

- изменение — модификация артефактов, не единица работы `openspec/changes/<имя>/` (10 расходится).
- решение — проектное решение с обоснованием, без человека и его слова (14 расходится).
- механизм — способ реализации (кэш, аутентификация), не именованный кусок кода (10 расходится).
- состав — состав системы или разделы артефакта, не включённые настройкой части шага (9).
- рекомендация — указание уровня SHOULD по RFC 2119, не один вариант с причиной (7).
- исход — результат шага, не выбор человека по кандидату (6).
- кандидат — черновик артефакта, не запись-развилка с четырьмя исходами (5).
- цель атаки — актив при моделировании угроз, не файл с хешем (5).
- ветка отказа — сценарий отказа или запасной вариант решения, не место в коде (6).
- такт, зависимость записи, место кода, тяжесть, просмотрщик, водитель («driver»), вариант — по
  2–4 уверенных иных прочтения на фоне «не знает».

### Группа C — не знает: гадает, часто в нужную сторону

- Гадает верно у большинства плеч: парковка (parking lot), развилка (точка выбора), порция
  вопросов, круг брейншторма, каталог изменения (папка изменения), адресат, запись.
- Гадает расплывчато или в сторону: улика (любой артефакт-свидетельство), антипод, слово человека,
  промпт возврата, след пробы, опора, факт.

### Группа A — знает близко: разница только в нашей привязке

- журнал решений (decision log), инвариант, допущение, pre-mortem (13 совпадает), brief (design
  brief), линза (ракурс), вердикт (итог проверки). «Частично» здесь значит «без атаки», «без
  журнала», «без хешей»: это добирает тело, не глоссарий.

### По плечам

glm-5.2 читает увереннее всех и чаще всех иначе: 46 «расходится» против 14 у deepseek через API
и 5 через opencode. deepseek оговаривает почти всё (66 и 87 «не знает»). Sonnet посередине.
Для слабой модели это значит: группа B у glm — не гипотеза, а наблюдённое поведение.

## Что из этого следует

1. `terms.md` — все 37 терминов, по одной строке, группа B первой. Цена — около 40 строк, модель
   читает файл целиком.
2. Развилка **Р12** к канону, разделу 7 (слово нужно). Термин группы B модель читает уверенно и
   за глоссарием не идёт, поэтому одного файла мало:
   - **A. Якорь в теле при первом употреблении** термина группы B — одна фраза в скобках: «решение
     (выбранный человеком вариант развилки)», «состав (включённые настройкой части шага)»;
     глоссарий остаётся источником. Цена — по фразе на термин в каждом теле, около 15 фраз.
   - **B. Только глоссарий**, тело называет файл во «Входе». Цена — ноль фраз; риск — модель группы
     B файл не откроет, потому что не сомневается.
   - **C. Переименовать термины группы B** туда, где общее значение совпадает с нашим: «состав» →
     «включённые части», «водитель» → «субагент-исполнитель», «цель атаки» → «файл цели». Цена —
     правка схемы, скриптов, страницы и плагина там, где слово стало именем поля или значения
     (`outcome`, `recommendation`, `consequences`).
   Рекомендация — **A**: против B — наблюдённая уверенность glm; против C — слова уже стали именами
   полей и значениями контракта, переименование дороже якоря.
3. Определения в файле оценки — мерило судьи — сверить владельцу: там, где определение уже, чем
   нужно телу (инвариант «чтобы строки атаки не было»), группа A могла бы стать «совпадает».
4. Повторять проверку после переписывания тел не нужно: она о словах, не о телах. Повторить —
   при добавлении термина в канон, тем же скриптом, одним термином.
