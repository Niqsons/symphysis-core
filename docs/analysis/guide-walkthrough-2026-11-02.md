# Прохождение `docs/GUIDE.md`, 2026-11-02

**Итог.** Модель Sonnet 5.5 прошла руководство буквально дважды целиком и ещё раз часть установки. `check: ok` с кодом 0 и `/opsx:continue` на месте все три раза. Шаг `consequences` оба раза показал строки описи и кандидатов. Текст поправлен трижды, последняя правка не перепроходилась: предел повторов исчерпан. Расход $4,25 из $10, настоящий конфиг OpenSpec не тронут.

## Среда

- Каталог прохода вне репозитория: клон ветки `impl/plan-tasks` и рядом проект. На каждый проход свежие клон, префикс npm, venv и конфиг.
- `XDG_CONFIG_HOME` и `APPDATA` на временные каталоги: вторая переменная закрывает и путь без `XDG_CONFIG_HOME`, поэтому `check` видел один конфиг, как на чистой машине.
- `npm_config_prefix` свой и первый в `PATH`. В `PATH` нет каталога с глобальным `openspec`, команды `symphysis` не было: первый `which` дал «нет» на обе.
- venv из обычного Python без PyYAML, первый в `PATH`: `import yaml` падал до шага установки, шаг был настоящим.
- Модель: `claude -p --model claude-sonnet-5-5 --output-format json --permission-mode acceptEdits --setting-sources project --strict-mcp-config`, дальше `--resume`; инструменты Bash, Read, Edit, Write, Glob, Grep, Skill. В окружении нет переменных с префиксами `CLAUDE`, `MCP_`, `ANTHROPIC_`, заданы три переменные чистого контекста.
- Две сессии, как у человека: установка в каталоге прохода, проект в каталоге проекта, потому что `/opsx:*` видны только там.

Человека вёл контроллер: первый ход — путь к руководству и просьба пройти буквально, дальше ответы на остановки.

**sha256 настоящего конфига** до и после каждого прогона одинаков, содержимое не открывалось: `1b57b12741b9ae7c4289a389db1747703effc3e85674dfc1fb4d44a8e0eb26c6`.

**Транскрипты.** Обращений к исходному репозиторию и к каталогам стенда и архива нет: 0 в вызовах инструментов всех пяти сессий. Вне проекта модель читала только руководство и свои рабочие файлы в `/tmp`. Из маркеров чужого контекста в сессиях проекта один раз встретился `sdd-superpowers`. Это не утечка: модель прочла установленный скилл, а в `skills/symphysis-attack/SKILL.md:40` стоит ссылка на источник механики. Остальных маркеров нет, в списке скиллов только скиллы проекта и встроенные в клиент.

## Отступления модели от скиллов

- Проход 1, атака: `python reminders.py list | wc -l`, хотя атака читает и не исполняет. В `skills/symphysis-attack/SKILL.md` прямо назван этот случай. На проходе 2 запусков во время атаки нет.
- Проход 2, `/opsx:apply`: чекбоксы отмечены одной командой после всех проверок, а не по мере выполнения. Текст команды — форка, здесь не правится.
- Проход 2, `/opsx:sync`: из основной спеки убраны комментарии следа проб. Текст форка этого не просит и не запрещает.

## Чего прохождение не проверило

- Кнопку «Скопировать промпт»: промпт написан вручную по грамматике страницы (один круг), остальное шло словом «реши сам».
- Клон по настоящему адресу и хранилище учётных данных: клон шёл из локального пути.
- Настоящий терминал и диалог клиента: модель шла через `claude -p`, а `/opsx:*` исполняла скиллом или чтением файла команды.
- Обновление на новый тарбол: прогон шёл на той же версии, `записано 0`.
- Windows PowerShell 5.1 и настоящее зеркало.
- Проект на opencode: только установка до `check: ok`.
- `/opsx:explore`, `/opsx:update`, `/opsx:propose`: только описаны.
