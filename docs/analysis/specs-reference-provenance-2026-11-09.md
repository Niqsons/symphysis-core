## Основание и правка

[Исторический эксперимент Terra](specs-as-code-terra-2026-11-08.md), замечание 1:
исполнитель квалифицировал унаследованные номера именами capabilities, хотя журналы
с такими именами не существовали. CLI пропустил эти ссылки. Подтверждение по числу
или по имени capability не устанавливает происхождение решения.

Правка находится в схеме symphysis: instruction specs, templates/spec.md, справке steps.md
и мастер-норме trace-conventions. Существующий continue получает instruction и template
через CLI. Шаблоны workflow и сгенерированные skills форка в этой порции не меняются.

Instruction отсылает к одному рецепту шаблона. Рецепт содержит три пункта:

1. MODIFIED берёт полный блок мастера, при переименовании — под именем FROM.
   Прежние ссылки сохраняются дословно, включая голые номера, имя журнала и буквы вариантов.
2. Новое своё основание берётся из текущего decisions.json без префикса;
   новая чужая ссылка получает имя подтверждённого журнала-источника.
3. Неизвестный источник прежней ссылки сообщается в итоге шага при сохранении ссылки.
   Имя capability и совпавший номер не доказывают источник.

В шаблоне дан сквозной пример коллизии собственного и чужого F-20.B при прежнем F-20.A.
Правила называют MUST и последствие подмены источника; новый мастер-контракт содержит
три сценария. Instruction: 137 → 143 слова, предел 150 сохранён.
Проза нового требования вместе с комментарием источника — 458 знаков, до сценариев.
Нормы деления требований и работа проб не меняются.

## Изолированное исполнение

Модель gpt-6.1-terra, effort medium, свежий fork_turns:none на каждый запуск.
Всего шесть запусков: исходный вариант, два первых исполнения правки, два исполнения
финальной редакции и канонический spec-driven. Первую пару не отбрасывали:
после неё фраза «capability не имя журнала» уточнена до «имя capability не доказывает источник».
Совпадение имён допустимо, если источник подтверждён независимо.

Основной вход — компактный учебный proposal с двумя capabilities, принятыми решениями
F-20.B/F-21.B/F-22.B, двумя архивными журналами и двумя мастерами.
Один мастер содержит неизвестный голый F-20.A и подтверждённый report-history/F-20.B;
второй — именованный список чужого журнала label-history с F-21.A.
Требуются сортировка, RENAMED + MODIFIED подписи и ADDED с новым чужим основанием F-30.B.
В proposal прямо указаны пути чужих журналов и неизвестность прежнего голого источника.
Это проверка работы при явных исходных данных, а не поиска утраченной истории.

Brief финальных повторов одинаков с заменой корня пробы. Доступ ограничен brief,
отдельная файловая песочница не настраивалась. Обёртка запускает настоящий CLI из
проверенной копии форка порции 4; отдельные XDG_CONFIG_HOME/XDG_DATA_HOME исключают
глобальную конфигурацию. Разрешена запись только delta specs.
Пробы краёв и запретов явно за границей эксперимента; новых решений нет.

Обе стороны читали одинаковый прежний trace-conventions. Тело установленного continue
совпадает с текущим шаблоном форка после нормализации имени slash-команды.
До/после различались только instruction и template specs; финальная пара получила
те же байты этих двух файлов, которые остаются в рабочем дереве.
