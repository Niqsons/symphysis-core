# B-51: деление требований, точечная правка и Terra до/после

Дата: 2026-11-09. Ветка: `feat/fork-symphysis-flow`, исходный HEAD `ed12c68`.

## Правка

В instruction `specs` схемы `symphysis` превышение 500 знаков при написании **или правке**
явно приводит к созданию дочернего требования; сокращение вместо деления названо ошибкой.
Сохранены номера оснований и решения о делении, кандидат при отсутствии записи,
фраза связи с родителем, отдельный сценарий дочернего и прежние сценарии родителя.
Инструкция стала короче: 148 → 137 слов.

Мастер-норма `trace-conventions` больше не говорит «когда его сокращают ради предела»;
добавлен сценарий перехода от 500 к 501 знаку с учётом номеров записей.
В spec-шаблоне добавлено условное пояснение деления MODIFIED → родитель MODIFIED + дочернее ADDED.
Его пример написан текстом: CLI распознаёт заголовки даже внутри HTML-комментария.

Применены правила `writing-skill-bodies` и канон `docs/skills-canon.md`:
наблюдаемый признак → действие → ошибка при нарушении, именованные референты,
провенанс в комментарии мастер-нормы. Скелет отдельного SKILL.md не вводился:
изменён короткий instruction существующей схемы. Сам `continue-change.ts`,
сгенерированные скиллы и общий форк не менялись. В исходных телах скиллов дополнительных
указаний ужимать требования не найдено; упоминания 500 у проб описывают положение следов.

На старте эти три файла совпадали с local main `f17434b`; незакоммиченных правок в них не было.
Отдельных коммитов/worktree B-51/B-45 не найдено; другая основная сессия работала над глобальной
установкой. Merge и установка для этой порции не выполнялись.

## Постановка пробы

Два свежих субагента `gpt-6.1-terra`, effort `medium`, без наследования беседы.
Brief одинаковый с заменой пути корня; отдельные каталоги и XDG config/data.
Это изоляция контекста и файлов задания, а не системная песочница прав доступа.
Один запуск на вариант; дополнительных повторов для статистики нет.

Оба получали прежний workflow continue, реальную instruction/template через
`openspec instructions specs --change contract-address --json`, соответствующий фрагмент
мастер-нормы, одинаковые proposal, решённые F-01/F-02 и исходную master-спеку.
Случай синтетический, по мотивам B-51, не точное воспроизведение архивного сбоя 538→499:
добавление смены адресата в контракт; согласованный текст — **507 знаков** с номером записи.
Есть девять обязательств: целый номер; рост при смене контракта; отсутствие роста от нового поля;
смена адресата считается сменой контракта; номер 4; `Why:` коммита ядра; абзац «С номера 4»;
`Needs:` плагина на коммит ядра; сообщение о несовместимости до обновления плагина.
Имеется прежний сценарий «Новое поле не меняет номер».

Граница — написание specs до двух проб краёв/запретов; их запуск исключён одинаково.
Редактировать разрешено только дельту specs. Контрольные хеши всех исходных файлов
совпали после выполнения; посторонних записей не обнаружено.
Одинаковость proposal, журнала, master и workflow проверена хешами.
Различались schema instruction, template, фрагмент нормы и производный JSON инструкции.

Дополнительная проверка реального форка, тексты ровно 500/501 знаков с `(F-01)`:

| Дельта | 500 | 501 |
| --- | --- | --- |
| ADDED | valid | warning о длине, strict завершился с кодом 1 |
| MODIFIED | valid | valid |

В `validator.ts` проверка длины намеренно стоит только у ADDED: комментарий ссылается
на сохранение существующего текста MODIFIED. Значит, `validate --strict` не доказывает
соблюдение B-51 для MODIFIED; в модельной пробе длина проверена отдельно парсером графа.
Текст диагностического сообщения ADDED по-прежнему предлагает альтернативу переноса примеров
в сценарии. Эти два места — отдельная оставшаяся несогласованность валидатора с B-51;
в этой порции форк и предел 500 не менялись.

Проверка журнала: 105/106 улик; прежнее предупреждение F-19 о старой цитате бэклога
сохранилось. Согласованный предмет работы внесён заметкой через apply; старые факты,
развилки и intent сохранены, ответы за владельца не выбраны. MD/HTML перерендерены.
