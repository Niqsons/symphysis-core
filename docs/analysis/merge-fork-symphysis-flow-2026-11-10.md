# Вливание fork-symphysis-flow после global-user-install

Дата: 2026-11-10. Владелец разрешил вливание и проверку конфликтов после проверки двух изменений.
Исходный main — f2e399ab (global-user-install), ветка — 294ea62 и последующее исправление справки 64057896.
Результат подготовлен в отдельном worktree integration/fork-symphysis-flow-20261110;
исходные worktree с локальными данными не очищались.

## Разрешение конфликтов

Пробный merge-tree выявил семь конфликтов:

- installer/lib/install.js: сохранён новый installManaged из main; прежняя реализация не возвращалась.
  Новый файл sync_check доставляется общей картой payload.
- installer/lib/check.js: объединены runtime_context.py и sync_check.py в составе инструментов.
- installer/test/check.test.js: сохранены проверки обоих новых модулей.
- config.symphysis.yaml: сохранены происхождение ссылок, точная область якоризации,
  отсутствие записи мастера при no-sync и владелец вызовов в workflow. Команды — через bootstrap.
- schema/tests/test_schema.py: объединены нормы формы ссылок и новый способ доставки.
- steps.md: сохранены обязательная подготовка графа и проверка sync, названия команд согласованы с dispatcher.
- GUIDE: сохранены частичный sync, полные тела задач и короткие подписи Mermaid;
  повторная якоризация завершённого результата не предписывается.

Лимит Mermaid по-прежнему относится к отображению; целью коротких подписей остаётся читаемость.

## Совместимость runtime

Текстового объединения было недостаточно: в main появился самостоятельный local/global runtime,
а новая вставка sync/archive искала инструменты в caller/.symphysis/tools.
Сохранить такую инструкцию для global-only установки означало бы потерять выбранные ресурсы.

Добавлен именованный вход symphysis sync-check через существующий dispatcher:
те же source/store, reader lease, проверка поколения и ранний Python bootstrap.
Имя изменения учитывается в проверке схемы также у anchors. Повторяемый --capability сохраняется.
Старая поставка без checker остаётся ready для имеющихся инструментов; запрос отсутствующего
checker получает resource-missing, без подбора файла из другой установки.
Если файл объявлен manifest, но повреждён/удалён, обычная проверка целостности остаётся обязательной.
Реестр файлов predecessor сохранён без нового модуля. Форматы и номера API/журнала не менялись.

Компилятор managed carriers переводит вставку нашего форка в bootstrap-команды с выбранным
source/store. toolsHome берётся из разрешённого runtime, roots — у выбранного store через dispatcher.
Поиск локальной установки и ручной выбор runtime-карты корней из managed тела исключены.
Неожиданное изменение маркера вставки вызывает отказ сборки. Для старого pin без этой вставки
прежний результат генерации сохранён. Оба актуальных тела sync/archive из форка проверены компилятором.

Перед исправлением новые регрессии воспроизвели неизвестную команду sync-check и оставшийся
в managed workflow локальный поиск Python-инструментов. После исправления они прошли.
Дополнительно реальный checker проверен в local/global reader-контексте: выбранный root,
подмножество capabilities и отсутствие записи файлов подтверждены тестами.

## Свежие исполнения managed sync

Четыре изолированных gpt-6.1-terra medium без истории. Две первые фикстуры оказались
невалидными: учебный журнал не имел обязательных полей. Freeze отказал, anchors при отсутствии
базы изменил также старую ссылку; checker сообщил review, обе модели отказались объявлять успех.
Rollback не обещается: отрицательные пробы оставили частично изменённый мастер.
Эти результаты сохранены, не заменены успешными.

Затем два новых запуска получили валидные журналы, заранее проверенные настоящим journal check.
У них один brief с заменой корня, global-only runtime и caller без локальных tools.
Оба создали снимок до записи, сохранили старую F-20, заякорили новую F-21 как mini/F-21,
получили match для primary и успешную валидацию. Мастер excluded, второй store beta,
дельты, журналы и runtime сохранили исходные хеши. Архивации не было.
У одной модели anchors повторён после неполученного вывода первого вызова; повтор ничего не изменил.
Это не доказательство одинаковой последовательности всех вызовов.

У судьи уточнено исключение для read-only store list до выбора store, предусмотренное workflow.
В одном вспомогательном JSONL был дублирован короткий хвост предыдущей строки;
он отмечен отдельно, исходный лог сохранён. Итог дополнительно проверен по файлам и настоящему checker,
а не только по этому логу. Ограничение чтения — brief; отдельная файловая песочница не создавалась.

## Временные файлы и границы поставки

Вначале одновременно работали pytest с вложенным Node-набором и лишний отдельный Node-набор.
На C: закончилось место. По замечанию владельца остановлены 41 проверенный процесс тестов;
удалены только 134 их временных каталога, около 2,2 ГБ. Принадлежность подтверждена PID lock
или хешем кода интеграции; reparse-цели не обходились. Свободное место восстановлено примерно до 2,9 ГБ.
Прерванные прогоны не засчитаны успешными. Финальные TEMP/TMP/TMPDIR, pytest basetemp
и npm-cache направлены на X:, Node ограничен четырьмя процессами; повторного заполнения C: нет.
